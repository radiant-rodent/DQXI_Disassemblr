# Native Code

## Two trees

| Tree | Status | Use |
|---|---|---|
| `asm/` | complete, bit-matching | canonical instruction stream and safe fallback |

The assembly tree reassembles to the retail `code.bin` with 0 differences:

```powershell
python tools/build.py
```

## Ghidra export

The readable C came from a raw ARMv6 import:

- binary: `original/exefs/code.decompressed.bin`
- base: `0x00100000`
- language: `ARM:LE:32:v6`
- loader: `BinaryLoader`
- function seeds: `decomp/function_seed.tsv` (18,787 entry points with ARM/Thumb mode)

The project is `decomp/ghidra_project/DQXI`. `tools/ghidra_scripts/ExportDQXI.java` creates
missing functions, sets Thumb mode where needed, decompiles, and writes one `.c` per function.
`tools/ghidra_scripts/DiagnoseMissing.java` recovers entry points that overlap an existing body.

Coverage:

- 18,748 decompiled;
- 38 addresses covered by a containing function (jump-table/label entry points);
- 1 unresolved address (`0x003D7BC8`);
- 0 decompiler failures.

`decomp/ghidra/COVERAGE.md` is regenerated by `tools/organize_ghidra.py`.

## Reading the C

`undefined4`, `uint`, `byte` and friends are presentation types from `dqxi_types.h`. Unknown
functions are named `FUN_<address>`. The core loop is:

1. open the address in `functions_merged.jsonl`;
2. open the `.c` file under `functions/`, `recovered/`, or `by_subsystem/`;
3. resolve calls through the index or `symbols.json`;
4. check field offsets against all call sites before promoting them to a struct.

Some functions still contain decompiler artifacts (`VectorSignedToFloat`, invalid control flow
from overlapping jump tables). Those are visible and honest; they are not hand-written code.

## Re-running

```powershell
python tools/organize_ghidra.py
```

This rebuilds the subsystem view, `functions.h`, `dqxi_types.h`, `functions_index.json`, and
`functions_merged.jsonl` from the raw export.

## Source replacement roadmap

The assembly remains the build source for most functions today; four functions are now compiled
from C. To make the readable C canonical, the next steps are:

1. recover real signatures and structs for a subsystem (start with memory/heaps);
2. compile with an ARMv6K toolchain using the original ABI;
3. replace the corresponding assembly range in `tools/build.py` and verify with `tools/diff.py`;
4. repeat per subsystem, keeping the bit-matching gate green.

This is intentionally incremental: a broken C file must never silently corrupt the ROM build.

## Syntax diagnostics

`python tools/check_ghidra_c.py --sample 100` compiles a random sample against the presentation
header. Current result: 26/100 pass; the rest expose real Ghidra artifacts (undeclared `DAT_`
globals, call-signature mismatches, built-in vector helpers). This is a reading tree, not a
buildable target yet. Use it to inspect logic, then replace functions incrementally under the
assembly verification gate.

## Clean subsystem models

`src/` contains 19 hand-oriented C files (memory, save, UI, battle, field, audio, graphics,
kernel, input). Start with `src/README.md` when you want readable logic without Ghidra artifacts.
These files are not yet the canonical build source; they are the bridge between the decompiler
output and a future source-replacement build.
