# Editor TODO — what a Godot-style DQXI Studio still needs

The shell and the level editor were reworked after Godot's editor (see
`viewer_rs/src/ui/shell.rs` and `viewer_rs/src/ui/panels/editor.rs`):

| Godot idea | DQXI Studio today |
|---|---|
| Menu bar (Scene/Project/Editor…) | File / Edit / View / Go / Help, with shortcuts shown |
| Workspace tabs (2D / 3D / Script / AssetLib) | Home · World · Assets · Data · Play, with section tabs under them |
| FileSystem dock | **Project dock** (Ctrl+B): every level, area, model, texture, sound, layout, table and script in one filterable tree; Enter/click opens it in its editor |
| Quick Open (Ctrl+Shift+O) | **Quick Open** (Ctrl+P) across all resource kinds |
| Output dock | **Output** (Ctrl+J): every status message with a timestamp, Copy / Clear |
| Scene dock | **Scene** tree of the open level: grouped nodes, filter, keyboard navigation, modified marker |
| Viewport toolbar + gizmos | Select / Move / Rotate / Scale (Q W E R), snap with a step, axis gizmos, focus (F), View menu |
| Inspector | **Inspector**: coloured X/Y/Z transform rows, per-field reset, record info, file fields, Changes list with revert |
| Command palette (Ctrl+Shift+P) | **Command palette**: type `>` in Quick Open, or Ctrl+Shift+P; save, undo, tools, docks, export, play, go-to-section |
| Unsaved-changes indicator | window title dot, status-bar `unsaved` count with a tooltip (open level, modified table cells) |
| Layout Inspector | in Assets > Layouts, click a pane in the preview to select it, drag it or edit translate / rotate / scale / size / text in the Inspector; undo, revert, a changed-panes count, and Save to mod (rebuilds the BFLYT and its pack through `tools/asset_replace.py`) |
| Delete actors | Delete on an actor removes it (array element) or masks it out (lone element); emulator-proven on the church priest |
| Actors (NPCs and field monsters) | the Scene tree has an **Actors** group; the viewport shows orange markers with a facing line; the Inspector edits position, facing and the typed **Properties** (entity id, entity class) with reset, undo, Changes and Save to mod; Duplicate adds a real NPC (emulator-proven) |
| Actor models | actors show the real model the game uses (id -> region npc_list -> res_model3d, docs/LEVEL_FORMAT.md "SOLVED") for NPCs and monsters in every level; Entity group has a character picker per region |
| Collision from a model | `tools/rcb_tool.py from_obj` builds a level's collision from an OBJ (`add_mesh`); see docs/COLLISION.md |
| Collision overlay | View > Collision draws the level's wall collision (`3d/bg/<level>/<level>_chit.rcb`, red = wall, teal = floor) in the viewport; the Inspector has a Collision group listing the shapes by name, click one to highlight it. Select a shape in the Collision group and drag its X/Y/Z offset: the overlay moves it, Save to mod writes `3d/bg/<level>.pack` with the moved shape (`tools/asset_replace.py` + `tools/rcb_tool.py translate_shape`; the same edit is emulator-proven, docs/COLLISION.md). Delete shape and Add box are emulator-proven; Restore shape. Undo collision edit (clicked in the real app). Not yet: rotated shapes, general triangle meshes in the editor |
| Gimmicks (chests, search spots, doors) | the `+0x240` records appear under **Gimmicks** labelled with their contents (`Flintstone x1`); the Inspector shows the item and count and the editable **drop row** (row of `fieldcmn/fixed_drop_param`; emulator-proven, docs/GIMMICK_DECOMP.md) |
| Reshaping and growing geometry | a cloned level slot can have its background reshaped with same-count vertex edits (`tools/model_patch.py`) and a draw call can be replaced by a bigger one (`tools/bch_writer.py grow_draw`; emulator-proven with a duplicated, lifted wall shell, docs/MODEL_IMPORT.md). OBJ import (`tools/model_import.py`, emulator-proven for one draw, attributes from the nearest original vertex); OBJ texture coordinates are applied (emulator-proven); OBJ normals are written (n * 127 byte normals); several draws can be replaced from one OBJ (`o draw<N>` groups); new materials and textures are next (CL3) |
| New maps | a level slot can be taken over with edited clones of another level (`tools/new_map.py`, FNV-1 64 pack-name hash decoded; emulator-proven: the church door to `b002_106a` loads the cloned house). A spare level_map row can also be re-pointed. Brand-new pack names need a rebuilt ROM (LayeredFS only replaces existing paths). **Level** (toolbar) opens a *Clone level into slot* window: pick a slot, optional background .bch, **Clone into slot** writes the three packs into mod/romfs (clicked through in the real app: all three packs written; compressed bg packs are handled too) |
| Exits | the level's map-jump table (+0x68) is listed under **Exits** with the destination level name, **Open level** and a destination picker (editable; PROVEN in the emulator: editing it re-routes the exit, docs/LEVEL_FORMAT.md) |
| Triggers (event volumes) | the container `+0x1B8` records appear as a **Triggers** group; the Inspector shows the level-local trigger id (`+0x28` low word). Corrected: it is NOT a map id (b001_101a has ids 0x100,0x103,0x184,0x11a.. ; child arrays hold event ids like 0x202f2de). Where a door leads is decided by script; the destination picker was removed |
| Dialogue Inspector | the Game text editor has a collapsible **Inspector** (bank, pack / member, category, font and box size, entry id and offset, role, speaker, location, length in characters / lines / pages, unchanged or edited state) above the editor and preview |
| Table Inspector | Data > Tables has a right-hand **Inspector** (Table, Schema with row count and size and whether field names are known, Changes with Save to mod and Revert all). Seen empty only; not checked with a table open |
| Audio Inspector | Assets > Audio has a right-hand **Inspector** (Stream, Format, Actions; read-only, loop points not editable yet). Textures already had a side panel with the export and replace workflow |
| Stage a model | Level > Clone into slot takes an optional background model (.bch, e.g. written by Import OBJ) and stages it into the cloned slot in one step (`tools/new_map.py --bch`) |
| Custom textures | a model texture can be replaced by a PNG (`tools/bch_texture_patch.py`) and shows on imported geometry in the game (emulator-proven, docs/MODEL_IMPORT.md); brand-new materials are not possible yet |
| Import OBJ | (clicked through in the real app: path typed, Import pressed, the .bch was written and parses with the box) the Models Inspector has an **Import OBJ** action (OBJ path, draw number, Import): runs `tools/model_import.py` and writes `build/exports/models/<name>_import.bch` |
| Model Inspector | Assets > Models has a right-hand **Inspector** (Model, Geometry, per-material groups, Actions). Read-only for now: the tools cannot edit materials yet (task ED_asset_inspectors; textures and audio still lack one) |
| Entities | actors resolve to their monster (name, model, Japanese name) from `gamecmn/enemy_base`; **Show model** jumps to the Models panel; **Change to monster...** is a searchable picker over all 1,043 monsters |
| Multi-select | Shift+click (viewport marker or Scene tree row) adds or removes nodes; the Inspector shows **Selection (N nodes)** with Move all by (X/Y/Z), Delete all and Clear selection, one undo step each (group delete clicked through in the real app). **Drag with the Select tool (Q)** or **Shift+drag** in any tool draws a selection rectangle and selects every marker inside (drag driven in the real app: 9 nodes selected, Selection (9 nodes) shown, all nine rows highlighted in the Scene tree). Dragging the Move gizmo of the primary node moves the whole selection (driven in the real app: dragging Placement 001's X arrow moved all 9 selected nodes, Changes (9)) |
| NPC dialogue | actor Inspector > **Dialogue**: every conversation of the NPC (story-flag condition, time of day, redirects, variants played in turn) with the lines shown as the player reads them (ruby and line breaks resolved) and an **Edit** button per line for the raw tagged text, and a dot plus **Revert** on lines that differ from the game file (builds; not clicked), **Save dialogue to mod**, and a warning with an **Open script** button when the area script starts an event for that character (`tools/npc_talk.py`, docs/DIALOGUE_FORMAT.md). Opened in the real app on the church NPC and expanded; typing and Save not clicked through; an edited line is emulator-proven to show in the game through a test event (docs/DIALOGUE_FORMAT.md); pressing A on the NPC itself not tested; selection rule read from the decompilation, not emulator-proven. Switching to an NPC of another region while the current bank has unsaved edits is blocked with a Save button (so no edits are lost). Each conversation also has **Appears when** controls (story-flag group, minimum, time of day) and **Save conditions to mod** (`tools/npc_talk.py set-cond`, applied after text edits by `text_tool save-mod`; the 2-byte patch checked in memory, the editor controls built but not clicked, not emulator-tested). Not yet: adding or deleting conversations, naming the story-flag groups, editing the event scripts inline |
| Drag and drop | model rows in the Project dock can be dragged (a ghost label follows the pointer); the actor Inspector's Entity group has a **drop zone** that sets the actor's NPC row from the model name (matched in the level's region table, `_h`/`_l` stripped), or says no row uses it. Drag and drop driven in the real app (the "no NPC row" answer); a successful match is not clicked through. Not yet: dropping into the viewport or other fields |
| Dock sides | the Level toolbar **View > Swap dock sides** puts the Inspector on the left and the Scene dock on the right (clicked in the real app; saved in `editor_prefs.json`). **View > Float Scene dock / Float Inspector dock** turns a dock into a free window (movable, resizable, closable; clicked in the real app: the Scene dock floated and the viewport widened; saved in `editor_prefs.json`). Not yet: dragging a dock by its title to a side, tabbing docks together |
| Dock toggles | the Level toolbar **View** menu shows or hides the Scene and Inspector docks (the viewport widens; the choice is saved in `editor_prefs.json`; hiding the Inspector clicked in the real app). Both docks were already resizable by dragging their edge. **View > Reset layout** (menu bar) restores the Project, Scene and Inspector docks, hides Output and sets UI scale 1.0 (clicked in the real app with both docks hidden) |
| Keyboard shortcuts | **Help > Keyboard shortcuts** opens a window listing every shortcut (everywhere, viewport, Scene tree), opened in the real app. Display only; rebinding is not built |
| Actor display mode (was "layer") | the actor Inspector says in which view the actor is created (3D only / 2D mode only / both) from the high byte of its entity class, which the level loader uses as a display-mode mask (decompiled, docs/CUSTOM_ROOM.md "SOLVED"); a class-0x200 NPC never appears in the normal 3D view; it also shows the record's **level group** (top byte of `key 60`), which the area script enables or disables, so a copy of a disabled group's record stays invisible (docs/CUSTOM_ROOM.md "Correction of the correction"). Built; the Inspector lines were not re-checked in the app after the last edit. The Scene dock has an **actor display-mode filter** (all / 3D mode / 2D mode, shown when a level mixes masks). Not yet: Duplicate defaulting to a visible class |
| Symbols (candidate monsters) | the 104-byte records at container `+0x218` of dungeon levels appear as a **Symbols** group (red markers, position at `+0x20`, editable `group` word); opened `d001_001a` in the real app: 8 symbols along the corridors. Their meaning (roaming monsters / encounters) is a lead, not proven (docs/CUSTOM_ROOM.md) |
| Scene hierarchy (first level) | when a level's actors belong to several level groups the **Actors** group splits into collapsible **Level group N** sub-groups (church: group 10 with two actors, group 11 with one); seen in the real app. Other kinds and real parent / child nodes are not done (ED_scene_hierarchy) |
| Demo button | the Level toolbar's *Clone level into slot* window has a **Demo** section with **Build demo room into mod/** (runs `tools/custom_room.py build --mod mod` with the church donor): the church door then leads into the custom room with an NPC who says the new line. The window was opened in the real app; the button was not clicked (it would overwrite files in mod/) |
| Duplicate keeps actors visible | Duplicate (Ctrl+D) of an actor whose class mask excludes the normal 3D view (class 0x200) sets the copy's class to 0x300 and says so in the status bar; the level group is kept (builds, unit tests pass; not clicked in the app, not emulator-tested as a whole; the mask rule is from the decompilation, the 0x300 copy of `0x152C` is emulator-proven) |
| Actor tags in the Scene tree | actor rows end with `[g10]` (level group) and `3D` / `2D` when the actor is created in one view only, e.g. `Actor 006 . cha02142a [g10 2D]`; the church's priest copy that works is `[g11]` (clicked through: seen in the real app) |
| Scene tree context menu | right-click a node: Focus, Duplicate, Delete (acts on the whole selection when several are selected), Clear selection (opened in the real app; Delete clicked from the menu and marked the actor deleted) |
| Duplicate / delete nodes | Ctrl+D and Delete (or the toolbar buttons) copy or remove a record; the level is rewritten with the array moved to the end of the file, nothing else shifts |
| Undo/Redo (Ctrl+Z / Ctrl+Y) | Edit menu follows the front editor: Level Editor (one step per drag or burst of field edits), the table editor, layouts, and the dialogue text editor (typing in one line is one step; unit-tested, not clicked through in the app) |
| History dock | toolbar **History** opens a window listing every level edit step (newest first, "Now" at top, "Original" at bottom) with what changed; clicking a step goes back to the state before it and the later steps move to the redo stack (clicked through in the real app). Level edits only; dialogues, scripts and layouts are not in it yet |
| Several scenes open | any number of levels stay open at once; edits, undo history, selection and camera are kept per level, and Save All writes every unsaved one |
| Viewport preferences | snap on/off and step, and the View toggles (grid, axes, labels, bounds, collision, markers) are written to `editor_prefs.json` when they change and restored at start (driven in the real app: a hand-written file produced snap 0.50, no grid, labels on). **Edit > Preferences...** opens a window with the same toggles plus a UI scale slider (0.75-2.0, saved in `editor_layout.json`); both checked in the real app (at 1.4 the whole UI scales and the Level toolbar wraps onto a second row instead of overlapping). Not yet: theme, fonts, keybindings |
| Saved layout | dock visibility and Project tree expansion are restored from `editor_layout.json` |
| Quit prompt | closing the window with unsaved edits shows an **Unsaved changes** dialog listing them: Save all and quit, Quit without saving, Cancel (all three clicked through in the real app) |
| Save All (Ctrl+Shift+S) | saves the open level, table edits and script through their own save paths |
| Script tabs | **Document tabs** under the section tabs: every resource you open stays one click away (middle-click or x closes; a dot marks an unsaved level) |

## Not provided yet (worker-board tasks `ED_*` in `orchestration/tasks/`)

1. **ED_scene_records** — actors can be added (Ctrl+D) and moved, and the game accepts an appended NPC
   (emulator, Cobblestone church). Duplicating a whole layer container crashes the game and is refused. Still
   missing: proof for deleting records and for 68- / 120-byte placements, creating a node of a kind the level
   does not already contain, moving nodes between containers, and a check of which scripts address records by index.
2. **ED_scene_models** — monsters now resolve to a model (see above); still missing: drawing that model at
   the marker instead of a dot, and resolving NPC ids (`npc_list`) and other record kinds to models.
3. **ED_scene_hierarchy** — parent/child nodes from the record `path` (`root/+0x38/items[0]/…`)
   instead of two flat groups, with reparenting disabled until the writer exists.
4. **ED_global_undo** — the Edit menu already routes to the level and table editors; still missing:
   a shared History dock (the script editor is a code text box with the text widget's own Ctrl+Z while focused, not the Edit menu; dialogues and layouts have undo, but only levels are in the History dock) (the dock itself exists for levels).
5. **ED_dirty_registry** — title dot and status-bar count cover levels, table cells, scripts and
   dialogue lines; Save All covers levels, tables, scripts and the open dialogue bank.
   Layout panes are covered (unsaved count and Save All). Models, textures and sounds have no in-app edit state:
   they are edited by exporting, changing a file outside the app and replacing (see ED_asset_inspectors).
   The quit prompt is in.
6. **ED_docking** — levels can be open side by side as tabs, but other editors (tables, models)
   still keep one live state each; dock show/hide exists; dock sides can be swapped and the Scene / Inspector docks can float; still missing: dragging a dock to a side by its title, tabbed docks, other editors' docks,
   and per-dock sizes in the saved layout.
7. **ED_multi_select** — box select and shift-click are in; group Move gizmo is in; rotate/scale of a group is not.
8. **ED_command_palette** — the palette exists with a fixed command list; still missing: a single
   registry shared with the menu bar, per-panel commands, and rebindable shortcuts.
9. **ED_asset_inspectors** — layouts now have an in-app Inspector (see above). Still viewers plus an
   export / edit-elsewhere / replace workflow: models (material blend and alpha, texture slots, bone
   transforms), textures (format, mip levels, pixel editing), sounds (loop points) and the BFLAN
   animations of layouts. Layouts still cannot add or delete panes in-app (`add_pane` exists in
   `tools/layout_tool.py`). Each needs undo, a Changes list, revert and a dot in the unsaved count.
10. **ED_project_dock_thumbs** — model drag-and-drop onto the actor Entity slot exists; still missing: thumbnails and dropping into the viewport and other asset fields.
11. **ED_preferences** — viewport toggles and snap persist; a Preferences window exists (viewport toggles, snap, UI scale); still missing: theme, fonts, keybindings.
12. **ED_level_2d** — edit `level2d` data (the 2D side of every map) in the same Scene/Inspector
    layout.
13. **ED_play_in_editor** — "Play this level" from the toolbar: stage the mod and boot Azahar
    straight into the open map.
14. **ED_dialogue_conversations** — add / remove conversations, name the story-flag groups, prove A-on-NPC in the street (`orchestration/tasks/ED_dialogue_conversations.md`).
15. **ED_materials** — brand-new materials for imported models (`orchestration/tasks/ED_materials.md`).
16. **ED_custom_room** — `tools/custom_room.py` (docs/CUSTOM_ROOM.md): entrance through a church exit, cloned slot with a custom room model, an NPC added by the record tools who answers A with an edited `npc_ie` line (all emulator-proven, `cr_23952`). Monster model placed in the room (proven, `cr_24056`). Open: the chest, a monster battle on touch, and doing all of it from the Level Editor instead of the script.
17. **CL_cloned_slot_actors** (superseded: duplicates must be made in the ACTIVE layer, see docs/CUSTOM_ROOM.md; the Level Editor should show a record's layer and warn when it is inactive) — solved in principle: actors spawn in a clone; the generated collision (`rcb_tool.from_obj`, header bounds shrunk to the room) removes actors that stand outside it (docs/CUSTOM_ROOM.md, bisect table). Next: make `from_obj` keep the bounds of the donor / cover all actor positions, then press A on the NPC / chest / monster.
18. **CL_field_monster** — a placed monster must start a battle on touch (`orchestration/tasks/CL_field_monster.md`).
