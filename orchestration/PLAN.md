# Master plan — DQXI 3DS: readable source + tailored game editor

Goal: the whole game (native code + scripts + data + assets) is readable and editable by a person
who just opened this folder, through a purpose-built editor ("DQXI Studio", the Rust app in
`viewer_rs/`), with one-click test (emulator) and export that runs on a real 3DS/2DS.

## State at plan time (2026-10-25)
- Tools exist for: ROM extract/repack (bit-matching), code.bin disasm/rebuild, Ghidra export,
  `readable_c.py`, Squirrel script decompile, BXON tables, BCH models, textures, layouts, audio,
  maps; Rust viewer/editor with panels for all of these.
- **Generated data is missing** (`original/` extracted parts, `decomp/`, `game_assets/`,
  `game_data/`, `build/`). Must be regenerated first (P0).
- Only ~460 of 18,787 native functions are named. Naming is the main readability gap.
- No emulator-playtest or mod-export path in the editor yet.

## Progress tracking (for humans) — modelled on AnyPS5's progress page
`tools/progress.py` → `progress/`: `progress.html` (tables per subsystem: named/documented/total
functions, scripts, assets per family, editor features, with %), `progress.svg` (coverage map: one
cell per function grouped by subsystem, coloured unnamed/named/documented/matching-C), badges,
`progress.json` (raw), `history.html` (one point per day from `progress/history.jsonl`), and
`tasks.html` (live worker board from `orchestration/state.json`, logs and done reports).
The dispatcher regenerates it after every finished task. Open `progress/progress.html`.

## Conventions
- Naming proposals: `orchestration/naming/out/<batch>.json` →
  `[{"address":"0x...","name":"Battle_CalcDamage","signature":"int Battle_CalcDamage(Unit* attacker, Unit* target)","summary":"...","confidence":0-1,"evidence":"..."}]`.
  Names: `Subsystem_VerbNoun`; confidence < 0.5 → prefix `maybe_`.
- Hardware export: Luma3DS LayeredFS (`luma/titles/<TitleID>/romfs/` + `code.bin`/`code.ips`)
  and a rebuilt `.3ds`/`.cia`. Never emulator-only formats.
- Orchestrator (Claude) only plans, reviews `orchestration/done/*.md`, and writes new tasks.
