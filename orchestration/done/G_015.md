## Key Findings

- **Vtable pointers in retail code**: While virtual method tables reside at `addr`, classes and constructors store `addr + 4` (pointing directly to slot 1, the deleting destructor) in the object's `vptr`, matching the standard ARM EABI / GCC C++ layout where slot 0 is the offset-to-top/RTTI pointer (0). `structs.json` classes were mapped accordingly.
- **Field2D power-of-4 tables**: The 2D field rendering and collision system uses multiple identical 16-entry tables containing `4^0, 4^1, ..., 4^15` (`0x1, 0x4, 0x10, 0x40, 0x100...`). These are indexed by `(delta) * 4` to extract 2-bit per tile layer masks across tile connectivity, grid rendering, tweening, and bob motion routines.
- **Trigonometric Fast Sin/Cos Table**: `0x0072FC50` is a 1024-float (4096-byte) table containing 256 entries of 4 floats each: `(sin(θ), cos(θ), sin_step, cos_step)`. It is accessed via `std_FastSinCos` and matrix composer functions via `(angle & 0xFF) * 0x10`.
- **NPC Emote System**: Field NPCs index `0x007263A7` (`g_fieldNpcEmoteBalloonEnabledTable`) and `0x007263ED` (`g_fieldNpcEmoteFaceStateTable`) using style byte `self->f_313` across 9 balloon/talk setup routines.
