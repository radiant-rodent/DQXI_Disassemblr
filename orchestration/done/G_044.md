# G_044 — Script globals (118) — DONE

## What was done

No earlier `orchestration/types/out/G_044.json` existed, so the batch was completed from scratch.

All 118 batch globals were resolved against the retail image (`build/code.bin`): for every record I
read the 32-bit word at each `literals[]` address and confirmed it equals the batch `address`
(118/118, 0 mismatches). Names/types were then derived from the string bytes, the referencing
function, the Ghidra pseudocode, and the surrounding data/BSS layout.

### Categories

1. **105 binding arity messages** (`0x007C15AF`..`0x007C20A7`, `.data`)
   - `char[27]` each, content exactly `"wrong number of parameters"`, laid out 0x1B bytes apart.
   - One copy per `Script_Bind_*` native binding; each is passed to `Script_Vm_ThrowError` on a
     wrong argument count.
   - Named `g_scriptBind<BindingName>ParamCountError`, e.g.
     `g_scriptBindCameraReguralyShakeStopParamCountError`. Confidence 0.90.

2. **`"integer"` type-error messages** (`0x007C20C2`..`0x007C20E2`, `.data`)
   - `char[8]` each; passed as the expected-type argument of `Script_FormatTypeError`
     (`0x00576564`), which formats `"wrong type (%s expected, got %s )"`.
   - `g_scriptGetByteArgTypeErrorInteger` (0x007C20C2),
     `g_scriptGetIntegerArgTypeErrorInteger` (0x007C20CA),
     `g_scriptGetIntArgTypeErrorInteger` (0x007C20D2),
     `g_scriptBindTypeErrorIntegerShared` (0x007C20DA; shared by `Script_Bind_AddPartyMemberHP`
     and `Script_Bind_Effect2DMove`),
     `g_scriptPlayerResurrectTypeErrorInteger` (0x007C20E2). Confidence 0.75–0.80.

3. **`0x007C20EC` `g_sqNullObjectRef`** (`u32`, confidence 0.60)
   - Image word is zero. `Script_RegisterSubThread` and `Field_SceneSubObject_Ctor` both load this
     address and copy the value into a Squirrel closure/reference field, i.e. it is the shared
     null reference source (not a real object).

4. **5 callback arity messages stored into the error state** (`0x007C212B`..`0x007C21E8`, `.data`)
   - `char[27]`, same `"wrong number of parameters"` text, but copied with `Str_CopyAllocated`
     into `func_005766A4()+0xC` instead of being thrown.
   - One per callback dispatcher:
     `g_scriptCallEventHandlersParamCountError` (maybe_Script_CallEventHandlers),
     `g_scriptCallBookIdCommandParamCountError`,
     `g_scriptNativeATrgMapJumpEventParamCountError`,
     `g_scriptCallSelectRuraPatternParamCountError`,
     `g_scriptCallSelectRiremitoUsableParamCountError`. Confidence 0.85.

5. **`0x008385F0` `g_sharedFormatBuffer`** (`char[256]`, confidence 0.75, BSS)
   - 0x100-byte scratch buffer passed as `(buffer, 0x100, fmt, ...)` to `func_00100188`
     (a variadic `vsnprintf`-style helper).
   - Squirrel compiler error paths store the pointer in `ScriptCompiler+0x70`
     (`self[0x1c] = 0x008385F0`); `Ui_Window_InitHeader` also formats a window title into it.
   - Size is exact: the next independently referenced BSS object starts at `0x008386F0`.

6. **`0x0083876C` `g_scriptErrorState`** (`u8[140]`, confidence 0.75, BSS)
   - Layout: `+0x00 u8` error flag, `+0x04` VM pointer, `+0x08` value vtable `0x00782514`,
     `+0x0C char[128]` formatted message.
   - `func_005766A4()` returns its address; bindings set the flag and copy the VM/message here;
     VM creation (`maybe_Script_EventVm_Init`) clears it.
   - Size 0x8C is bounded by the next referenced BSS global at `0x008387F8`.

## Open problems / not verified

- The first 105 names are systematic (one per binding) and highly reliable, but the coupling
  “string belongs only to that binding” is inferred from the literal slot in that function; the
  compiler may have emitted copies per translation unit rather than strictly per binding.
- `g_sqNullObjectRef` is the least certain entry (confidence 0.60): it is a zero word used as a
  null source; it may be a compiler-pooled constant rather than a semantically named global.
- `g_sharedFormatBuffer` is genuinely shared between the script compiler and UI code; the name is
  deliberately generic. It is not thread-safe.
- `g_scriptErrorState`'s internal layout is inferred from writes (`+0/+4/+8/+0xC`) and the exact
  size is bounded by the next referenced BSS global, not by an explicit allocation.
- No emulator or in-game test was performed; this task is naming/type metadata only.
