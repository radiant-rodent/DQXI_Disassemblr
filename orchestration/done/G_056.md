## Key finding: the batch is mostly text, not integers

`tools/typedb/inventory.py` only fills `string` for width-1 globals, so 138 words arrived as
`u32` with a numeric `initial_value`. Re-dumping the retail bytes at every address showed:

* **32 UTF-16 format strings** (`L"%ls"`, `L"%d"`, `L"+%d"`, `L"\u00d7%d"`, `L"\u30fb%ls"`,
  `L"\u3000"`, `L"\n"`) - typed `u16[N]`, used with `Ui_TextFormat_ReleaseSlot` /
  `func_00707C1C` / `func_006F0F1C`.
* **ASCII names whose first word was read as an integer**: `field_collision`,
  `mainitem_3d_up.bflyt`, `dive_dngn_damage_3d_up.bflyt`, `ui/item/%s.bch` - typed `char[N]`.
* **8 literal slots that point 1-6 bytes before the text they name** (0x007BFE64, 0x007C016E,
  0x007C2222, 0x007C223C, 0x007C228C, 0x007C2352/54/56, 0x007C26B2). I read the slot words
  directly with `word_at` to confirm this is in the image, not an inventory bug. Those entries
  say so in the comment and stay at confidence <= 0.4.

## Open problems / not verified

1. **~20 `Ui_RegisterStaticObject_7A38xx` targets** (0x007C34FC, 0x007C45F4, 0x007C4644,
   0x007C4720, 0x007C47C0, ...) are only ever passed to their registration function. They are
   `maybe_g_uiStaticObject<addr>` at 0.35 - a refine pass with the registration function bodies
   would name them.
2. **19-byte engine blocks** 0x007F305C / 0x007F4F1C / 0x007F52B8 (122 / 42 / 122 users) are
   `maybe_g_engineGlobalBlockA/B/C` at 0.30. Whether they are one struct or three separate
   objects is unresolved; the 19-byte size hint is suspicious (probably a truncated array).
3. **`Ui_Layout_LoadAndBind_Type1..5` may be misnamed** (R_026, 0.50). Every string they use is a
   `.bxon` data-table name resolved through `Fs_ResourceFindByName`, not a `.bflyt` layout, so
   the functions look like data-table pack loaders. The global names here follow the string
   content (`g_resName...`), so they stay correct either way, but the function names deserve a
   refine batch.
4. **0x007C4C5C** is used as a class descriptor by `maybe_Ui_Component_FindAndNotify` /
   `FindAndSetFlags`; the owning class is not identified (`maybe_g_uiComponentClass`, 0.55).
5. No runtime/emulator check - this is a name/type-only change.
