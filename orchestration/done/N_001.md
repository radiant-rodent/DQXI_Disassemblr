## Decisions
- **The batch label is wrong.** `N_001.txt` says "Battle", but the 20 remaining addresses are engine
  code: FX emitters (`0x0052…`), secondary-motion/soft-body simulation and skeleton math (`0x0056…`,
  `0x0057…`), battle action + unit display (`0x0059…`), scene-node teardown (`0x005C…`), actor movement
  steering (`0x005E…`) and libm (`0x006B…`). I followed the code, not the label.
- Soft-body/scene names use the `Model_` / `Anim_` / `Fx_` / `Battle_` / `Actor_` prefixes; the generic
  maths helpers use `Math_`; the CRT helper uses the allowed `std_` prefix.
- `0x006B8138` really is an **in-place** helper: `std_ParseHexFloat` passes `&double`, so the signature
  is `void std_Scalbn(double* value, int exponent)`, not `double ldexp(double,int)`.
- `0x0059EE14` and the other structural guesses at confidence 0.5 keep a `maybe_` prefix (existing style
  in this file also uses `maybe_` at exactly 0.5); the 12 old entries with the same convention were
  left untouched.
- Rule 7 of the worker rules (full test run) does not apply to naming batches, and the task explicitly
  says to skip it. Nothing in `decomp/`, `asm/` or any other owner's files was modified.
