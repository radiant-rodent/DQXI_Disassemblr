## Method (reproducible)

Throw-away harness in `%LOCALAPPDATA%\Temp\opencode\n022` (nothing added to the repo):

1. **Caller/callee index** — regex over all 18,748 `decomp/readable/{functions,recovered}/*.c`
   files. 81 of the 150 have no `bl` caller after excluding self-recursion; that is itself
   evidence (vtable slot, inlined helper, or dead/unreferenced code).
2. **Name merge** — `symbols.json`, `symbols_recovered.json`, `decomp/native_names.json` and all
   existing `orchestration/naming/out/N_*.json`, so names are consistent with N_002/N_010 etc.
   (e.g. `Ui_Pane_SetVisibleWithAnim`, `Text_LayoutLines`, `Ui_PartySelectWindow_InitPanes`,
   `Message_SetArg`, `Ui_ActionPane_AnimCtor`, `Ui_EquipmentWindow_Confirm`).
3. **Literal resolution** — every `g_XXXXXXXX` in the batch was read from
   `original/exefs/code.decompressed.bin` (image base `0x00100000`), including pointer-to-string
   chains. This is what proved `0x17E8FC/0x17ED3C/0x17EDE0` (`ui/map/%s`,
   `ui/map/world_map_%c_%s.pack`), `0x1849B4` (`npc_ie.bxon`, `book_ie.bxon`),
   `0x124E6C` (`npc_list.bxon` at its caller), `0x197254` (`icon_next`, `icon_prev`),
   `0x1473EC` (`cannot serialize a %s`), `0x1651CC` (`invalid or corrupted closure stream`) and
   `0x1833E8` (animation-name table `Nut`/`Ecstacy`).
4. **Script-native table check** — the game's native registration table at `0x0024A1C8..` was
   parsed as `{function pointer, inline NUL-terminated name}`; it has 455 entries. **None** of the
   150 batch addresses is a bound Squirrel native, so these are internal helpers of the native
   layer, not the `native_names.json` entries. That ruled out a tempting but wrong shortcut.
5. **Disassembly cross-checks** — for helpers Ghidra rendered poorly, the annotated asm was read:
   - `0x1902A4` = `ldrh r2,[r0,#0xda]; bic r1,r2,r1; strh r1,[r0,#0xda]` → clear-flag-bits
     (this is what makes the `Actor_ClearStatusFlags` family defensible).
   - `0x1902B4` = copies actor `+0x14/+0x16` to `+0xe8/+0xea` and returns `actor+0xc8`, the
     equipment/inventory sub-block used by `Party_AddEquipmentBonus`.
   - `0x35EB98` = `world + 4 + id*0x4bb*4`, i.e. a **0x12EC-byte actor record array**.
   - `0x6291EC`/`0x629214` count non-`0xFF` bytes in the 40-byte array at `+0x1274` and the
     60-byte array at `+0x129c`; `0x6298E0`/`0x6298F0` read one byte from each → the
     `Party_AddInventoryItem`/`Party_HasInventoryItem`/`Party_HasBagItem` trio.
   - `0x613FC0` clamps a subtraction at zero on `world+0x24a98+0x28` (the field used by
     `Party_SpendGold`, `Shop_CanAfford` and `Shop_BuyItem`).
   - `0x1901F4` shifts/clears the 0x18-slot equipment array at `+0xec` (this corrected the last
     entry from "remove item" to "unequip selected item").
6. **Bottom-up order** — leaf getters/setters/flag helpers first, then the callers (shop, dialog,
   equipment list, world-map loader).

## Confidence notes

  the resource lookup (`Fs_ResourceFindByName`), the record reader (`Fs_ReadRecord`,
  `Fs_ReadRecordBlock`), the name sort/comparator pair, the party-select window setup, the
  message pager, `Shop_BuyItem`/`Shop_CanAfford`, `Ui_ActionPane_Init`, `Ui_ActionWindow_Setup`
  and the typewriter timer.
- **0.5 – 0.59 (44)**: actor flag/visibility helpers, inventory helpers, event dispatch tables,
  map/section setters, action-window/equipment-list handlers, item-list removal. The role is
  proven by the field offsets and callers; the owning class is inferred.
- **< 0.5 (94)**: mostly (a) the low-address Nintendo-SDK runtime (`Os_*`, `Fs_*`, TLS/syscall
  wrappers, mutex/lock helpers) where the public `nn::` names are not present in the binary,
  (b) dialog state-machine variants whose exact page class is not distinguishable, (c) tiny
  one-line trampolines, (d) decompiler-damaged functions (`0x153D18`, `0x166056`, `0x167210`,
  `0x193450`, `0x17EDE0`). For these the name states only the role that is actually visible.

## Honest gaps / not verified

- The low-address cluster `0x00106440–0x00124E6C` is Nintendo SDK/runtime, not game logic.
  SVC `0x32` and the TLS command ids `0xa0000`/`0xb0000` are private to the SDK; I could not map
  them to public `nn::os`/`nn::fs` names. `0x0010F3E0` is called a party **save snapshot** because
  its four callers load/verify an exact 0xc8b0-byte blob with a CRC32 (`0x51BB08`) and copy 31
  actor `+0xc8` blocks; I did not verify it against an actual save file.
- `0x0014ECF8` is called a sound decode-buffer init from the 1.5-bytes/sample buffers, the 0x80
  silence fill and the caller `0x6B9254`; it could be a glyph/texture cache instead. This is the
  weakest "specific" name in the batch and should be re-checked before merge.
- `0x001833E8` is a by-name animation lookup (the table's first strings are `Nut`/`Ecstacy`), but
  `func_005F7948` itself was not decompiled, so whether it plays or merely loads is inferred.
- `0x001585F8` is a table multiplier used from battle code; the exact stat (damage, drop rate,
  experience) is not proven.
- 81 addresses have no direct caller. Some are certainly vtable slots or reached through computed
  dispatch; a few may be dead code. I did not prove liveness for them.
- The `0x001522A8` 31-actor init loop and the `0x00174E40/0x0017505C` 0x50x5 slot tables are
  described structurally; the game-facing feature names (which screen/phase owns them) remain
  hypotheses.
- Nothing was booted or emulated. No test suite was run (naming batches are exempt per the task).
  Mechanical validation: JSON parses; 150/150 addresses exactly in batch order; 150 unique names;
  no name collision with any other `out/N_*.json`; all seven keys present; every signature
  contains its own name; every `params` map is `param_1..param_N` and matches the signature arity;
  `confidence < 0.5` exactly for the `maybe_` names.
