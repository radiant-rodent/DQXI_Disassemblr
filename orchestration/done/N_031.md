# N_031 — naming batch `0x0064D488-0x007218A8` (113 functions)

**Status:** completed. Lane was a resume with *no* prior work (no JSON, no done report, no log
entry, `state.json` only `RUNNING`), so all 113 entries were produced from scratch.

Deliverable: `orchestration/naming/out/N_031.json` — 113 objects, exact batch order, 113 unique
names, one per address in `orchestration/naming/batches/N_031.txt`.

## Method

1. **Context first.** Read `README.md`, `orchestration/PLAN.md`, `docs`-level conventions and the
   existing `out/N_*.json` style (especially N_029/N_030) before touching anything.
2. **Merged name map** from `symbols.json`, `symbols_recovered.json`, `decomp/native_names.json` and
   all 27 existing `orchestration/naming/out/*.json` (address -> name, 4.7 k names).
3. **Caller index**: scanned all 18,159 `decomp/readable/functions/*.c` for call tokens, giving a
   reverse-caller map (11,453 distinct callees). This is how the 60+ functions without a direct
   caller were placed at all.
4. **Annotated digest** (`%TEMP%/opencode/n031/gen.py`): per batch function, the stripped readable C
   body plus every callee with its resolved name and signature, its callers, and its string literals.
5. **Assembly for damaged bodies** (`asm/text/text_00xxxxxx.s`) — required for ~15 functions where
   Ghidra either truncates the body (`halt_baddata`, `does not return`) or loses the arguments.
   This is where most of the real progress came from (see findings).
6. Squirrel scripts in `game_assets/scripts/` were grepped for the relevant native names
   (`GetPartyMember*`, `GetPlayableMemberNumber`, ...) to confirm that this range is internal code,
   not bound natives (matches N_030's finding about the native-registration blob).

## Cross-cutting findings (reusable by other lanes / M1_merge_names)

- `0x00100B74` is a **Thumb UTF-16 `strlen`** (`ldrh/cmp/bne`, `bx lr`), not a noreturn abort.
  Ghidra's "Subroutine does not return" on ~10 functions in this batch is wrong; reading it turned
  `0x66AD94`, `0x66B19C`, `0x66B1FC`, `0x66B264` and `0x7088A8` from stubs into real functions.
- `func_0035EB98(base, id)` = `base + 4 + id * 0x12EC` → **character work record** (31 slots;
  31*0x12EC = 0x24A94, which is exactly where `Work+0x24A98` begins). `f_D8` in those records is the
  **level** (used to grade enemies in `0x64EF98`).
- `Work+0x24A98` is a **sub-object of the global Work** containing, in order: party member-id list at
  `+4` (count in a u16 at `Work+0x27218`, exactly what `IsInParty` walks), a 90-bit id bitset at
  `+0x89A8`, a per-id byte table at `+0x3165`, a 90-entry `u16` table with `0xFFFF` sentinel at
  `+0x27C4`, 5-byte per-id records at `+0x2D2D`, and two 0x8C-byte row tables at `+0x5FE4` /
  `+0x7B3C` (rows: UTF-16 name at +0, id at +0x88). N_030 read the latter two as bag/row tables —
  compatible; the merge should keep one wording for the whole object.
- `func_0066B0E4(base, i)` = `*(u8*)(base+i+4)` (**party member id at index**), `0x66B534` = bitset
  test, `0x66AF08` = `*(u8*)(base+id+0x3165)`, `0x66B17C` = `*(u8*)(base+id*5+0x2D2D)`,
  `0x66B4F4` = first-free index in the `0xFFFF`-terminated u16 table.
- The three tag-string builders `0x28B820` (init) / `0x28B70C` (append weight) / `0x28B71C`
  (evaluate → bool) form a tiny **text-based condition evaluator**. `0x654710` uses it for the
  pre-emptive-strike roll, `0x64EF98` builds the encounter-condition tag set and rolls the
  appearance variant through `0x5F9650(&v,3,...)`.
- `0x71428C-0x7218A8` (41 functions of this batch) are **libstdc++ template instantiations** for the
  bag lists: `__push_heap` / `__adjust_heap` / `__insertion_sort` / `introsort_loop`, each
  identifiable by the comparator it calls (`0x71428C` id, `0x7143A8` name, `0x644154`, `0x6112EC`,
  `0x6113D0`, `0x611460`, `0x611538`, `0x63C16C`, `0x666D7C` monster order) and its element size
  (1/2/4/8/16 bytes). They are named `std_*` on purpose — a precise `Item_*` name would be wrong for
  the generic ones.
- `0x6D3EDC`/`0x6D3F18`/`0x6D3F54` reset slot `i` of three global 0x108-byte **wide-text channels**
  (destroy the heap buffer at +8, restore the inline pointer at +4); consistent with N_028's reading
  of `0x6D3EA0`. My names are `maybe_Text_ResetChannelSlot{A,C}` (0.35).

## NOT verified / open problems

- **List-entry semantics.** `0x64D488`, `0x650804`, `0x651424` (and the cursor/scrollers
  `0x6E4DC8..0x6E5EE4`) filter/scan entries by "id flag bit clear **and** per-id byte < 10". I proved
  the mechanics and the tables they touch, but not whether those ids are characters, items or bag
  rows; the `Ui_List_*` names are deliberately vague for that reason.
- **Decompiler-damaged bodies.** `0x6E59C4`, `0x6E5EE4`, `0x71E598` contain `halt_baddata` /
  bad-instruction truncation; `0x7088A8` keeps only its first basic block (asm shows the kana-table
  name normaliser); `0x66AD94/0x66B19C/0x66B1FC/0x66B264` had to be read from assembly. Their clamp
  arithmetic and argument lists are inferred, not proven.
- **Actor object roles.** `0x64DB70` (visibility flags), `0x66D398/0x66DAD0/0x66DBA0/0x66DD10/
  0x66E2BC/0x66E67C` (teardown / event handlers) are named from structure and neighbours, not from a
  known class name — the classes they belong to are not anchored by any vtable string.
- **`0x66A604`/`0x66A660`** test two pairs of `f_74` bits whose selection depends on the global bytes
  `Work+0x27C5A/0x27C5B`; I could not determine what those switches mean (rows/formation/gender all
  fit), so they are `maybe_Party_MemberFlagPairA/B` (0.30).
- `0x6F2224` is a second lazily-created root singleton next to `Ui_GetCore`; its identity is unknown
  (0.30).
- Nothing was booted, emulated or executed; no behaviour was checked in-game.

## Suggested follow-ups

1. **Promote the tooling**: `%TEMP%/opencode/n031/{gen.py, names.json, sigs.json, callers.json}` make
   an annotated per-batch digest + reverse caller index in seconds. N_028/N_029/N_030/N_033 each
   rebuilt the same thing. A single `tools/naming_context.py` (address -> body, callers, resolved
   callees, strings) would save every future `N_*` lane hours.
2. **Resolve `Work+0x24A98`'s per-id tables once and for all** (bitset at +0x89A8, u16 table at
   +0x27C4, 5-byte records at +0x2D2D, 0x8C row tables at +0x5FE4/+0x7B3C) by looking at the loader
   that populates them; that single answer would let ~25 names in this batch and ~40 in N_030/N_032
   drop their `maybe_`.
3. **Field clock**: add a `docs/NATIVE_STRUCTS.md` note documenting that the timestamp is a 64-bit
   fixed-point tick and that `0x50EB54` returns (year, month, day) via three out-pointers; the seven
   `Field_Clock_Get*` names then become trivial to verify against the clock UI.
4. **Sort family**: add the comparator table (`0x71428C` id / `0x7143A8` name / `0x644154` /
   `0x6112EC` / `0x6113D0` / `0x611460` / `0x611538` / `0x63C16C` / `0x666D7C`) to the same doc so the
   remaining ~40 `std_*` instantiations in other lanes can be named consistently.
5. **Native table**: N_030 found the `{name, argc, thunk, impl}` blob at image offset
   `0x251ca0-0x252520`. Decoding it fully would let `M1_merge_names` auto-name every bound native
   (`GetPlayerID`, `AddItemInPlayer`, ...) instead of relying on script-name matching.
