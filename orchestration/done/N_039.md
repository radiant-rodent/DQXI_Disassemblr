## Important finding: the batch label is wrong

`N_039.txt` is tagged **Camera**, but the tag comes from `tools/make_naming_batches.py`,
which propagates a subsystem label through the *call graph*. The camera seed reached a
very large connected component, so `N_037`–`N_078` (the whole middle of the image) are all
tagged Camera. The actual N_039 range is three different modules:

| Address range | What it really is | Entries |
|---|---|---:|
| `0x0016BA4C`–`0x001762B4` | Battle manager / action queue / targeting / AI / battle presentation | 65 |
| `0x001763FC`–`0x00184EC0` | Field zone check, NPC action & perception, field scene objects, actor spawn/model/equipment, world-map ship icon, pagers and fade window (Ui/Field) | 76 |
| `0x00185720`–`0x00187140` | Squirrel script compiler (lexer-driven recursive-descent parser; `0x005FC86C` is the lexer and the `0x001BCE5C/0x001BDD50` trio is line/column/instruction emit) | 8 |

Only one routine is genuinely a camera routine
(`0x00182B2C Camera_UpdateFollowPosition`, field camera rail/collision follow point), and
one `Model_Equip_UpdateActorEquipment`. Names follow what the code does, not the lane tag.

## Method

1. Read the readable C for **all 150** functions (0 missing files; 7 come from
   `decomp/readable/recovered/`).
2. Identified the shared helpers bottom-up before naming callers:
   - `0x006F1EEC` = lazily created game/world singleton accessor (used ~120 times);
   - `0x002AB62C` / `0x002AB698` / `0x002ABAD8` = container index / find-by-id / enumerate
     active elements (the 4 × 26 unit lists at `world+0x428c`, ally list `+0x4254`,
     enemy list `+0x4270`);
   - `0x00627B24` / `0x00627D04` = battle-busy predicates; `0x16F28C` = insert action slot
     (shifts 0x50 × 0x2c8 slots), `0x16B810` = append action into the current slot,
     `0x3CDF74` = fill one slot + its five 0x8c sub-records;
   - `0x5F5F54` = write a 3-word transform (+ quaternion when arg3 != 0);
   - `0x5FC86C` = Squirrel lexer; `0x1BE454`/`0x1BCE5C`/`0x1BDD50`/`0x1BE384` =
     token line/column, emit instruction, patch line span.
3. Used caller evidence (`decomp/readable` grep) to pin lifecycle functions, e.g.
   `0x16BA4C` is called only from battle teardown (`0x6034BC`, `0x606CEC`),
   `0x16C714` from the battle frame update (`0x606DA4`), `0x16E680` from the battle-scene
   setup (`0x607B7C`), `0x17A7BC` from `Field_InitNpcAction` (`0x1775D4`).
4. Used literals as anchors: `win_fade`, `collision`, `ZONETRUE`/`ZONEFALSE`/`ZonePoint`,
   `Gesture`/`Sleep`/`Ecstacy`/`Mimic`/`FrogJump`, `anim01`/`anim_01`, `defaultTalk`,
   `moveSt`/`movePa`.
5. Cross-checked all names against `symbols.json`, `symbols_recovered.json`,
   `decomp/native_names.json` and every other `orchestration/naming/out/N_*.json`
   (no collisions). Overlapping already-named neighbours (N_001/N_002/N_010/N_022/N_023)
   were used as context, not re-named.

No Squirrel script was needed: the batch contains the script *compiler*, not a bound native.

## Explicitly unverified / weakest calls

- `0x00170450 maybe_Battle_UpdateActionScene` (0.35): clearly an action-presentation
  state machine (effects + model + camera target) but the split between camera, impact
  effect and unit animation is not proven.
- `0x0016D438 maybe_Battle_SpawnUnitEntryEffects` (0.35) and
  `0x00174174 maybe_Battle_SpawnBattleEndEffect` (0.35): the effect-spawn callee
  (`0x3FE054`) is not itself named, so "entry" vs "battle-end" is inferred from the
  manager state/flags.
- `0x0016D258 maybe_Battle_DispatchUnitAction` (0.40): the small function table at
  `self[actionType]` is real, but the individual handlers are not recovered.
- `0x001763FC Field_CheckZonePoint` (0.50): the `ZONETRUE`/`ZONEFALSE` strings are hard
  evidence for a zone test; whether it is a *point* or *volume* test is an interpretation.
- `0x00182B2C maybe_Camera_UpdateFollowPosition` (0.48): strong camera-position structure
  (rail table, collision search, sin/cos, stored camera xyz), but the field names are
  inferred.
- Squirrel parser levels `0x00185E18/0x00186904/0x001869C4/0x00186B28/0x00187140`
  (0.42–0.55): the operator/token structure is clear, but the exact Squirrel grammar
  level (bitwise/xor/and/binary/statement-list) is assigned from token IDs and call
  order, not from a symbol.
- `0x00184958` / `0x001849F0` are decompiled with `unaff_r*` registers (entry points
  inside/next to `0x00184168`); names are deliberately generic (`maybe_...RailActors2`,
  `maybe_...SpawnObjectRecordD`).
- Nothing was executed or emulated. Per the task, the bit-matching test run was skipped
  (rule 5 exemption for naming batches); only JSON-level validation was performed.
