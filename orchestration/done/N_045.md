## Important finding: the batch label is wrong

`N_045.txt` is tagged **Camera**, but that tag comes from `tools/make_naming_batches.py`, which
propagates a subsystem label through the call graph (the same problem already documented in the
reports for N_039–N_043 and N_046). **There is no camera code in this address range.** The batch is
seven adjacent modules in link order:

| Address range | What it really is | Entries |
|---|---|---:|
| `0x00234EBC`–`0x00235804` | scene-object state / sub-slot helpers (component table insert via `0x002A8BA4`) | 5 |
| `0x00235A50`–`0x0023E8AC` | **12-slot on-screen marker overlay** (tagged handle arrays, 12-byte entry list, 17 widget classes, world→screen placement, touch hit-test, collision avoidance) | 26 |
| `0x0023AE34`–`0x0023D68C` | shape/flag scan helpers + **line-ribbon (trail) buffers** submitted to the line renderer | 12 |

| `0x002403B8`–`0x00245BC0` | icon widgets: async resource icon, portrait/face icon, two-state toggle (`syscmn.bch` nodes `g3085`/`g3085_jp`) | 11 |
| `0x00245FD0`–`0x00248AC4` | **Squirrel VM** (default delegates, VM state block, string hash table) | 5 |

The strongest identifications are the ones backed by literals: the Squirrel delegate registrar
(`0x00245FD0`, 24 engine strings), and the event wrappers, whose whole body is
`0x006D4588(self, 0xff, "On…"/"Trg…", arg)` / `0x006D4854(...)`.

## Method

1. Built an index of every address→name pair available (`symbols.json`, `symbols_recovered.json`,
   `decomp/native_names.json`, all other `out/N_*.json`) and a caller index over all 18,748
   `decomp/readable/{functions,recovered}/*.c` files, then dumped one digest per batch function
   (callers, callees with resolved names, globals, string literals, hex constants, body).
2. Read all 150 readable C bodies (0 missing files; 4 came from `decomp/readable/recovered/`).
3. Worked bottom-up: first pinned the hot helpers (`0x006F1EEC` game-work accessor,
   `0x006F20C0` HUD singleton with the `+0x24a98` block, `0x0062AB3C` mode query,
   `0x0063D6B8` per-slot sprite record, `0x0022C148` sprite-from-handle, `0x006D4588` script event
   dispatcher, `0x006BB984`/`0x006BB0F4`/`0x005B4C34` Squirrel call API), then named their callers.
4. Used caller context to separate modules: e.g. `0x00249074`–`0x00257780` only makes sense once you
   see `0x00249DB4`/`0x0024CB38`/`0x00253290` all end in the same dispatcher with different literal
   names, and the `Ui_LoadScreen_*` family only makes sense once you see the identical
   `0x001DAD58`/`0x0062F680`/`f_14(state)`/`f_10` skeleton in all ~30 of them.
5. Named by the state/interaction constant where the semantics were not provable
   (`Ui_LoadScreen_EnterState30`, `Ui_Overlay_UpdateSlotVisibility`) rather than inventing a story.

No Squirrel script under `game_assets/scripts/` was needed: none of these functions is a
script-bound native (the batch is engine internals behind the natives).

## Explicitly unverified / weakest calls

- **The overlay module's purpose is inference.** The twelve slots, the actor ids, the 17 widget
  classes, the world→screen projection (`0x003196D0`), the touch hit-test (`0x0031AD20`) and the
  field-bitmap collision test (`0x0062CB64`/`0x0062C23C`, direction bits 0xb–0xe) are all facts.
  Whether the markers are name plates, damage numbers or bottom-screen map pins is not proven, so I
  used the neutral `Ui_Overlay_` prefix and put the structural facts in each `evidence` field.
- `Gfx_Trail_*` (`0x0023BBD4`, `0x0023BF3C`, `0x0023D518`, `0x0023D68C`, 0.35–0.40): two
  fixed-capacity per-point buffers (56 × 0x30 and 0xee × 0x40) submitted to
  `0x006F511C`/`0x006F4FD8` with per-point width/alpha and raycast clamping. "Ribbon/trail" is a
  shape argument (ribbon vs. rope vs. route line), not a symbol.
- `maybe_Field_FindOverlapIndex` (0x0023AE34) and `maybe_Field_ApplyShapeToTarget` (0x0023B148):
  8-argument and mask-driven, the shape/flag helpers (`0x00649AAC`, `0x00649B48`, `0x00640AC0`,
  `0x00640B8C`, `0x003DF8D8`, `0x002F2210`) are all still unnamed, so "shape test" is as far as the
  evidence goes.
- Decompiler-damaged bodies (`unaff_r*` / `halt_baddata`): `0x00239794`, `0x0023AE34`,
  `0x0024C814`, `0x0024BCB8`, `0x0025BB0C`, `0x0025C1AC`, `0x00241FF0`. Named only from the
  surviving call pattern; each `evidence` says so.
- `0x002403B8` (0.25) is a constructor that only installs static pointers (`PTR_DAT_00240508/…`);
  Ghidra produced mostly dead stores, so the name (`Ui_List_InstallStaticTables`) is deliberately
  vague.
- The `Ui_LoadScreen_*` family (≈30 entries at 0.30) rests on `win_load_main`/`bg_jumon` plus the
  shared state skeleton. The state numbers (0x0b, 0x18, 0x26…) are facts; what each state means in
  the game is not.
- Nothing was executed or emulated. Per the task, rule 5's test run was skipped for this lane; only
  JSON-level validation was performed.
