## Naming notes

- `Battle_UiFlow_*` / `Battle_UiRow_*` / `Battle_UiList_*` (48) is the battle window step
  machine. I deliberately did **not** claim "camp menu": the list it walks is the battle unit
  list (`work+0x4260`) and it drives the battle target window. The summary of each entry states
  the concrete window id, flag and data it touches.
- `maybe_` is used for every entry below 0.5 confidence. The decompiler-truncated bodies
  (`0x2EBB08`, `0x2F2210`, `0x2F22C8`) are at 0.20-0.22.

## Not verified / open problems

1. **Which battle screen exactly.** The mechanics are facts (unit rows, window ids, item/party
   calls, target-window hide), but whether this is the command window, the item sub-menu or the
   message-window sequence of the battle flow is inferred, not proven. The flow also calls the
   menu subsystem (`0x20C294`, `0x20D23C`, `0x20D268`, `0x207DEC`, `0x20F2CC`), which can mean
   either a shared battle/menu UI core or a field menu; the `Battle_` prefix is anchored on the
   battle-unit list (`work+0x4260`) and the target-window call, not on a proven screen name.
2. **Damage window class.** `0x2DBB58` is named from its vtable (`0x760E6C`, slot +8) and its
   neighbours (`0x2DB99C` "Damage" text, `0x2DBB30`), not from a proven class name.
3. **Vtables were recovered from static `.rodata` word tables**, not from loader code; for
   classes with runtime-relocated entries a slot could shift.
4. **Shared engine callees are still `FUN_`**: `0x6F1EEC`, `0x6F1DF8`, `0x6F202C`,
   `0x2AB62C/0x2AB698/0x5797D8` (window/entry pool), `0x5E7848`, `0x617D7C`, `0x27BD68`,
   `0x707E98/0x7141A8/0x714160` (scene entry maps). Names here are only as precise as those
   helpers allow.
5. **Cluster C semantics.** The object is clearly the scene-sprite/draw-entry holder, and the
   slot/handle/region logic is read directly, but whether the regions are used for culling,
   fade or camera occlusion was not proven.
6. **Truncated decompilation:** `0x2EBB08`, `0x2F2210`, `0x2F22C8` (`halt_baddata`) and the
   removed unreachable blocks in `0x2DD958`/`0x2DD81C`; these names describe only the surviving
   code.
7. No Squirrel script was used for confirmation: none of these addresses are bound natives
   (checked against `decomp/native_names.json`; the bound-native table starts at `0x146xxx`).
