# N_055 — naming batch "Camera"

**Status: complete for the assigned scope.** All 150 addresses in
`orchestration/naming/batches/N_055.txt` have an entry in
`orchestration/naming/out/N_055.json`.

Resume check: no `N_055.json`, no `done/N_055.md` and no N_055 entry existed in `AGENT_LOG.md`,
so the batch was done from scratch. Sibling batches N_052–N_054 finished while this one was being
worked on; their outputs were folded into the name map and used to correct two interpretations
(see "Late corrections" below).

## What is actually in the range

The batch header says "Camera", but there is no camera code in `0x0038AB68-0x003A25D0` (this is
the same propagated-label noise as N_045–N_054). In link order the band is:

1. `0x38AB68-0x38AC74` — two battle-actor action helpers: a target-marker/selection update and
   the actor-table resolver. N_054's `0x38AA18 maybe_Battle_Actor_FinishMove` calls the resolver
   directly, which identifies the family.
2. `0x38AD38-0x38BF2C` — the **battle enemy-list window**: seven left/right text rows
   (`txt_l1..l7`, `txt_r1..r7`), seven `win_enemy_select%d` frames, row rebuild, cursor skipping,
   selection commit/clear and the base destructor.
3. `0x38C604-0x38FF08` — the **battle command state machine**: the 29-sub-window container update,
   result dispatch, per-category page openers (item / spell / skill / equipment / tactics /
   special), item/attack/spell/skill target pages, equipment apply and cancel paths.
4. `0x3900F0-0x390E20` — battle command hide-all, the five-pane **party-status row renderer**
   (name, level, HP, two counters), party-window cursor sync, `Ui_BattlePartyWindow_InitPanes`
   (name/hp/num panes and `win_enemy_select1..4`) and row refresh.
5. `0x391070-0x392E00` — the **spell-list and skill-list windows**: entry build/sort, cursor
   select, usability check, list clear, and the deleting helpers. The spell page at 0x38D098 calls
   the 0x391xxx list; the skill page at 0x38D1E8 calls the 0x392xxx list.
6. `0x392400-0x39263C` — battle text-layout object; loads `battle_Text.bxon` and refreshes the
   four party text rows.
7. `0x39314C-0x394D78` — next-battle icon, a two-intrusive-list UI object, the **casino
   slot-machine window** (`belt0`, side lamps, `queen_select0`, freespin/metalchange/queen,
   `menu_casino_jackpot`), save-icon window and three layout-animation wait helpers.
8. `0x39620C-0x39860C` — the **cutscene/TCS scene manager**: loads
   `3d/cs/scenario/%s/%s.pack`, applies 2D/3D layout and layer flags, creates actor models and
   attachments (`cbhm_tcs_mant`), opens message text, advances the timeline and tears everything
   down.
9. `0x398ADC-0x39A6B8` — shared three-line text cache, dungeon-list window, credits/ending pane
   groups, field actor action set (`nut`, `run`, `jump`, `exit`, `skill`, `sklEd`, `dmg`, `dead`),
   attachment update and the field command menu.
10. `0x39AA28-0x39D1BC` — text command executor, emotion balloon (`emotion_chara_ex`), NPC anchor/
    face/move helpers, NPC actions (approach, walk, turn, patrol, idle, LinkEnd, jump, move) and
    the three text-layout/wrapping routines.
11. `0x39EF94-0x3A06E8` — **field-object sprite/draw entries**. These build the scene's
    `Gfx_Scene_AddSpriteEntry*` / `AllocSpriteSlot` records and their debug/display actors.
12. `0x3A11BC-0x3A25D0` — field gadgets: script trigger commands
    (`Field_Gadget_AddAndTriggerCommand`), model-record application, sprite creation, touch/drag
    state and the gadget constructor/destructors.

## Method (reproducible)

Scratch files are in `%TEMP%/opencode/` (`n055_meta.py`, `n055_xref.py`, `n055_str.py`,
`n055_cond.py`, `build_n055.py`, `patch*_n055.py`, `n055_*.txt/json`); nothing was added to the
repo.

1. **Name map** — merged `symbols.json`, `symbols_recovered.json`, `decomp/native_names.json` and
   every sibling `out/N_*.json`, including N_052–N_054 which appeared during the work.
2. **Sources** — read all 150 readable C bodies (no file missing). For the larger functions a
   condensed extractor kept branches, vtable offsets, calls, writes and literals.
3. **Callers** — indexed every `func_XXXXXXXX` reference across all 18,748 readable files to get
   the caller set for each address (e.g. the battle-command callers at 0x0027Exxx, the scene-flow
   callers at 0x0019Fxxx, the field-object builder at 0x0033A140).
4. **Strings / data** — read the actual bytes at every `s_*`/`g_*` address from
   `original/exefs/code.decompressed.bin` (VA-0x100000), which confirmed
   `win_enemy_select%d`, `battle_Text.bxon`, `icon_next_battle_3d/2d`, `win_save_icon`,
   `3d/cs/scenario/%s/%s.pack`, `bt_Dead`, `Act_Def`, `wbhm_grip_on`, `LinkEnd`, `Nut`, `Walk`,
   `nut/run/jump/exit`, `null_ex`/`emotion_chara_ex`, `win_dungeon_list2`,
   `menu_casino_jackpot`, `belt0`/`queen_select0`, and the `%ls/%ls` format.
5. **Window ids** — cross-referenced the battle window factory at `0x0027B86C` (29 sub-windows,
   ids 1/3/5/6/8/0x14/0x15) with the openers here. The item/spell/skill mapping is strong; the
   equip/tactics/special labels in the 0.38–0.40 entries are inferred, not proven.
6. **Sibling cross-checks** — N_016/N_004 already named `Ui_ThreeRowTextWindow_*`,
   `Ui_FourRowTextWindow_*`, `Ui_SlotMachine_*` and `Casino_Slot_*`; those names were reused for
   consistency. Names were collision-checked against every sibling output and the symbol files
   (0 collisions).

## Late corrections (worth knowing)

- **N_054** shows `0x0038AA18` is `maybe_Battle_Actor_FinishMove`, not a UI constructor. The two
  first entries were therefore renamed from a target-marker class to `Battle_Action_*`.
- **N_050** names `0x002E5E18 Gfx_Scene_AllocSpriteSlot`, `0x002E5934/59B8
  Gfx_Scene_AddSpriteEntryLarge/Small` and `0x002E5C60/5D0C/6398` as node attach helpers. That
  proved the `0x39EF94-0x3A06E8` group is **field-object sprite/draw entries**, not collision/hit
  boxes; those 15 entries were corrected from the first draft.
- `0x0039B8A8` was first read as "walk" because of the neighbouring 0x0039BADC. Reading the
  literal at `0x0039BA04` showed it is `Nut` (the neutral action), so it is now
  `Field_NpcAction_Approach`; `0x0039BBA8` also points at `Walk`, so it is a second walk
  initialiser, not a run initialiser.

## Open problems / honest gaps

- The exact window class/vtable ownership of the many 0x38C–0x392 methods is only partly proven;
  the page category ids are inferred from the 0x0027B86C factory and actor-state offsets.
- `0x38CBB4`, `0x38CDC4` and `0x38D338` (equip/tactics/special pages) are the weakest of the
  battle group (0.38–0.40, all `maybe_`).
- `0x39EF94`'s group depends on `0x002F2144`, which has no readable C file (merged by Ghidra).
  The interpretation comes from the named `Gfx_Scene_*` callees and call-site structure.
- `0x3A11BC`/`0x3A15A8` only validate the field context; their exact predicate is unknown
  (`maybe_Field_Gadget_IsReady*`, 0.35).
- `0x3969F0` is probably a cutscene message window setup with speaker/actor token; the exact
  speaker-name split is not proven.
- `0x394B10` has no visible state read; it is named from its neighbouring save-icon class only.
- The gadget drag group (`0x3A2018`, `0x3A24D4`) could be a touch-driven prop or a camera-like
  control; the script trigger calls prove "gadget", the drag semantics are inferred.
