# N_062 — native naming batch (resumed)

**Task:** name and document the 150 native functions in `orchestration/naming/batches/N_062.txt`
(addresses `0x00448F10`–`0x00464424`, non-contiguous, batch header says "Camera").

**Status:** complete. `orchestration/naming/out/N_062.json` has 150/150 addresses, one entry each,
seven keys each, unique names, no address or name collision with the other `out/N_*.json` files.

## Starting point

Nothing from the previous worker existed: no `orchestration/naming/out/N_062.json`, no
`orchestration/done/N_062.md`, no `N_062` entry in `AGENT_LOG.md`, no scratch files. Everything was
done from scratch.

## Method

1. Batch contents: all 150 entries had readable C under `decomp/readable/functions/`; no fallback to
   `decomp/ghidra/` was needed.
2. Built a global caller index over all 18,159 readable-C files (address extracted from the file name,
   callees from `func_*/FUN_*` references), plus a name map from `symbols.json`,
   `symbols_recovered.json`, `decomp/native_names.json` and all sibling `out/N_*.json`.
3. Scanned `original/exefs/code.decompressed.bin` for every occurrence of the 150 addresses. This
   exposed the **class descriptors in `.data` at `0x00770350`–`0x00770b00`**: entries shaped
   `{typeinfo-getter, 0, deleting-dtor, vtable…}`, whose vtable slots contain the base
   `Field_SceneNode_*` methods (`0x005F2E24 UpdateMapRecord`, `0x005F5520 SyncChildInstances`,
   `0x005E754C` child event dispatch) and the overrides in this batch. That is how most
   `Field_SceneObject_*` show/hide/update/event slots were identified by role instead of by guess.
4. Decoded literal pools with Capstone and resolved every pointer into the image to a C string. This
   produced the decisive in-function strings: `"Break"`, `"sprite"`, `"Act_Def"`, `"Start"`,
   `"hazure"` (miss), `"atari"` (hit), `"start"`, `"kekka"` (result), `"hit_d_%d"`, `"Skull_Run"`,
   `"null_txt_0"`.
5. **Discovery worth recording:** the executable contains a native/script name table at
   `0x0024e800`–`0x00250300`: `{code pointer, impl pointer, symbol name}` triples (e.g.
   `0x00704064 / 0x00157770 "CameraReguralyShake"`), which is where `symbols_recovered.json` gets its
   names. Only **two** of this batch's addresses are referenced by that table (and both turned out to
   be false-positive parses), so the table cannot name internal methods — but future batches that hit
   Squirrel-bound natives should parse it (structure and offsets are in
   `%TEMP%/opencode/n062/symtab.py`; a naive 4-byte-aligned scanner yields false positives, use the
   "name, pad, two pointers" order).
6. Read every function body bottom-up: leaf helpers first (`Field_SceneObject_ShowModel`,
   `..._IsFieldUsable`, deleting destructors), then the overrides that call them.

## Honest gaps / what is NOT verified

- The sub-family name "enemy symbol" is inferred from behaviour (monster-table lookup by
  `0x0066A7B8`/`0x0062C388`/`0x0062C3B0`, `func_0066B748(player,id)` = already-defeated test,
  show/hide of a symbol handle via `0x003DB2BC`, distance culling, break reaction/animation). The code
  does not expose a class-name string, so the exact engine class name is unproven; the functions are
  named by role, not by an RTTI name.
- `0x00448F20` / `0x00449174` sit in a UI-part class descriptor next to `"TrgBookIDCommand"`
  (item-bag/“book”) code but themselves call the map-jump/`TrgCommand` field commands. I named them
  after the observable action (`maybe_Ui_Part_StartMapJump`, `..._UpdateMapJumpSelection`) at 0.38–0.40;
  whether the owning window is Zoom/Book or a shared field-command panel is unresolved.
- `0x0044FE04`–`0x00450878`: "recipe/alchemy" is proven by `Ui_Recipe_BuildGetMessage` in
  `0x00450010`, but the surrounding part functions are named by their text-control behaviour; the
  exact window class is not proven.
- `0x00451428`/`0x00451888` are two structurally identical overlap-flag updaters (bits 1 and 3); the
  meaning of the bits is inferred from the break path in `0x004515BC`.
- Decompiler-damaged bodies: `0x00454004` (`halt_baddata`, argument registers unreliable), `0x0044C844`
  (partly unreachable/undefined values) and `0x0044BD70` (very large, truncated analysis) are named from
  the surviving call sequence only.
- Several tiny `Ui_Object` ctor/dtor thunks have no caller other than one window; they are named after
  that caller (`..._PartCtor`) at 0.45–0.55 and may need renaming once the window is named.
- No Squirrel script binds any of these addresses except through the native table; they are internal
  methods, so `game_assets/scripts/` contributed nothing beyond confirming the absence.
