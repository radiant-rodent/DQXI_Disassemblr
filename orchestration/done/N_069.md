# N_069 — name and document 150 native functions (resumed)

## What existed when I started
Nothing for this lane: no `orchestration/naming/out/N_069.json`, no `orchestration/done/N_069.md`,
no N_069 entry in `AGENT_LOG.md`, and no N_069 scratch files in `%TEMP%/opencode`. None of the 150
addresses was named in `symbols.json`, `symbols_recovered.json`, `decomp/native_names.json` or any
sibling `orchestration/naming/out/N_*.json` (checked mechanically), so all 150 were done from
scratch.

## Result
`orchestration/naming/out/N_069.json` — **150 entries, one per batch address, sorted by address**,
each with `address`, `name`, `signature`, `params` (`param_1..param_N` → role), `summary`,
`confidence`, `evidence`.

- 150/150 addresses, exactly the batch set; 150 unique names; **zero name collisions** with the
  three project symbol tables and the other 67 `out/N_*.json` (checked mechanically).
- Confidence: 1×0.75, 1×0.70, 4×0.65, 16×0.60, 30×0.55, 48×0.50, 31×0.45, 15×0.40, 2×0.35,
  2×0.30; mean 0.503. The 50 entries below 0.50 are `maybe_`-prefixed, as required (50/50 exact).
- Signatures follow the readable C (return type + real parameter list); only role-bearing
  parameters were renamed, and `params` maps the positional keys to those roles.
- **The "Camera" label is wrong.** The batch is a cross-section of the executable: battle UI /
  action sequence, lamp and field scene objects, menu windows, sound channels/3D audio/streams,
  the bffnt font and text-glyph renderer, the model/animation/resource binder, the scene-entry
  handle pools and the scene ray/primitive query engine. Subsystem prefixes (after removing the 50
  `maybe_` prefixes): Gfx 33, Ui 19, Sound 13, Field 8, Math 6, Battle 5, Fx 3, Font 3,
  Anim/Pack/Model 2 each, Text/Fs/Mem/Camera 1.

## What the range actually is (grouped)
1. **0x4F7274–0x4F8028 — battle action-sequence director.** Two nearly identical deleting
   destructors (16 × 0x58-byte member rows at +0xB464, base vtable 0x769398) and the 3 KB
   state-machine update 0x4F7320. The update calls almost the entire `Battle_ActionSequence_*`
   family named by earlier batches, reads the battle work at self[0x498] and drives 16 state ids
   (0xC7E..0xD4F). Its vtable also holds the reset at 0x4F7F7C (`maybe_Ui_Screen_ResetActorFlagsB`
   from another batch) — that is how the class is proven.
2. **0x4F8624–0x4FC20C — UI screen/widget code.** The battle party name lines (the only strings,
   `null_txt_l1..l4`), the four-row text window destructor (its vtable contains
   `Ui_FourRowTextWindow_InitPanes`), the lamp-glow effect entry (lookup/spawn/remove/random
   rotation; anchored by `lamp_core`/`lamp_out` and the Field_LampGimmick class vtable), field
   scene-object record handling, the clock window ctor/dtor, the scene-sprite window open/close
   pair, the Effect2D overlay begin/end pair, the `Rura_Start` field action constructor, and the
   title-pager window destructor chain (anchored by `txt_title`),
3. **0x4F9A44–0x4FAC54 — lamp/field object cluster** (see above), plus the field model-object
   sprite creation/release pair that drives `Gfx_Scene` sprite instances.
4. **0x5168A8–0x5199B0 — sound channel and wave buffers.** The three setters that build the DSP
   wave-buffer parameter block and the immediate-mode block applier next to the already-named
   `Sound_Channel_WriteParamBlock`, plus the fixed-point channel-parameter converter.
5. **0x51D040–0x542890 — Fx system, resource-set binding, ANIM/BFLAN clips, sound streams.**
   Includes the three `Gfx_ResourceSet_Lookup*` mappers (0x38 / 0x74 / 0x88 metadata tables), the
   BFLAN parser (`FLAN`, 0x7020100) and clip loader (`%s_%s.bflan`), the font resource loader
   (literal `font`), the child-sprite attach/detach pair used by ~13 UI windows, the Fx system
   shutdown/release chain, and the four-voice stream buffer group.
6. **0x542C54–0x547E40 — 3D audio.** Distance attenuation, pan with ±π/2 clamp, distance
   normalisation, per-source falloff and the matrix pan wrapper. Conclusive constants
   (1/2π, 2π, π/2) and the listener/source field layouts.
7. **0x559D94–0x55D91C — bffnt font + glyph rendering.** The bffnt parser (CFNU/CFNT/FFNU/FFNT,
   FINF, KRNG), the glyph-quad builder (0x48-byte instances, Text_BuildCharTransform), the
   glyph filter and the model-instance matrix setter.
8. **0x5634E0–0x56FF4C — handles, model resources, Fs worker.** Packed-handle release, model
   resource-set binding (three metadata sub-tables), the eight model resource slots named
   `00`..`07`, and the file-system worker destructor.
9. **0x572C50–0x5755C8 — math.** Euler→quaternion (two sign variants), 4×4 matrix inverse and
   multiply, quaternion from axis-angle, AABB from sphere+offset. These are the best-proven names
   in the batch (determinant/cofactor and the full 4×4 product are unmistakable).
10. **0x5769BC–0x57D4F8 — scene node / model instance / camera.** Node base destructor with its
    two intrusive lists, animation channel advance, the resource-slot binder, the widget child
    counter (45 callers), and the camera frustum rebuild (called by
    `Camera_UpdateViewAndProjection`).
11. **0x57EF20–0x586494 — the scene ray/primitive query engine.** Three parallel variants
    (A/B/C) of: triangle-soup intersection, mesh walk, and node walk. Proven by the dispatchers
    0x58E770 / 0x58E918 / 0x58E3F4, which are the callees of `Gfx_Scene_DrawSprite`,
    `Gfx_Scene_DrawSpriteEx` and `maybe_Gfx_Scene_DrawSpriteVariant` and of
    `Gfx_Scene_FindEntriesAlongLine`.
12. **0x588328–0x58BC78 — scene entry pools and spatial queries.** Handle-tagged alloc/free
    (0x9C-byte sprite entries with tags 0x1000000/0x2000000, 0x74-byte node entries with tags
    0x4000000/0x8000000), the four bitmap pools, the full pool release, ray/point/segment
    candidate collectors sorted by distance (std_qsort, comparator 0x153B60), the grid query,
    and the sphere/box/sphere-sweep candidate filters plus the capsule query entry.

## Method (reproducible)
1. Parsed the batch file; built a name map from `symbols.json`, `symbols_recovered.json`,
   `decomp/native_names.json` and all 67 sibling `out/N_*.json` (one file, N_014.json, is not
   valid UTF-8; read with replacement).
2. Rebuilt a caller/callee index over all 18,748 files of `decomp/readable`, so every entry has its
   real caller and callee lists with current names.
3. Per function digest: signature, callers, callees, strings/`s_*` symbols, all referenced
   `g_XXXX` globals dereferenced from `original/exefs/code.decompressed.bin` (base 0x100000) to
   real ids/floats/strings, plus all integer/float constants. Readable strings retrieved this way
   include `null_txt_l1..l4`, `%s_st`, `%s_%s.bflan`, `Rura_Start`, `lamp_core`, `lamp_out`,
   `font`, `txt_title`, plus the raw 32-bit magics (`FLAN`, `CFNU`, `FINF`, `KRNG`, `0Hx`).
4. Vtable grouping: located every entry point's pointer in the image, then the surrounding table
   slots, and used already-named siblings in the same table (e.g. `Ui_FourRowTextWindow_InitPanes`,
   `Ui_TitlePagerWindow_InitPanes`, `Field_LampGimmick_InitModels`,
   `Battle_ActionAnimElement_Ctor_77CCBC`) to fix class names.
5. Read the full bodies of the 40+ non-trivial entries (including all eight 1.5–5 KB query
   functions) and the compact digest of every other entry.
6. Checked the query engine top-down as well: the three dispatchers are reached from
   `Gfx_Scene_DrawSprite*` and `Gfx_Scene_FindEntriesAlongLine`, which fixed the subsystem (Gfx
   scene) that the "Camera" batch label got wrong.

## Honest gaps / not verified
- **0x57EF20–0x586494 (12 entries, all `maybe_`):** the three query variants are structurally
  proven (three dispatchers, three triangle tests, three mesh/node walkers) but which variant is
  ray vs swept-sphere vs capsule is **not proven**. They are named A/B/C with confidence 0.40–0.45.
  `0x584C70` and `0x586494` also have Ghidra-damaged bodies (`bad instruction data`, lost
  registers); only their call sequences are trusted.
- **0x588328–0x58BC78 (12 entries):** the handle tags (0x1000000/0x2000000/0x4000000/0x8000000)
  and the two entry sizes (0x9C / 0x74) are read from the code, but the semantic names
  sprite/node vs. "first/second pool" are inferred from the tag values. The paired
  Create/Find/Destroy functions are honestly labelled with `B`/`ByIndex` suffixes rather than
  pretending to know which pool is which.
- **Lamp cluster (0x4F8FF4, 0x4F9A44..0x4F9F54):** the owning class is proven by the vtable that
  contains `Field_LampGimmick_InitModels` (0x4FA11C) and the `lamp_core`/`lamp_out` strings, but
  that the effect entry is a light *glow/halo* (rather than, say, a smoke puff) is inferred from
  the caller's colour/flicker parameters; 0x4F8FF4's two-point beam is the least certain entry in
  the cluster (0.40).
- **0x4FA7D0 / 0x4FC20C:** the owning classes cannot be recovered (base vtable 0x760350 and a
  Ghidra-garbled `this`); named by mechanism only at 0.30/0.35.
- **0x4FA84C / 0x4FA9D4:** the callee 0x2AE7E4 is the model-view selection helper used by menu
  screens; the field-object side is inferred from the forwarding fields, not from a recovered
  class.
- **Sound channel group (0x5168A8–0x518368):** the DSP parameter-block layout is read from the
  code (flags 1/2/4, offsets +0x2A/+0x2E/+0x30..+0x5A), and 0x518368 sits next to the already
  named `Sound_Channel_WriteParamBlock`; the difference between the three setters (slot, source,
  full wave params) is a reading of the block contents, not a confirmed symbol from the SDK.
- **0x55B71C / 0x55C84E:** the glyph filter's exact bit meanings (layer bits 0..4, type bits 5..7)
  and the split Thumb fragment's damaged stack frame are inferred; the latter is named from the
  identical call sequence to 0x55B984.
- **0x579AA4:** the 0x6BCxxx SDK-style service is not identified; "Light_Init" is a guess from the
  0x40-byte object and callback registration (0.35).
- **0x576CC0:** the `std_strstr` string argument is lost, so only the operation is named (0.30).
- **0x58AA3C:** Ghidra truncated the body at an indirect jump after the first call, so the grid
  query name rests on the 4096.0 cell scale and the caller set (0.50).
