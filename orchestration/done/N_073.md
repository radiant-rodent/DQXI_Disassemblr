## The batch label is wrong

The header says **Camera**; that is a P0 grouping artefact. Only a handful of functions have
anything to do with a camera. What the range actually is, in order:

| Range | Real content |
|---|---|

| `0x5F533C`–`0x5F5B94` | effect-part ("billboard") instances: named part init/reset (`std::string` inline at `f_17C..f_19C`), target object/point, and the talk-motion name builder (concatenates `cbla`/`cbha` with `_yes`/`_no`/`_lookaround`/`_talk0` table entries) |
| `0x5F5CEC`–`0x5F8120` | the **Gfx scene-graph node** class: child-list tick/release, quaternion orientation (`f_120`) from Euler angles or by facing another object, 3×4 matrix application, culling flag (`f_50` bit 1 vs camera), draw submission, 4 effect-handle slots, destructor |
| `0x5F87C4`–`0x5F92C0` | `Ui_Balloon_*` win-banner part binder (literals `balloon_bottom1`, `balloon1_win`, `balloon_top1`, `balloon3_win`, …) and two pack-path formatters (`2d/bg/%s.pack`, `3d/bg/%s.pack`) |
| `0x5F9534`–`0x5F9650` | `Math_WeightedRandomIndex` (+ default-RNG wrapper) — 9 unrelated callers confirm it is a generic weighted pick |
| `0x5FA0C4`–`0x5FC86C` | **Squirrel VM/compiler**: stack-slot read/write, new stack slot, instance ctor/dtor, keyword lexer (`Sq_VmInit` registers `while/else/break/…` from real rodata), hex/number-string literal readers with the real error strings (`too many digits for an Hex number`, `unfinished string`, `newline in a constant`, `unrecognised escaper char`, `decimal number expected`), token dispatcher |
| `0x5FDC24`–`0x600A54` | the Squirrel **hash table** (0x14-byte buckets: key/value/hash/next) plus `Sq_HashTable_*` init/set/find/remove/rebuild/resize/destroy |

Two strings pinned the battle module: `battlecmn.bch` at `0x60B8E0` (used by `0x607500`) and
`switchback_start` at `0x6079E0` (used by `0x607924`). The module's own state byte sits at
`work+0x4201` and its transition fields are `f_300`/`f_304`; `BattleScene_Finish` (`0x607D24`)
calls `0x1714D4` and sets `f_46C = 7`.

## Method

1. Read `README.md`, `orchestration/PLAN.md`, `orchestration/naming/TEMPLATE.md` and the
   existing `out/N_*.json` files.
2. Built a name map from `symbols.json`, `symbols_recovered.json`, `decomp/native_names.json`
   and **all** existing `out/N_*.json` (so callees named by other lanes show up), plus a
   caller index over all 18,159 `decomp/readable/functions/*.c`.
3. Dumped a per-function digest (address, size, callers, callees with known names, body) and
   worked bottom-up: leaves first (`Gfx_Trail_ClampProgress`, hash-table primitives, path
   formatters), then their callers.
4. Resolved every literal/constant claim against the real binary
   (`original/exefs/code.decompressed.bin`, base `0x00100000`) — this is how `2d/bg/`,
   `3d/bg/%s.pack`, `battlecmn.bch`, `switchback_start`, `balloon*`, `_yes/_no/_lookaround/_talk0`,
   `cbla/cbha` and all the Squirrel error strings were verified rather than guessed.
5. Used `asm/text/text_005C0048.s` for the functions whose readable C is wrong
   (`0x5F533C`/`0x5F539C` are virtual-slot forwarders with s0/s1 float args; Ghidra lost the
   tail jump at `0x5F53F0`).
6. Wrote the JSON in eleven chunks, merging by address each time (idempotent, resumable).

## Honest gaps / not verified

- Fully static work: no emulator, no debugger, no playtest. Behaviour descriptions are
  mechanical (fields/callers/constants); the *purpose* labels are the uncertain part.
- **Naming the battle module "BattleScene"** is the biggest judgement call. Evidence for
  "battle": `Battle_Initialize`/`Battle_FinishBattleScene`/`Battle_UpdateActionQueue`/
  `Battle_RefreshBattleUi` callees, `battlecmn.bch`, `switchback_start`, `cb_%d`, the battle
  state byte and `f_46C = 7`. It is *not* proven that this is not the 2D-battle variant
  specifically — sibling lanes used `Battle2D_LoadEnemyModel`/`Battle2D_LoadBackgroundModel`
  for `0x5A5144`/`0x5A5200`, which may be right or wrong. I deliberately used the neutral
  `BattleScene_` prefix and renamed my own draft `Battle2D_*`/`Menu_Party_*` names to it.
- 66 entries are `maybe_` (< 0.50), concentrated in the battle-scene module where one function
  is often a permutation of another (e.g. `0x606234` state dispatch has 8 states; which state
  is which screen is inferred from call order only).
- Ghidra-damaged bodies that limit confidence: `0x5F48A8`/`0x5F491A` (bad instruction data),
  `0x604ED2` (Thumb misdetection, duplicate of `0x604C94`), `0x60B408` (unrecoverable loop),
  `0x60C014` and `0x60C2C8` (truncated at `halt_baddata`). For `0x60C2C8` only the first
  `func_006F1EEC` call survives, so its name is a placeholder at 0.25.
- `0x5F56A0`/`0x5F574C` are called from billboard/effect creation paths and store a 12-word
  + 4-word parameter block; I called them "effect part" but did not prove whether the blocks
  are a transform, colors or animation params.
- `0x5FA0C4`/`0x5FA19C`/`0x5FA484` are Squirrel stack/registry accessors; the direction of the
  copy is certain, the exact Squirrel API name (`Get`/`Set`/`GetStackObject`) is not.
- `0x600D34`–`0x601970` are named from the callers another lane already named
  (`Casino_AddJackpotPayout`, `Casino_RefreshJackpotCounters`, `Casino_IsJackpotClockExpired`);
  I did not verify those caller names independently.
- No symbol merge was done (that is M1's job). Names are proposals only.
