## Evidence chain (bottom-up)

1. `0x00722A50` calls `0x00420CCC` twice per comparison. That is the key extractor N_060 named
   `Ui_Widget_GetLowestPriority` (0.5): it walks a widget's array of 0x3C-stride layer records
   (`obj+0x1C`, count `*(obj+0x20)+0x64`), skips records whose `+0x20` is the `0xFFFF` sentinel,
   and returns the minimum u16 at `+0x30`.
2. `0x00722A50` calls `0x007185E8` on the leftover tail. Asm `0x007185E8` is a textbook
   `__insertion_sort` over 4-byte elements with the same comparator. The function itself does the
   same insertion sort inline for every full 7-element chunk (asm `0x00722A58` / `0x00722A68`
   load the literal 7).
3. After the chunk pass it runs two merge passes per doubling of the run length, alternating the
   destination between `arg3` (odd pass: array → buffer) and `arg1` (even pass: buffer → array).
   That is exactly `__merge_sort_loop(first,last,buffer); step*=2; __merge_sort_loop(buffer,buffer+len,first); step*=2;`.
4. The merge helper it calls, `0x00722E50`, has no readable C file: `0x00722A50`'s recorded size
   `0x494` ends exactly at `0x00722EE4`, so Ghidra merged the real entry point into our file. Asm
   `0x00722E50` is a 3-argument sorted-run copy that returns the destination end pointer —
   `__move_merge`.
5. Sole caller `0x0072298C` is `__stable_sort_adaptive`: `len=(end-start)/4`,
   `mid=start+(len+1)/2`, recurse when `buffer_size < len`, otherwise sort both halves with
   `0x00722A50`, then merge with `0x007220A8` (`__merge_adaptive`; it even uses `std::rotate`
   `0x0011CD80` on the buffer-less path).
6. Sole caller of `0x0072298C` is `0x00420858` (asm `bl` at `0x00420B80`) — N_060's
   `maybe_Ui_SortWidgetsByLayer`, which allocates the temp buffer from the pool at `g_00420CC8`
   and sorts widget pointers.
7. Sole caller of `0x00420858` is `FUN_004B8A84` line 168 (`self+0x78 -> self+0x9c`), a UI
   object child-widget update that re-sorts up to three children before handing them to the
   layout.

Net: the closed call chain (`UI child-widget update → Ui_SortWidgetsByLayer → __stable_sort_adaptive
→ __merge_sort_with_buffer → __insertion_sort / __move_merge`) plus the 7-element chunk size and
the alternating buffer passes identify the function with high confidence. It is generic library
code, so the `std_` naming style of the sibling batches (N_009 `std_introsort_loop`,
N_031 `std_insertion_sort_*`) is used instead of a game subsystem prefix.
