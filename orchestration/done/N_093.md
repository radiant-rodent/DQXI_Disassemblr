# N_093 — native function naming (Save_and_Persistence lane)

**Result:** 150/150 functions named and documented in `orchestration/naming/out/N_093.json`
(152,461 bytes, valid UTF-8 JSON, batch order). No prior `N_093.json`, done report or log
entry existed, so this was a from-scratch pass despite the "RESUMED" label.

## What this range actually is

The batch header says `Save_and_Persistence`, but **none** of the 150 functions is save code.
The range `0x0055828C-0x005A6D18` is the game's **rendering / UI / battle-2D engine**:

| Address block | Content |
|---|---|

| `0x00558FF4-0x0055A28C` | Font object family: `Font_LoadBffnt` caller, `Font_Create` / `Font_DestructBase` / `Font_CreateDerived` / `Font_DestructDerived`, texture-descriptor setup and the lazily built 2,412-byte glyph display list |

| `0x0055CAD4-0x0056A300` | Gfx model-instance draw-pass emitters (screen projection, rect/sprite/fullscreen-quad/textured passes), `Gfx_StateCache_EmitStateBlock` (ordered-map state dedup), model secondary-motion chain builder (`0x0055FEF4-0x005631D8`), char-shadow vertex/curve setup, and the shared `Gfx_ModelInstance_BindTextureAndDraw` tail, plus sprite-set/overlay sprite drawing (`0x00576EEC-0x0057A26C`) |
| `0x0056C738-0x0056F0A8` | Gfx resource descriptor/command-stream helpers and the Squirrel byte-stream (`Script_ByteStream_Init/Read`) used by `Script_LoadBytecodeOrText` |
| `0x00573B6C-0x00576768` | AABB math (`Math_ComputeRotatedAabb`, `Math_UnionAabb`), sprite-set selection/refresh, and the Squirrel argument converters (`Script_GetPlayerIdArg`, `Script_GetIntArg`, `Script_GetFloatArg`, `Script_FormatTypeError`) |

## Method

1. Built `%TEMP%\opencode\n093\` scratch: name map from `symbols.json`, `symbols_recovered.json`,
   `decomp/native_names.json`, `decomp/ghidra/functions_merged.jsonl` and all 87 existing
   `orchestration/naming/out/N_*.json` (N_014 is invalid UTF-8 and was skipped); one-pass
   caller/callee index over all readable C; per-function dossier with **literal-pool resolution**
   (reading the 4 bytes a `g_`/`DAT_` reference points at, so `0x000F0227`, `0x50494843`, `'CHIP'`,
   `'xp::PlayerID'` etc. are decoded, not guessed).
2. Scanned the binary for 4-byte pointers to each batch address (vtable-like tables in `.data`,
   e.g. `0x00781DA0`, `0x0077EC48`, `0x0077E828`) and printed the neighbouring slots with their
   already-known names — this is what grouped the model/CharModel/Battle2DUnit/Font methods.
3. Worked bottom-up (leaf copy/state helpers first), then grouped the virtual methods using the
   shared tables and the named callers from N_069 (Font), N_083/N_019/N_007 (Gfx model/scene),
   N_070/N_071 (battle/2D), N_092 (text/glyph command builder) and N_001 (model secondary motion).
4. Analysed the 15 ten-function chunks in five parallel passes, then merged, checked every
   address/name against the batch and cross-checked all names against the 87 sibling batches +
   `symbols.json` (one collision found and renamed: `0x00577E9C` → `Gfx_Overlay_DrawSpriteQuad`;
   N_082 already owns `Gfx_Overlay_DrawSprite` at `0x002D2930`).

## Validation (mechanical, no code changed)

- 150/150 batch addresses, exactly once, in batch order; no extras.
- Schema: exactly the seven required keys, non-empty summary/evidence for all 150.
- Names unique; every name appears in its own signature; every `params` value appears in the
  signature; `param_1..param_N` keys contiguous; ASCII only.
- Prefix rule enforced both ways: confidence `< 0.5` ⇔ `maybe_` prefix.
- Confidence: min 0.15, max 0.70, mean 0.487; 68 `maybe_`, 25 entries ≥ 0.60.
- Prefix histogram after stripping `maybe_`: Gfx 80, Battle2DUnit 15, Script 13, Ui 11, Font 7,
  Model 5, Battle 5, Text 4, Field 3, Container 2, Math 2, std 2, Pack 1.
- Rule 5's full test run is explicitly exempt for naming lanes; no source, data or asset file was
  touched, so the bit-matching build is unaffected (only `N_093.json`, this report and
  `AGENT_LOG.md` were written).

## Honest gaps / not verified

- Fully static analysis: no emulator, debugger or playtest. Mechanisms are read from the decompiled
  bytes; the *purpose* labels are inference, which is why 68 entries are `maybe_`.
- PICA200 command words (`0x000Fxxxx`, `0x7FFFxxxx`, `0x804Fxxxx`) are recognised as GPU commands
  but were **not** resolved against a PICA200 register reference, so several `Gfx_CmdBuf_*` and
  `Gfx_GpuCmd_*` names describe the data flow rather than a named hardware register.
- Class identity comes from shared vtable-like tables and already-named slots, not from RTTI names
  (the data has no Itanium typeinfo name strings), so `Gfx_CharModel_*`, `Gfx_SpriteSet_*` and
  `Ui_PartyMemberSlot_*` are family-level labels.
- Ten entries are left at confidence ≤ 0.35 and should be treated as placeholders:
  `0x00558670/0x00558698` (plain 0x18/0x30-byte copy helpers), `0x005586BC` (packed range/ramp
  builder), `0x0055935C`/`0x0055AC74` (small containers), `0x0055CE34`, `0x0055DBB8`,
  `0x0055F5B4`, `0x0056A300` (register-passed Thumb variant), `0x00579778`, `0x005A2214`,
  `0x005A616C`, `0x005A6C88` (bare static-constructor thunks), `0x005A69F8`.
- Some bodies are truncated in the Ghidra export at a `std_ConstructArray` (`0x00100050`) call or
  are constructor prefixes; names are based on the visible prefix and the allocation/vtable shape.
- `0x0055A500` is named `Gfx_ParseChipFile` from the literal `'CHIP'` magic and version `0x102`;
  whether "CHIP" means map chip, UI chip or a texture container was not established.

   entries `0x00569350`, `0x0056A300`; several low-confidence names are limited by the export,
   not by the binary.
4. Resolve the vtable tables `0x00781D98`, `0x00781424`, `0x00782200`, `0x007822BC`, `0x007828D8`,
   `0x0077E0E0`, `0x0077E828`, `0x0077EC40` to class names (one pass over the whole
   `0x0077E000-0x00783000` table block) — that would give proper class names to the Font,
   CharModel, sprite-set and Battle2DUnit families.
5. Re-label this batch group from `Save_and_Persistence` to `Gfx + Ui_and_Message + Battle` so
   future workers do not look for save semantics.
