## Method & Key Findings

1. **Squirrel Native Script Binding Tables Decoded**:
   Analysis of binary data at `0x0024AF00`-`0x00254000` revealed the engine's static native script registration table layout:
   - Each entry consists of an ASCII method name string (padded to a 4-byte boundary), followed by a 4-byte wrapper function pointer (`0x00705FF0`-`0x007077A4`), followed by a 4-byte native C++ implementation pointer.
   - All 15 wrapper functions in `0x00705FF0`-`0x007077A4` matched verbatim symbol names in this table (`CameraShakeEx`, `ActorSetFaceEX`, `ActorMeshShake`, `PictureCardMoveTarget`, `MessageFunc`, `Actor2DMoveSylviaShip`, `Effect2DAttachActor`, `Actor2DMove`, `Actor2DWarp`, `BookIDMessageSetupEx`, `ScenarioMessageSetupEx`, `IEMessageSetupEx`, `PictureCardZoom`, `CameraReguralyShake`, `Actor2DMoveEx`).
   - The wrappers unpack arguments from `HSQUIRRELVM` using the shared helper `0x007078E4` (`Script_GetIntegerArg`, which has 183 callers across the game) and validate against type names (`xp::CameraShakeType`, `xp::FacialKindID`, `xp::MouseOrderID`, `xp::MessageCursor`, `xp::ChipDirection`, `xp::RegionBookID`, `xp::ScenarioMessage`, etc.).

2. **Standard Library `std::sort` and Introsort Decomposition**:
   Functions `0x00716858`-`0x007231A0` represent compiler-instantiated standard library sorting templates (`libstdc++`):
   - In GCC `libstdc++`, `std::sort(first, last)` executes `__introsort_loop(first, last, depth_limit)` down to a threshold of 16 elements, followed by a final `__insertion_sort(first, last)` pass.
   - The addresses `0x00722EE4`, `0x00722FD4`, `0x007230C4`, and `0x007231A0` are exact matches for the top-level `std::sort` template for 16-byte records, predicate pointers, and u16 record indices.
   - They call the respective introsort loops (`0x007186E0`, `0x00718C80`, `0x00719220`, `0x0071D06C`) and insertion sort passes (`0x00716850`, `0x007169C4`, `0x00716B38`).

3. **Field2D Spatial Grid & Viewport Culling**:
   Call graph analysis across all 18,748 readable-C source files revealed that `0x00714658`-`0x00715BAC` and `0x0072370C`-`0x00723950` are called directly by 2D field rendering passes:
   - `0x005C5F24` (`maybe_Field2D_Scene_RenderObjects`), `0x005C6E12` (`maybe_Field2D_Scene_RenderChips`), `0x005C6E92` (`maybe_Field2D_Scene_RenderSprites`), and `0x005C1438` (`Field2D_MapChip_ResolveTileLayers`).
   - The functions perform 2D AABB collision/overlap queries (`queryRect.x < obj.x + obj.w && ...`) on spatial grid buckets to filter which background map chips and character entities need drawing.
