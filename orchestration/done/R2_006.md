## The xref caveat (important for the next worker)

`decomp/xref.json` is not trustworthy in this tree (R2_013 reported the same). Two failure modes:

1. **False callers.** `fn.py`/xref listed e.g. 18 callers for 0x00612430, 17 for 0x00648A80,
   several for 0x00300314 / 0x004AC46C / 0x004BF224 / 0x00434820 / 0x00233BC8 — all with **zero**
   real `bl`/`blx`/`b` sites to those addresses.
2. **Off-by-one callers.** A call site is attributed to the nearest *preceding* symbol rather than
   the function that contains it.

I therefore demoted the two entries that had been promoted on xref-only caller evidence
(0x00648A80, 0x00612430) and rewrote every other caller claim. Callee names are safer because they
appear literally in the readable body, but the call graph itself should be regenerated. Suggested
follow-up task: regenerate `decomp/xref.json` from `asm/text/*.s` + `functions_merged.jsonl`, or fix
`tools/xref.py`'s symbol resolution.
