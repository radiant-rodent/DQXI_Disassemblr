## Method

1. Located each readable file by its address suffix (some first-pass files have already been
   renamed, so the path in column 4 can be stale) and read the doc header (previous name,
   confidence, evidence) before the body.
2. Re-read the neighbourhood: current caller/callee names from `tools/fn.py`, the address-adjacent
   readable functions (class clusters), `scores.jsonl` / `neighbour_names`, `FACTS.md`, and the
   scripts where useful.
3. Checked every candidate name for collisions against `decomp/symbols.json`,
   `symbols_recovered.json`, `decomp/native_names.json`.
4. Wrote the JSON with a generator script that copies `previous_name`/`previous_confidence` from the
   batch row and asserts all prefix/change rules; then ran `tools/check_refine.py`.

## Kept maybe_ (28)

Most are genuinely under-determined: the remaining images are the lowest-context rows of the
batch (every one scores 3). Two recurring blockers explain almost all of them:

* **0x00636AFC** — the shared callee of nine of these functions. Ghidra folds it into
  `Field_Npc_HasBalloonEntry`'s symbol, but it is a separate 52-byte function (verified from the
  disassembly at 0x00636AFC): it calls a virtual through `eventState+0x3DC` and returns 0 only when
  the result is the sentinel `0x01000001`, i.e. a *field event-scene handle validity test*. I
  described the thunks/predicates by that operation and did not invent a class for them.
* **Enclosing-symbol callee names** — `fn.py` reports the *preceding* symbol for call targets that
  Ghidra did not split (0x002D0E84 inside `Anim_ClipSet_Build`, 0x005E7848 inside
  `maybe_Actor_SelectAnimEntry0`, 0x005F4F9C inside `Field_SceneObject_SetAnimatorLastFrame`,
  0x001CD7C8 inside `Actor_SpawnEffectBlock`, …). I used those names only as neighbourhood hints,
  never as proof of a call's role.
* 0x0027E1B8 remains `maybe_Ui_BattleCmd_Noop` because its 44-byte body is undecodable
  (`halt_baddata`); 0.30 was kept.

## Not verified / open problems

* Confidence was deliberately capped at 0.50; no new name is claimed as proven. The 28 `maybe_`
  entries are honest descriptions, not resolutions.
* The first 100 entries were not re-derived in this run (they were already accepted by the
  previous worker); I only re-validated them structurally. Their `previous_*` fields match the
  batch.
* 0x00636AFC itself should get its own name (`Field_EventState_GetValidSceneHandle` or similar) in
  a separate batch — nine functions here inherit its ambiguity.
* 0x0062EF8C is documented as a float-returning anim-speed getter, yet at least five call sites
  discard `s0`; its real effect is inside `Field2D_ShouldUpdateActorVisual` (0x0062F110). Worth a
  dedicated look, because it decides whether the 0x001E09xx / 0x00301D8C family is
  "show/hide actor" or "refresh field-2D visual".
* Several `scores.jsonl`/`fn.py` callee attributions are off by one symbol (see above); the
  symbol-overlap problem (mid-function symbols like 0x002D0E84) should be fixed centrally, not per
  batch.
