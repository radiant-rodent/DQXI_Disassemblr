## The decisive evidence was the vtable structure, not the call graph

Only ~14 of the 113 have any direct `bl` caller; the rest are reached exclusively through vtable
slots. So the useful new context was *which table each function is installed in and what its
neighbours are*. I parsed `asm/rodata/*.s` into `out/scratch/R2_013/rodata.json` and indexed every
address by (vtable, slot, named siblings). Two shapes recur across the batch:

- a 4-slot **notification interface**:
  `[0] Ui_Window_CloseAndHide, [1] <class>_NotifyCommandNN, [2] <the gate>, [3] Ui_SlideWindow_OnEventB`
- a 32-slot **main vtable** with the same gate body at **slot 30** — the slot that carries the
  already-confident `Actor2D_IsEventSlotFree` (0x003A2E74, 0.50).

That is what let me name the owning class of 20 gate copies from their siblings instead of guessing,
and it is what turned 60 first-pass guesses into corrections.

## The 26 manager-0x7C slot accessors (0x0070C02C..0x0070C3EC)

All confirmed at 0.50. `func_00387CA4` is proven to be a **pure getter** by its own disassembly:

```
cmp r1,#0xff ; ldreq r0,[r0,#0xc4] ; addne r0,r0,r1,lsl #2 ; ldrne r0,[r0,#0x24] ; bx lr
```

and each wrapper is

```
push {r3,lr} ; bl Os_GetGameWork ; … ldr r0,[r0,#0x7c] ; cmp r0,#0 ; movne r1,#<idx> ;
blne func_00387CA4 ; pop {r3,pc}
```

`r0` survives the `pop`, so these **return** the entry — Ghidra typed them `void` and dropped the
return. Index `0xFF` is the special case (`mgr->f_C4` instead of `mgr->f_24[0xFF]`).

## Signatures

Signatures keep the readable C's **arity and types**; only the names change, and arguments the body
never reads are named `unused` / `unusedA..C`. This matters because `tools/merge_names.py` rewrites
the readable C definition from the signature — changing arity would leave call sites passing the
wrong number of arguments. The rest of the corpus agrees: 7 of 1098 entries in the other `R2_*`
batches change arity, and my first draft changed 36, which I reverted.
