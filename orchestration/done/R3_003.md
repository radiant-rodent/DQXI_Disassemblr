## Confirmations worth noting

- `Ui_Window_DtorWithTwoPanels` (0x002A45D8) — disassembly shows the full deleting destructor:
  vtable store, `std_destroy_range(self+0x78, 0x001F0700, 0x414, 2)`, `Ui_Object_DtorBase`,
  tail call to the free routine 0x0010F6CC.
- `Ui_Window_DtorWithPanelArrays` (0x002A4838) — same shape plus a second 0x414 x2 array and a free.
- `Ui_TwelveRowTextWindow_Ctor` / `_DtorDeleting` (0x0029DD44 / 0x0029DDAC) — vtable 0x0075EB0C,
  exactly 12 rows of 0x10 bytes (`std_destroy_range(..., 0x10, 0xC)`), scroller sub-object at +0x54.
- `Ui_Window_BuildMessageArgFromToken` (0x002A285C) — named caller `Ui_Window_GetMessageArg`,
  named callee `Ui_SakusenWindow_BuildMessageArgs`, literal icon ids 0x4D..0x51 plus the
  `Party_CountAliveMembers == 1` special case.
- `Ui_EnsureSubObject` (0x002D25D8) — the callee is the declared `Ui_GuideWindow_Ctor` and the
  0x1D4 allocation matches; called only on the not-yet-initialised path.
- `Ui_EquipPart_Ctor` (0x002B28A4) — the constructor at 0x003331A8 (equip-window class block)
  chains it four times; the body writes the part vtable at +0 and copies three default triples.

## Kept `maybe_` (honest doubts)

- The four anim-ref-list initialisers (0x001D8478, 0x002158D4, 0x002F6C90, 0x00364BE8) and the
  3-list ctor 0x002F72D0: the body shapes are certain, but no caller/vtable names the class, so
  the first-pass class labels stay at 0.4-0.45.
- `maybe_Field_Action_CreateDig` / `CreateNut` (0x001BA3B8 / 0x001BA4D4): bare vtable stores; the
  attributed caller 0x0022E494 is a 4 KB Thumb chunk whose callee list mixes unrelated actor
  functions, so it does not identify the factories.
- `maybe_Actor_Action_NutTask_Ctor`: the `"nut"` tag may name the animation rather than the task,
  and the caller's own header still says "emote", hence 0.45 with `maybe_`.
- The battle slot-table family 0x00208E04 / 0x0027C9B0 / 0x0020DF9C: the five 0x40-byte slots and
  the three per-unit ids are literal, but whether they hold party members, items or spells is open.
- The sound-gated script steps 0x00450550 / 0x00450878: `RecipeInfo`/`craft` is still only the
  first pass (the sound lookup and idle test are now proven).
- 0x002A2C0C is a mid-function artifact (`halt_baddata`), kept at 0.3 so the merge has a symbol.
