## Key decisions / new evidence

1. **The 13 window "Finalize" slots are command handlers of the table at `0x0072B570`** (8-byte
   `{handler, 0}` entries). Its other entries are already named `Ui_Window_AdvanceScriptCmd03 / 03B /
   05Or0B / 06A / 06C / 0F / 12 / 14A / 15B / 15D`. The readable C was truncated because Ghidra marked
   `Gfx_Node_SetVisible` (0x0029126C) `noreturn`; reading the disassembly shows each handler resets the
   panes, pushes a script state byte into the inline vector at `+0x10A8` (A=6, B=8/9, D=record byte,
   E=0, F=6, G=1..5, H=3, I=4, L=5; C and J jump straight to the updater) and tail-calls the shared
   updater. They are now `maybe_Ui_Window_ScriptCommandHandlerA..L` (@0.35–0.40) and
   `...M` for 0x001C69BC (slot 0x0072B598). The exact command ids are not recoverable, hence `maybe_`.
2. **0x00263CD8 is a split/phantom symbol** (`maybe_Ui_SplitFunctionArtifact`, 0.15). It is not in any
   rodata table, the ARM listing has no function boundary there (it is a `bl Gfx_Node_SetVisible` at
   0x263CD8 inside the preceding handler), and `symbols.json`'s record is self-referential (source
   `R_026`, mode thumb, size 16). Follow-up: delete this symbol.
3. **`0x0029126C` is `Gfx_Node_SetVisible`** (confirmed by the named `Actor_Node_ShowVariantA/B`
   wrappers and by the disassembly: stores the byte at `+0x14`, mirrors bit 0 into the owned child's
   `+0x44`). It returns normally, so the "does not return" annotations in the recovered files are wrong.
4. **The seven `ReleaseChildWidgets` copies do not release anything**: `0x00123594` is a doubly-linked
   list splice of the widget at `+0x4BC` into the queue at `self+0x110`, and `Ui_Object_BroadcastToChildren(...,0)`
   deactivates the children at `+0x244` (named `Ui_Window_PopChild` sends 1 to reactivate the new top
   child). Corrected to `maybe_Ui_Window_DeactivateChildWidgetsB..G`.
5. **Class fixes from named neighbours**: `0x00394CD0` is a dialog command (table
   `0x00728F6C..0x00728FA4`, siblings `Ui_Dialog_SetVisibleState` / `Ui_Dialog_ResetAnimation`) →
   `maybe_Ui_Dialog_SelectPage`; `0x003B4FC8` calls `Save_SlotUi_BuildThree` and is the byte-identical
   twin of the already-named `maybe_Save_SlotUi_ResetThree` → `maybe_Save_SlotUi_ResetThreeB`;
   `0x003A7CDC` is a generic pane-group binder (all three callers are binders) → `maybe_Ui_PaneGroup_BindSlotAnimations`;
   `0x0046BFC4` is a casino-slot path (all three callers) → `maybe_Casino_Slot_ShowPaneOnAnimEnd`;
   `0x00332E88` is slot 0x00764964 of the item-select window, called by `Menu_ItemSelect_CreateRows` →
   `maybe_Menu_ItemSelect_UpdateRowSelection`; `0x00402F94` is a straight visible-flag thunk →
   `maybe_Ui_PartyPanel_SetVisible`.
6. **Confirmations (≥0.5)**: `Ui_List_UpdateRowA` (0x003A953C), `Ui_List_UpdateRowB` (0x003A9640),
   `Ui_GuideWindow_SetCell` (0x003A972C) — now backed by the named `Ui_GuideWindow_*` callers and the
   six-column table at `+0x11C`; `Ui_WindowHolder_Ctor` (0x002C1C08) — vtable sibling
   `Ui_WindowHolder_DtorDelete`; `Monster_BehaviorAction_Start` (0x003AEA9C) — vtable slot 1 of the
   family whose ctor and two siblings are named.
7. **Honest keeps (20)**: damaged or truncated bodies (`0x001D784E` unaff_r6; `0x002CF070` bad
   instruction / `halt_baddata`), single-call vtable thunks whose owner class is only vtable position

   effect is clear but whose class/role is not (`0x004CC2BC`, `0x001E0D44`, `0x001E10F4`, `0x003096D4`,
   `0x004A168C`, …). All remain `maybe_` at <0.5 with corrected summaries.
