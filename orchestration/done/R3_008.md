## Main decisions

1. **Party-member stat accessors (0x00150D48 / 0x00150D8C / 0x00152D5C / 0x00152D98 /
   0x0015858C / 0x0015E7A0 / 0x0015E7D0).** All seven resolve the member through the known
   `0x0035EB98` and touch the known `PartyMember` fields: +0x14 = current HP, +0x16 = current MP,
   +0x12 = max MP (FACTS). They became `Party_Member_AddHP`, `AddMP`, `SetHP`, `SetMP`,
   `GetMaxMP`, `GetHP`, `GetMP` (0.55). The old `Actor_*Field14/Field16` names hid which stat they
   were.
2. **`0x00151164` is the wallet getter.** R_010 had already verified `0x0066B2CC(work,i) =
   work[i*4+0x31F4]` and `Ui_AmountSpinner_Step` (0x003D28FC) reads entry 0 as the wallet in the
   9,999,999 cap check. The disassembly confirms the callee's `r0` survives (Ghidra dropped the
   return). Confirmed as `Work_GetGold` (0.50). FACT's canonical gold at `bag+0x28` is exposed by
   `GetGold` 0x001633B4; this wrapper exposes the counter-array copy the spinner uses.
3. **`0x0018CC14` is not a throw.** The old `Text_ThrowError` was a Ghidra artefact: `0x00100B74`
   is `wcslen` (FACTS trap) and the function continues after it. The full disassembly shows it fills
   a 16-word style block (leader name from member 0, level, three global bytes, allocated name
   buffer, changed flag). Renamed `Text_ResolveStyleBlock` (0.50), matching the N_010/N_022
   description of the same function as the style resolver used by `0x00193248`.
4. **`0x00640D08` / `0x00640DB0` are trigger predicates, not bag setters.** The callee `0x0066B3B0`
   is the field-trigger bit test bounded by `id < 0x306` (FACTS: bitmask at `bag+0x5418`) and returns
   `!bit`; both wrappers preserve `r0`. The only genuine caller is `IsThereGimmickFixedItem`, which
   calls them for its two fixed-item class tokens. Renamed `Actor_IsGimmickTriggerUnfired` (0.50)
   and `maybe_Actor_IsGimmickTriggerUnfiredB` (0.45).
5. **`0x0015E9E4` was the opposite operation.** `0x0066B004` returns `flagByte[index] & 1`, so the
   old `Field_SetState` is wrong; renamed `Field_TestFlagBit` (0.50). `0x0015DB24` (which calls the
   bit-0 setter `0x00612550`) was confirmed as `Field_SetFlagBit` (0.50).
6. **UI/class corrections.** `0x0066E67C` is a UI-object event handler (its receiver is the UI
   object, disassembly `sub r5,r0,#0x258`, sibling of `Ui_Object_OnEventPathOrToggle`), renamed
   `Ui_Object_OnEventApplyStoryFlag`; `0x003A7F3C` is a shared highlight-list helper (three
   unrelated named callers), renamed `maybe_Ui_HighlightList_ApplyMapState`; `0x001CDF04` clears
   (not sets) flag 0x10, renamed `maybe_Ui_PartyStatus_ClearFlag10`.
7. **`0x00641F90` confirmed.** Disassembly shows the stride-0x1C row scan, the key at
   `work+0x27C5C` and the 0xFFFF free-slot fallback; `Ui_FindRowByCurrentKey` (0.50) is accurate.
8. **`0x0062F918` confirmed** as `Item_ComputePriceWithMultiplier` (0.50): multiply by count/base
   row value, scale by `2^f_22C`, clamp against the 9,999,999 cap.
9. **Honest keeps (21).** These are mostly functions whose *effect* is legible but whose class or
   data meaning is not: the two party flag-pair tests (the dossier's long caller lists actually
   belong to the adjacent `0x0066A6BC` handle check), the three party-member teardown variants,
   the three dialog page-transition variants (one body has bad instructions), the four-row reset
   wrappers, the save/recipe block accessors, and the damaged Thumb formatters
   (0x001636DC, 0x00167210, 0x001F1F78, 0x001F2958).
