# R3_009 — second naming pass (refine), 50 low-confidence `maybe_` functions

## What I did

Read `README.md`, `orchestration/PLAN.md`, `orchestration/naming/FACTS.md` and the pre-baked dossier
`orchestration/naming/refine/dossiers/R3_009.md` (all 50 blocks, in four chunks), then decided every
address in `orchestration/naming/refine/batches/R3_009.txt`.

Result: **10 confirmed, 18 corrected, 22 kept_maybe** (12 entries at confidence >= 0.5).
Output: `orchestration/naming/refine/out/R3_009.json` (50 objects, UTF-8, validated).

Decisions worth recording:

- **The `0x0066A7xx..0x0066B9xx` "bag flag" helpers are split symbols.** Only `0x0066B264`
  (`maybe_Work_AreAllNamedRowsUsed`, a 3,124-byte blob) exists in `symbols_recovered.json`, but callers
  branch into it at many offsets. Reading the disassembly directly gave the real helpers (25-bit test at
  bag+0x3AE0, 123-bit at bag+0x3AD0, 90-bit at bag+0x89A8, first-`0xFFFF` scan over the 90 x u16 table at
  bag+0x27C4, byte at bag+id+0x5762, …). Several dossier callee names in this batch are therefore fictional;
  I used the disassembly instead. **`tools/xref.py` / the function boundary table need fixing** before the
  next batch generator run (same class of problem R3_007 reported).
- **`0x00100B74` = `wcslen` mis-marked `noreturn`** (FACTS trap): all five `Ui_TextFormat_Set*` bodies in
  the readable tree are truncated at that call, so those verdicts come from the disassembly (slot offsets
  2=+0x218, 8=+0x848, 9=+0x950 on `*0x007AC834`), not from the C.
- **`0x0035E6B8` (`maybe_Ui_SceneFlow_DestroyObjectBody`) is a phantom callee** of those writers; the real
  target `0x0035EB98` is the `Party_Member` record (split-symbol merge).
- Corrections with the strongest new evidence: `0x004A4ADC` is `Party_Member_KnowsSpell` (u8[40] spell list
  at member+0x1274, not the item slots); `0x006327AC` is `Party_Member_GetAttack` (`ldrh [member+0x1A]`,
  FACTS +0x1A = Atk); `0x0048833C` reads a spell/skill record's bit 0x80 or the party member's
  +0xDED/+0xDEE (never a monster); `0x004A3DA0` is a monster-book detail builder (vtable slot 0x007755CC,
  monster record + `Text_CopyMessageLine` + the display-mode getters used by the named `Ui_MonsterBook_*`).
