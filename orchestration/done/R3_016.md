  The body only hides panes 3/4/5 and writes one of four hard-coded delta texts; nothing is tweened.

  confirmed `Ui_ReleaseSubObject` (0x003BC520); callers are `Gfx_Resources_Release`,

  confirmed array *destructor* `std_destroy_range` with element destructor `0x0032686C` for the 7-slot
  arrays at +0xC / +0x23C; every caller is a poker/roulette/slot class. "Init" was backwards.
- `0x0041CA58` `maybe_Ui_ListWidget_ResetScroll` -> `Ui_ListWidget_ResetToFirstEntry`. It re-inits the
  item iterator and selects row 0; no scroll offset is touched.
- `0x0044C5C8` / `0x0044C544` -> `Field_SceneObject_SpawnItemFieldEffect` / `...B`. Item kind byte
  `+0x0C == 0x25` -> 2D effect at the object tile; the old "IfItemRecord" wording described a test.
- `0x0048ED38` `maybe_Member_GetEquipmentCategory` -> `Party_Member_GetAttackCount`. Returns 2 for the

  rows/instances), not as an equipment category.
- `0x004D5168` `maybe_Ui_FormatModelLabelArgs` -> `Battle_Ui_FormatActorNameArg`. All callers are battle
  UI paths; the body formats the member name at `member+0xCA` or a gimmick text and writes message arg 2.
- `0x004E2020` `maybe_Gfx_Model_UpdateLodByScreenSize` -> `maybe_Battle_Effect_SpawnFocusEffect`. The
  ratio uses vt[+0x90] (HP per FACTS) / vt[+0x94] and selects one of the two named FocusPoint effect

- `0x004E4BA4` / `0x004E4FC4` `maybe_Ui3D_*` -> `Gfx_SceneSprite_Dtor` / `_DtorB`. Both install their
