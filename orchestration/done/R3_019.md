## Problems / notes

1. **The pre-baked dossier was empty on arrival.** `orchestration/naming/refine/dossiers/R3_019.md`
   reported "no readable file found" for all 50 functions. It had been generated while another
   worker was rewriting `decomp/readable/functions/`. I re-ran `python tools/make_dossiers.py R3_019`
   (108 KB, all bodies present) and used that. Individual `fn.py` calls also hit transient
   "no readable file" answers during the same regeneration window and worked on retry.
2. Several names that appear as *callees* in this batch are still wrong and influenced the first-pass
   summaries. I worked around them rather than editing outside my scope:
   - `0x00487FC0` (`Text_MarkLayoutDirty`) is a float scale/round helper used by the battle damage
     math (`vmov s0/s17`, `vldr 100.0`, `bl 0x6731EC`, float return in s0).
   - `0x0035E6B8` (`maybe_Ui_SceneFlow_DestroyObjectBody`) has 508 callers — it is a ubiquitous
     shared helper whose current name is definitely wrong.
   - `0x0051CBF8` (`maybe_Sound_ChannelWork_Ctor`) is the `nn::err::FatalErrInfo` constructor.
   - `0x0048FE28` (`Text_GetRowAdvance`) and the camera-named callers around 0x006542CC are not
     text/camera code either.
3. Not verified (name-only change, no emulator run): which screens vtables 0x7609AC / 0x77E6B8
   serve; what the two floats returned by 0x0048FEFC are; whether 0x006542CC's six-row table is a
   smith recipe; whether 0x0050D864/0x00658858 belong to the icon cache or to CECD; the exact page
   semantics of 0x006E5C68 (body truncated by `halt_baddata`).
