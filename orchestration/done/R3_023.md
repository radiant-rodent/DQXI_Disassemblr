### Main findings

- **0x001E6C58 `Event_RebuildIdSet`** (was `maybe_ItemList_BuildOwnedIndex`). Its sibling
  `Event_UpdateIdSet` (0x001E7660, 0.5) maintains the same byte vector with the same 2..6 state
  window and forwards to `Event_OnQuestFlagChange`; this function rebuilds that quest/event id set
  from the save work on scene open. It is not an item list.
- **0x001DA410 `Field_RegisterActorModels`** (was `maybe_Model_RegisterActorTables`). Called from
  `Field_ResetTalkState`; resolves names from the two field tables and registers them through
  `Ui_RegisterActor` into the Field_ObjectManager class lists (+0x1C/+0x20).
- **0x00277D28 `BattleUnit_GetLinkedModelByIndex`** (was `maybe_BattleAi_GetTargetUnit`). No AI code:
  it walks the same +0x704/+0x708 model-slot lists as `Actor_UnlinkFromParentList3` and returns the
  entry's +0xC model. The `BattleAi_` prefix came from the neighbouring address range, not the body.
- **0x002F5D34 `Ui_SceneFlow_SelectStatusCharacter`** (was `maybe_Ui_JockeyPanel_SetPreviewVisible`).
  The entire body is `Ui_StatusWindow_SelectCharacter(work+8->+0x88, id)`; there is no jockey panel.
- **0x001CA91C `Battle_ActionModel_ApplyPartParams`** (was `maybe_Model_UpdatePartScale`). It copies
  ~30 part parameters from the `0x0063E5C8` record; the RNG only randomises one scale. It runs once
  from `Battle_ActionModel_InitFromDescriptor`, not per frame.
- **0x001EAE88 `Ui_ShopItemList_ResetListPanes`** (was `maybe_Ui_ShopWindow_ReleaseListsC`). The C
  suffix was a placeholder; the body is the shop list's open-reset (cursor + two text layers +
  intrusive lists + row pane).
- **0x001F3084 / 0x001F2F94** still `maybe_`, but the summary now records the verified base: the
  assembly at 0x001F3084 computes `work+0x24800+0x298+0x8800+0xED = work+0x2D385`
  (= save work+0x88ED), and `SaveSlot_GetStateByte`/`SaveSlot_GetDisplayByte` read the same 11-byte
  block. The index meaning (save slot vs recipe/variant index) is still undecided.
- The two "callers" `Ui_FiveRowStatusWindow_InitRows`/`Ui_SelectRowWindow_InitPanes` in the dossier
  are the mid-function split twin 0x001F3148 (party-member count), not real callers of 0x001F3084.

  `Script_CallSelectRuraPattern`; whether the branch opens or closes the pane is inferred.
