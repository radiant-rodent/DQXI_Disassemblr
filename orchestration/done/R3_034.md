## What the second pass changed

### 1. `func_0064C740` is a one-instruction getter, and it flipped four names

`0x0064C740` disassembles to `ldrb r0,[r0]; cmp r0,#5; moveq r0,#1; movne r0,#0; bx lr` — a pure
"phase == 5" query. `Field_Object2D_UpdateTouchState` writes 5 as the terminal phase after sending
the release, so the four 28-byte copies are all *"advance the touch state machine, return
`phase != 5`"*:

| address | old name | new name |
|---|---|---|
| 0x001A3C88 | `maybe_Gfx_Sprite2D_IsReady` | `Gfx_Sprite2D_UpdateTouchAndIsBusy` |
| 0x0021B510 | `maybe_Actor2D_TestStateAfterScroll` | `Actor2D_UpdateTouchAndIsBusy` |
| 0x00290580 | `maybe_Gfx_IsSpriteHidden` | `Actor2D_SpriteNode_UpdateTouchAndIsBusy` |
| 0x003A1CD0 | `maybe_Field_Gadget_IsTouchOutside` | `Field_Gadget_UpdateTouchAndIsBusy` |

The old names had the polarity backwards and described hit tests that are not in the body.

### 2. `asm/rodata` resolves vtable slots that the dossier reports as `vtable=None`

Grepping the ten touch-record addresses in `asm/rodata/*.s` found five of them as real slots. Every
2D touch class has a **refresh slot immediately followed by a getter slot**:

```
0x0075903C 0x001A3E68 refresh   / 0x00759040 0x001A3C80 getter (returns self+0x4D8)
0x0075A038 0x001D7098 refresh   / 0x0075A03C 0x001D6EA8 Ui_Widget_IsTouchActive
0x0075BE10 0x0021B6F0 refresh   / 0x0075BE14 0x0021B508 getter
0x0075D904 0x00290760 refresh   / 0x0075D908 0x00290578 getter
0x007677D8 0x003A1EB0 refresh   / 0x007677DC 0x003A1CC8 getter
```

That proves "RefreshTouchInfo" for all six and fixes one class: `0x00290760` is
`Actor2D_SpriteNode_RefreshTouchInfo`, not `Ui_Sprite_*` — slot `0x0075D904` lies inside the vtable
`0x0075D888` installed by `Actor2D_SpriteNode_Ctor` (`0x002907D8`).

### 3. The "six byte-identical screen thunks" were neither identical nor screens

`0x0030E948 / 0x0030EAA0 / 0x0030EB0C / 0x0030EB78 / 0x0030EBD0 / 0x0030F100` differ in the two
broadcast flags and in the message control code they run (0x2C/0xFF, 0x2B/0x00, 0x01/0xFF, or
none). All six call `Ui_Root_ReleaseAll` (`0x0030E4B8`) and four call
`Ui_MessageWindow_ExecControlCode` (`0x0030F258`) with `self`, which reads the tag table at
`self+0x1930` — so `self` is a message-window derivative. All six sit in the same dispatch table at
`0x0072B9xx`, alongside the confident `Ui_ShopWindow_*` and `Ui_MessageWindow_*` handlers.

### 4. The "DestroyChildren" family frees nothing

`func_0062F070` counts the ring at `self+0x110`, `func_0010EBD8` detaches one child,
`func_00123594` splices an embedded pane back in, `Ui_Object_BroadcastToChildren` only calls virtual
`+0x1C`. So the six copies are *"reset the child ring to the class's fixed panes and set their
visibility"* → `maybe_Ui_Window_ResetChildrenA..F`. The three shop-list bodies
(`0x001EAC9C / 0x001EAD74 / 0x0029442C`) only reset ring heads and re-link panes →
`maybe_Ui_ShopWindow_ResetListsA/B/C`; `0x0029442C` touches exactly the same offsets as the other
two, so its old `Ui_MainMenu_` prefix named the wrong class.

### 5. Best confirmations

- `Ui_Shop_EnsureGold` (`0x001C0EBC`) — the disassembly shows the dropped third argument, so the
  write is `bag[10] = record->f_18`. `func_00612B08` is `*(u32*)(bag + idx*4 + 0x2998) = value`,
  and `10*4 = 0x28` is exactly the gold slot from `FACTS.md`.
- `Ui_Window_AppendControlBytes` (`0x001C6788`) — an entry of the window script-command table
  `0x0072B698`, whose neighbours are the confident `Ui_Window_AdvanceScriptCmd12 / 13Or14 / 14B /
  14C / 15C`. It appends two bytes (0x09 then 0x11 or 0x12), so the old singular "AppendByte" was
  slightly off.
- The four byte-identical destructors (`0x001C635C / 0x002598B4 / 0x002D5734 / 0x00572BBC`) all
  store vtable `0x007824E0`, and `0x00572BBC` is literally that vtable's slot 1 — one class, four
  emissions, previously named with three different schemes.

## Suggested follow-ups

1. **`tools/fn.py` should glob `decomp/readable/recovered/`.** 11 of the 50 addresses print
   "no readable file found" in both the dossier and the live tool (same report as R3_026, R3_028,
   R3_032).
2. **`tools/make_refine_batches.py` / the scores generator should scan `asm/rodata/*.s` for
   vtable membership.** Five of my ten touch-record functions are real vtable slots but the dossier
   said `vtable=None`; that single grep turned six guesses into a confirmed family.
3. **`Ui_Root_ReleaseAll` (`0x0030E4B8`) is misnamed.** It is called from message-window page
   transitions (`Ui_MessageWindow_StepCode3D`, `Ui_MessageWindow_ResetAndExecTag`,
   `Ui_MessageWindow_ShowNextPageWithControls`) and only resets the child ring and the two lists at
   `+0xD1C` / `+0x1614` — nothing is released. `Ui_Window_ResetChildRing` would be honest.
4. **`Ui_Widget_IsTouchActive` (`0x001D6EA8`) is a getter, not a predicate.** It returns
   `self + 0x4D8`, the address of the touch record. `Ui_Widget_GetTouchRecord` would be honest.
5. **`func_00123594` / `func_001235A4` / `func_0010EBD8` / `func_0062F070` are still unnamed** and
   appear in dozens of UI teardown bodies. Naming them once (`Ui_Object_SpliceChild`,
   `Ui_Object_DetachChild`, `Ui_Object_CountChildren`) would unblock a whole family of
   `maybe_Ui_Window_ResetChildren*` entries.
