## Open problems

1. **The pre-baked dossier for this batch is truncated** at 31 of 50 functions (it stops after
   0x0028A5B4). `tools/make_dossiers.py` should be checked for a line/size cap.
2. **`decomp/readable/recovered/` is empty** while 16 batch rows point into it. The raw C lives in
   `decomp/ghidra/recovered/`. `tools/fn.py` and `tools/make_dossiers.py` should fall back to it
   (same complaint as R3_024 / R3_030 / R3_033).
3. **`os.listdir` on `decomp/readable/functions/` is flaky under WSL** — it returned 1,985 entries
   on one call and 17,994 on the next for the same directory, which silently produced a half-empty
   name map and a page of false `?` lookups. Any worker building a name index should retry until
   the count exceeds ~17,000 and cache it.
4. **The nine "recovered" 0x0028/0x0029/0x003B handlers are one family.** All call
   `Save_Task_DispatchStep` (0x00249074) on `self+0x13C`, copy the 0x10-byte task to `self+0x14C`
   and branch on `0x006496A0`, which the disassembly shows is just "is any of the first six bytes
   non-zero" — so the two states each handler requests are "empty record" vs "record has data".
   Four of them also gate on `0x0063071C(soundPlayer, id)`, which scans the player's 0x40-entry
   ring at +0x1848 and returns 0 while the id is present ("sound still playing"). Naming the
   remaining unnamed helpers (0x006496A0, 0x0063071C, 0x003D2CD0, 0x0062F070, 0x00123594) would
   let a later pass finish this family.
