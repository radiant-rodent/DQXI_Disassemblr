## Open problems

1. **The pre-baked dossier `orchestration/naming/refine/dossiers/R3_038.md` was generated EMPTY** — all
   50 blocks said "no readable file found" although every `decomp/readable/functions/*.c` path in the
   batch exists. Same failure as R3_037. I did not re-run `make_dossiers.py`; I rebuilt the equivalent
   context with `python3 tools/fn.py <addr> -b 0 --max 30` for all 50 addresses (61 KB, ~25 s) and read
   the readable C directly. `make_dossiers.py` should verify its output size and retry.

2. **`decomp/functions_index.json` has badly wrong function boundaries, and this poisons every
   caller/callee name in this lane.** Examples found here:
   - 0x00384C64 is recorded as 28 bytes but the disassembly runs to 0x003853F0 (literal pool at
     0x003853EC), so its "callees" are really the next function's.
   - 0x0035EB98 (the party-member resolver from FACTS.md) is listed as *inside*
     `maybe_Ui_SceneFlow_DestroyObjectBody`.
   - 0x00629280 is listed inside `maybe_Field_Actor_LoadEquipmentModel`; 0x005E7848 inside
     `maybe_Actor_ActionList_Rebuild`.

   Consequence: several "named callers" in this batch are pure artifacts. `Field_CreateActorRenderObject`
   does not call 0x003788E8 (it calls 0x00378914, the constructor that starts right after it);
   `GetDisplayMode` does not call 0x00384C64; `Ui_MessageWindow_SetTextByIdAnimated` does not call
   0x003B7298; and none of the 20 field/scene "callers" of 0x003DB0A4 branch to it. **Always confirm a
   caller by grepping the caller's own readable C or its asm range before using it as evidence.**

3. **`tools/fn.py` cannot see `decomp/readable/recovered/`** (same complaint as R3_024..R3_037):
   0x003BC418 and 0x00412B6C print "no readable file found" although their files exist under
   `recovered/`. It also cannot show a function that has no readable file at all (still `func_*`),
   which is most callees.

4. **Two callee names in this batch are provably misnomers** and should be fixed by whoever owns them:
   - `Ui_DataPanel_GetRowNameLength` (0x00612848) is not a length getter: it computes
     `bag + rowId*0x8c + 0x5fe4`, uses `wcslen` only as a `>= 7` guard, then scans the 20 entries at
     `bag+0x7b3c` for a free slot and memcpys 0x84 bytes. It is "add row to view".
   - `Ui_GlyphSlot_Reset` (0x004EE2F0) is an *effect-handle* slot reset (`Effect_ReleaseHandle` on two
     handles plus three u16 ids to 0xffff), not a glyph slot.

5. **`work+0x31f4` is the casino-coin counter.** The split symbol 0x0061251C adds a signed delta to it,
   clamps at `0x0098967F` and sets bit 2 of `*(u32*)(work+0x5be0)` — a *separate* 9,999,999-capped
   counter, not the gold field at `bag+0x28` that the neighbouring 0x00612570 adjusts. Worth adding to
   FACTS.md.
