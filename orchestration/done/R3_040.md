## What decided the verdicts

- The pre-baked dossier `orchestration/naming/refine/dossiers/R3_040.md` was **empty**: all 50 blocks
  said "no readable file found" although every batch path exists. I used `python tools/fn.py <addr>`
  on all 50 addresses instead (plus a tiny scratch helper for disassembly windows,
  `out/scratch/R3_040/look.py`, for the functions whose signature or return was damaged).
- The readable tree was being **rewritten concurrently** while this batch ran: `glob` returned 1,023,
  then 17,994, then 17,975 files within a few minutes and several batch `.c` paths temporarily
  vanished (including 0x0059F408, which appeared under its new merged name). `fn.py` therefore
  printed "no readable file found" twice for files that existed before and after. Worth knowing for
  the next worker: do not trust a single negative lookup during a merge.
- Every `scores.jsonl` row in this batch has score 6 and no vtable/string data, so the batch is in
  plain address order; the leverage was entirely the now-named callers/callees.
