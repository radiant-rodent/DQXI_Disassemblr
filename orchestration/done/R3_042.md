## How the decisions were made

The pre-baked dossier `orchestration/naming/refine/dossiers/R3_042.md` was generated **empty**: 42 of its
50 blocks say "no readable file found" although every path in the batch exists (same failure as
R3_036/R3_037/R3_038/R3_039). I did not re-run `make_dossiers.py`; the 50 readable files are 18-111 lines
each, so I read them directly, then used `tools/fn.py` for the live caller/callee/vtable view and read
single `asm/text/text_*.s` files when a constant or a branch target had to be checked.

`tools/fn.py` also cannot see `decomp/readable/recovered/`: 9 of these 50 live there (0x00119E8C,
0x0011B22A, 0x003BD9F4, 0x00195148, 0x002A5B4C, 0x002A5C60, 0x002A6464, 0x002FD158, 0x002FD384) and print
"no readable file found". I read those files directly.

**The xref caller lists are not trustworthy for this batch.** 9 of the 20 caller claims I checked were
mid-function split labels: `tools/xref.py` attributes a branch to a label a few bytes after a function
start to that function. Refuted examples (all named in the JSON evidence so the next pass does not repeat
them): `Ui_TsuyosaWindow_DtorBody` branches to 0x003B8AC0, not 0x003B8AA8; `Ui_SmithMenu_Dtor`,
`Ui_Overlay_Dtor`, `Input_Initialize`, `Sound_Driver_BuildTwoEvents`, `Monster_UpdateBehavior`,
`Gfx_GpuCmd_WriteTextureUnits`, `Gfx_DrawRecord_ApplyColorModulation` and `Ui_FieldScreen_Init` never textually reference the
address they were listed as calling. Every caller used as evidence here was re-checked in the caller's own
readable body.

## Confirmations worth keeping

- 0x004C3048 `Ui_SlotPlateWindow_UpdateStopSequence`: the animation literal at 0x004C3540 decodes to
  `"slot_stop"`, and the body waits on the clip's own time field before the 10-frame count.
- 0x0051AF38 `Gfx_Y2r_SendGetStatus`: writes the parameterless request 0x00260000 into the thread command
  buffer and sends it with svc 0x32 (`svcSendSyncRequest`); `Gfx_Y2r_WaitForCompletion` polls it.
- 0x00656D5C / 0x00656FCC: the PICA texture-state and per-texture-unit block writers that
  `Gfx_MaterialState_WriteAndCacheBlock` chains (verified in that function's body).
- 0x005BBBC0 `Field2D_Bob_Update`: the frame delta arrives in `s0` and was dropped by Ghidra (FACTS:
  ARM hard-float s0 arguments), so the signature gained the parameter.
- 0x003E72D4 `Field_Actor_RefreshModelVariantB`: the record lookup 0x0035EB98 is the documented
  party-member getter, so the variant choice is a member-state test on `member+0xDA` bit 0x10.

  names are wrong or the helper is more generic than "texture rows".
- The three class constants 0x00286E68 / 0x00287794 / 0x00286D68 compared in 0x00632AF0/0x00632BC4 are

- The shared reset/re-link/activate template family (0x00195148, 0x002A5B4C/B/D, 0x002FD158/0x002FD384)
  cannot be split by class: four window classes share one body and no caller identifies them.
