## What was done

Read the pre-baked dossier in five chunks, then re-decided every function against the now-named
neighbourhood. Extra evidence came from `tools/fn.py` on ~20 addresses (bodies, callers, asm) and
from 13 single-file reads of `decomp/functions/<name>.c` for the addresses whose readable file is
missing.

### Infrastructure problems found (worth fixing centrally)

1. **`decomp/readable/recovered/` is empty.** 13 of the 50 batch rows point at
   `decomp/readable/recovered/...` and every one of them printed "no readable file found" — in the
   dossier, in `tools/fn.py` and in `tools/make_dossiers.py`. The directory exists but holds zero
   files. Workaround used here: `decomp/functions_index.json` maps address -> `decomp/functions/<name>.c`,
   and those raw Ghidra files still exist and still carry the *current* callee names, so they are
   usable evidence (they are the older, damaged decompilation — `state = result` loses the `self`
   register — but the call targets and offsets are correct).
   **Suggested fix:** `make_dossiers.py` and `fn.py` should fall back to `decomp/functions/` when the
   readable file is missing.

2. **`decomp/functions_index.json` function boundaries are wrong, and that poisons caller lists.**
   Proven by disassembly in this batch:
   - `0x001E160C` is a complete 24-byte deleting destructor
     (`push {r4,lr}; str r1,[r0]; bl 0x00294C88; pop {r4,lr}; b 0x0010F6CC`); the next function
     starts at `0x001E1624`. The three xref "callers" of `0x001E160C` actually call `0x001E1624`,
     and the eleven "callers" of `0x001E1B70` call `0x001E1B88`.
   - `func_0062F070` / `func_0062F038` are attributed to `maybe_Actor_UpdateVisibilityForCamera`
     (`0x0062EF8C`, 320 bytes) but are separate functions.
   - `func_0010F6CC` is listed inside `Ui_DestroyRootSingleton` (`0x0010F6BC`) but is a separate
     12-byte function: `cmp r0,#0; beq; sub r1,r0,#8; ldrd r0,r1,[r1]; ldr r2,[r0]; ldr r2,[r2,#4]; bx r2`
     — the virtual deleter that every deleting destructor tail-calls.
   **Rule for future workers:** a caller list is only usable after checking the call target against
   the asm.

3. **New cheap technique that decided most of this batch: the address-neighbourhood test.**
   Load `symbols.json` once and ask "which confident names bracket this address?". The UI code is
   laid out class by class, so this identifies the owning class block far more reliably than the
   vtable hints the first pass used. It produced the biggest corrections here (see below).
   **Suggested:** add this to `orchestration/naming/FACTS.md`.

### Best corrections

- **The seven-function `maybe_Text_Block_Dtor*` / `maybe_Actor_SubObject_Release*` family**
  (`0x002FD81C`, `0x002FD918`, `0x002FDD50`, `0x002FE428`, `0x00307B70`, `0x00307C54`, `0x00308110`)
  is neither text nor a destructor. No text/string/glyph data is touched, there is no free call, and
  the base reset they all run is the named `Actor_SubObject_Reset` (0.50) — the shared "detach
  everything and rewind" routine that the confident `Ui_DiveForm_Close` (0.50) also calls. Renamed
  `maybe_Ui_Widget_Reset*` (0.40).
- **`0x001E160C` / `0x001E1B70` / `0x00413A7C`** were `Field_ActorMove_DtorThunkC/D` and
  `Field_ActorAction_DeletingDtor_2`. The asm shows `str r1,[r0]` (the vtable arrives as an
  argument) + shared base destructor + virtual deleter: three copies of one shared
  deleting-destructor body -> `maybe_Object_DeletingDtorWithVtable{,B,C}` (0.40).
- **`0x00292CE8` `maybe_Ui_PaneGroup_Ctor`** ends with the virtual deleter, so it is a destructor ->
  `maybe_Ui_PaneGroup_DeletingDtor` (0.45).
- **`0x001DC3E0` `maybe_Gfx_CreateNodeB`** is not graphics: the confident `Field_RegisterActorActions`
  (0.65) allocates 0x38 bytes and calls it with the literal `"nut"` (`0x001816FC`), exactly like its

  `maybe_Field_ActorNutActionCtor` (0.45).
- **`0x002A6140` `maybe_Ui_Window_CompareNameWithSlot_2`** compares nothing; it tail-calls the

- **`0x0028781C` / `0x00286EE0` / `0x00286DB8`** were `Ui_TextScroll_*` but sit inside the contiguous
  `Ui_CreditWindow` block (`CollectTextPanes` 0x00286B6C 0.60, `CloseSubPanel` 0x00286D30 0.75,
  `SetupTextPaneA` 0x00287FC8 0.50) -> `maybe_Ui_CreditWindow_*`.

  `Ui_AnimWidget_ResetAndSetFrame` (0.50) on the `+0x11C` sub-panel — they reset, they do not show ->
