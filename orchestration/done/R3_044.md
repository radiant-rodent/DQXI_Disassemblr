## What decided the verdicts

The batch's `scores.jsonl` rows are all `score: 0`, `vtable: null`, `neighbour_names: ""`, so the
"highest context score first" ordering does not apply here — the batch is in plain address order and
the pre-baked dossier carried no vtable information at all.

The leverage was a 30-line helper (`out/scratch/R3_044/vt.py`) that parses the flat `.word` listing in
`asm/rodata/*.s` into an address→word map and prints the ±N words around any slot address with the
current function names. That turned every "vtable slot 0x0075xxxx" claim in the previous evidence into
a checkable fact and decided 20 of the 50 verdicts. **Suggested follow-up:** teach `tools/fn.py` to do
this — it currently only reads `scores.jsonl`, which is empty for these rows.

## Stale previous evidence, now refuted

- **0x002A5448** claimed "next to the named `Ui_Font_IsBffntName`". No such function exists in the
  readable tree any more, and its base destructor 0x005799D4 sits in the Squirrel script-VM block
  (`Script_CallWithStackTop` 0x005799F4, `Script_InvokeScriptCallback` 0x00579B64). The `Ui_Font`
  label is unsupported; the entry stays `maybe_` at 0.40.
- **0x002B0B5C** claimed "the vtable 0x0075EA78 includes the named `Ui_Window_LayoutRows`". The slot
  after it is 0x002B11B0 and the next named entry in that table is
  `Field_ActorMotion_CopyTransformAndPlay` (0x0075EAAC), so the class is not proven.

## Twelve of the fifty are not functions

`0x002AFB24`, `0x002B7700`, `0x002B7798` and the nine `0x002B8EB0 … 0x002B90AC` addresses are
mid-function split symbols: each starts with a bare `bl` and then reads the caller's registers or
stack (`[sp,#0xAC]`, r4/r5/r6/sl). The instruction before 0x002B8EB0 is `mov r0, r4`. They belong to
the routine that ends at 0x002B90D4 — which is *not* `Ui_WindowFrame_ApplySkin` (that one ends exactly
at 0x002B8EB0) but the routine that calls it from 0x002B90AC. All twelve keep `maybe_` at 0.30 with
that fact in the summary instead of the old "interior block of 0x002B7DAC" claim.
