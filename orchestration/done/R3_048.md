# R3_048 — refine pass 2 on 50 low-confidence `maybe_` functions

## What I did

Read `orchestration/naming/refine/dossiers/R3_048.md`, re-read the readable C of all 50 batch
functions, and cross-checked the interesting ones with `python tools/fn.py ... --asm` and by reading
their named callers/callees. Decided every address and wrote
`orchestration/naming/refine/out/R3_048.json` (50 entries, one per batch row, batch order).

Verdicts: **17 confirmed, 22 corrected, 11 kept_maybe** (32 at >= 0.5, 18 keep the `maybe_` prefix).

### The dossier was stale and I regenerated it

`make_dossiers.py` output in the delivered tree said "no readable file found" for all 50 rows (the
readable files were renamed by `M1_merge_names` after the dossier was built). Running
`python tools/make_dossiers.py R3_048` rebuilt it (72 KB) from the current tree. It still reports
"no readable file found" for the three rows whose files live in `decomp/readable/recovered/`
(0x0015F0E4, 0x001623C8, 0x0018D24C) because `tools/fn.py` only globs
`decomp/readable/functions/`; I read those three files directly.

## Main decisions

1. **The ten 0x0014B5D8..0x001661E8 wrappers are Squirrel bound natives, not VM routines.**
   Every one is a 16–92-byte `push {r4,lr}; bl Script_Vm_*; cmp r0,#0; movge r0,#1; mvnlt r0,#0`
   body that forwards r0..r3 untouched, has no `bl` caller (table-registered), and sits in the
   0x00148xxx..0x00166xxx `Script_Native_*` block. Renamed `Script_Native_NewSlot`,
   `_GetInstanceUserPointer`, `_TableRemoveKey`, `_SetSlotFromStack` (returns 0 = no result value),
   `_GetInstance`, `_TableGetSlot`, `_Clone`, `_PushRootTable`, `_ToString`, `_CheckOneParam` (0.5–0.55).
   The old `Script_*` names duplicated the VM routine names.
2. **0x001A619C is the shared UI text setter, not a node finaliser.** Disassembly shows the guard
   `self->f_30 && self->f_34 && paneName`, then `bl Ui_Window_CollectNamedPane`, then `wcslen` and a
   tail `b Ui_TextElement_SetString`. 57 UI update routines call it (equipment, shop list, status,
   number roll, ...). Renamed `Ui_Widget_SetNamedPaneText` (0.52).
3. **0x00152EA8 is real code mis-decoded as `halt_baddata`.** The ARM body is intact (six-slot loop,
   `mla` scale by `[sub+8]`, wrapping index) and its only real caller is `Gfx_MovieQueue_Push`
   (0x006B95E4), which stores the return in the movie frame ring. Renamed
   `maybe_Gfx_MovieFrame_BuildEntry` (0.45); the caller list also contained a bogus
   `Input_ProcessKeyCallbacks` at 0x00152ECA, which is an address *inside* this function.
4. **0x0016925C is battle command-slot code, not a UI animation pop.** Its offsets
   `+0xFD/+0x100/+0x103/+0x106` with params `+0xFF/+0x102/+0x105/+0x108` are exactly
   `Battle_CheckUnitCommandCondition`'s (0x001745E8) four 3-byte command slots, and it validates
   through that function. Renamed `maybe_Battle_CommandSlots_TryDecrement` (0.45).
5. **The two event handlers 0x0015F0E4 / 0x001623C8 are field level-view commands, not UI.**
   Both are `{handler, style}` entries of the table dispatched by `Event_DispatchHandlerByte4`, and
   both fetch the level-view object (0x005E64E0) and call a vtable slot on it (0x38 with event 0x0E,
   or 0x40 with 4). Renamed `Event_Cmd_LevelViewEvent0E` (0.5) and
   `maybe_Event_Cmd_LevelViewSlot40` (0.42).
6. **Split-symbol fragments got fragment names.** 0x00152254 (`maybe_SQCommand_Tail`) is inside the
   1.00-confidence seed symbol `SQCommand` (0x0015179C, 2744 bytes); 0x00159C48
   (`maybe_MessageRegistActor_Continuation`) is inside `MessageRegistActor` (0x00159B7C). Their
   callee lists are the enclosing function's, which explains the absurd entries (Party_Member_*,
   Ui_ItemList_*).
7. **Other corrections**: 0x00158010 -> `Event_DispatchHandlerTimeline` (its only caller is
   `Event_TimelineDispatchRange`; table 0x007A6880 vs 0x007C310C for `Event_DispatchHandlerByte4`);
   0x00196A68 -> `Ui_List_GetSelectedRow` (60-byte row stride, caller is the shop confirm handler);
   0x001B6E88 -> `Gfx_Movie_SamplePairValues` ("Overlay" was the caller's business, the object is the
   movie player); 0x0017CC38 -> `maybe_Container_AddInstanceWithHandle` (caller is the junk symbol
   `tP_`, so "Map"/"IfVisible" were unsupported; f_e0 may be enabled or visible);
   0x00123B68 -> `maybe_Os_RefreshCachedHandle` (handle swap via IPC command 0x0C, no timer anywhere).
