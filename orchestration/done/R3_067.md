## The main findings

### 1. 31 of the 50 addresses are interior switch cases, not function entries
Continuing the pattern identified in R3_066:
- **26 addresses (`0x0034D0B8`..`0x003529F8`)** sit inside the massive 36,916-byte field scene-object spawner (`0x0034A03C..0x00353070`).
- **5 addresses (`0x0035B3A0`, `0x0035C0E4`, `0x0035C0F8`, `0x0035C650`, `0x0035C758`)** sit inside the third field scene-object spawner (`0x0035A1D0`).

In each case, an ARM store instruction containing the byte pair `0xB5xx` (e.g. `b0 b5 cd e1` `strh fp, [sp, #0x50]`) was misinterpreted by the batch scanner's Thumb heuristic as a function prologue `push {..., lr}`. Because the instruction is a store into an already-built stack frame inside a single enclosing function with one prologue and one epilogue, these addresses are not independent functions.

However, the semantic roles identified by the earlier pass remain completely accurate: each block builds an on-stack parameter record and invokes a specific setup function for that actor/model/effect type. Furthermore, 13 of these setup callees have since been confirmed and renamed in recent refine batches:
- `0x003A3CC8`: `Gfx_ModelPart_InitMeshColored`
- `0x003635B0`: `Gfx_ModelPart_InitWithTransforms`
- `0x00472474`: `Gfx_SpriteActor_InitFromDescVector`
- `0x004E6C38`: `Gfx_SpriteActor_InitMinimal`
- `0x003A2B6C`: `Gfx_ModelPart_InitRotated`
- `0x003DD974`: `Gfx_ModelPart_InitSimpleB`
- `0x0044AE10`: `Effect_HelixEmitter_Setup`
- `0x004E60D0`: `Gfx_SpriteActor_InitFromDescReleaseNodes`
- `0x004CAFA4`: `Field_SceneObject_BuildFromDescAlt`
- `0x004CAD68`: `Field_SceneObject_BuildFromDesc`
- `0x003A15E0`: `Gfx_ModelPart_InitColored`
- `0x004F0348`: `Gfx_SpriteActor_InitFromDescAligned`
- `0x0044CF94`: `Effect_SelectEmitterVariant_Setup`

All 31 blocks are preserved as `kept_maybe` (confidence 0.40 - 0.45) with updated summaries referencing their confirmed callees.
