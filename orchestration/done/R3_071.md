## The two problems that shaped this batch

### 1. `decomp/xref.json` caller lists are wrong for merged symbols

The project call graph attributes a call to the *nearest preceding symbol*, and Ghidra merged many
small functions into one symbol here. `0x00642248` is recorded as 252 bytes
(`0x00642248..0x00642344`) but its real body ends at `0x0064227C`; the remaining 0xC8 bytes are six
unrelated accessors. `xref.json` therefore credited it with the callers of all six neighbours.

Concretely: `xref.json` lists `IsEndActorMove` (0x0014DCCC) as a caller. The disassembly at
`0x0014DD48` is `bl #0x6422d8`, not `#0x642248` — a different function inside the merged range.

I wrote a scratch helper (`out/scratch/R3_071/xref.py`) that greps the raw disassembly for the exact
target address and maps the hit back to its containing function. It runs in ~5 s for the whole
`asm/text/` set and replaced the dossier's caller lists for every decision below. The same problem
affected the *callee* lists: `0x00642248` was reported as calling `Ui_HitTest_FindCell` (0x0062C988)
because its real callee `0x0062CB64` is a mid-entry of that merged symbol.

### 2. The readable tree is being rewritten concurrently

`decomp/readable/functions/` changed under me mid-task (17978 -> 17972 files, then back), so
name-based paths from the batch file intermittently 404'd. I resolved files by their `_<addr>.c`
suffix instead (`out/scratch/R3_071/show.py`). No file outside my ownership was touched.

## Decisions

### Confirmed (10)

The six `Sound_SeqField_Get*` accessors plus two of their siblings are the solid win. All of them are
one-argument getters over the shared tagged-field lookup `0x00661534`, and each now has a **named**
caller that consumes the value in a specific slot:

| address | name | named caller | how the result is used |
|---|---|---|---|
| 0x0065FBD4 | `Sound_SeqField_GetByte_Off08` | `Sound_Seq_GetTrackChannelBase` | stored as a byte |
| 0x0065FBFC | `Sound_SeqField_GetByteHi_Off08` | `Sound_Seq_GetTrackChannelBase` | stored as `!= 0` |
| 0x0065FCA4 | `Sound_SeqField_GetValue_Off08` | `Sound_Seq_GetWaveRefBase` | `outWaveRef[1]` |
| 0x0065FD24 | `Sound_SeqField_GetValue_Off0C` | `Sound_Seq_GetTrackKindBase` | `*outTrackKind` |
| 0x0065FD44 | `Sound_SeqField_GetByte_Off0C` | `Sound_Seq_GetTrackKindBase` | stored as a byte |
| 0x0065FD6C | `Sound_SeqField_GetFlag_Off0C` | `Sound_Seq_GetTrackKindBase` | stored as a byte flag |
| 0x0065FF50 | `Sound_SeqField_GetInt_Off14` | `maybe_Sound_Seq_GetTrackOffsetBase` | tail-jump target |
| 0x0065FF98 | `Sound_SeqField_GetPointer_Off14` | `Sound_Seq_GetEntryPairBase` | dereferenced as a record |

Disassembly also fixed their signatures: all eight are **one-argument** functions. The readable C's
four-parameter signatures (`rec, arg2, arg3, index`) are the `push {r3, lr}` 8-byte-alignment artefact
documented in FACTS.md — the body only ever reads `r0`.

Two more confirmed:

- **0x006483D4 `Ui_Window_FindPageByEntryId` (0.50)** — its only exact caller is the named
  `Ui_MemoriesWindow_SelectEntryById`, which uses the returned page/index pair to open the page that
  owns a list model's current short id. Page stride 0x8C, count at `+0x1CFC`, u16-array walk with
  count at `[0]` and relative offset at `[4]`.
- **0x0064D630 `Ui_SmithMenu_GetCellValue` (0.50)** — the cell-index expression is byte-for-byte the
  one in the already-confident `Ui_SmithMenu_GetCellIndex` (0x0064D59C, N_021 at 0.50):
  `u16 at row+0xC + f_13*5 - vtbl[+0x68]()`. Only the final byte load (+0x40 / +0x54) differs.

### Corrected (5)

- **0x00642248 `maybe_Ui_List_CellMatchesAtPoint` -> `Field_Placement_CellMatchesAtPoint` (0.55).**
  The five real callers are all field placement (`Field_Placement_TestAreaA`,
  `Field_FindPlacementCellByDelta`, `maybe_Ui_List_MoveCursorToFreeCell`,
  `maybe_Ui_List_CanMoveCursor`, `maybe_Ui_Overlay_CheckEntryPlacement`). Disassembly of the two
  callees: `0x0062CB64` = cell index from a point over the s16 rect at `+0x30..+0x36` (returns -1
  outside), `0x0062C23C` = "cell state byte == expected". `Field_Placement_TestAreaA` builds the
  descriptor as `{word, word, expectedState=1}`, exactly the shape read here. The `Ui_List_` prefix
  described a menu cursor that does not exist.
- **0x00643744 `maybe_Actor_IsHandleAliveC` -> `maybe_Actor_IsHandleSlotUnused` (0.45).** The callee
  `0x0062F680` is `ldr r0,[r0,#0x28]; return r0 == 0`, so the first test is "the pointer at
  actor+0x1F60 is null". All three conditions are "must be zero" — the opposite of "alive".
- **0x00647F70 `maybe_Ui_Object_HasModel` -> `maybe_Object_IsNestedCounterBehind` (0.30).** The callee
  `0x00669DD4` is a two-counter comparison with two null guards
  (`obj+0x160 -> +0x568 -> +0x34 <= obj+0x160 -> +0x56C`). No model, mesh or handle lookup anywhere.
- **0x0064D5D4 `maybe_Ui_BagRow_GetSlotState` -> `maybe_Ui_SmithMenu_GetRowState` (0.45).** The
  address is a slot in the rodata table at 0x0076E7C4 whose neighbours are `Ui_List_ScrollToTopRows5`,
  `Ui_StatusPanel_UpdateSlotText`, `Ui_SmithMenu_CommitRow` and `Ui_SmithMenu_SubObject_Ctor`.
- **0x0064DB1C `maybe_Ui_SmithMenu_SlotsIdle` -> `maybe_Battle_UnitModel_AreSubSlotsIdle` (0.40).**
  The address appears in **four** rodata tables (0x0076EFF8, 0x00775A78, 0x00775B34, 0x00777134) and
  every neighbour in all four is a `Battle_UnitModel_*` method. It is a shared battle-unit-model
  slot, not a smith-menu helper.

### Kept maybe (35)

Mostly honest keeps: no caller at all, a damaged body (`unaff_`/`in_r12`/`in_ZR`), or a name whose
class attribution rests on one offset. Notable ones where the summary improved without a rename:

- **0x00642814** — the middle test is a float compare (`*(float*)(owner+0x148) != 0.0f`), not a
  boolean flag; the callee `0x00649BFC` is a mid-entry of the 0x00649BD8 blob.
- **0x006436C4** — the two-hop virtual forwarder is confirmed by disassembly, but whether `+0x70` is
  an owner getter (notify *up*) or a child getter (notify *down*) cannot be decided; the neighbouring
  rodata strings `common_3d_up_joy.bflyt` / `common_2d_up_joy.bflyt` only place it in UI layout code.
- **0x0065556A** — not a function (literal pool, `halt_baddata()`); confidence dropped 0.45 -> 0.30.
- **0x00658C40** — `in_ZR` continuation entry; confidence dropped 0.45 -> 0.30.
- **0x00660A80 / 0x00660CAC / 0x00660E0C** — the A/B/C variants are now distinguishable: they resolve
  the sub-tables at `+0x34`, `+0x2C` and `+0x1C` respectively (`ldr r1,[r0,#off]; add r0,r0,r1`).
- **0x00660AD8** — the second call (`0x0065FF20`) is a pure tag-to-kind mapping with no side effect,
  so "NotifyChange" cannot be right; kept only because no better short description exists.
- **0x00660D3C** — the old `void` signature was wrong: it tail-jumps into
  `Sound_SeqField_GetInt_Off14` and returns that value.

  sound range.
