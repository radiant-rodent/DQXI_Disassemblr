## Detailed Findings

### 1. Confirmed Functions (2)

- **`0x00666700` `Ui_SelectHighestVariantCode` (0.65)**
  - *Previous:* `maybe_Ui_SelectHighestVariantCode` (0.35)
  - *Context:* Called by named caller `Battle_Ui_PartyPanel_ResetRows` (0x0059B294) to query a UI child via `vtable+0x48` and probe variant codes 0x89..0x8F via `vtable+0xE8`. The returned code is stored at `win->f_4C7` and used throughout party panel updating to filter unit lists. Clean decompiled body without register damage.

- **`0x0066B264` `Work_AreAllNamedRowsUsed` (0.65)**
  - *Previous:* `maybe_Work_AreAllNamedRowsUsed` (0.45)
  - *Context:* Disassembly inspection revealed a clean 104-byte function (`0x0066B264`..`0x0066B2C8`). It iterates through 20 140-byte (0x8C) entries at `table+0x7B3C`, calling `wcslen(r4)` (`0x00100B74`), checking `length < 7`, non-null first wchar, and active flags. It returns 1 if all 20 entries are valid/used, 0 otherwise. Ghidra had truncated the function because the Thumb BLX to CRT `wcslen` (`0x00100B74`) was mis-flagged as `noreturn`.

### 2. Video Decoder Track C Routines (18)

- **`0x00140490`..`0x00141DC8` (18 functions: `maybe_Video_McPredict*`, `maybe_Video_DecodeCoefficientGroup*`)**
  - *Context:* These routines form Track C of the Mobiclip/MoLive video decoder pipeline, operating on half-size frame buffers (row pitch 0x200 vs 0x400 in Track A).
  - *Analysis:* Disassembly shows they match instruction-for-instruction with the Track A routines (`0x00133890`..`0x001351C8`). However, in all 18 functions, Ghidra's decompilation produced damaged parameter passing and register allocation (`unaff_r4`, `unaff_r5`, `unaff_r6`, `unaff_r11`, unrecovered jump tables). Per project rules (FACTS.md and `check_refine.py`), functions with damaged decompilations must retain `maybe_` and confidence < 0.5.
  - *Verdict:* All 18 are kept tentative with `maybe_` prefix at confidence 0.45-0.48 with detailed evidence noting their Track A twin relationship and register allocation damage.

### 3. Field 2D Screen Rect & Animation Sub-Object Family (10)

- **`0x00667BE4`, `0x00667D78`, `0x006681F0`, `0x00668840`, `0x0066D9FC`, `0x0066DA64` (`maybe_Field_Object2D_CalcScreenRectA..F`)**
  - *Context:* Virtual methods computing axis-aligned screen-space bounding boxes (x, y, w, h) for 2D field objects via coordinate transform `func_0031A658`. They differ in whether position is read from `object+4` or `object+8`, and whether extent is constant (1x1, 2x2), dynamic (`object->f_c/f_10`), or loaded from sprite frame headers (`object+0x298`).
  - *Verdict:* Kept as `maybe_Field_Object2D_CalcScreenRectA..F` at confidence 0.45 because the letter suffixes are arbitrary disambiguation tags across distinct vtable classes.

- **`0x00668108`, `0x00668178`, `0x006681DC` (`maybe_Field_Object2D_GetAnimField10/16/1C`)**

  - *Verdict:* Kept as `maybe_` at confidence 0.45 pending isolation of the exact semantic meanings of sub-offsets +0x10, +0x16, and +0x1C.
