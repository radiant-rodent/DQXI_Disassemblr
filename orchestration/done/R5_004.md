## Open problems / not verified

- **78 of 150 stayed `maybe_`.** Most are Ghidra-split fragments (`0x004D1CDE`, `0x001637F4`,
  `0x0047F9AA`, `0x004DE588`, the `0x006E5xxx` Thumb block) or state-machine steps whose only stable
  identifier is a numeric state id (`0x00480B44` 0x29DD, `0x00482C7C` 0x2A9D, `0x00483308` 0x2AE9,
  `0x00482FF4` 0x2BA5). Naming them properly needs the battle-UI state enum, which nobody has
  recovered yet.
- **`0x004B5A6C`** (`maybe_Ui_MessageWindow_ApplySpeakerGauge`) has a body that is clearly a
  party-gauge/text-colour refresh, but **all five callers are camera/gfx code**
  (`Camera_UpdateTransition`, `Camera_UpdateObstructionBlend`, `Camera_TestOcclusionByIndex`,
  `Gfx_Actor_CreateFromConfig`, `Ui_MotionPath_UpdateTransform`). Either the call graph is wrong for
  this address or the function is a shared helper whose real role is unknown. Left `maybe_` at 0.45.
- **`0x0018D7C4`** (`maybe_Ui_List_BuildRowRecord`): four of six callers are field scene-object /
  gimmick code, so the UI-list attribution is doubtful. Left `maybe_` at 0.45 rather than inventing a
  field name.
- **`0x003C9990`** (`maybe_Battle_ActionSequence_DispatchActorEvent`): the body calls
  `Battle_SelectActionTargets` and shows a gate + popup 0x636, no event dispatch. The noun is still
  the first pass's guess; a follow-up should decide between "select targets" and "gate check".
- **`0x002CF950` / `0x002CF9BE` / `0x006E5CCA` / `0x006E61DE` / `0x006E540A/B/C`**: Thumb fragments
  with lost arguments. Their callee lists (`Ui_Object_SetDrawPriority`, `Ui_Widget_SetNamedPaneText`,
  `Ui_List_SelectEntryById`) look like a shared list-scroll helper family, but the argument recovery
  is too damaged to name them individually.
