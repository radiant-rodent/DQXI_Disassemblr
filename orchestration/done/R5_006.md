## New facts established (verified in the code, worth adding to FACTS.md)

- `work+0x295C8` **is** `(work+0x24A98)+0x4B30`, i.e. the per-item ownership bitmask from FACTS.
  It is tested directly by `0x0063BF8C`, `0x0063C048`, `0x0063C0F4` and the whole
  `Item_BuildCandidateList` family (`0x002C2144`, `0x002C3774`, `0x002C38FC`, `0x002C3AF0`,
  `0x002C3CA0`, `0x002C3E30`, `0x002C43C4`, `0x002C45B0`, `0x002C4784`).
- Item id block **0xAA3..0xB3A** (152 ids) is special in three unrelated places: SE selection
  `0x005D9C84` (SE 10 vs 0xE), owned-state icon `0x00283488`, bag transfer `0x002FE9B0`.
  Adjacent blocks seen as item-list filters: 0x32..0xA3, 0x9BF..0xA18, 0xA19..0xA81 (0x69 ids).
- The `Item_BuildCandidateList` family is one template: clear count at list+0x8A, gate
  `ItemRecord+0x20 & 0x20` set and `& 0x40` clear, optional extra filter, insert sorted by
  `0x0066C368` into the u16 array at list+0x0A. The siblings differ only in that extra filter, so
  their names should always state the filter, never just a letter.
- `0x0022CFC4` and `0x00235E0C` (`Ui_Overlay_ApplySlotSetup`) are the entry point for "create an
  actor 2D part": 0x68-byte sprite object, name built from a template at 0x0022D170,
  `Gfx_SpriteObject_Ctor_2`, attachment at actor+0x74, then overlay manager mode byte
  `(work+8+0x48)+0x27F`.

## Tooling problem (not fixed — outside my ownership)

`tools/make_dossiers.py` only scans `decomp/readable/functions/`, so eight functions of this batch
printed `no readable file found` although their readable C exists under
`decomp/readable/recovered/`:
`0x00153DD8`, `0x0025BB0C`, `0x00283488`, `0x002A73C8`, `0x002C1EEC`, `0x002FE9B0`,
`0x00308B9C`, `0x003095D0`. `python tools/fn.py` says the same thing for those addresses.
I read the recovered files directly instead. Suggested fix for whoever owns the tooling: make the
dossier generator fall back to `decomp/readable/recovered/` (same naming convention) and make
`fn.py` do the same, otherwise every future refine batch will keep reporting them as missing.
