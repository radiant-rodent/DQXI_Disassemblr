`orchestration/naming/refine/dossiers/R5_007.md` in ten chunks, and appended the decisions to

## The decisions that matter (what a modder/user of these names should know)
* **Not functions** (should be merged/removed by a later cleanup): `0x0011E98E`
  (`maybe_Ipc_OpenSessionTailFragment` — interior label of 0x0011E940), `0x00426784`
  (`maybe_BattleUi_UnitListTailFragment` — 16-byte duplicate prefix of 0x00426794),
  `0x0024039C` (literal pool after a ctor), and `0x0011223E` which is a *merged* fragment: its first
  half is byte-identical to `0x00112250`, its tail belongs to a sound-unit neighbour.
* **`0x00591204` is real code, but the symbol starts ~0x18 bytes early.** The first pass called it a
  `.rodata` blob; the body actually allocates and registers a camera regular-shake work object
  (`Mem_AllocAligned_2(0x94)` + `Container_NameHash_Ctor` + `Container_NamedMap_Insert` on
  `(work+8)->+0x78`). The 'ReguralyShake' string sits at 0x00591204 and the real prologue is at
  0x0059121C, so the symbol needs splitting before the name can be trusted. Renamed
  `maybe_Camera_RegularShake_CreateWork`, kept at 0.4.
* **Item-prefix removals where the body is not the 0xB3B item table**: `0x00278604`, `0x0027909C`,
  `0x00279F1C`, `0x00279C48` now use `Bag_`/`Data_` (they all use the 0x121-entry / `func_0063E05C`
  container, which FACTS says is message-ish, not items). `0x001E7300` keeps `Item_` but is now
  `Item_GetFirstOwnedVariant` (the "valid" of the old name hid an ownership probe).
* **`0x00380BF0` was wrong on both halves of its name**: reading the tail shows it sums distance
  deltas over eight range entries and writes a 0..3 range *bucket* into the caller's 6-byte
  out-struct. It is `maybe_Item_ClassifyRangeBucket`, not an equipment-category getter.
* **`0x00168200` was Field_ but is Battle_**: sole caller is the confirmed `Battle_InitWork`, and it
  installs `g_stateSequence40Vtable` with 19 states → `maybe_Battle_InitStateSequence` (body damaged,
  0.3).
* **`0x00119498` / `0x0011F3C0` are the gfx IPC worker pair**, not a generic engine service: the init
  is called from the confirmed `Gfx_InitDrawState`, uses `Gfx_WriteHwRegsMasked` /
  `Gfx_SetTextureSource`, and passes 0x0011F3C0 as the thread entry.
* **`0x00123260` is the `srv:` session release** (`g_srvSessionHandle` / `g_srvClientState` /
  `g_srvDefaultHandle`) → `Srv_ReleaseSessionHandle`.
* **A family of `CreateDefault` thunks** (`0x0016096C`, `0x00161DC4`, `0x00162758`, `0x00162DE8`,
  `0x0056D6D4`) is really "new + shared ctor `func_00579974` + install vtable"; they are now named
  after the vtable they install, because the old `Ui_Widget`/`Container` names were contradicted by
  them (e.g. 0x00162DA8 installs `g_soundPlayerVtable`). Three of them (`0x00162084`, `0x00162278`,
  `0x00162DA8`) stay `kept_maybe` because the vtable itself is unnamed/misnamed.
* Squirrel-side naming was not needed anywhere in this batch.

## Duplicate-name fixes

`naming/out` and `refine/out` batches):
