# R5_008 - refine pass on 144 low-confidence `maybe_` functions

## What I did

Second (refine) naming pass over the 144 addresses in
`orchestration/naming/refine/batches/R5_008.txt`, using the pre-baked dossier
`orchestration/naming/refine/dossiers/R5_008.md` (read in 5 chunks, never walked the
`asm/`/`decomp/` trees) plus, for the five addresses whose readable file `tools/fn.py`
could not find, the recovered bodies in `decomp/readable/recovered/`.

Output: `orchestration/naming/refine/out/R5_008.json` - **144/144 addresses covered**,
one object each, UTF-8, validated by `python tools/check_refine.py R5_008` ->
`R5_008: OK`.

Totals: **26 confirmed, 5 corrected, 113 kept_maybe**.

- 0x00607B7C `maybe_BattleScene_InitAndUpdatePartyStatusFlags` -> `maybe_BattleScene_Init`:
  a 24-byte thunk that only calls `Battle_Initialize`; the printed party-status body belongs
  to the split symbol at 0x00607B94.
- 0x004A7654 `maybe_Anim_InstanceList_ApplyModeByte` -> `maybe_Ui_Overlay_ApplyModeRecord`:
  no animation list at all, only the overlay mode byte `+0x281` and the mode-record getter
  0x0063D6B8; all seven callers are model-variant setters.
- 0x003B3FD4 `maybe_Event_Handler_CancelMotion` -> `maybe_Field_ActorMotion_PlaySubMotion4`:
  the body *plays* sub-motion 4 (poll `+0x14`, play `+0x10`); it never cancels anything.
- 0x003719B4 `maybe_Field_Actor_ResetInteractionState` -> `maybe_Ui_Overlay_ResetInteractionState`:
  the actor argument is never read; the call goes to the overlay manager (work+8->+0x48).
- 0x00374440 `maybe_Field_ActorAction_StoreActorValue` ->
  `maybe_Field_ActorAction_ApplyFacingFromTimer`: the body does two specific things
  (overlay interaction clear + `targetActor->facingDirX = actionTimer`), none of them
  "store actor value".
