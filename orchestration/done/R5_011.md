## Decisions worth recording

- **Vtable-name evidence is treated as class evidence.** Where a constructor installs a named
  vtable (`g_uiTextPaneWindowVtable`, `g_uiRacingWindowVtable`, `g_uiObjectBodyVtable`,
  `g_sharedRenderStateVtable`, `g_stateSequence50/78Vtable`, `g_uiDungeonCheckWindowVtable`,
  `g_uiTxtL1WindowVtable`, `g_uiFourRowTextWindowVtable`), I renamed the function after the vtable
  instead of after its address or its caller. Those vtable names are themselves earlier guesses, so
  the confidence stays at 0.40–0.45 and the `maybe_` prefix stays.
- **The `Ui_GetCore()->f_14->f_1C` family stays `maybe_`.** ~25 functions are one- or two-line
  wrappers around virtuals `+0x8/+0xC/+0x10/+0x14/+0x18/+0x24/+0x30/+0x3C/+0x44` on that
  sub-object. The bodies are certain; the class and the meaning of each slot are not. I kept the
  existing mechanical names and rewrote the summaries to say exactly which slot is called.
- **The "copy a two-word global pair if a view query succeeds" family stays `maybe_`.** Eight
  functions (0x001B68A0, 0x001B68E4, 0x001E23F8, 0x001E2808, 0x001EF8A0, 0x001EF8E4, 0x00211270,
  0x002C6BFC, 0x002C6F30, 0x00327448) copy a pair from a different `0x0072xxxx` global into a
  different destination. Nothing in the batch identifies the pair (position? colour? frame range?),
  so "Rect"/"Pos" wording is flagged as a placeholder in the summaries rather than promoted.
- **`0x00310C90` was renamed by caller breadth, not by body.** 67 callers spread over actor and
  event code (InnMessage, Actor2DMoveEx, GimmickDoorOpen, NPCEnemyDisable) rule out a UI window
  destructor; the body is the generic "install base vtable, release two children, free" template.
- **Damaged bodies keep confidence ≤ 0.3** (0x005DC35C, 0x005DFB14, 0x00417BC4, 0x002FCA04,
  0x003B9BF0, 0x001D5AE0, 0x00310900, 0x00169076/7A), per the Ghidra-traps rule.
- **`0x005D5A24` is typed `void` but forwards a callee result that is discarded** — noted in its
  evidence as a possible dropped return, so the `Get...Flag` reading is not promoted.

## What is NOT verified

- The vtable-derived class names (`g_uiTextPaneWindowVtable`, `g_uiRacingWindowVtable`,
  `g_sharedRenderStateVtable`, `g_stateSequence50/78Vtable`, `g_uiDungeonCheckWindowVtable`,
  `g_uiTxtL1WindowVtable`, `g_uiFourRowTextWindowVtable`, `g_uiMemberOrderWindowVtable`,
  `g_uiMovieWindow*Vtable`, `g_uiCursorSpriteWindowVtable`) are earlier guesses. If any of them is
  wrong, the eight `confirmed` names and the eight vtable-based corrections inherit the error.
- The 33 recovered-listing functions have no readable body; their summaries describe the recovered
  pseudocode only, and several are damaged (`unaff_*` registers).
- `0x00310C90`'s 67-caller list comes from `tools/fn.py`; I did not disassemble the call sites, so
  "shared base destructor" is an inference from caller breadth plus body shape.
- `0x004B7454`'s rename assumes `0x00633560` is the id→handle resolver used by 0x002FC280 and
  0x005923BC. That is consistent across three call sites but not proven by disassembly.
