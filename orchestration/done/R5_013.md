# R5_013 — refine pass on 149 low-confidence `maybe_` functions

## What I did

Second naming pass over the 149 functions in `orchestration/naming/refine/batches/R5_013.txt`.
Read the pre-baked dossier (`orchestration/naming/refine/dossiers/R5_013.md`) in six chunks,
decided each function from its now-named callers/callees/vtable siblings, and appended the
verdicts to `orchestration/naming/refine/out/R5_013.json` after every chunk.

Because the readable bodies are unchanged since the first pass, the new evidence is almost
entirely in the call graph. I therefore extracted the `DESC` / `PREV` / `CALLERS` / `CALLEES`
headers for all 149 functions into `out/scratch/R5_013/headers.txt` and worked from that, opening
the full body only where the header was not enough (the four functions whose dossier block said
"no readable file found", plus the five predicate-named functions where I had to confirm the
return type before keeping an `Is*`/`Can*`/`Check*` name).

## Decisions I made without asking

- **Template copies stay `maybe_`.** Nine functions (0x001BA350, 0x001BA46C, 0x0022AF34,
  0x002C0628, 0x00302184, 0x003AE244, 0x00477310, 0x004B40E4, 0x004E7060) are byte-identical
  "if motion done, select attract animation N" vtable slots. Their class labels (`Ui_SpriteMarker`,
  `Ui_Message`, `Field_ActorBehavior`, `Cut`, `Dig`, `Landing`) are unsupported by any caller,
  vtable or string, and giving them all one honest generic name would collide. I kept the
  existing distinct names at 0.45 and recorded "same body as 0x001BA350" in each summary.
- **Damaged bodies stay below 0.5.** Where the readable C contains `unaff_r*`/`in_*`/`halt_baddata`
  (0x00384C80, 0x003AAB10, 0x003BDAF8, 0x003DA364, 0x004A6840, 0x00502128, 0x00518154,
  0x005D35B8, 0x00316388, 0x0023CF0C, 0x001F2D10, 0x004E237C) I did not raise confidence even
  where the callers are named, and said "damaged decompilation" in the evidence.
- **Predicate names were checked against the return type.** `IsRowActivated`, `IsDetailOpen`,
  `CanMoveCursor`, `CheckFrameSpike`, `IsCursorCellFree`, `IsCacheCurrent`, `HasAnyRosterEntry`
  all have non-`void` signatures in their readable headers, so the FACTS.md "Ghidra dropped the
  return value" trap does not apply.
- **Four functions had no readable file in the dossier** (0x003AF284, 0x002D8970, 0x0032ABE0,
  0x00386F94). I read them from `decomp/readable/recovered/` instead of regenerating dossiers.

## Not verified

- **No test run.** Per rule 5, refine batches skip `tests/run_all.py`; nothing here changes code,
  only one JSON file, and the dispatcher validates it. `tools/check_refine.py R5_013` is the only
  check I ran, and it passes.
- **Static analysis only.** Nothing was executed in Azahar; every claim is from the readable C,
  the call graph and the named symbols. Names at 0.5 are "supported by the call graph", not
  "proven by behaviour".
- **Class labels at 0.5 are still labels.** For example `Ui_ShopItemList_StepConfirmSell` is
  certain about the *sell* part (it is the only twin that calls `Shop_SellItem`) but the
  `Ui_ShopItemList` prefix rests on the named callee `Ui_ShopItemList_ConfirmEntry`.
- **Some call-graph callee names are themselves misnomers** (e.g. `Snd_DetachChannel` appearing
  as a list-insert helper, `Ui_LoadIconTextures` inside an action sequence, `SaveData_ResetAllSaveData`
  inside a handle teardown). I did not trust those edges and said so in the affected evidence fields.
