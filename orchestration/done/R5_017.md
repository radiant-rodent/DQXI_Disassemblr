# R5_017 — refine pass 2 on 126 low-confidence `maybe_` functions

## What I did

Re-named / re-scored every address in `orchestration/naming/refine/batches/R5_017.txt` (126
functions) from the pre-baked dossier `orchestration/naming/refine/dossiers/R5_017.md`, reading the
readable C of each function and its now-named callers/callees/vtable siblings.

Outcome: **41 confirmed, 22 corrected, 63 kept `maybe_`** (47 entries now at confidence >= 0.5).

Seven addresses had **no readable file in the dossier** (`0x0050BDF4, 0x001607D4, 0x00285554,
0x003B7640, 0x00119E8C, 0x0011B22A, 0x001D03D0`). The files do exist under
`decomp/readable/recovered/` and I read them directly, which produced the only easy win of that set:
`0x001607D4 Field_ResetLocatorDefaults` (identity matrix + empty 31-char name + 0xFFFF ids + state 3,
confidence 0.2 -> 0.5).

Deliberate non-upgrades: anything whose body is `halt_baddata`/unaff-damaged, anything whose only
caller is itself a `maybe_`, and the four byte-identical container-node deleting destructors at
0x001C635C/0x002598B4/0x002D5734/0x00572BBC (the newly readable vtable global is
`g_osSequenceTaskBaseVtable`, but 0x00572BBC's callers are UI-label/equip-display code, which
contradicts that reading) stay `maybe_` at 0.45.
