## Findings worth reusing (add to FACTS.md if the orchestrator agrees)

- **`0x0029126C` is the shared visibility setter** `(object, visible)`: `ldr r2,[r0,#4]; strb r1,[r0,#0x14]`
  then, if the sub-object chain exists, `and r2,r2,#0xfe; orr r1,r1,r2; strb r1,[r0,#0x44]` — it stores
  the flag at `+0x14` and propagates it into **bit 0 of the pane's `+0x44` byte**. It is a real function
  entry (0x00291220 `Ui_Widget_ReleaseSub` ends at 0x00291264), not a split symbol.
- **`0x001A6680` is the shared pane-frame setter** `(container, paneId, frame)`. `Ui_Gauge_AddValue`
  calls it with `layoutNodeId << 16`; `0x002ABFE4` calls it with four pane ids and frame 0.
- **`0x006692A0` (`x6_`) is the shared handle/list predicate** used by every `*_IsHandleStale`
  function (`Field_Actor_IsHandleStale` 0x0064362C, `Field_Object2D_IsHandleStale` 0x0064C6C0,
  `Field_AnimObject_IsHandleStale`, `Field_SceneNode_IsRefRegistered`, `Ui_CheckObjectRefValid`).
  The five `maybe_Ui_IsRefStaleA..E` in this batch are byte-identical copies of that body on
  different handle offsets (+0x2F8/+0x2D8/+0x2CC/+0x2F4/+0x2FC) — the established verb is
  `IsHandleStale`, not `IsRefStale`.
- **The 0x00298xxx block is a save/load window**: its methods reference `Save_BeginLoadRequest`,
  `Save_Task_DispatchStep`, a state controller at `+0xD8C`, a record widget at `+0xD5C` and a
  "task finished" byte at `+0xD65`. The old `Ui_ListWindow_*` / `Ui_SmithMenu_*` labels there were wrong.
- **`0x0050F1C8` / `0x0050F204` / `0x0050F248` are NDM service commands** — the readable C names the
  session `g_ndmServiceHandle` (headers 0x00070040, 0x00010042, 0x00020002). `0x0050D978` is a CFG
  command on `g_cfgServiceHandle` (header 0x00030040). The old "unnamed session" evidence was stale.
- **Vtable-name evidence settles three class prefixes**: `0x002E8C68` installs `g_battlePopup3DVtable`
  (→ `Battle_Popup3D_Ctor`, not a list widget), `0x005D6588` installs `g_fieldGimmickValuePairVtable`,
  `0x0060EE9C` installs `g_fieldSpriteSceneObjectVtable` (→ `Field_SpriteSceneObject_Dtor`).
- **20 of the 150 addresses are not function entries** (Thumb/ARM interior blocks or split symbols):
  0x002AFB24, 0x002B7700, 0x002B7798, 0x002B8EB0, 0x002B8F14, 0x002B8F74, 0x002B8FC0, 0x002B900C,
  0x002B9060, 0x002B907C, 0x002B9094, 0x002B90AC, 0x005022A6, 0x005022E6, 0x0050DEA6, 0x0051045E,
  0x005104F2, 0x00526814, 0x00535EDC, 0x00535F50, 0x00537AE8, 0x00537B50, 0x00537C4C, 0x00537C5C
  (plus 0x00530054, a misdecoded ARM `bl`). They are now named `maybe_Split_InteriorBlock_<addr>` /
  `maybe_Thumb_MisidentifiedEntry` so they read as markers instead of fake functions.

## Open problems / not verified

- The 24 split-symbol markers are honest but useless as names; they should be **excluded from future
  naming batches** rather than re-guessed. I did not delete them from the symbol table (not my file).
- `maybe_Gfx_RenderParams_Init` (0x002AFA88) is a guess: the body initialises a ~0x1A4-byte block with
  **two** identical view-matrix groups (basis + negated direction + zero + a shared camera word), which
  looks like a stereo camera parameter block, but nothing names the owner. Confidence 0.3.
- `maybe_Ui_CreditWindow_ClampToRange` (0x00286DB8) still does not clamp anything in the readable body —
  it only picks an anim-widget frame. The verb describes the caller's intent.
- `maybe_Sound_ResetChannelState` (0x00518768) and `maybe_Sound_GetSystemThunkArg` (0x00517B54) have
  truncated bodies; their real callee sets (mutex/semaphore + `Sound_Channel_MixBuffers`) contradict
  "ResetChannelState", but no honest verb can be chosen from the C alone.
- `maybe_Field_IsHandleStale_2F8/2D8/2CC/2F4` and `maybe_Ui_IsHandleStale_2FC` are correct in verb but
  their owning classes are unknown; the offset suffix is a placeholder, not a real name.
- `maybe_Battle_Ui_MessageWidget_SelectActor` (0x005959AC) is one of seven byte-identical member-widget
  vtable slots; only the owning widget differs and that is not recoverable from the body.
- I did not verify any of these names against the running game or the emulator.
