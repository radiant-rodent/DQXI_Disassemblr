## Method

* Read `orchestration/naming/refine/dossiers/R5_019.md` in four chunks (dossier bodies + callers +
  callees + neighbours), then decided function by function.
* **16 of the 116 addresses had "no readable file found" in the dossier** (they live in
  `decomp/readable/recovered/`). I read those bodies directly from the recovered files; that was
  where most of this batch's real value came from, because several of them had never been read by
  any pass (`00160F14`, `00161918`, `0019B130`, `001C63C0`, `00248A88`, `003F30EC`, `003F3160`,
  `0025B10C`, `0025B838`, `0025E380`, `0025E4EC`, `0025B9A4`, `0025C1AC`, `00285474`, `002E9CD0`,
  `0018D24C`).
* No whole-tree searches, no dumps: only the dossier, the recovered bodies, and `check_refine.py`.

## Confirmed (5)

* `0x001356D4` / `0x0013BCD4` / `0x001422D4` → `Video_IdctSubblocks`, `..._B`, `..._C`.
  The recovered body is exactly "run the named `Video_IdctBlock4x4(_B/_C)` once per set bit of the
  sub-block mask byte at `0x08010400[index]`".
* `0x0016925C` → `Battle_CommandSlots_TryDecrement`. `Battle_CheckUnitCommandCondition(self,5)` is
  the validation of the four slots that were just decremented, and the rollback restores the saved
  counts. **Note for the M-tasks:** the readable struct field names in this file
  (`maybe_soundStateFD`, `maybe_soundTimerFF`, …) are stale/wrong — the four triples at
  `+0xFD/+0x100/+0x103/+0x106` are command slots (state byte, count byte), not sound state.
* `0x00279F88` → `Ui_Row_ApplyDefaultIconSet` (body is `Ui_Row_SetDefaultIconSet` + apply-to-unit,
  both callers are 3D battle-model code).

## Kept as `maybe_` (98)

The bulk are **CTR-SDK / nn::os / nn::fs / nn::snd internals** (`0x0010xxxx..0x0012xxxx`) and
**anonymous UI class overrides** (deleting destructors, per-class input handlers). For those the
operation is often certain but the object/class is not, e.g.:

* `Snd_SetChannelMode` / `Snd_SetChannelWord34` / `Snd_SetChannelWord3A` /
  `Snd_SetChannelAdpcmParams` — real per-channel setters with dirty bits, but the field meanings are
  read off offsets only.
* `Ui_Widget_DtorDeleteF` / `Ui_Widget_DeleteB` / `Ui_Widget_DeleteC` and the four
  `Menu_ClearPendingFlagA..D` — byte-identical template copies in different vtables/callback tables;
  the letter suffixes only distinguish the copies, so dropping `maybe_` would claim knowledge of the
  class that we do not have.
* The row-list input template family (`0x0025C1DC`, `0x0025B838`, `0x0025E380`, `0x0025E4EC`,
  `0x0025B10C`) — now documented in the summaries as the same template with different animation ids
  (0x2A/0x28, 6/7, 0xB/9, 0x1B/0x19).

Two confidence values were **lowered** (`0018CEA4` 0.40→0.35, `00286350` 0.45→0.40,
`002583F0` 0.40→0.35) because the bodies are truncated or depend on the caller's flags (`in_ZR`).
