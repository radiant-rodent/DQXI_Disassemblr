## Corrections (the first pass was wrong or misleading)

| address | old | new | why |
|---|---|---|---|
| 0x0050D73C | `maybe_Font_MapCharToLanguageFallback` | `maybe_Svc_Cfg_ResolveTextLanguage` | The value read from config block `0x000A0002` is a small language/region index (0..11), not a character. The switch on `Svc_Cfg_GetSystemLanguageCode` returns a language index (0/1/6/7/0xB), so there is no font and no char mapping. |
| 0x0051BD7C | `maybe_Sound_NotifyServiceThread` | `maybe_Err_NotifyServiceThread` | FACTS marks `0x0051BA34..0x0051CD40` as CTR SDK `nn::err`; the `Sound_` prefix is poisoned. The asm shows the TLS IPC block and `svc #0x32` in the callee, so it is a raw IPC send, not a sound call. |
| 0x0055DC04 | `maybe_Gfx_ModelInstance_ReleaseSlotEmittersIfUnused` | `maybe_Gfx_ModelInstance_ReleaseSlotEmitters` | The guard tests that the resource is still alive (refcount non-zero or flags set), which is the opposite of "if unused". |
| 0x005950F4 | `maybe_Battle_Ui_MemberScreen_SetupAttachments` | `Battle_Ui_MemberScreen_SyncMemberVisibility` | The body *releases* the attachment at +0x224 and drives member visibility/state (slot 0x98 for hidden, slot 0x3C state 4 for visible); it does not set attachments up. |
