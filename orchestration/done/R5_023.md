## Method

* Read `orchestration/naming/refine/dossiers/R5_023.md` end to end in six chunks (bodies, callers,
  callees, vtable neighbours, constants), decided function by function, wrote the JSON in three
  parts and merged.
* Two addresses had "no readable file found" in the dossier (`0x001C9F9C`, `0x00304900`); I read
  their bodies directly from `decomp/readable/recovered/`. `0x001C9F9C` turned out to be a real
  constructor body (pool getter + vtable install), `0x00304900` is `halt_baddata` only.
* Tried to resolve the unnamed helper callees that decide several names (`0x0018C1B8`,
  `0x001A6680`, `0x00629128`, `0x0065114C`, `0x00640248`, `0x005F5818`, `0x0063EFB0`) — none has a
  readable file or a symbol, and `asm/text/*.s` is a linear byte dump with wrong disassembly, so
  they stay unnamed. That is the main reason the batch has so few confirmations.
* No whole-tree searches, no dumps, no git, no `AGENT_LOG.md` read.

* `0x001C4E00` → `Ui_MessageWindow_UpdateNamePlateFlag` (0.50). The only callee is the 16-bit string
  length helper `0x00629128` (0x80 bytes after the named `std_Str_Length16B`), so the stored flag is
  literally "the name string is empty" — exactly what a name-plate visibility flag should be.
* `0x001C8588` → `Field_ClearSlotListsAndSwapTag` (0.50). Three named teardown callers
  (`Gfx_ResetViewHandles`, `Ui_StatusWindow_ReleaseSlots`, `Cutscene_Teardown`) plus the visible
  `+0xD58`/`+0xD70` double-buffer swap and virtual `+8` destroy. Kept at 0.5 because the first loop
  body is empty in the decompilation (the destroy call was dropped).
