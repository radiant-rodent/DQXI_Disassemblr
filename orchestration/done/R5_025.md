## What I did
Re-examined all 91 functions of `orchestration/naming/refine/batches/R5_025.txt` from the pre-baked

`python3 tools/check_refine.py R5_025` → `R5_025: OK`.

## The main finding: most of this batch's "new context" is symbol-resolution noise
This batch is the low-context tail (context score 0 or 1 for 88 of 91 functions). Where the dossier
did show named callers/callees, a large share turned out to be **nearest-symbol artifacts**: the
call-graph tool resolves a callee address to the nearest preceding *named* symbol, so a call to
`0x001235A4` is reported as `Snd_DetachChannel` (`0x00123564`), a call to `0x00245C80` as
`Ui_Toggle_FreeHandle` (`0x00245BC0`), a call to `0x00193E44` as `Gfx_ObjectDesc_Init` /
`Ui_MonsterDetailPane_DeletingDtor`, and so on. I checked each named callee against the body before
using it, and recorded the artifact in the evidence field where it mattered. Two consequences:

- `0x00245D6C` lost its `Ui_Toggle` class entirely (both the caller and the callee link were bogus).
- `0x002D9A2C` lost its five unit-model callers: the disassembly is a 16-instruction leaf ending in
  `bx lr` at `0x002D9A68`, and the callers actually enter at `0x002D9A6C`, a *different* function
  that starts right after it.

## Corrections (old name was wrong, not just weak)
- `0x00245D6C` `maybe_Ui_Toggle_UpdateAllNodes` → `maybe_NodeGraph_UpdateAllNodes` (0.40). The
  `Ui_Toggle` class came from two bad links: the "caller" `Sq_VmNewStackSlot` is a Squirrel VM
  function that only shares the constant `0x01000001` (Squirrel's null tag, used here as the
  child-array skip marker), and the "callee" `Ui_Toggle_FreeHandle` is really `0x00245C80`. The
  update-all-nodes operation itself is verified (transform context vtable +0xC, child array, twelve
  fixed sub-nodes, update list vtable +0x14).
- `0x002614C8` `maybe_Ui_TrainingWindow_StoreRowRecord` → `maybe_Ui_Window_SetRecordValueB` (0.40).
  Its twin `0x0025841C` is now confident as `Ui_Window_SetRecordValue`, so the operation is verified,
  but this copy uses different member offsets (`+0xDD8/+0xDDC`, list at `owner+0x80` instead of
  `+0x30/+0x34`, `owner+0x4A8`) — a different class. "TrainingWindow" had no support at all.
- `0x002C21AC` `maybe_Ui_DateDisplay_AdvanceByFlags` → `maybe_Ui_DateDisplay_HandleInput` (0.35).
  The body masks a u16 flag word with the same `0x142/4/1` pattern as the intact input handlers
  `0x0025DEF4` and `0x00263E18` and requests states 9/0xB/10 — it is an input handler, not a
  flag-advance routine.
- `0x002D9A2C` `maybe_Ui_Widget_BeginSubTweenOut` → `maybe_Ui_Widget_StartSubControllerState` (0.35).
  No tween anywhere in the body: it calls vtable +0x14 of the sub-object at `self+0x14`, sets the
  returned controller's `+0x6D`, then `self+0x120 = 1`, `self+0x121 = 0`.

## Open problems / not verified
- 86 of 91 names are still `maybe_`. This batch is genuinely low-context: 88 of 91 have context
  score 0–1, and after removing the nearest-symbol artifacts most functions have **no** named caller
  and **no** named callee. Another refine round on the same addresses will not help; they need
  either the callee helpers named first or a disassembly pass.
- The nearest-symbol artifact is systematic and affects other batches too. `Snd_DetachChannel`
  (`0x00123564`) is a real sound function (`func_0011FCBC(mixer, &channel->f_110); channel->f_18 = 0`),
  but it is being reported as the callee of every function that calls the unrelated list helpers
  `0x00123594` / `0x001235A4`. Any batch that trusted those links has wrong evidence.
- `0x002B1100`, `0x002C0654` and `0x002D1E40` are three copies of the same 4-entry × 0x18-byte step
  table dispatcher as the confident `Field_SceneNode_UpdateAnimation` (`0x002B54D4`). Naming that
  dispatcher once (a shared `std_`/engine helper) would settle all three.

## Suggested follow-up tasks
1. **Fix the callee-name resolution** in the call-graph tool: resolve a callee to a symbol only when
   the address is an exact symbol start, otherwise print the raw address. This is the single biggest
   source of false evidence in the refine batches.
2. **Name the shared list helpers** `0x00123594` (unlink) and `0x001235A4` (insert) — they appear as
   callees in dozens of functions across this batch alone.
3. **Name the step-table dispatcher** (`0x002B54D4` family) and the state-sequence helpers

   `0x002D1E40`, `0x002D1F1C` and the five `Ui_DateDisplay_EnterState*` entries.
4. **Drop the non-code entries** `0x00264CD8`, `0x00264FC8`, `0x002D3E06`, `0x002DF856`, `0x0025BBC8`
