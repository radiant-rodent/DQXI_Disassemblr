## Open problems / findings for the orchestrator

1. **`decomp/xref.json` caller lists are unreliable and this batch was sorted by them.** Verified
   counter-examples:
   - xref says `Ui_SmithMenu_UpdateRowDescription` (0x003EFAA0) calls 0x003818C0; the readable C
     does not reference that address at all.
   - xref says `Ui_MonsterBook_BuildEntryList` (0x003B2958) calls 0x003B2734; it actually calls
     0x003B2420 / 0x003B2494 / 0x003B2664 / 0x003B27B4.
   - xref says `Battle_ActionSequence_ExecuteMemberActions` (0x003C52E0) calls 0x003C46C8; it does
     not.
   Some edges are right (`Ui_ListWindow_SelectEntry` -> `Ui_TextBuilder_InitLayout` checks out), so
   the file is stale rather than systematically shifted. Consequence: the "context score" that
   orders refine batches is partly noise, and any name derived only from a caller list should be
   treated as a hint. Suggest regenerating `xref.json` from the current Ghidra project before the
   next refine round.
2. **`tools/fn.py` cannot see `decomp/readable/recovered/`.** It prints "no readable file found"
   for the 15 batch addresses whose readable C lives in `recovered/` (e.g. 0x00394CD0, 0x003B42D4,
   0x003C2660, 0x003D10FC). I read those files directly. One-line fix in the path list would help
   every later batch.
3. **`func_0029126C` is the single most reused unnamed helper in this batch** (called with 0 or 1
   on a widget/element pointer by 0x00398D8C, 0x003B3E04, 0x003B49B8, 0x003B4CA4, 0x003D51BC,
   0x003D7DDC, 0x003DE758, 0x003DEA44, 0x003ECA7C, 0x003ECAC0). Its semantics are known from the
   disassembly (stores the byte at element+0x14 and mirrors bit 0 into user+0x44) but it has no
   name. Naming it would let ~10 of these functions be named properly in one go.
4. **`func_0029E488`** (read by 0x003ADB74 and 0x003E41D4) is likewise unnamed and blocks those two.
5. Not verified: nothing here was checked against a running game or emulator; all verdicts are
   static (readable C, disassembly notes already in the doc headers, vtable sibling data).
