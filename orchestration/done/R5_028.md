# R5_028 — refine batch (131 low-confidence `maybe_` functions)

## What I did
Second naming pass over the 131 functions in `orchestration/naming/refine/batches/R5_028.txt`.
Worked from the pre-baked dossier (`orchestration/naming/refine/dossiers/R5_028.md`) in chunks,
opened the recovered readable files for the seven addresses that had no `decomp/readable/functions`
entry (`decomp/readable/recovered/*`), and used `python tools/fn.py` only to look up a handful of
unnamed callees (`0x001835AC`, `0x001B7A54`, and the `0x0066Bxxx` flag accessors) plus the seven
"no readable file" addresses. No whole-tree searches, no dossiers or batch files regenerated, no
other files edited.

## Open problems / not verified
- ~55 of these bodies are `halt_baddata()` (bad instruction data), dozens are split symbols or
  unaligned interior labels. Their new names describe the callee set or the byte range, not the
  semantics; several are almost certainly not real functions.
- Seven addresses (`0x00210880`, `0x002116C4`, `0x005A6738`, `0x005B14A4`, `0x005B1598`,
  plus the two no-body recovered files) had no `decomp/readable/functions` entry; for the three
  with no body at all the old names are still guesses and were kept.
- No call graph exists for the vtable-only functions (0x004D98E8, 0x004DCF64, 0x004EE7E4-style
  forwarders), so they stay `maybe_`.
- I did not run the full test suite: this is a naming batch, the dispatcher validates the JSON
  (`check_refine.py` OK). Nothing in this batch changes code.
