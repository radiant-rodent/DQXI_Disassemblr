## Findings worth reusing
- `Item_LookupRecord(ref, id)` resolves ITEM rows. Loops `for i < 0xB3B` with it are item walks.
  Many first-pass "Text_CharSet_*" / "glyph" names were item-list builders; renamed
  `maybe_Item_BuildCandidateList_*` (0x002C2144 family). Other "Text_*" names elsewhere that take an
  Item_LookupRecord id are probably wrong too.
- `func_0035EB98(work, id)` returns a party member record (name at +0xCA);
  `func_006292F0(member, slot)` returns the item equipped in that slot (6 slots).
  `0x0024C5D4` = maybe_Party_MemberHasItemEquipped.
- Equipment item ranges: 0xA4..0x9BF and 0xB19..0xB1C. 0xA19..0xA81 and 0xAA3..0xB3A are other blocks.
- `Ui_PopupEntry_SpawnFromTable(func_001FD96C(self), {actor, 0, msgId, 0xFFFF..}, 1)` is the battle
  message queue; several "effect"/"packet" names were battle messages (0x0031D428, 0x0042565C, 0x001FCE0C).
- `Ui_TextFormat_ReleaseSlot(n, fmt, str)` sets numbered message arguments (not debug logging).
- `0x0019259C` writes the per-item ownership bitmask at +0x4B30; `Item_CountOwnedTypesFromBitmask` confirmed.
- The 0x001E4CF4/0x001E4DD0 "PokerWindow" functions handle equipment for a party member; renamed EquipMenu.
