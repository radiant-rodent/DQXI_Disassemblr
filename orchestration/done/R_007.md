## Notes for the merge / later passes

- `0x0047F794` and `0x0047F600` are sibling methods of `Battle_Ui_UpdatePartyPanel` in vtable
  `0x00774680`; their state fields are all at self+0x5E5 with state ids 0x274B/0x2758/0x27AE/0x27BA/
  0x24D3/0x24F4/0x253B. A future pass that decodes that one state machine would resolve both names.
- `0x001C8B48` is the "2D sprite/2D actor render object" creator; its 3D counterpart is
  `maybe_Field_CreateActorRenderObject` (0x001C9208). Keeping the two names parallel is deliberate.
- `maybe_Party_IsReserveMember` (0x00629748) is still an inference from usage — the body only reads
  bits 0/1 of `func_0063F8F0(dm, member+0xC8)`'s flags byte. If a later pass decodes that
  32-entry character table, rename it.
- `maybe_Party_GetMemberRecordBit1` (0x0062923C) is named for its mechanism on purpose; it is a
  three-instruction flag getter, not equipment code (the old name was wrong).
