# R_009 — second naming pass (refine), resumed and finished

Batch: `orchestration/naming/refine/batches/R_009.txt` — 137 low-confidence `maybe_` functions.
Owned output: `orchestration/naming/refine/out/R_009.json` (only file changed besides `AGENT_LOG.md`
and this report).

## What the previous worker left

The JSON existed and already held all 137 addresses, but:

- `python tools/check_refine.py R_009` reported **54 problems**: 25+ entries had dropped the
  `maybe_` prefix while staying below 0.5 confidence, 7 entries were "0.5+ on a damaged body", and
  several names were not names at all (`Ui_CreateListWidget_1170`, `Model_NodeCtor_78217C`,
  `Ui_PaneSetupD`, `Container_MaskedEntryList_AddAt08`, `Field_EntrySet_AddShortE2`).
- The evidence fields were generic boilerplate ("Doc clearly supports …") and several signatures
  were wrong (arguments dropped, e.g. `Map_CheckCellBlocked(void* map, int x, int y)` for the real
  4-argument body; `ActorPart_CreateNamed(ActorPart*, char*)` for an actor + name).
- No `orchestration/done/R_009.md` existed.

## What I did

Read the batch, `scores.jsonl` neighbour lists, and the doc header of **every** readable file in the
batch (the headers carry the first pass's body reading). Then re-read the bodies where the verdict
was in doubt, searched the named callers with the `bl` sites (`asm/` + `functions_index.json`), and
checked `symbols.json` for the vtable and callee names. Rewrote all 137 entries:

- **68 confirmed** (0.50–0.60), **17 corrected**, **52 kept_maybe** (< 0.5, `maybe_` kept).
- Signatures taken from the recovered signature line and repaired where the header wrapped or where
  the recovered argument list was lost; `params` now names `self`/`record`/`handle`/… where the
  header or callers prove the meaning.
- Evidence names the concrete new context (named callees/callers/vtable siblings/string literals) and
  says explicitly when a part stays an inference.

`Gfx_ModelInstance_DrawAllPasses` (0x566BA8) and `maybe_Gfx_ModelInstance_DrawPassDispatcher`
(0x56AFFC) give the pass identity, so those names are confirmed at 0.5: VertexColor (f_31/f_4d),

(f_1b8) stay `maybe_` at 0.45: the flag that gates them is proven, the *meaning* of the flag is not.
0x569350 and 0x56A300 are damaged thumb bodies with no callers → `maybe_` at 0.40.
