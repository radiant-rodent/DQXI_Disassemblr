# R_014 — second naming pass (refine), resumed and finished

Task: re-examine the 119 low-confidence `maybe_` functions in
`orchestration/naming/refine/batches/R_014.txt` using the merged readable context, and write
`orchestration/naming/refine/out/R_014.json`.

## What already existed
The previous worker had produced a 119-object JSON (all addresses covered) but it was not usable:

- every `summary` was the same sentence template ("Confirmed: previous guess (...) is supported by
  readable evidence and named neighbours (context score ...)");
- every `evidence` string repeated the old evidence and added the context *score*, i.e. no new
  evidence at all, and several "confirmed" entries were promoted to 0.55 purely because the score
  was non-zero;
- `tools/check_refine.py R_014` had never been run (and two of its rules would have failed).

So I kept nothing verbatim: I re-derived every verdict from the readable body plus its named
callers/callees, and rewrote the file from scratch with `out/scratch/R_014/gen.py`.

## Method
1. Read the batch, the readable C of every function (header + body), and the `scores.jsonl`
   neighbours.
2. Built a reverse caller index over all 18,737 readable files (files mentioning each batch name)
   so each function could be read next to its named callers.
3. Spot-read the full bodies where the header claim was the load-bearing evidence
   (0x00199A10/0x00199B60, 0x001C2C84, 0x0025D2E8, 0x002DB8BC, 0x00465E58, 0x001D8C80,
   0x002F3930, 0x002B558C), and checked the ARM for the one "damaged" flag (0x001A549C).
4. Verified the family naming against the merged names of the surrounding functions
   (e.g. 0x001E53F8 = `Ui_PokerWindow_Confirm`, 0x005E7A34 = `Field_SceneObject_Hide`,
   0x0025A82C/0x0025B704 = the other `Menu_OpenMessageDialog*` siblings).
