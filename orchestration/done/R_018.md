Method (scripts kept in `out/scratch/R_018/`):
- `pack.py` — per function: header + **named callers** (built from an inverted index of every
  `func_XXXXXX` / `maybe_Name` / `Pascal_Name` token in all 18.7k readable files, so only real body
  references count, not doc mentions) + named callees + the first 30 body lines.
- `sup.py` — per function: the 10 nearest readable functions by address, its vtable cluster and
  `neighbour_names` from `scores.jsonl`.
- `vt.py` — per function: which `0x007xxxxx` class/vtable constants its body installs and which other
  readable functions install the same constant (this is what cracked the ctor/dtors).
- `build.py` — merges `dec1..dec4.json` into the output, regenerates each `signature` from the readable C
  definition (so it cannot drift), derives `params`, and enforces the batch rules (coverage, `change`
  semantics, confidence ↔ `maybe_`, duplicate names) before writing UTF-8.

## Corrections worth knowing
- **0x002F6B14** was `maybe_Field_FindJockeyObject`, but the body is a constructor that installs class
  pointer `0x00761E68` (the word before the item-info window vtable row `0x00761E78` used by the confident
  `Ui_ItemInfoWindow_Update`), and every named caller is a window that shows item details (shop, prize,
  equip-text, poker payout) → **Ui_ItemInfoWindow_Create**. 0x002F7738 has the same shape with
  `0x0076216C` (the list-window class) → **Ui_ListWindow_Create**.
- **0x0061BBDC** was `Ui_StatusWindow_Ctor`; it installs `0x007800C0`, the class of the confident
  `Ui_TimeWindow_Dtor` at 0x0061BC4C, so → **Ui_TimeWindow_Ctor**.
- **0x00191120** was `Ui_GetItemIconType`, but named callers feed its result into the actor appearance
  table (`maybe_Field_FindActorEntryByModel` compares it with `entry+0x30`) and it reads equipped item ids
  via `func_006292F0` → **maybe_Actor_GetEquipAppearanceType**.
- **0x0023A410** was `Ui_Menu_IsBusy`, but it reads `work+0x54` (the actor manager, per FACTS) and runs the
  attract/idle helpers on its two children, ignoring its argument → **maybe_Actor_UpdateIdleAnimationPair**.
- **0x002D9894** was `Ui_Object_Dtor1`, but there is no free call; the callees are the item-list iterator
  init and scroll-to-top → **maybe_Ui_ScrollList_Reset**.
- **0x005959AC** was `Battle_Ui_PlayMemberSe_Pair`; the body is byte-identical to
  `Battle_Ui_MemberWidget_SelectActor` (0x003C332C) and plays no sound → **maybe_Battle_Ui_MessageWidget_SelectActor**
  (“same body as 0x003C332C”).
- Nine 44-byte “finish” functions are one shared template (`if (func_00669DD4(actor)) func_002340B0(actor,N)`).
  The old `CanFinishCut`/`CanFinishDig` names described a query although the functions perform the finish,
  so they became `maybe_Field_Action_FinishCutIfDone` / `...FinishDigIfDone`; `maybe_Actor_ResetBattlePose`
  (no battle evidence at all) became `maybe_Actor_FinishMotionIfDone`. The other copies were kept as
  `kept_maybe` with the template body stated in the summary instead of pretending the verb is proven.
- **0x00255B3C** “ReleaseJumpRecords” frees nothing (it only sets a done byte) → **maybe_Event_MarkJumpRecordsDone**;
  **0x00253EA0** “SetEventParams” actually calls four fixed Squirrel functions → **maybe_Script_CallEventCallbacks**;
  **0x001F29D4** “Retag” releases *and invalidates* every handle → **maybe_Ui_HandleSet_ClearAll**.
- **0x0042A3B4 / 0x0042A780** sat in the middle of the named `Battle_UnitModel_*` class, not under
