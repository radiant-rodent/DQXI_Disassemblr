# R_020 — second naming pass (refine), 139 low-confidence `maybe_` functions

**Status: complete.** `orchestration/naming/refine/out/R_020.json` holds one entry for every address
in `orchestration/naming/refine/batches/R_020.txt` (139/139), and
`python tools/check_refine.py R_020` prints `R_020: OK`.

## What I did

The previous worker left nothing behind: no `R_020.json`, no done report, no scratch. I started from
the batch file (not regenerated) and the doc header of each readable file, which carries the first-pass
name, confidence and evidence.

New evidence for this pass came from:

1. **A call graph with names.** `scores.jsonl` only stores counts, so I imported the project's own
   `tools/make_refine_batches.score_candidates()` and dumped the named callers and callees of all 139
   addresses (`out/scratch/R_020/edges.txt`). That is what turned most `confirm`/`keep` decisions: a
   function whose callers are all `Battle_*` actions is not a UI queue, one whose callees are
   `Field_Actor_InitAttachedEffect`/`Gfx_EffectPart_SetDirection` is not a window builder.
2. The `neighbour_names` / vtable / cluster fields of `scores.jsonl`.
3. `symbols_recovered.json` (current names) plus the proposal batches `orchestration/naming/out/N_*.json`
   to check for a conflicting earlier name. There is no newer conflicting name for any of the 139.
4. Bodies of the readable C, opened where the header was thin (`recovered/` fragments) or where the
   first-pass name looked wrong.

Decisions: **56 confirmed / 9 corrected / 74 kept_maybe**. Only three names reach 0.60
(`Model_AttachAccessoryMesh`, `Field_Gimmick_SpawnNutEffect`, `Battle_CommandQueue_PushEntry`); the rest of
the confirmations sit at 0.50–0.55 because the evidence is a call-site/neighbour argument, not a string
literal or a byte-level check.

  balloon/popup helpers and both queue the same command 0x4B; kept as `maybe_` at 0.40.

  `Script_Native_TokenizeString` (0x0014872C), not entry points. The behaviour ("read arg 1/2 as a
  number") is right, so I kept the names at 0.45 with `maybe_` and said so, rather than promoting a
  non-function to a confident name.
- `0x0048356C` is a Thumb tail without a prologue; left at 0.25.
- Damaged bodies: `0x00552914` (unaff_r7 voice priority) and `0x0018BF48` (in_r12 owner pointer) were
  first proposed at 0.55 and `check_refine.py` flagged both. I re-decided them as `kept_maybe` at 0.45
  instead of weakening the checker.
- 72→74 `kept_maybe` entries remain because the only new context was a *count* of confident callers, or
  the caller names themselves are `maybe_` (the 0x005Dxxxx gimmick reaction family and the 0x0028xxxx
