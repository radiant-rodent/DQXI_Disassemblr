# R_021 — second naming pass (refine), 148 low-confidence `maybe_` functions

Batch: `orchestration/naming/refine/batches/R_021.txt` — **148** functions.
Output: `orchestration/naming/refine/out/R_021.json` — **148** entries, complete, in batch order.
Gate: `python tools/check_refine.py R_021` → `R_021: OK` (exit 0).

Final split: **68 confirmed / 29 corrected / 51 kept_maybe**; average confidence 0.47
(no name was pushed to 0.7 — the strongest evidence here is matched spawn-block callers and named
callees, not a decoded API).

## How the batch was worked

1. Read the readable C header (previous name, confidence, evidence), then the body.
2. Re-read the body against the *now-named* callees and against the caller list. The batch
   generator greps for the raw address, which misses callers that already use a name, so I built a
   name→callers index over all 18.7k readable files (`out/scratch/R_021/ctx.py`) and a symbol
   lookup (`sym.py`).
3. Where the readable body was obviously collapsed (a 56–200-byte function decompiled to a single
   "subroutine does not return" tail call), I read the ARM/Thumb in `asm/text/*.s`
   (`out/scratch/R_021/asm.py`). That is where most of the corrections came from: the decompiler
   drops the second half of many small virtual setters.
4. Only then decided. Families (sprite/effect part setups, popup slot factories, ctors) were decided
   as a group so the suffixes stay consistent.

## Not verified / open problems

- Everything is static evidence. No emulator run, no Squirrel-native cross-check (none of the 148 is
  a script binding), no bit-match run.
- **A background merge consumed this file while I was working**: `symbols.json` and
  `decomp/readable` were regenerated with `Recovered: R_021` at 22:57, before my last three edits.
  The final JSON differs from the merged state for `0x00190B48` (`Party_Member_ApplyPageContent`),
  `0x003B7C90` (`Ui_DiveForm_CreateBase`) and `0x004DA790` (`Ui_UmaWindow_Dtor_2`) — a re-merge is
  needed. The two rename targets (`Ui_DiveForm_Ctor`, `Ui_UmaWindow_Dtor`) are existing catalogue
  names that would otherwise have been overwritten.

  itself unrecovered, which is why the ordinals survive.
