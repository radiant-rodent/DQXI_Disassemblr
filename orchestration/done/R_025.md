# R_025 — second naming pass (refine), 123 low-confidence `maybe_` functions

## What was done

Processed **all 123** addresses in `orchestration/naming/refine/batches/R_025.txt` and wrote
`orchestration/naming/refine/out/R_025.json` (one object per address, in batch order).
No other repository file was modified except `AGENT_LOG.md` and this report; scratch helpers live in
`out/scratch/R_025/` (`show.py`, `callers.py`, `strings.py`, `res.py`, `build.py`, `c*.py`).

**Result:** 49 `confirmed`, 53 `corrected`, 21 `kept_maybe`; confidence 0.20–0.65 (mean 0.49).
`python tools/check_refine.py R_025` → `R_025: OK`. The JSON was re-read as strict UTF-8 and every
address in the batch is covered exactly once.

Method per entry:

1. started from the readable file's doc header (previous name, confidence, original batch, previous
   evidence) instead of re-deriving the guess;
2. re-read the body against the named neighbourhood: a caller index was built by scanning
   `decomp/readable/**` for every batch name (the C files call their callees by the merged names), and
   vtable dumps in `asm/rodata/*.s` were used to find sibling slots (e.g. the equipment-window vtable
   0x0076A318 holding `0x00617EA8`, `0x00617FB0`, `0x00617DD4`, `0x003D66C4`);
3. **decoded the inline pane-name literals**: `original/exefs/code.decompressed.bin` maps to the
   address space with `file_offset = address - 0x100000` (checked against a known symbol:
   `pager_num_r` at 0x0029D4F4 = offset 0x19D4F4). That resolved a dozen literals the first pass had
   given up on (`0x4ADD00`/`0x4B741C`/`0x4CF83C`/`0x4DCE8C`/`0x4E74AC`/`0x4AAD00` = `"txt"`,
   `0x3E9FD8` = `"txt_l"`, `0x4EE878` = `"txt_l1"`, `0x3EB560` = `"txt_r"`, …);
4. cross-checked the named callers/callees of each address, then wrote new evidence and a fresh summary.

  refine batches; `tools/check_refine.py R_025` is the applicable check and passes).

  Nothing I wrote changes behaviour.
- Judge calls that should be re-checked by a later pass:

    "equipment" ownership is only inherited from the neighbouring window.

  - `0x002E5294 maybe_Battle_PopupPool_Init` — the pool structure is certain, but its only caller is
    0x0019CD50 (currently `Field_InitSceneObjects`), so "battle" may be wrong.

    called with a field object, so the "camera" owner is doubtful.
  - `0x0023A080/0x0023AE04` — the two bodies are identical; whether part group 8 means "hide" or
    "refresh" is not decidable without naming `Ui_Widget_DispatchToGroupedChildren`'s mode.
  - `0x0032E668 maybe_Ui_TitleWindow_SetAnimFrame` and `0x0046CE28 maybe_Ui_FieldMessageWindow_InitB` —
    both hinge on unnamed callees and are kept below 0.5.
  - `0x00207A8C maybe_Party_InitBattleSlots` — ids 0xBB..0xC0 are set through the unnamed
