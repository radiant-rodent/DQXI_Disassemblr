# R_035 — second naming pass (refine), 150 low-confidence `maybe_` functions

## What I did

Read `README.md`, `orchestration/PLAN.md` and the batch header, then re-read all 150 readable C bodies
with their now-named neighbours. For every address I checked the batch's `neighbour_names` **and** the real
call direction (grep the current name across `decomp/readable/functions` / `recovered`), because the score
line mixes callers, callees and shared constants. Decisions were taken from named callees, the caller's own
confident name, twin functions with the same instruction sequence, and string literals in the frame.

Result: **60 confirmed, 29 corrected, 61 kept_maybe** — all 150 addresses covered.

## The most valuable corrections

- **Save-slot getters** (0x001F2E60/2E84/2F20/32D4): `Save_*` / `Work_GetRecordField10` were wrong —
  the single caller `Ui_SaveSlotWindow_UpdateSlots` passes the save-slot index and treats `0xFF` as
  "empty". Now `SaveSlot_GetStateByte`, `SaveSlot_IsUsed`, `SaveSlot_GetDisplayByte`,
  `SaveSlot_GetRecordField10`.
- **0x00249074** `Event_DispatchScriptCallback` → `Save_Task_DispatchStep`: every branch is a named
  `Save_LoadTask_Update` / `Save_SaveTask_BeginSlot` / `ClearLoadTask` call; nothing dispatches a script
  callback.
- **0x003C16D8** and **0x00388904**: both were described as command/flag work but both end in
  `Ui_PopupEntry_SpawnCurrentLogEntry`, i.e. they emit queued battle messages
  (`Battle_Sequence_EmitQueuedMessage`, `Battle_Ui_FlushPendingLogEntries`).
- **0x00627F20** `GetTargetBoneTransform` → `Battle_Unit_SelectMimicEndCommand`: the frame owns
  `s_MimicEnd_Soil/_Snow/_Wet` and returns the first name the actor has.
- **0x0023CDE0** `Ui_Overlay_ApplySoundParam` → `Menu_Equip_SetMemberVisibilityFlag`: the value lands on
  the party-member record (+0x12E4) and drives `Model_Equip_UpdateNodeVisibility`.
- **0x00256A58** `Event_SubObject_Destroy` → `Ui_SceneFlow_ReleaseSubObject` (caller
  `Ui_SceneFlow_TeardownAll`, three named release helpers).
- **Four `*_InitHandlers`** (0x0020D294/D970/E628/F330) register no handlers — they only call
  `Gfx_EffectParams_Create`, like the confident `Menu_InitCursorEffectParams`; renamed to
  `*_InitEffectParams`.
- **0x0020B320** `CountVisibleSlots` never returns a count (`budget < limit+count`) →
  `Menu_IsSlotBudgetExceeded`, which is how `Menu_CheckSlotSelectable` uses it.
- **0x0023E794** `GetMarkerRect` → `FindMarkersInRect` (returns scene hit lists; rects are inputs) and
  **0x005AA038** `SubmitFromDescriptor` → `UpdateDescriptorProjection` (writes the projection back into
  the descriptor).

## Open problems / honest gaps

- 61 entries stay `maybe_` because only the *shape* is known: pure constructors distinguished only by a
  vtable id (0x00373A74, 0x003E4960/C/D), one-store mirror setters (0x002FCBF8, 0x003AC114, 0x003ACA54),
  and the 0x0023xxx effect-parameter initialisers whose page is unidentified.
- Two entries were demoted by the checker because the body loses a register (`unaff_r4` at 0x002FCA04,
  `unaff_r6` at 0x00653F5C). A disassembly read of those two would settle the page/index arithmetic.
- Several names depend on callees that are themselves only `maybe_` (e.g.
  `maybe_Ui_Window_ReleaseChildAndRequestMode`, `maybe_Gfx_ModelPart_ApplyAttribute`,
  `maybe_Actor_FindCommandByName`, `maybe_Shop_GoldWouldExceedCap`). If a later pass renames those, the
  evidence strings here should be re-read.
- Suspected mis-names noticed while reading (not in this batch, worth a dedicated pass): several call
  sites use `maybe_Sound_Channel_PauseIfPlaying` / `maybe_Gfx_Scene_DrawSpriteVariant` where the callee is
  the shared `0x002E6828` scene setter / `0x002E7F08` ray probe; `ToD` (0x001D863C) is still a placeholder
  base method with many callers.
- 0x0025D9D4 / 0x0025CAD8 are recovered-file entries whose own callee names include the unverified
  `Casino_Slot_*` family, so their summaries were kept deliberately vague.
- Not verified: everything here is static (decompiler text + names). No emulator run and no bit-match run
  were made; `M1b_merge_refined` has not run, so the readable C still shows the old names.
