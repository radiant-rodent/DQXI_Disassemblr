# R_037 — second naming pass (refine), 150 low-confidence `maybe_` functions

## What was done

All **150** addresses in `orchestration/naming/refine/batches/R_037.txt` were re-examined and written to
`orchestration/naming/refine/out/R_037.json` (one object per address, batch order, 150/150 covered).
No other repository file was modified except `AGENT_LOG.md` and this report. Scratch (caller index,
call/body dumpers, JSON builders, validator) is in `out/scratch/R_037/`.

**Result: 86 `confirmed` / 32 `corrected` / 32 `kept_maybe`; confidence range 0.32–0.60.**
`python tools/check_refine.py R_037` → `R_037: OK`.

Method per entry: start from the readable file's doc header (previous name/confidence/evidence), then
re-read the body **for its call names**. The batch's context score counts confident callers/callees, but
in this batch most *callers* are still `maybe_`; the reliable new evidence was therefore:

1. **callees that the merge just named** (`Gfx_Y2r_Convert`, `Ui_SlotPlateNumber_Set3Digits`,
   `Battle_SceneInit_Shared`, `Casino_CalcJackpotPayoutAmount`, `Sound_Dsp_QueryState`, …) — this is what
   moved most entries from "plausible" to "the code says so";
2. **vtable siblings / same-class field layouts** — e.g. the five Ui window-part setters share
   f_34D/f_294/f_2F0/f_358 and the same three-step tail;
3. **`asm/text/*.s`** where the readable C is damaged (0x004FFD00, 0x0055B468, 0x005EB0E0) — cited
   by instruction address in the evidence field.

Two mechanical helpers were used and are reusable:
`out/scratch/R_037/calls.py` (first-level call list per readable file) and `callers.py` (reverse index of
the batch names over `decomp/readable/**/*.c`).

## Open problems / suggested follow-ups

- `maybe_Mem_FreeGraphicsBlockByType` (0x0053242C): all nine call sites zero a block field, call it and
  store the **return** value back, while the body submits a command-queue transfer from old to new
  address. It re-acquires a replacement block; "Free" may be wrong (rename once 0x006BA1DC is known).
- The four `Ui_ObjectList_*` constructors (0x005D18E0/0x005D2880/0x005D3B9C/0x005D17FC) have no owning
  class: their only callers are the generic field-gimmick ctor/dtor, and the vtable owners
  (0x783D04/0x783D14/0x783D24) are still anonymous.
- `maybe_Data_IsSlotEmpty` (0x0066AAD0), `maybe_Field_HandleList_Ctor` (0x00627404) and
  `maybe_Fs_Archive_QueueTeardown` (0x00543484) need the object they manage / the work-queue tag 0x33
  handler named before they can be promoted.
- A future batch could name the `std_Vector20/44_Reserve` record types and `func_0051CF40` (the element
  ctor of the layout-text string descriptor), which would finish several entries left at 0.45 here.
