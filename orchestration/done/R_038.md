Other findings worth carrying into the merge:

- **The `Gfx_Pica_*` family must be renamed before any UI work relies on it** — three of the four
  are BCH material command-buffer builders/sizers, one is a shader-symbol lookup.
- **`Item_CountEquipped` is misnamed** (FACTS carries the name, so I did not rename it here): in
  0x006301A4 its result is compared against a *pointer*, and in 0x006302EC it is used as a
  boolean kind+id presence test (`(work, kind, id, 0) -> char`). Whatever it is, it is not a count.
  That is why both 0x006301A4/0x006302EC stay `maybe_`.
- **`Ui_Object_DtorBody` is used on field/gimmick objects** (0x002BE718, 0x0028EFB8, 0x002B6274),
  so its name is probably too narrow. Left alone (not my file).
- **0x00105ACE is a Ghidra mis-split** — it is the tail of the ARM routine 0x00105584 but the batch
  lists it as a Thumb entry; renamed `maybe_Snd_StreamVoice_UpdateFragment` at 0.35.
- **Duplicate template bodies**: the 56-byte deleting-destructor template exists at
  0x001A3BA8, 0x001A5AAC, 0x00219938, 0x002B385C, 0x002F41F0 **and already at 0x0044CEB0/0x0044FB8C**
  (named `Field_SceneObject_DeletingDtor(/B)` by another lane). To avoid a name collision at a
  different address I used `Field_SceneObject_DeletingDtorC/D` for 0x002B385C/0x002B3E44 and
  `Gfx_Sprite2D_DeletingDtorA/B/C` + `Gfx_Sprite2D_DestructorBodyA/B` for the 2D sprite copies.
- **0x003E3628** (now `Ui_Layout_HideNumberedPanes`) also corrected a factual error in the old
  header: the base name is at 0x007BFB88, not 0x003E36EC.
- Six libstdc++ throw helpers (0x0010018A/0x001001C4/0x00100246/0x00100272/0x001001FC/0x001002AE)
  stay `maybe_` at 0.4: the narrow/wide × range/fixed/parameterised matrix is provable from the
  bodies and the caller blocks, but which exception class each literal denotes is not.
