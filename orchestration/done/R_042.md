# R_042 — second naming pass (refine): 150 low-confidence `maybe_` functions

## What I did

Decided all 150 addresses in `orchestration/naming/refine/batches/R_042.txt`
(76 confirmed / 32 corrected / 42 kept_maybe). Method, per function:

1. read the doc header (previous name, confidence, batch, evidence), then the body *as it now is*, i.e.
   with the merged callee names;
2. re-read the neighbours: `orchestration/naming/refine/scores.jsonl` (`neighbour_names`, vtable,
   strings, shared constants), `symbols.json` (what the previous batches named at the ctor/dtor
   addresses around the target), the string literals in the body and — where useful — the newly named
   sibling in this same batch;
3. checked every caller I quote with `grep -n` in the caller file. The batch-wide caller scan I built
   matches a name anywhere in a file *including the doc header*, so a raw caller list contains
   commentary, not calls; this bit me once (the "callers" of 0x0063B018) and is called out in the log.

Everything is static analysis of the existing readable C, disassembly headers and `symbols.json`. No
Ghidra, no emulator, no build (rule 5's full run does not apply to refine batches, per the task).

## Open problems / honesty notes

- 42 entries stay `maybe_` (0.15-0.45). The common causes: register-damaged bodies
  (`in_ZR`, `unaff_r4..r11`, `halt_baddata`, `software_interrupt`), template-copy destructors that no
  data table points at, and functions reached only as vtable slots. I did not promote any of them just
  because the mechanism was clear - the class/verb would have been invented.
- Two entries where the readable body is a truncated tail call (`0x0066B1FC`, and its sibling
  `0x0066B19C`) cannot be checked at all; both keep `maybe_` at 0.3.
- `func_00100B74` is used as `wcslen` in one earlier evidence note, as a "sound trigger" in another and
  as a non-returning assert here (0x00629AE4). It is almost certainly one variadic panic/abort helper and
  the two other readings are wrong; see follow-ups.
- Some names I now cite as evidence are themselves `maybe_` (`maybe_Anim_Resource_Bind`,
  `maybe_Ui_Actor_FindPortraitId`, `maybe_Battle_MonsterUI_Dispatch`, `maybe_Ui_DataPanel_InsertRowCopy`,
  `maybe_Ui_ItemListCore_*`). Their verdicts are only as good as those, which is why the dependants stay
  `maybe_` at < 0.5.
