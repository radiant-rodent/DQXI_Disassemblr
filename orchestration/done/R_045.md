- Output: `orchestration/naming/refine/out/R_045.json` — one object per address, in batch order.

- Checker: `python tools/check_refine.py R_045` → `R_045: OK` (exit 0). The file was re-read with a strict

## Method

This batch is almost entirely vtable-only code: only **12 of 150** addresses are referenced by another
function's body in `decomp/readable` (and one of those references is a literal-pool comment), so per the
task's rule "a correct vague name beats a precise wrong one" most entries stay `maybe_` with a sharper
summary instead of a promoted name.

For every address I:

1. read the doc header (previous name/confidence/batch/evidence) and the **current** body, i.e. with the
   callee names that `M1_merge_names` installed;
2. listed the named callees actually used by the body and looked up what each one is documented to do;
3. searched `decomp/readable` for the previous name to find real callers (header mentions were filtered out —
   the first pass had mistaken header cross-references such as "Ui_Window_StartAction14" for callers);
4. checked the vtable / translation-unit neighbourhood from the header, and compared byte-identical twins;
5. checked `scores.jsonl` (`neighbour_names`, `vtable`, `shared_constants`) — for this batch they are empty,
   so all new evidence came from steps 1–4.

Scratch tooling (kept for a resume): `out/scratch/R_045/ctx.py` (dumps header + named callees + real callers +
body per index range), `index_cache.json` / `id_cache.json` (name → file/summary, name → callers),
`part1..part6.json` (decisions), `merge.py` (validates against the batch and writes the final JSON).

## Open problems / not verified

- **No build/emulator run** (rule 5's full run does not apply to refine batches). This is a static-only pass;
  the readable C keeps the old names until `M1b_merge_refined` runs.
- 13 of the 150 (the nine `0x002B8EB0`–`0x002B90AC` fragments, `0x002AFB24`, `0x002B0230`, `0x002B7700`,
  `0x002B7798`) have `halt_baddata` bodies (Thumb interior blocks of larger routines). Their summaries now say
  "interior block of …" explicitly; nothing beyond the first pass could be re-verified. They are candidates
  for an *unsplit/remove entry* pass rather than another naming pass.
- Confident names that are probably wrong elsewhere and mislead this batch (recorded, not fixed here —
  outside this task's ownership):
  `ActorActionSeq_RunNode` is called with a UI window `self`;
  `maybe_Map_RefreshLevelGrid` (0x00179084) is a cached-revision refresh, not an animation reset;
  `maybe_Actor_CreateModelFromCharacterTable` (0x0022D278) receives a float3, i.e. it is a position setter.
- Suggested follow-ups: (1) a pass that renames/merges the `ActorActionSeq_RunNode` cluster (0x003BD8A4 /
  0x003BD908 / 0x003BD9C4 called from the Ui window input handlers); (2) revisit `maybe_Map_RefreshLevelGrid`;
  (3) mark the 9 interior blocks as non-entries in the function index so future batches stop listing them.
