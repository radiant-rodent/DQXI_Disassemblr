## Main corrections (what the first pass got wrong)
- **Wrong subsystem**
  - 0x004A1564 `Menu_Slot_UpdateCursorState` → `Casino_Slot_UpdateCursorState`: the body calls the named
    `Casino_Slot_SetDigitSprite` and drives the f_D8C/f_D90 slot-machine state.
  - 0x003D562C `Ui_DungeonWindow_SetInputHandlerB` → `maybe_Field_Gimmick_InitComponentE`: it initialises
    the sub-object at +0x210 and stores it at gimmick+0x12C, exactly like the four already-named gimmick
    component inits (A/B from N_057, C confirmed by R_042, D corrected by R_027). "E" because C is taken.
  - 0x0041B4E8 `Ui_TalkWindow_PushCallback` → `maybe_Ui_Window_PushCallback`: the only caller is
    `Ui_ListWindow_DispatchInput`, so the talk-window attribution was wrong.
  - 0x003F043C `..._BuildEntriesFromScript` → `Ui_SlotTable_BuildEntriesFromRecords`: the entries come from
    the 0x14-byte record table behind `Game_GetDataManager`, not from a Squirrel script.
  - 0x00424CA8 `Field_ActorActionSeq_BuildEntryFromUnits` → `Battle_Ui_BuildEntryFromUnitsA`, pairing with
    the B variant at 0x004256D8.
- **Wrong kind of function**
  - 0x004D7F48 `..._UpdateSlotB` → `Field_ObjectSprite_Hide` and 0x003DE080 `..._EnsureMapRecord` →
    `Field_SceneObject_AttachDrawObject`: both bodies are byte-identical to the named hide / deferred-register
    functions 0x003DE054 / 0x004B0B04.
  - 0x003D2D44 `..._CheckLoaded` → `Gfx_Resource_MarkLoaded`: it sets `*ref = 1` and returns nothing, so the
    Check prefix promised a predicate that does not exist.
  - 0x003EC71C `..._ValidateEntry` and 0x003D26CC `..._HideSubPane`: both are calls to the now-named
    `Gfx_Node_SetVisible` with a dropped/derived boolean, not validation and not necessarily a hide.
  - 0x004A3C74/0x004A3D14 `..._LogRecordA/B` → `maybe_Ui_InteractJob_FormatRecordArgA/B`: per FACTS.md,
    `Ui_TextFormat_ReleaseSlot(n, fmt, str)` sets message **argument n**, so these are argument formatters.
  - 0x003C3118/0x003C36AC/0x003C36C4 `..._SpawnMemberEffect*` → `maybe_Battle_ActionSequence_BuildMemberRow*`:
    the callee is `Text_BuildRowForMember` and the 0x00491E3C effect spawner the old evidence cited is not in
    the body.
  - 0x003C24D8 `..._SetOwnerAndRelease` → `maybe_Gfx_SceneNode_DeleteThunk`: store vtable + dtor body +
    free is a deleting destructor.
- **Text module is really the text filter / NG-word matcher** (callers `Text_MaskPatternMatches`,
  `Text_NgWord_MatchWord`): 0x0050F3B4 `Text_LayoutParagraph` → `Regex_MatchTextRange`, 0x0050F6C8
  `Text_LayoutSingleLine` → `Regex_MatchTextLine`, 0x0050F9A8 `Text_ParseRun` → `Regex_ParseTokenStream`,

## Honest kept-`maybe_` decisions
25 functions stay below 0.5. The important ones:
- 0x003D2EE4 — 976-byte body of which only five descriptor stores survive, then a non-returning jump into
  0x00100B74 (the shared abort). "StaticCtor" is doubtful; kept at 0.25.
- 0x004B8DEC — clear SetModelAnim shape, but the arguments arrive in `in_ZR`/`in_r12`; kept at 0.48 rather
  than claiming 0.55.
- 0x003C36AC / 0x003C36C4 — `unaff_r5..r7`, lost arguments; kept at 0.30.
- 0x0049AA74 — `halt_baddata` truncates the body; only the data-manager fetch is visible.
- 0x004FD2C8 (`Gfx_StreamSlot_ReleaseIfDone`) and 0x0042165C (`Gfx_SubObject_Release`): in both cases the
  single callee is now named the *opposite* of what the first pass thought (`Gfx_Vram_AllocEntry`,
  `Container_AddUniqueIdEntry`). One of the two names is wrong; I could not tell which from the body.
- 0x003B1698/0x003B17C0 (`Camera_PickLayerAtPoint*`): the hit-test body is certain, but nothing new ties the
  layer list to a camera rather than a UI/view stack, so the subsystem label stays a guess.
- 0x003E5FD8 (`Model_UpdateBlink`): the trigger callee is now named `Sound_Emitter_PlaySe`, which does not fit
  a facial blink; kept at 0.45.
- 0x003CB148 (`Battle_Ui_MemberAnim_PlayNamedAnim`): the callee is now `Text_ApplyRowStyle`, so "play" is
  questionable.
- 0x003A8C64 (`Ui_GuideWindow_Create`): the only caller is `Ui_StampBookWindow_Ctor`, so the class label
  lost support even though the allocator+vtable-stamp shape is certain.
