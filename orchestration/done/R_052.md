## Method

1. Started from every readable file's doc header (previous name, confidence, evidence).
2. Re-read each body against the *current* callee names, then built a caller/callee report for the whole
   batch from `decomp/readable/**/*.c` + `decomp/ghidra/functions_merged.jsonl` (by-name call graph) and
   read the important call sites.
3. Read the readable headers of the decisive callees, because several "named" partners turned out to be
   badly misnamed: `Fx_BuildDistributionTable`, `maybe_Gfx_ResourcePool_Purge`, `Mem_BitmapPool_Init`,

4. Cross-checked `refine/scores.jsonl` neighbour names, other `naming/out` and `refine/out` files for the
   same addresses, and FACTS.md (damaged-body rule, getter trap, twin bodies).

## Most important corrections

- **0x0064553C** `maybe_Ui_LoadingScreen_SetState` -> `maybe_Gfx_ResourcePool_PurgeUnreferenced`.
  The body is `Pack_HandleTable_Get` + a 16-bit "keep" bitmap built from a byte index list + one
  `maybe_Gfx_ResourcePool_Purge(handle, i)` per unreferenced slot. The purge callee's own header already
  says "caller FUN_0064553C builds a 16-entry bitmap ... and calls this only for slots no longer referenced
  (cache eviction)". Nothing sets loading-screen state.
- **0x0064A2C8** `maybe_Casino_Slot_EvaluateWinLines` -> `maybe_Ui_Window_GetLabelText`.
  It returns a text pointer: inline text at self+0xC, or a relative string inside the row found through
  `func_0063F2F0(dm, id)`; its callers are `Ui_SaveWindow_LoadSlotName` and
  `maybe_Ui_Window_SetLabelFromSelection`. No reel/payout logic exists in the body.
- **0x00656D5C / 0x00656FCC** `Pica_SetShaderUniforms` / `Pica_SetTextureLod` ->
  `maybe_Gfx_Pica_WriteTextureStateBlock` / `maybe_Gfx_Pica_WriteTextureUnitBlocks`.
  One emits a 14-word fixed PICA command block from the texture-unit bytes at ctx+0x164..0x18E; the other
  loops the eight units and calls 0x00657014 per unit. No uniform floats and no LOD values in either body;
  both are called in sequence by the confident `Gfx_MaterialState_WriteAndCacheBlock`.
- **0x0065973C** -> `Fx_DistributionTable_WriteEntry` (0.5). `Fx_BuildDistributionTable`'s header states that
  its sole caller 0x0065973C stores the 512-byte table into a 0x218-byte per-spawn FX record and marks it
  valid. The old "Gfx_StateTable_StoreEntry" pointed at the wrong subsystem.
- **0x0066D0D0** `Svc_IsSubsystemReady` -> `maybe_Ui_Scene_EnsureCreated`. It lazily creates the same
  0x21C-byte vtable-0x007829E0 object as 0x00623914 and returns `!Ui_LoadingScreen_IsFinished`.
- **Field2D map family (0x00670DB0, 0x671318, 0x6719D4, 0x671A30, 0x671AA0, 0x671AFC, 0x671B14)**:
  re-labelled from the now-named callees - detach/release of f_338 + collision re-check, move-controller
  rebuild, appearance-node rebuild (x2), draw + view-bounds update (x2), tween-move creation. The old names
  ("ReplaceOverlay", "ResetOverlay", "CreateOverlayObject", "PrimaryObject") were guesses contradicted by
  the confident callees; the two "ResetOverlay" functions are draw/update, not clear/reset, and the
  "CreateOverlayObject" one builds a tween-move controller.
- **0x0067E73C** `Field_InitPackedTableReader` -> `Mem_BitmapPool_InitStartupPoolB`. Both its calls are the
  confident `Mem_BitmapPool_Init` (the same two-call shape as 0x00678A88); no table reader is called.
- **0x0072157C** `std_introsort_itemEntry8` -> `std_introsort_itemEntry`. The rows are 4-byte
  {u16 id; u8; u8}: the body copies a u16 + a u8 and steps its `u32*` by one, so the "8" was wrong; I did
  not replace it with a different number because the suffix's meaning in the sibling `*Id8` names is
  itself unproven.
- **0x007208B4** `Text_SortPairsByY` -> `Text_SortPairsByFloatKey`. The comparator is provably the float at
  +4 of each pair; "Y" was an unproven interpretation.
- Others worth reading: 0x0061BBB4 `IsClockReady` -> `maybe_Ui_TimeWindow_GetClockState` (returns -1 or a
  signed byte, not a bool); 0x00652160 `HasDirectionChanged` -> `maybe_Ui_MapIcon_ShouldShowDirection`
  (the caller stores it into a flag bit); 0x00652ED8
  `Event_ActorModels_ClearSlot` -> `maybe_Battle_Ui_TargetGroup_InitBounds` (callers are battle
  target-group routines passing a struct pointer); 0x0062FA90 `Ui_EntryTable_LookupValue` ->
  `maybe_EntryTable_LookupHandle` (shared camera + layout table, and Ghidra dropped the return value);
  0x0065FE24 `GetByte18B` -> `maybe_Sound_SeqField_TestByte18` (returns a predicate).
