## What I did

1. Read `README.md`, `orchestration/PLAN.md`, `orchestration/naming/FACTS.md`, the batch file and the
   previous evidence in each readable file's doc header.
2. Built the missing context myself, because 132 of the 135 rows have context score 0 (no confident
   caller/callee/vtable sibling/string):
   - `out/scratch/R_053/analyze.py` — rebuilt the call graph from `decomp/readable` (callers/callees,
     including `maybe_` neighbours) and listed every `0x007xxxxx` constant used by each target with the
     functions that cite it.
   - `out/scratch/R_053/headctx.py` — mapped every 6/8-digit constant in each target's doc header to
     the functions whose evidence cites it.
   - `out/scratch/R_053/part1-3.py`, `fix.py`, `merge.py` — the decisions, saved in chunks of 45,
     patched after an accuracy audit, then merged with `previous_name`/`previous_confidence` taken from
     the batch file and `params` derived from the final signatures.
3. **Accuracy audit (important).** "Function A's evidence cites constant X" is *not* the same as
   "the function at X is named A". I resolved every cited address against `symbols_recovered.json`
   before writing evidence; this caught several claims from my own first draft (and one from the first
   pass) — e.g. `0x001D6CEC` does not release a stream, it runs the movie read pump; `0x001D8C30` is
   not a getter; `0x001E3C70`/`0x001F9B58` are unnamed helpers, not the named functions that cite them.
   The evidence strings now say "cited by the named X" when the name belongs to the citing function.

## Kept `maybe_` (90) — reasons

- **`halt_baddata` / thumb control-flow loss**: 0x001E6038, 0x001F16A4, 0x001F19EC, 0x001F1AD8. The
  bodies cannot be checked; the header's raw-word notes are all there is.
- **Damaged decompilation** (`unaff_*`, `coprocessor_*`, over-long entries): 0x001C1F24, 0x001C7D78,
  0x001CA7E4, 0x001CB070, 0x001E1EC8, 0x001E1EF2, 0x001F2004, 0x001F2DB6.

  panel-row helpers (0x001F909C/0x001F953C/0x001F96D4/0x001FB1A4/0x001FC7EC/0x001FE184), the
  message-window field caches (0x001C4E00/0x001C4E50/0x001C4EE8), the ShopWindow trio
  (0x001EB16C/0x001EB368/0x001EB42C). The action is described, the class/field name is not invented.

  "maybe_Camera_UpdateFollowPosition" is used as an actor clip/timer helper; `0x0053DED0` is
  `maybe_Field_SceneNode_Destroy`, not an intrusive-list clear.
- The `0x0072A944` table is the shared panel duration/position table used by every `EnterXX` helper;
  naming its entries (0x30/34, 0x40/44, 0x48/4C, 0x50/54, 0x70/74, 0x80/88, 0xA0/A4, 0xB0/B4) would let
  a later pass name the durations instead of "pair from +0x..".
- `0x00729554` / `0x007295C0` / `0x007297BC` are three different state-handler tables (item screen,
  shop item list, window on-active-state). A dedicated pass over the 0x00729xxx table block would
  settle the `maybe_Ui_State_*` trio in this batch.
