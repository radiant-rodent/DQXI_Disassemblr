## The main finding: the `Ui_Tween_Eval*` family (30 of the 70)

The previous interpretation ("tween player / curve sampler") was mostly wrong in *what the data is*,
although the names still describe the code they name. What is actually there:

- `0x007286A0` is a 72-entry table of `{code*, 0}` pairs (0x240 bytes).
- `0x00326564` memcpys that table into a per-instance object (dst is the first 0x240 bytes).
- `0x00326428` is the dispatcher: it reads `record->f_8` as the keyframe index, looks at
  `player+0x244 + 0x30 + index*0x2C`, rejects the call unless `entry[+0x28] < 0x48` and
  `entry[+0x29] == kind`, then loads `player + entry[+0x28]*8` and tail-jumps to that evaluator.
- `0x00325BDC` / `0x00325C78` are the two samplers: `base ± range` where `base`/`range` are
  `entry+0x18/+0x1C` (first) or `entry+0x20/+0x24` (second), drawn with the **game RNG**
  (`work+8 -> +0x98`, rolled via `0x51B1FC`) when `player+0x248 == 0`.
- All nine dispatcher callers are text-layout row builders (`Text_Layout_BuildDefaultRows`
  0x48AAE8 builds the 8 default rows and asks for kind 6 and 0xA; `Text_RowHasNewline` 0x48AC14)
  plus a gold-clamping routine at 0x3C2E00 (evaluates record id 0x2D = price, clamps to bag gold,
  subtracts it).

So this is a data-driven **layout/parameter record evaluator** with randomised ranges, used by text
layout and by a gold/purchase calculation. The `EvalModeC*` names were kept because they honestly
describe the type-byte test, but every summary now states the real tail math that Ghidra dropped
(e.g. `*Only` slots return `record->f_0` on a type mismatch; `DefaultE..L` are `sample*f_0`, i.e.
byte-identical to `EvalScale` 0x325A44, not "unconditional curve samples").

## Corrections worth knowing about

- `0x00329A8C` / `0x00332E88` — both bodies used to decompile to a single call to a "noreturn"
  `0x29126C`. `0x29126C` is a plain `bx lr` flag setter; the real bodies broadcast the window's
  selected id (`+0x64`) to 2 (resp. 5) children via `vtable+0x1C`/`+0x0C`. Names:
  `maybe_Ui_Window_UpdateChildSelection`, `maybe_Field_NpcGesture_UpdateChildSelection`.
- `0x0032B110` `Gfx_SpawnScreenShakeAlt` -> `maybe_Dive_Effect_SpawnOriented`: builds a 0x60-byte
  effect block with an orthonormalised basis + mirror fixes and calls `Effect_FindOrCreateInstance`
  with effect id 0x45C. The generic name `maybe_Effect_SpawnOrientedInstance` is already used for
  0x5E54B8, hence the `Dive_` prefix (its only caller is the dive-effect spawner at 0x32B04C).
- `0x0032C2DC` `Model_ShowItemModel` -> `maybe_Ui_DiveResultWindow_ShowItem`: the callees are
  `Ui_ListItemRef_ResolveRow`, `Text_SetCommandArgs`, `Text_ExecuteCommand` — a text command that
  renders an item row, not a 3D model.
- `0x00327E00` / `0x00327FB4`: the invented `Casino_Slot_` prefix is gone; both are entries of the
  slot-window method table at 0x72ABA4 next to the named `Ui_SlotWindow_*`. 0x327FB4 also turned out
  to call `Ui_Widget_Update` (0x1DAD58) on its embedded widget, so "HandleInput" was misleading.
- `0x00332DCC` / `0x00332E18`: the callee 0x179084 is the named `maybe_Map_RefreshLevelGrid`
  revision-cache refresh, so these refresh the actor's grid state, they do not restart animations.
- `0x0032C91C` -> `Ui_DiveManager_DeletingDtor` (0.55) and `0x00336AB8` ->
  `Field_SceneObject_DeletingDtorAlt` (0.60). Both are the plain destructor + the allocator delete
  at 0x10F6CC (checked: 0x10F6CC is a virtual deallocate through the 8-byte block header).
  0x336AB8 installs the same vtable literal 0x764ABC as the named `Field_SceneObject_Dtor`;
  `Alt` because 0x44CEB0 already owns the unsuffixed name.
- `0x00326B20` `Os_LogDebugString` confirmed at 0.50: 0x707C1C is a fixed-size log formatter
  (`vsnprintf(buf+4, 0x80, fmt=arg2, ap)`) and this function passes the record's `+8` string as the
  format, then compacts the record.

  (`coprocessor_function`, `unaff_r*`).
- 0x336190, 0x33DF68, 0x33ED60 are interior labels of larger functions (Ghidra false Thumb
  entries). They cannot be given honest *function* names; the summaries say which real function
  they belong to.
- Worth adding to `orchestration/naming/FACTS.md` (not owned by this task): the evaluator table

  game-RNG sampling), and that `0x10F6CC` is the allocator delete used by every deleting dtor.
