## 2. Key Findings and Corrections

### 2.1 Major Correction: StateSequence Family SetState Trampolines (38 functions)
`0x006C97C4`..`0x006D0E58`: `maybe_std_StateSequence01_DeleteIfDone` through `maybe_std_StateSequence38_DeleteIfDone` -> **`std_StateSequence01_SetState`** through **`std_StateSequence38_SetState`** (`corrected`, confidence 0.65).
- **The Initial Error**: In `N_123`, the first pass guessed that slot `+0x10` of the vtable was the `Delete` stub and slot `+0x14` was a "done" predicate, suggesting a `DeleteIfDone` sequence retirement trampoline.
- **The Disassembly Evidence**: Inspecting the ARM disassembly of `0x006C97C4` in `asm/text/text_006C0048.s`:
  ```arm
  push {r4, lr}
  mov  r4, r0
  ldr  r0, [r0]        ; r0 = vtable
  ldr  r2, [r0, #0x14] ; r2 = vtable[+0x14] (QueueState)
  mov  r0, r4          ; r0 = this (r1 = target state passed untouched)
  blx  r2              ; call QueueState(this, state)
  cmp  r0, #0
  beq  #0x6c97f8       ; if queue rejected, return 0
  ldr  r0, [r4]        ; r0 = vtable
  ldr  r1, [r0, #0x10] ; r1 = vtable[+0x10] (ChangeState)
  mov  r0, r4          ; r0 = this
  pop  {r4, lr}
  bx   r1              ; tail-call ChangeState(this)
  ```
- **Architectural Evidence**:
  - In `symbols_recovered.json` and `N_122`, the entire `std_StateSequence` subsystem (spanning `std_StateSequence39_SetState` through `std_StateSequence85_SetState`, e.g. `0x006C34F4`, `0x006C3838`, `0x006D11A4`) has the identical 56-byte implementation.
  - As explicitly noted by `N_122` for `0x006C34F4`: *"N_123 named the same trampoline 'DeleteIfDone' (0.45), but the two slots are queue-state and ChangeState and the queue-state routine is byte-identical to 0x006C3384/0x006C5398"*.
  - Because `r1` (the requested target state id) is forwarded untouched into `QueueState`, Ghidra dropped `r1` from its outer signature. The method is the standard transition entry point: it queues the new state and, if valid and accepted, immediately executes `ChangeState`.
  - All 38 sequences (`std_StateSequence01` through `std_StateSequence38`) are corrected to `std_StateSequenceXX_SetState`.
