# SF_037 - Text_Layout (party stat context)

Class re-examined: `Text_Layout` (1 chunk). The class turned out to be a party-member
stat calculation context, not a text layout engine; naming below follows the actual use.

## Confirmed / better names (67)

- `+0x8a extraSkillIdList` (0.7) - filled with the member's extra skill slot ids and
  terminated by 0xFFFF in Party_StatCalc_ApplyBaseStats (0x00459FE0) and
  Party_StatCalc_SetupMemberContext (0x0045A5C8).
- `+0x310..+0x394 appliedCharScale0..33` (0.55, 32 fields) - each slot is written from the
  matching `charScaleN` at the end of Party_StatCalc_CalcAttackDefense (0x00456D68).
- `+0x6d0..+0x754 charScale0..33` (0.6, 34 fields) - float conversion
  (VectorUnsignedToFloat) of bytes +0x01..+0x22 of the per-character record returned by
  func_0063E164 in Party_StatCalc_CalcAttackDefense (0x00456D68).

## Improved guesses, still uncertain (11)

- `+0x92..+0xa4 maybe_statBonus0..9` (0.45) - halfwords copied from member+0x1C8..+0x1D8
  by Party_StatCalc_SetupMemberContext (0x0045A5C8) and added into the accumulated stat
  totals in Party_StatCalc_CalcAttackDefense (0x00456D68); replaces the "advance"
  guesses, which came from a misread of the accumulators.
- `+0xa8 maybe_scratchBlock` (0.4) - 0xf00-byte area cleared by
  Party_StatCalc_ApplyBaseStats (0x00459FE0) and merged by func_0045B22C from
  Party_StatCalc_CalcMagicalStats (0x00459654); not a glyph buffer.

## Left as is (32)

- Virtual-dispatch artifacts (`+0x30, +0x120, +0x180, +0x2b0, +0x3a0, +0x430, +0x490,
  +0x4a0, +0x4c0, +0x4d0`): the "field" is a vtable slot offset, not a data member.
- `+0x39d` unknown gating byte, `+0xc6` stat word clamped to 999 in
  Party_StatCalc_ComputeAllStats (0x0045BD14), `+0x468` level-row word, and
  `+0x4a8..+0x4bc` dwords copied from the character record (+0x24..+0x30): no naming
  with enough evidence.
