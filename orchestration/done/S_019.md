# S_019 — Cutscene class/field naming

**Status**: completed. Output: `orchestration/types/out/S_019.json` (1 class, 43 fields).

## What the batch contained

`orchestration/types/batches/S_019.json` has one class, `Cutscene_Scene` / `CutsceneScene`,
subsystem Cutscene, batch size 416 (`max_strong_field+width`), vtable `0x00766E7C` (7 slots
resolved), two recovered methods (`Cutscene_Scene_Init` 0x003984B8 ctor, `Cutscene_Scene_Dtor`
0x0039860C) and 40 field offsets.

## What I did

Read the ctor and dtor readable C, then every other recovered `Cutscene_*` method
(`Cutscene_Init`, `Cutscene_Teardown`, `Cutscene_UpdateTimer`, `Cutscene_AdvanceTimeline`,
`Cutscene_LoadScenarioPacks`, `Cutscene_ApplyLayoutMode`, `Cutscene_ResolveActorResource`,
`Cutscene_Close`, `Cutscene_Finish`, `Cutscene_FindResourceEntry`,
`Cutscene_OpenMessageForActor`, `Cutscene_ReleaseMessageAndCamera`,
`Cutscene_CreateActorModels`), plus the helpers the fields are passed to
(`Anim_ModelInstance_Release`, `Anim_UpdateModelInstance`, `Anim_KeyframeTrack_EvaluateAll`,
`Anim_Table_ClearActiveEntries`, `std_ConstructArray`, `std_destroy_range`,
`Pack_ReleaseHandle`). Literal-pool values were read straight out of
`original/exefs/code.decompressed.bin` (base 0x00100000) because the `asm/text/*.s` files are
misaligned by two bytes in this region and decode as garbage.

## Findings

1. **The batch size is wrong: the object is 0x210 (528) bytes, not 416.**
   `Field_InitSceneObjects` (0x0019CD50) does
   `iVar2 = Mem_AllocAligned_2(0x210, scene->f_c, 4); ... Cutscene_Scene_Init(iVar2, &local_80);
   scene->f_70 = uVar9;` — an allocation-backed size. The tail +0x1C4..+0x210 is real: the camera
   step index is at +0x1CC (`self->f_73` in `Cutscene_AdvanceTimeline`) and the message flag at
   +0x20C (`Cutscene_OpenMessageForActor` sets it, `Cutscene_Close` clears it). I set `size: 528`
   and documented the tail in the class evidence; the two tail fields are **not** in the batch, so
   they are not in my JSON (the merge emits them as padding).

2. **`struct_db` dropped three fields the ctor writes**: +0x0C (u16, written as 0xFFFF — the scene
   id), +0x14 (u8) and +0x24 (u8). I added them (40 batch offsets + 3 = 43 fields) because
   `Cutscene_Init` / `Cutscene_UpdateTimer` / `Cutscene_ApplyLayoutMode` read them. The merge keeps
   them with a "offset has no access evidence; kept as worker hypothesis" warning — that warning is
   a `struct_db` clustering gap, not an invented offset.

3. **Layout** (all offsets byte offsets from the object base):
   - +0x00 vtable 0x00766E7C; +0x04 the shared rodata constant 0x00782234 (292 functions reference
     it and `Anim_Sequence_CtorBase` stores it at +0xC, so it is a shared base/interface vtable, not
     a per-class one → `maybe_secondaryVtable`, 0.40).
   - +0x08 **allocator**: the ctor's second argument is `{uVar12, memoryManager+0x344}` and it copies
     word 1; `Cutscene_ResolveActorResource` forwards this word to
     `Anim_KeyframeTrack_EvaluateAll`, which hands it to `Mem_AllocAligned` as the pool (0.80).
   - +0x0C u16 scene id; +0x10 scene record (`func_0063D85C(dm, id)`); +0x14/+0x15/+0x16 the three
     definition bytes; +0x18 scene pack handle; +0x1C resolved resource; +0x20 tagged resource;
     +0x24 timer flag; +0x28 f32 remaining time (0.5f set, -1.0f when expired); +0x2C animation
     resource.
   - +0x30/+0x34/+0x38 `{begin, end, capacity}` of an 8-byte `{handle, resource}` vector whose
     32-entry inline storage is +0x40..+0x140; +0x140 is the **cursor** into it
     (`self[0x50]` in `Cutscene_AdvanceTimeline`, and the bound in `Cutscene_FindResourceEntry`).
   - +0x144 BGM file id (`Sound_AllocFileSlot`), +0x148 BGM voice handle (`func_001EDD64` release,
     `func_001EE698` play).
   - +0x14C..+0x204 is an **embedded `Anim_ModelInstance`** (184 bytes): `Anim_ModelInstance_Release`,
     `Anim_UpdateModelInstance`, `Anim_KeyframeTrack_EvaluateAll` and `Anim_Table_ClearActiveEntries`
     all take `&self->f_14c`. Its first 8 words are +0x14C..+0x168 (word 3 = the animation resource,
     word 5 = the 0x60-byte node-state array), its 3x4 default transform is +0x16C..+0x198 (12 words
     copied from the shared table 0x007E7110) and its two 20-byte override tracks are +0x19C..+0x1C4
     (`std_ConstructArray(self+0x19C, 0x005646B8, 0x14, 2)`, updated by `func_005644E0`).

4. **The batch vtable is truncated at 7 slots** because of three null words at
   0x00766E98..0x00766EA0. `Cutscene_AdvanceTimeline` calls slot +0x44 (0x006459D8) and the dtor is
   at 0x00766ECC, so the real table is ~20 slots. Not changed here (vtable resolution is not an
   S-batch deliverable), but worth a follow-up.

## Open problems / not verified

- +0x04 is only "some shared base/interface vtable"; the class it belongs to is not identified.
- The five words +0x150/+0x154/+0x15C/+0x164/+0x168 inside the embedded model instance have no
  reader in the recovered code → `unknown_*` at confidence 0.0.
- The row/column order of the 12-float transform is not proven (named `transformMatrix00..11` by
  position, following the S_014 precedent).
- The 20-byte override-track sub-objects (vtable 0x00782254, updated by 0x005644E0) are not named
  as a class; I only named the block `overrideTracks`.
- No emulator run: nothing here changes code or data, only names.
