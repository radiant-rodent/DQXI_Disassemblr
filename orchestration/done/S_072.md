# S_072 - Sound subsystem classes and fields

**Task**: name the 15 classes and every field of `orchestration/types/batches/S_072.json`
(subsystem `Sound`).
**Output**: `orchestration/types/out/S_072.json` - 15 classes, 35 fields, every batch offset
covered exactly once.

## Result in one line

The batch is the CTR Sound sequence/stream layer, and **three of the fifteen "classes" are not
objects**: `Sound_SeqField` is a sparse tagged-field block layout, `Sound_SeqTrack` is the same
sequence-data object seen by the track reader, and `Sound_StreamThreads` is a misnamed Gfx/Ui
subsystem. Three batch offsets are outright phantoms from `struct_db` mis-parsing and are emitted
as `unknown_*` at confidence 0.0.

## What I did

1. Read `README.md`, `orchestration/WORKER_RULES.md`, `orchestration/types/README.md`, the batch,
   `orchestration/types/structs.json`, and `tools/typedb/apply.py` (merge rules: type whitelist,
   offset bounds, `maybe_` convention, 400-char class evidence / 300-char field evidence
   truncation, padding emitter).
2. Dumped the readable C of all 88 batch functions into `out/scratch/S_072/c/<class>.txt` and read
   them class by class. No whole-tree walk, no caller-search script.
3. Followed the ambiguous helpers with `tools/fn.py` and targeted `asm/text/*.s` reads:
   `0x00661534` (the sparse-field lookup), `0x0065F678` (24-bit record resolver),
   `0x0065FB98/0x0065FBB0/0x0065FBC8` (self-relative section getters), `0x0064C740` (touch-phase
   test), `0x00663380` (record data offset), `0x0065F324` (archive data section), and the literal
   pools at `0x00549420` (bank magic) and `0x00518EA4` (DSP bank index).
4. Wrote the JSON with `out/scratch/S_072/write.py` (deterministic, UTF-8, `\n`), then validated it
   with an inline checker and with `python3 tools/typedb/apply.py --validate`.

## Findings worth keeping

| Item | What it really is | Evidence |
|---|---|---|
| `0x00661534(base,out,tag)` | sparse tagged-field lookup: `mask=[base]`, count set bits `0..tag`, return `[base+count*4]` | asm `tst r6,r7,lsl ip` loop then `ldr r0,[r0,r3,lsl #2]` |
| `Sound_SeqField` | **not one object**: the `Get*` accessors are called on different sub-records, so `+0xC/+0x14/+0x18` cannot coexist in 64 bytes; only `+0x3C` (sequence blob pointer) is a field of the outer object | callers `Sound_Seq_GetVoiceSlot` 0x006604F8, `Sound_Seq_GetVoiceParamsBase` 0x00660C30, `Sound_Seq_GetTrackKindBase` 0x006612B4 |
| `Sound_SeqTrack` | the same sequence-data object: both `ReadDescriptor*` start with `FUN_0065f678(*(u32*)(self+0x3C))` and branch on the version at `+8` | 0x00660E20, 0x006610EC |
| `Sound_SeqParam` | polymorphic facade (vtable at `+0`, not in the batch): base sequence data at `+4`, optional extension at `+8`, results OR-ed | ten `Get*` methods with slots 0x0C..0x50; `NotifyChange` 0x00660330 dispatches on the id's top byte |
| `Sound_WaveInfo` == `Sound_Resource` | the same 16-byte handle `{archiveBlob, waveRecord, dataOffset, isLoaded}` | `Sound_Resource_CheckMagic` 0x006609FC reads only `+0` and `+0xC` |
| `Sound_WaveCache` == `Sound_WaveArchive` | identical 524 bytes and offsets 4/64/522 in `structs.json` | `structs.json` |
| `Sound_Bank` | CBNK bank handle: magic `0x43424E4B` at `0x00549420`, version `0x01000000..0x01000100` | `Sound_Bank_ValidateHeader` 0x005493C0 |
| `Sound_DspChannel` | DSP channel register interface: two 0x60-byte banks of channel-block pointers at `+0x10B4`, status/info banks at `+0x10AC`/`+0x1174` | `Start` 0x00518D04, `GetPlayPosition` 0x00518E58 (literal `0x00001320` at 0x00518EA4) |
| `Sound_SceneBgmTrigger` | a `Field_Object2D` (same 972 bytes) whose update plays a scene BGM on tap | `FUN_0064C740` is `ldrb r0,[r0]; cmp r0,#5`; `Field_Object2D_BeginTouchEvent` 0x0060ED9C resets `+0x3C4`/`+0x3C8` |
| `Sound_StreamThread` | the stream-transfer worker | `Snd_StopStreamTransfer` 0x00547884 doc: `+0x14` stopping, `+0x15` transfer active |
| `Sound_StreamGroup` | 4-slot voice-stealing group, thresholds `0x7FFFFFFF/1/1/1` | `Sound_Voice_SelectLowestPriority` 0x0054B48C on `+8/+0x18/+0x28/+0x38` |
| `Sound_StreamThreads` | **misnamed**: its only method `0x00383EC8` is `Gfx_ShutdownRenderServices`, no sound call, 12 Ui/Gfx callers | `decomp/readable/functions/Gfx_ShutdownRenderServices_00383ec8.c` |

## The three phantom offsets

| Class | Offset | Why it is not a field |
|---|---|---|
| `Sound_SeqParam` | `+0x40` | only evidence is `(**(code **)(*param_1 + 0x10))(param_1)` - a vtable dispatch through slot 0x10, which `struct_db` read as the array element `param_1[0x10]` |
| `Sound_WaveCache` | `+0x40` | same cause: `(**(code **)(*param_1 + 0x10))(param_1,uVar1)` |
| `Sound_BgmChannel` | `+0x04` | only evidence is `local_2c[1] = local_2c[1] + 1` - the stack local returned by `FUN_006111A4`, not `param_1[1]` |

All three are emitted as `unknown_*` with `confidence: 0.0` and the reason in `evidence`, per the
"never invent a purpose" rule.

## Decisions

* **Kept every generated class name and type.** `apply.py` resolves classes against
  `structs.json` and rejects renames, so the real identity lives in `summary` + `evidence`.
* **Kept the generated type `Sound_DspChannel`** verbatim instead of the underscore-free
  `SoundDspChannel`, because `structs.json` and other batches already reference it in signatures.
  This is the one place where I did not follow "type = class without underscores".
* **Corrected field widths** where the batch default of 4 would overlap the next offset: `u8` at
  `Sound_WaveInfo +0xC`, `Sound_SceneBgmTrigger +0x3B8/+0x3C4`, `Sound_StreamThread +0x14/+0x15`,
  `Sound_WaveCache +0x20A`, `Sound_StreamGroup +0x58/+0x59`, `Sound_Resource +0xC`; `u16` at
  `Sound_DspChannel +0x131E/+0x1320`.
* **Left `Sound_StreamChannel` size at the batch value 8** but said in the evidence that the ctor
  builds four 0x10-byte buffers at `+8`, so the real object is at least 0x48 bytes.
* **`Sound_BgmChannel_Command` (0x001634CC) is damaged decompilation** (`unaff_rN`, `in_crN`,
  `halt_baddata`); the class stays at confidence 0.3.
* **`Sound_SceneBgmTrigger` base set to `Field_Object2D`** (same 972-byte size, shared touch-event
  layout). `apply.py` accepts it because `Field_Object2D` is in `structs.json`.

## Not verified

* The meaning of the two `Sound_FadeTimer` words: the function has no caller and the readable doc
  rates it 0.40, so both stay `maybe_` at 0.3.
* The purpose of `Sound_StreamGroup +0x59` (written 0 by the init, never read).
* `Sound_WaveInfo +8` - it is added to the channel record's data base by `FUN_00663380`, but
  whether it is a sample-data offset or a per-wave key is not proven.
* Whether `Sound_StreamThreads` belongs to Sound at all (its only method is Gfx/Ui).
* `Sound_SeqField`'s `+0xC/+0x14/+0x18` are block positions inside *resolved records*, not fields
  of one 64-byte object; the merge will emit them as members of `SoundSeqField`, which is
  structurally wrong but is the only way to satisfy the one-name-per-batch-offset rule.
