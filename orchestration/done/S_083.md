## Open problems / what is NOT verified

1. **Batch class = several embedded objects.** `Ui_UmaWindow` mixes the window (ctor stores
   0x0077874C) with the embedded `UiUmaSub` (vtables 0x0077A104/0x0075B218, ctor 0x004D9EEC) and the
   panel object (vtable 0x0077A0B4, ctor 0x004D8B44). The batch vtable 0x007786EC matches none of
   the stores seen. Fields +0x4..+0x2B8 that only appear in those sub-object ctors may belong to the
   sub-object, not to the 0x90C window.
2. **`Ui_TalkWindow`**: ctor 0x0041B5D8 installs vtable 0x0076E710, while the batch vtable is
   0x0075D340 (a controller table). The +0x11C..+0x130 words are the `select`/`pop`/`pop2` panes in
   BuildWidgets, but a float timer at +0x124/+0x2A8 appears in the update path — the two views are
   different embedded objects. Both are documented in the field evidence; the class type keeps the
   batch spelling `Ui_TalkWindow` (with underscores).
3. **struct_db artefacts kept honest**: 20 offsets are only virtual-call slot expressions
   (`(**(code**)(*self + N))`), not members; they are `unknown_*` at confidence 0.0. Three more
   (`Ui_TalkWindow` +0xE50/+0x1000/+0x1740) have evidence that actually addresses +0x394/+0x400/+0x5D0,
   so they are `unknown_*` as well.
4. **Only-zeroed words**: `maybe_field*` entries at 0.1–0.2 are written 0 (or one constant) and have no
   reader; they are deliberately not given an invented purpose.
5. Widths: I kept the batch widths except where a field is clearly a pointer (`void*`) or a small
   flag (`u8`/`u16`, e.g. `spriteGroupId`, `keyMask`, `lineIndex s16`, `talkId u16`). No field was
   typed with a class type, so the generated header cannot overlap a later offset.
