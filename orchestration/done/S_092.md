**Status:** completed
**Output:** `orchestration/types/out/S_092.json` (37,970 bytes UTF-8), plus this report and one appended `AGENT_LOG.md` entry.

3. Cross-checked base-class usage against `orchestration/types/structs.json` and the earlier named

4. Wrote the JSON, then validated it with Python: strict UTF-8 decode, `json.loads`, class/type/size

- Classes: 15 / 15, offsets: 125 / 125 (no duplicates, no missing, no extra).
- Names: 89 named, 10 `maybe_*` (confidence < 0.5), 26 `unknown_*` at 0.0.

## Decisions

1. **Virtual-call artefacts.** Offsets whose only "evidence" is `(**(code **)(*self + 0xNN))(...)` are
   not members: struct_db multiplied the vtable byte offset by 4 (0x34 -> 0xD0, 0x38 -> 0xE0,
   0x48 -> 0x120, 0x3C -> 0xF0, 0x58 -> 0x160). They are emitted as `unknown_vtableCallNN` at 0.0 with
   the real slot named, never given an invented purpose.
2. **Mixed variants are documented, not averaged.** `Ui_TwoColumnListWindow` merges two ctors with
   different layouts, `Ui_NumberedTextWindow` and `Ui_LargeWindow` group methods of other classes,
   `Ui_StampBookWindow`'s low offsets come from BXON resource objects. Each class evidence says so and
   the affected fields stay `unknown_*` or `maybe_*`.
3. **Sizes are echoed from the batch on purpose.** `Ui_SixteenRowCheckListWindow`'s computed size 292
   cannot contain its 16 x 0x5C array; the real extent is stated in the class evidence instead of
   inflating `size` (so `apply.py` padding stays within the observed object). Same caveat for
   `Ui_TwoColumnListWindow`.
4. **Field widths follow the code**, not the batch: `Ui_GridWindow` +0x110/+0x111/+0x112 are u8/s8/s8
   (three consecutive bytes), not a u32 word.
5. **Base classes kept** as generated (Ui_Object, Ui_Window, Ui_AnimRef, Ui_AnimClip, Gfx_Sprite) because
   the batch's `bases_seen` matches base-constructor calls; only `Ui_LargeWindow` / `Ui_NumberedTextWindow`
   have class confidence below 0.4.

## Not verified

- Every `maybe_*` field (10) and `unknown_*` field (26); the reasons are in each `evidence`.
- `Ui_GridWindow` +0x38: pointer to a record whose u16 +0xC is compared with 6 - the record type
  (item record / compare row) is not proven.
- `Ui_DungeonOperationWindow` +0x4C: inline draw-node handle passed to func_006564C0; the callee has no
  readable file.
- `Ui_TitleLoopWindow` +0x98 / `Ui_LocationWindow` +0x98: inline layout-context object, only proven by
  its vtable slot +0x2C usage.
- `Ui_StampBookWindow` +0x58/+0x5C/+0x60/+0x11C: the batch evidence is relative to BXON/part objects,
  not to the stamp-book window; left unknown.
- The real sizes/extents of the two mixed `Ui_TwoColumnListWindow` layouts and of the
  `Ui_SixteenRowCheckListWindow` row array are not encoded as `size`.
- Nothing was compiled or exported; only the naming JSON changed.
