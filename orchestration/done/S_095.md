## Key decisions

1. **Batch offsets 208 / 224 / 288 are not fields.** In
   Ui_FiveRowPagedWindow, Ui_KeyHintWindow, Ui_PagedIconSelectWindow,
   Ui_PartyListWindow (only 208), Ui_SelectRowWindow, Ui_ThreeLineTwoColumnSelectWindow,
   Ui_ThreePositionWindow, Ui_ThreeRowTextWindow, Ui_TitlePagerWindow and
   Ui_TwoAxisSelectWindow the only "evidence" is
   `(**(code **)(*param_1 + 0x34/0x38/0x48))(...)`; struct_db multiplied the
   vtable byte slot by 4 (0x34→0xD0, 0x38→0xE0, 0x48→0x120). They are emitted
   as `unknown_vtableCall34/38/48` at 0.0 with the real slot named, so a later
   emitter can drop them instead of creating fake members. This matches the
   S_092/S_093 convention.
2. **Offsets that belong to another object are `unknown_*`.** In
   Ui_SenrekiStoryWindow the accesses at 0/8 are the lazily created 0x1C-byte
   singleton (vtable 0x00782950), not this window (whose data starts at +0x34);
   +0x68 is inside the embedded Ui_StoryModel at +0x38. In Ui_MultiTextWindow
   the ctor is a builder of seven embedded text/list windows, so +0x4C/+0x58
   are words of the embedded Ui_CursorWindow. These are 0.0 with the owning
   sub-object named in the evidence — no purpose was invented.
3. **Sizes are echoed from the batch.** For several classes the ctor builds
   larger inline arrays (eight 0x50-byte rows at Ui_MemberOrderWindow +0x54,
   three 0x50-byte Ui_AnimRefList at the select windows +0x4C, five cursors at
   Ui_SelectRowWindow +0x50 + 0x50·i). The class/field evidence states the real
   extent so an emitter can widen the type later; the `size` value itself was
   not inflated to keep padding inside the observed object (same choice as
   S_093).
4. **`maybe_`/`unknown_` used exactly when confidence < 0.5**, and `vtable`
   is kept for every offset 0 that really holds a vtable.

## Verification

- Strict UTF-8 decode + `json.loads` pass (32,720 bytes).
- Per class: class/type/size equal the batch, emitted offset list equals the
  batch offset list exactly once, field names unique, `maybe_`/`unknown_`
  prefix exactly when confidence < 0.5 — **0 structural problems**.
- Real merge dry run (`tools.typedb.apply.Evidence` + `merge_structs` on this
  file only): **15 classes / 74 fields / 0 issues**.
- `python tools/typedb/apply.py --validate`: **no S_095 issue**. The single
  error is another worker's (`S_066: Save_SlotUi@0x324 unknown type 'UiWindow'`);
  the 11 warnings belong to S_005/S_019/S_022/S_055/S_062.
- `tests/run_all.py` and `tools/verify_project.py` deliberately skipped:
  WORKER_RULES rule 5 excludes naming batches (N_/R_/R2_/G_/S_/V_) because
  this task only writes one JSON file. No source, header or binary changed.

  - Ui_KeyHintWindow +0x4C `maybe_iconAnimNode` (0.35), +0x58 `maybe_callback` (0.35)
  - Ui_MemberOrderWindow +0x4C `maybe_selectedIndex` (0.3), +0x54 `maybe_memberRows` (0.4)
  - Ui_MultiTextWindow +0x4 `maybe_ringPrev` (0.3), +0x8 `maybe_ringNext` (0.3)
  - Ui_PartyListWindow +0x14 `maybe_childRingHead` (0.4), +0x18 `maybe_stepCounter` (0.3),
    +0x50 `maybe_selectionIndex` (0.45)
  - Ui_SevenSlotTextWindow +0x25C `maybe_frameCounter` (0.45)
  - Ui_ThreeRowTextWindow +0x84 `maybe_ownedResource` (0.4)
  - Ui_TitlePagerWindow +0x50 `maybe_rowList` (0.45)
  - Ui_AnimInOutWindow +0x104 `maybe_animSpeed` (0.4)
  - `unknown_*` all at 0.0: the 208/224/288 vtable-call artefacts (17: FiveRow 2,
    KeyHint 1, PagedIcon 3, SelectRow 3, ThreeLineTwoColumn 2, ThreePosition 1,
    ThreeRowText 3, TitlePager 1, TwoAxis 1), plus Ui_SenrekiStoryWindow
    0/0x8/0x68, Ui_MultiTextWindow 0x4C/0x58 and Ui_PartyListWindow 0x4C.
- The class of the scroller object at Ui_FiveRowPagedWindow +0x54 (vtable
  0x0077F71C) is unknown because 0x00622248 has no readable file; it is typed
  `void*`. The same function's row-count store is at scroller+0x18 (= self+0x6C),
  while the batch lists offset 0x18.
- Ui_KeyHintWindow +0x58 holds the code address 0x002D5B50; the target's
  signature was not recovered, so `void (*)(void)` is a guess about the shape,
  not the behaviour.
- Ui_MultiTextWindow's ctor is a damaged Thumb decompilation (unaff_r4/r6/r9,
  self-referential ring writes); the true class boundary of the composite is
  not proven, and the batch offsets come from different embedded sub-objects.
- Ui_PartyListWindow "StepEntry" (0x004ADF70) may belong to the item-use window
  rather than to the party list (it uses self+8 as an item id); the counter at
  +0x18 is named with 0.3 for that reason.
- All echoed sizes are lower bounds for the classes whose constructors build
  larger inline arrays (see decision 3).
