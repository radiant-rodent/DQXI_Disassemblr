## Decisions (also in the JSON evidence)

1. **Vtable-call artefacts.** Offsets 208 / 224 / 288 in nine classes are not fields:
   `(**(code **)(*self + 0x34/0x38/0x48))(...)` are vtable slot *bytes*, and struct_db multiplied
   them by 4. Verified in asm: `ldr r1,[r4]; ldr ip,[r1,#0x34]`. They are emitted as
   `unknown_vtableSlot34/38/48` at confidence 0.0, matching the S_010/S_093 convention.
2. **ModeListWindow base.** The batch's `Ui_TenRowModePanes` base is composition: asm
   `add r0,r4,#0x50` then `Ui_TenRowModePanes_Setup(self+0x50,self,1)`. Base cleared, field
   `modePanes` at +0x50 (0x330 bytes).
3. **MessagePairWindow +0x20.** The only write is `puVar3[8] = puVar2` into the embedded
   `Ui_MessagePair` at window+0x11C (pair+0x20 = owner back-pointer), so window+0x20 stays
   `unknown_20` 0.0.
4. **Extra fields.** Added `vtable` (+0) for the 11 polymorphic windows and `paneSetId` u16
   (+0x28) for the 11 text windows: both are proven by every method (`ldr r1,[r4]`,
   `ldrh r0,[r4,#0x28]`, ids built as `paneSetId<<16 | n`). `paneSetId` uses the same name as
   S_093's Ui_StatusParamWindow for merge consistency.
5. **Sizes.** Batch sizes are echoed on purpose; the merger extends them from proven field
   extents (MessagePairWindow 0x410, ModeListWindow 0x380, TalkYesNoWindow 0x210C).
6. **Talk/yes-no receivers.** +0x11C/+0x1DC8 are typed `Ui_TextLayer` (0x38): the yes/no object
   must fit in the 0x50 bytes before the pair at +0x1E18, which excludes `Ui_Text` (0x137C).
