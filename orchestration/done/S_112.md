## What the classes are

* **Ui_PageList** - five-row paged text list. `ShowPage` (0x0045F09C) fills the five row descriptors
  at +0x70 (stride 0xC: paneA/paneB/rowId) from the total row count +0x4C, computes the rows on the
  current page into +0x50 (mod 5), reads the list at +0x38 (`Ui_List`, selected id at +0xC), and
  `StepSelectionUp/Down` (0x002CF878/838) step the embedded row table at +0x54 and forward +0x64
  to the owner's vtable +0x6C. Same 436-byte layout as `Ui_TextListWindow`.
* **Ui_SelectList** - five-row `select1..select5` list: `InitPanes` binds five 0x50-byte anim rows
  from +0x4C using the layout pointer at +0x4 via `Ui_AnimRef_Bind`; `BuildRows` tests five
  save-work flags (`0x00629FB8(work+0x24A98, i)`), keeps row ids at +0x1DC (not in the batch) and
  checks the selectable-entry table at +0x1E4 (count +0x60, entry array +0x58).
* **Ui_TwoColumnList** - two-column (left/right, 7+7 cells) paged list: 14 x 12-byte cell array at
  +0x70, `pager_num_l/r` panes bound through the embedded row table at +0x54.
* **Ui_GridList** - grid table: row/column counts clamped from the parameter block into u8 +0xD/+0xE
  and 0x34-byte row / 0x2C-byte column record arrays whose pointer slots are +0x94/+0x98.
* **Ui_ScrollList** - scrolling page list: page index +0x4C (12 rows/page in `ScrollToIndex`),
  `Ui_List*` +0x38, refresh via vtable +0x60, entry count via vtable +0x64.
* **Ui_SevenRowList** - this generated name is the **battle damage-popup group** the project already
  calls `Ui_DamagePopupGroup` (vtable 0x00778A90, slot 8 = `Ui_DamagePopupGroup_Init` 0x004CEFC0).
  Six 0x50-byte `pop_damage1..6` sub-windows start at +0x4C; each keeps its layout pane at +4 and
  its number-part handle at +0x4C. "Seven" = base object + six popups. Class name kept as generated
  (merger keys on it); the identity is stated in the summary/evidence - see "Follow-up" below.
* **Ui_TextList** - a small text-measure record (pending flag at +0 + wide string at +0x1C + result
  flag at +0x2C). This "class" is a struct_db merge of the 0x10-byte ctor 0x004A5D60 with the
  measure-update code 0x001B827C; three of its four batch offsets are 4x artefacts (see traps).
* **Ui_BagList** - bag/equipment list: current party member at +0x49 (< 0x1F, member records from
  `0x0035EB98`), selected equipment slot from the list at +0x38 (+0xC < 6), item id via
  `Ui_Member_GetEquippedItemId` 0x006292F0; row state from the save-work byte table at bag+0x5A4E
  indexed by the u16 base +0x298.
* **Ui_CommandList** - six-row command window: `BuildRows` 0x004799CC writes `txt_title` and six
  rows from the 9-entry command-id table at 0x00479B38 via vtable +0x34/+0x38, refresh +0x48.
* **Ui_PartyList** - party roster: eight 0x60-byte member rows (0x5D-byte records) at +0x944C, a
  one-row memmove (0x2A0 bytes from +0x94AC) when the roster exceeds 7, insert slot +0x96EC.
* **Ui_ResourceList** - resource-backed layout element list: resource id +0xC resolved through
  `Container_BuildPointerCache`, 8-byte entries, inline at +0x34 when count == 1.
* **Ui_TextElementList** - intrusive text-element list: begin/end at +0x84/+0x88, elements 0x14 bytes
  before their node, destroyed elements are linked into the second container at +0x90.
* **Ui_TwoColumnValueList** - four-row label/value list: member names (member record +0xCA) into
  left pane `i | u16(+0x28)<<16` and right pane `(u16(+0x28)<<16 | 4) + i`; the byte at +0x48
  selects a dim/tint palette mode.
* **Ui_WindowWithList** - generic window with an embedded row table at +0x54 and a 0x3C-entry
  8-byte row array at +0x70 (0x250-byte object); only the ctor 0x0041D760 was recovered.
* **Ui_WorldMapMarkerList** - singleton world-map marker collection: count +0x11C, 25 x 0x50-byte
  marker records at +0x120 (std_ConstructArray count 0x19), used by the world-map loader.

## Decisions / problems found

1. **struct_db vtable-slot artefacts** (19 fields, emitted as `unknown_<hex>` at 0.0 with the exact
   expression quoted). `(**(code **)(*param_1 + N))` is scraped as a field at `N*4` whenever
   `param_1` is an `int*`: Ui_PageList +0x1B0 (slot 0x6C), Ui_SelectList +0xB0/+0xD0/+0xE0/+0xF0/
   +0x120 (slots 0x2C/0x34/0x38/0x3C/0x48), Ui_TwoColumnList +0xD0/+0xE0, Ui_ScrollList
   +0x180/+0x1A0 (slots 0x60/0x68), Ui_TextList +0xE0, Ui_CommandList +0xD0/+0xE0/+0x120,
   Ui_TwoColumnValueList +0xD0. Four more are 4x-scaled *byte* offsets of `char*` params
   (Ui_TextList +0x70 = 4*0x1C, +0xB0 = 4*0x2C) or through a re-assigned sub-object pointer
   (Ui_TwoColumnList/`Ui_WindowWithList` +0x18 = 0x54+0x18). Upstream should teach `struct_db.py` to
   skip `*param + N` and to honour pointer-type changes.
2. **Sizes corrected where the construction evidence is stronger than "highest field + 4"** (the
   emitter pads to `size`, so a too-small size would truncate real structure):
   Ui_SevenRowList 480 -> 556 (0x4C + 6*0x50; structs.json's own `Ui_DamagePopupGroup` is 556),
   Ui_TwoColumnList 228 -> 280 (cell array at 0x70 + 0xE*0xC), Ui_PartyList 38640 -> 38732
   (0x944C + 8*0x60), Ui_ResourceList 56 -> 60 (inline 8-byte entry at 0x34),
   Ui_WindowWithList 88 -> 592 (row array at 0x70 + 0x3C*8),
   Ui_WorldMapMarkerList 292 -> 2288 (0x120 + 25*0x50).
3. **Two `vtable` words added at offset 0** for Ui_PageList and Ui_TwoColumnValueList: both have
   explicit vtable evidence but the batch's fields start later because their functions only reach
   the vptr through the base ctor (`drN`). The merger reports them as "kept as worker hypothesis"
   warnings; without them the emitted structs would begin with padding instead of a vptr.
4. **Kept every generated `class`/`type`** even where the identity is known to be wrong, because the
   merger keys on `class`: the important case is `Ui_SevenRowList`, which is `Ui_DamagePopupGroup`
   (R3_021 already named the vtable 0x00778A90, its init `0x004CEFC0` and both dtors). The summary
   says so; a later rename batch should merge the two classes.
5. **No field was invented to fill a slot**: 19 offsets are `unknown_*` 0.0 and 6 are `maybe_*` < 0.5;
   the other 36 rest on a named callee, a string, a vtable slot or a direct store/compare.

## Not verified

* Every `maybe_*`/`unknown_*` field: Ui_PageList/Ui_TwoColumnValueList `maybe_paneGroupId`
  (+0x28 is always shifted <<16 into pane/entry ids; the exact "text layer/group" meaning is not
  proven), Ui_BagList `maybe_rowTableBase` (the save-work table at bag+0x5A4E is only seen as a row
  state), Ui_TwoColumnValueList `maybe_isDimmed` (the +0x48 flag only selects palette/tint),
  Ui_TextElementList `maybe_freeElementList`, Ui_TextList `maybe_measurePending`.
* The real identity of `Ui_TextList` (mixed struct_db grouping) and of `Ui_CommandList` (only its row
  builder survived, its own fields are unknown).
* Whether the embedded row table at +0x54 (Ui_PageList/Ui_TwoColumnList/Ui_WindowWithList) is really
  a pager or a generic row/cell table: its ctor 0x00622248 installs vtable 0x00780224, stores two
  text panes at +4/+8 and an index at +0x10, and its ctor-built array starts at +0x1C - the class it
  belongs to was not recovered, so `rowTable` is descriptive, not a recovered class name.
* Ui_PartyList's `memberRows` interpretation (eight 0x60-byte slots, 0x5D-byte records) rests on the
  memmove sizes and the two Insert functions only; the record field meanings are unknown.
* Whether Ui_TwoColumnList/Ui_WindowWithList really end at the constructed array or continue.
* Nothing was compiled, exported or emulator-tested - static naming only.
