## Decisions recorded

1. **Extra offsets kept.** The previous worker added 9 offsets beyond the batch (the real
   `self` fields of `Ui_FadeWipe`, `Ui_AnimSequence` and `Ui_ScreenAnchor`). I kept them: they
   are the only well-evidenced fields in those classes, and the merge accepts them with a
   warning. The batch's own offsets in those three classes are mistyped-`self` artifacts and
   are kept as `unknown_*` at confidence 0.0 rather than given invented purposes.
2. **`Ui_LayoutPane@0x90` is inside the 24-byte name.** The batch's evidence line for it is a
   vtable call through slot `+0x24`, not an access at `+0x90`. The 24-byte name at `+0x80` is
   a verified fact (`nw::lyt::Pane`, and `Ui_LayoutPane_FindByName` compares it byte by byte),
   so I kept the name whole and left the 0x90 entry in place. `apply.py`'s emitter drops it
   with a `/* skipped ... inside the embedded base */` comment, which is why the real merge
   reports 0 errors.
3. **`Ui_PaneSet` is not a class.** It is a cluster of seven deleting destructors, each
   releasing an embedded `UiLayoutRef` at a different offset. `Ui_LayoutRef_Release`
   (0x003E04BC) has 171 callers, all destructors. The offsets are named
   `maybe_layoutRef_XX` and the summary says so; class confidence 0.3.
4. **Class names kept as generated.** Per the task rules I did not rename any `class`; where
   the generated name is misleading (`Ui_CmdQueue` is a battle command queue,
   `Ui_SpiritCapture` is unproven) the summary says so instead.

## Not verified

- **No runtime or emulator check.** This is static typing only; nothing was compiled into the
  game or run on hardware.
- **`Ui_TextScroller` size 12944** assumes the `param_1` of `Ui_TextScroller_Step` is the same
  object as the class. The batch attributes it, but I did not trace a caller.
- **`Ui_TextPart`** mixes two allocation bases in the batch (the caller's six words and the
  allocated part). I named the offsets under the `puVar3` base, which is what `struct_db`
  used for `+0x18`/`+0x20`; if the merge later splits the class, `+0x00..+0x14` may belong to
  the caller's object instead.
- **`Ui_AnimShake` `targetX`/`targetY`** is an inference from the two float arguments; the
  second one's −1.0 "randomise" sentinel is proven, the x/y meaning is not.
- **`Ui_SpiritCapture`**'s constructor is damaged (`unaff_r5`, `UNRECOVERED_JUMPTABLE`), so the
  queue reading rests on the memmove in the second method alone.
- **`Ui_Frame` size 6296** assumes the sixth tile is a full 0x1A4 bytes; the dtor releases six
  tiles but does not prove the last one's extent.
