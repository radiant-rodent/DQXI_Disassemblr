## What the classes turned out to be

1. **`Ui_TweenSequence`** (0x50): Three-step animation timeline object. An embedded tween sub-object at `+0x2C` owns the step index (`+0x30`, bounded to 0..2) and the elapsed/frame counters (`+0x34` f32 accumulated time, `+0x38` u32 frame count, `+0x3C` f32 last delta). `maybe_Ui_TweenSequence_Update` (0x0032B3DC) calls virtual `+0x10` on `+0x2C` and dispatches the callback of the current step from the 0x18-byte step table at `+0x60`. `+0x4C` (`maybe_thunkTable`) is indexed using the ARM PMF adjustor pattern (`add r0, r3, r0, asr #1`).
2. **`Ui_TwoChoiceDialog`** (0xF0, base `Ui_AnimRef`): Two-page selection/list window used in equipment selection (`Ui_EquipmentWindow_Update` 0x00199E30). Stores the layout group id at `+0x28` (`paneGroupId`, u16), the page index at `+0x49` (`currentPage`, s8) and refresh flag at `+0x4A` (`pageNeedsRefresh`, u8). Owns three 0x50-byte `UiAnimRefList` groups at `+0x4C` (`initialRowsAnim`), `+0x9C` (`page0Anim`, reset when page==0 for 4 rows) and `+0xEC` (`page1Anim`, reset for other pages for 5 rows).
3. **`Ui_WindowStateSlot`** (0x380): Window state-queue controller with vtable 0x00762C4C (slots 6 and 7 are `DispatchPending` and `Step`). Shares the exact same timeline state machine structure as `Ui_TweenSequence`, shifted by offset `0x330`: embedded state queue at `+0x35C` with `stateQueueVtable`, `stepIndex` at `+0x360` (bounded to 0..1), `elapsedTime` at `+0x364` (f32 accumulating 1/30s ticks), `frameCount` at `+0x368` (u32), `lastDelta` at `+0x36C` (f32), and adjustor table at `+0x37C`.
4. **`Ui_WindowWithTweens`** (0x5C, base `Ui_Object`): Battle HP/MP gauge window with vtable 0x007697B8 (`g_battleHpGaugeWindowVtable`). Owns two 0x50-byte animation reference lists: `hpGaugeAnim` at `+0x58` (binds `gau_hp`) and mpGaugeAnim at `+0xA8` (binds `gau_mp`), plus gauge tweens at `+0xF8`. `+0x4C..+0x55` are zeroed/initialized flags.
5. **`Ui_Card`** (0x12C, base `Ui_Object`): Casino card UI object (ctor 0x00445C2C installs vtable 0x0076FF34). Allocates a 300-byte UI part (vtable 0x00769AA4) and initializes part fields `+0x11C..+0x128`. Used by `Ui_PokerWindow_Ctor` (0x001E3E78) and `Ui_JackpotScreen_Ctor` (0x002C90EC).
6. **`Ui_CriticalPopup`** (0xD4, base `Ui_AnimRef`): Critical-hit battle popup window (vtable 0x0077DAD8). Binds two 0x50-byte animation reference lists: `appearAnim` at `+0x4C` (`pop_critical_in`, with busy flag at `+0x68`) and `loopAnim` at `+0x9C` (`pop_critical_loop`, with busy flag at `+0xB8`). `+0xD0` is a vtable dereference artifact.
7. **`Ui_IconFlashing`** (0x224): Flashing message-icon object registered with `Ui_NodeList_Register(self, 1, 0x1EF)` with vtable 0x00766058. Stores owner at `+0x1C` and `isEnabled` byte at `+0x220` (written by `Ui_IconFlashing_SetEnabled` 0x00381C14, which selects 'Flashing' vs idle anim). `+0xD0` and `+0x210` are vtable slot artifacts (+0x34 and +0x84).
8. **`Ui_ItemSelect`** (0x2B7C): Item selection window managing two intrusive slot lists: active slots (`+0x2B74` sentinel, `+0x2B78` head) and cached/free slots (`+0x2B68` sentinel, `+0x2B6C` head). `ReleaseAllSlots` (0x002150C8) walks active slots and splices them into the free pool via `func_0057989C`. `+0x98` is a polymorphic layout owner (`maybe_layoutOwner`).
9. **`Ui_ObjectWithArray`** (0x2D8): Actor2D-derived compound object. Deleting dtor 0x0040E2CC installs secondary vtable `vtable + 0xD4` at `+0x258`, runs `Ui_Object_DtorBody` on embedded `Ui_Object` at `+0x2D4`, and destroys Pack_Handle at `+0x2CC`. Ctor 0x002C5A00 zeroes `+0x04/+0x08`.
10. **`Ui_PageStack`** (0x3940): Two-deep UI page stack. Holds a 3-entry 0xC-byte table at `+0x1C68` storing `{void* page, void(*callback)(void), u32 thunk}` per depth; `+0x1C8C` is the current stack depth (capped at 2). `+0x393C` stores the resolved `currentPage` activated via `Ui_Object_BroadcastToChildren`.
11. **`Ui_SakusenTutorial`** (0x1E8): Tactics ("sakusen") tutorial window. `Ui_SakusenTutorial_InitPanes` (0x00319198) sets `isInitialised` (`+0x108`) to 1, binds sub-windows `win_sakusen_tutorial2` (`+0x11C`) and `win_sakusen_tutorial3` (`+0x180`), and links into parent doubly-linked list via `+0x134`.
12. **`Ui_StatCompare`** (0x170, base `Ui_AnimRef`): Equipment stat comparison panel (vtable 0x00773178). Owns an embedded text element at `+0xD4` (`textElement`), and two 0x50-byte `UiAnimRefList` groups at `+0x11C` (`panel0Anim`, mode==0) and `+0x16C` (`panel1Anim`, mode!=0) for stat gain/loss layout.
13. **`Ui_TextConsole`** (0x258): Console text object (ctor 0x0054B804). Installs primary vtable 0x00781AE4 at `+0x00`, zeroes `+0x04/+0x08`, calls base ctor on embedded sub-object at `+0x0C` (secondary vtable 0x00781B04), and writes flag bytes at `+0x254/+0x255` (relative to `+0x0C`, real byte offset `+0x260/+0x261`).
14. **`Ui_TextElement`** (0x12C): List-row text element widget. `+0x28` (`paneGroupId`, u16) forms the high 16 bits of pane IDs (`<< 16` and `<< 16 | 1`). `+0x34` (`textLayer`) is the element container for `Ui_TextElement_SetString`. `+0x4C` (`rowWidget`) controls row column visibility (bit 0 of `+0x44`). `+0x128` is an embedded object from sub-allocator.
15. **`Ui_TextScroll`** (0x2BC): Scrolling text display (part of `Ui_CreditWindow` 0x00286B6C..0x00287FC8). `+0x11C` (`animWidget`) is an embedded animation widget, `+0x22C` (`maybe_paneContainer`) provides the pane list, and `+0x2B8` (`scrollOffset`, f32) tracks running vertical scroll position. `+0x0A0` and `+0x0C0` are vtable slot artifacts.

## Traps and decisions

1. **Vtable slot artifacts emitted as unknown_0xx:**
   Several batch offsets (e.g. `Ui_CriticalPopup` +0xD0, `Ui_IconFlashing` +0xD0 and +0x210, `Ui_TextScroll` +0x0A0 and +0x0C0) have batch evidence referencing vtable slots (`(**(code **)(*param_1 + 0x34))`, etc.), not structure field accesses. They are honestly recorded as `unknown_0d0`, `unknown_210`, `unknown_0a0`, `unknown_0c0` at confidence 0.0 with full explanation in evidence.
2. **ARM PMF adjustor tables:**
   `Ui_TweenSequence` (+0x4C) and `Ui_WindowStateSlot` (+0x37C) index an adjustor table via the ARM pointer-to-member-function idiom (`add r0, r3, r0, asr #1`), allowing dynamic member function dispatch across states.
3. **Shifted structures / template bodies:**
   `Ui_WindowStateSlot` is structurally identical to `Ui_TweenSequence` shifted by `0x330` bytes (the embedded timeline controller).
4. **Base offset adjustment in `Ui_TextConsole`:**
   In `Ui_TextConsole`, struct_db produced offsets `+0x254/+0x255` relative to the sub-object at `+0x0C` (real byte offsets `+0x260/+0x261`). The batch offsets were retained so all batch offsets remain covered.
5. **Types and sizes:**
   All field types are valid C types: builtins (`u8`, `u16`, `u32`, `s8`, `f32`, `void*`), function pointers (`void (*)(void)`), or known structs (`UiAnimRefList`). All confidences below 0.5 carry the required `maybe_` or `unknown_` prefix.
