# S_134 - UI struct/field naming batch

**Status:** completed (static naming only - nothing compiled, exported or emulator-tested)

## What I did

Named all 15 classes and every one of the 45 offsets in
`orchestration/types/batches/S_134.json` (Ui subsystem) and wrote the result to
`orchestration/types/out/S_134.json`.

Method: for each class I read the readable C of its ctor/update/method in
`decomp/readable/functions/` (`decomp/readable/recovered/` for the two functions that only
exist as raw asm, 0x003096D4 and 0x002D946C), then checked suspicious offsets against
`asm/text/*.s` and the callee dossiers from `python tools/fn.py`. `orchestration/types/structs.json`
was used for base layouts and valid C type names.

Files changed:
- `orchestration/types/out/S_134.json` - the answer (15 classes, 45 fields, UTF-8, 26,775 bytes)
- `AGENT_LOG.md` - one appended entry (Entry 464)
- `orchestration/done/S_134.md` - this report
- `out/scratch/S_134/validate.py`, `out/scratch/S_134/validate_merge.py` - scratch validators

## Decisions and traps

1. **Vtable-slot artefacts.** `(**(code**)(*self+0xNN))()` was recorded by struct_db as a field at
   `0xNN*4` for Ui_EquipCharacterIconGrid +0xD0/+0xE0/+0x120, Ui_EquipCompare +0x100,
   Ui_FieldSignboard +0x30 and Ui_EmotionBalloon +0x30. These are virtual calls, not data; emitted as
   `unknown_*` at confidence 0.0 with the call quoted.
2. **Offsets relative to embedded sub-objects.** DiveFormEx/DiveStartWindowPart +0x20 comes from
   `puVar3[8] = self` where `puVar3` is the Ui_Object member pair at +0x3574/+0x35C (real byte
   +0x3594/+0x37C). Ui_LayoutRef +0x3C is inside the embedded anim-ref element. Named honestly as
   inner-object data, never as a self-owned field.
3. **Generated bases cleared with `""`.** Ui_EmotionBalloon and Ui_LayoutRef call
   `Ui_AnimRefList_Ctor(self+8)`, so Ui_AnimRefList is an embedded member, not a base;
   `Ui_LayoutRef_Release` also proves +0 is a refcounted owner (its +4 is passed to the
   reference-drop helper), not a vtable.
4. **Sizes left at the batch's max-field value** (size_source is `max_strong_field+width`). The real
   minimum from the ctor/dtors is stated in each evidence string.
5. **Width corrections backed by byte stores:** Ui_DragScroll +8 is u8 (not u32), Ui_HitNumber
   +0x54, Ui_Fade +0x250 and Ui_EquipCompare +0x49/+0x4A are u8.
6. **Confidence split:** 19 fields at >=0.5, 17 maybe_* (<0.5), 9 unknown_* at 0.0.

  (vtables 0x0075AB10 / inner part vtable are not in structs.json).

  (template copy of the battle target-marker destructor, no identifying string/vtable).
