## What the classes turned out to be

- **Ui_TextBlink** (156): embedded blink timer, no vtable. `+0x28` u16 layer half of the packed
  text/pane id (`f_28 << 16`), `+0x94` alternating block index, `+0x98` 30-frame countdown
  (`-1` disables; sibling 0x0022A8A4).
- **Ui_TextBox** (1656 = 0x678): the BFLYT `txt1` text box; three colour slots 0x20 bytes apart
  at `+0x634/+0x654/+0x674`, all written with one value by `Ui_TextBox_ResetLineColors`.
- **Ui_TextFormat** (524): message-label formatter. `+0x208` sprite-span id, `+0x20A` skip-text
  flag, `+0x20B` question-mark flag (chooses U+FF1F vs U+FF01 — bytes read from
  `asm/data/data_007BB000.s`).
- **Ui_TrainingWindowPart** (288, vtable 0x0075CC00): copy of `Ui_WindowPart_Ctor` with 22
  callback entries instead of 62; embedded anim-ref widget at `+0x11C`.
- **Ui_TwoLineTextWindow2** (292): two-line numbered text window; its three batch offsets are
  vtable slots +0x34/+0x38/+0x48 → `unknown_*` at 0.0.
- **Ui_Widget5Anim** (80): five 0x50-byte `Ui_AnimRefList` entries at `+0x4C`.
- **Ui_WidgetWith10Rows / Ui_WidgetWith12Rows** (88): embedded row table at `+0x54` (vtable
  0x0077F71C, count 10/12 at real `+0x6C`, 0x18-byte rows at `+0x70`).
- **Ui_WindowHolder** (52): owns one 0x3E0-byte dive-start window variant at `+0x8`.
- **Ui_ActionPane** (100, base `Battle_ActionAnimEntry`): animator family; `+0x48` float 1.8f,
  `+0x60` action-anim entry pointer (both weakly supported).
- **Ui_Actor2D** (92): **not UI** — it is `Field_ActorAction_ApplyCurvePositionC`; embedded
  curve at `+0x58`, target object at `+0x28`. Name kept, documented.
- **Ui_AnimWidget12** (80): `Ui_LayoutRef12Widget`, twelve `Ui_AnimRefList` at `+0x4C`.
- **Ui_AnimatableElement** (8): only the head; two linked `Ui_AnimRefList` members at +8/+0x64
  (the generated "base" was the first member's ctor).
- **Ui_CellGrid**: 10 display-cell slots at `+0x8BC4`, 0xB8 bytes each; `+0x92F4` is the loop
  end address, not a field.
- **Ui_Delegate** (24): ARM C++ member-function-pointer delegate: function pointer `+0x10`,
  this-adjustment/virtual flag `+0x14`.

## Open problems / not verified

- Every `maybe_*` and `unknown_*` field (12 + 10 of 39) is unverified.
- `Ui_ActionPane` is a mixed batch: `Ui_ActionPane_InitAnimators` / `AddReactAnimator` operate
  on a larger action window; whether `+0x48` and `+0x60` belong to the same class is unclear.
- The type behind the `+0x54` row table of the 10/12-row widgets is unknown (initialiser
  0x00622248 has no readable C); likewise 0x005F3ADC (position setter) behind `Ui_Actor2D +0x28`.
- `Ui_TrainingWindowPart` base kept as `Ui_Object` (as the batch says) because its ctor does
  not call `Ui_WindowPart_Ctor`; structurally it is a sibling copy, not a derived class.
- `Ui_TextBox`'s three slots may be per-line colours or the BFLYT gradient trio; only the
  reset writes were recovered.
- `Ui_AnimatableElement` base changed from `Ui_AnimRefList` to `null` (explained in evidence).
- `Ui_CellGrid` batch size was 4; the merger grows it to 37624 from the `+0x92F4` offset. The
  real extent is 0x8BC4 + 10*0xB8 = 0x92F4, so the class is a fragment of a much larger object.
