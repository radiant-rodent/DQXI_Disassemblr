## What was left out and why

Nothing was left unnamed. Every variable in every "variables still to name" table received a name,
including the ones that could only be described loosely (matrix/stack scratch slots, libm register
inputs, misaligned decode artefacts). Variables not in those tables (including all previously named
ones) were left untouched, and no name from the "already used names" note was reused.

Fourteen entries were submitted with confidence < 0.5 and therefore carry the `maybe_` prefix on every
name, as required: 0x005626F4 (quaternion/matrix stack slots), 0x005F6558 (trail sample/vertex scratch),
0x005F79E0 (identity copies, node matrix, quaternion), 0x006347EC, 0x00672DA0 (`std_Ceilf` is a
misaligned slice of the atan2f literal pool), 0x006733C2 / 0x006733C6 (bogus `std_Modf` fragments),
0x00107FC0 (bucket field layout guessed), 0x00148E28 (cell-table layout guessed) and
0x00161974 (no dossier/body context for the attach parameter block).

Three answers were filled only with a single object-pointer name because the tool listed a single
variable there (0x0010F050, 0x0011AE5C, 0x00672A14) or a single vtable/object pair on the
"create default object" helpers (0x0016096C, 0x00161160, 0x00162084, 0x00162278, 0x00162758,
0x00162DA8, 0x00162DE8).
