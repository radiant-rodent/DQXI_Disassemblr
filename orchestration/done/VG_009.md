## Recurring naming decisions

- Rolling display-name buffers: the `"txt_…"`, `"null_txt_…"`, `"icon…"`, `"poker_…"` string builders are
  4-char word + 4-char word + packed 2-char counter + digit + terminator. Named `<stem>Name0/1`,
  `<stem>SuffixChars`, `<stem>SuffixDigit`, `<stem>Term` so the carry logic is readable.
- Child/sprite descriptor stack blocks (the 0x004718A4 family and 0x004B03A4): `childKind`, `childFlags`,
  `scaleX/Y/Z`, `childDescWord0..5`, `modeByte`, `visibleFlag`, `blendByte`, `angleX/Y/Z`, `anglePi`,
  `spanFlags`, `param274Copy`.
- Effect-node child factories (0x00471308, 0x004721C4, 0x004B143C, 0x004B1994, 0x004B1F74, 0x004CB33C):
  `elementCtor`, `childObj`/`effectChild`, `defaultBlockPtr`.
- `Battle_Action_*_Ctor` / `Monster_Action_*_Ctor` stubs: `objectPtr` (+ `vtablePtr` where the vtable is
  staged in a local), unused `arg3` -> `maybe_unusedArg3`.
- Forwarded window-init parameters that are never interpreted in the body: `initArgN`/`paneArgN`/
  `popupArgN`/`plateArgN`, with the low confidence they deserve.

## Left out, and why

Nothing from the tool's tables was left unnamed — the tool asks again only for variables it can still
list, and `--check` reports 0 problems. The only things deliberately *not* asserted are semantics:

- `in_fpscr` in `Ui_DamagePopup_SetNumber` (0x00485A0C) and `Ui_MpDamagePopup_SetNumber` (0x004AAD14):
  the word is read only for its rounding-mode bits before `VectorUnsignedToFloat`. Named `maybe_fpscr`.
- `maybe_Gfx_SpriteActor_Ctor` (0x004C9C64): the decompilation is damaged (unaff_* registers), so every
  name there is `maybe_`-prefixed with entry confidence 0.45.
- `maybe_Anim_Instance_CreateForModel` (0x004A781C), `Anim_ModelLoad_ByName` (0x004D2538) and
  `maybe_Field_SceneInit_Shared` (0x004D7B4C) have tails cut off by the tool; the descriptor fields there
  are named by their stack offset (`descByteXX`, `maybe_wordN`) since only the constant being stored is
  visible.
- Parameters that are provably unused (`arg3` of most `*_Ctor` stubs, `arg2` of
  `Container_AddUniqueIdEntry`, `arg1` of `maybe_Container_LookupType4Value`) are named
  `maybe_unusedArgN` rather than invented.
