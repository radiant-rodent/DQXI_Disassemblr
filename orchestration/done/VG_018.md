170 functions covered, `python tools/gapfill.py VG_018 --check` reports `170 answers, 0 problem(s)`.

## Variables named

619 variables (params + locals) named across those 170 functions, in 24 chunks.
Nothing was left in the "variables still to name" tables.

54 of them (in 13 functions) were named with the `maybe_` prefix at entry confidence
< 0.5 because the body was too damaged or too register-spilled to justify a firm name:

- 0x004546A8, 0x004A6EDC — unrecovered `unaff_*` registers
- 0x005D364C — seven rotation terms of the actor matrix product
- 0x005D5A24, 0x005D9EE0, 0x005D9F1C, 0x005DB228, 0x005DF260, 0x00600B74,
  0x00600B5C — incoming register only spilled into the `Ui_GetCore` scratch word
- 0x005DB0D0 — stack descriptor built field by field, exact field roles unknown
- 0x00604EA6, 0x00604EBA — literal-pool words decoded as VFP instructions

Recurring patterns that were named consistently:

- parameters that are never read -> `unusedArgA` / `unusedArgB`
- parameters only used as the `Ui_GetCore(&arg)` / `Gfx_GetContext(&arg)` slot -> `scratchArg`,
  with the local -> `coreScratch`
- lazy-init / alloc idioms -> `elementStride` / `elemSize` / `allocSize` / `blockSize`,
  handle exchange -> `handleWord` / `entryPtr` / `newHandle` / `handleTableBase`
- intrusive-list sentinels -> `localListHead` / `localListTail` / `localListEnd`,
  unlink pairs -> `nextLink` / `prevLink`
- inline pane-name buffers -> `nameSuffix*` / `nameDigit*` / `nameTerm*` / `nameWord0..3`
- FPU rounding register -> `fpscr`

## Left out

Nothing. Every variable the tool listed in VG_018 was given a name. No variable outside
the "variables still to name" tables was renamed, and no name from a function's
"already used names" note was reused.
