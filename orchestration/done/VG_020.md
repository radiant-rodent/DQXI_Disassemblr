## How the names were chosen

Priority order used for every entry: the body itself, then `calls`, then `fields`, then `consts`,
then the `hint` column.

Recurring, deliberately plain patterns:

- **Unused parameters** — the majority of leftovers were parameters that the body never reads
  (`arg2`/`arg3`/`arg4` in handlers that only use `self` + `context`). Named `maybe_unusedArg`,
  `maybe_unusedArg2`, `maybe_unusedArg3` with entry confidence 0.45.
- **Context arguments** — `arg4` copied into a local and then handed to `Game_GetWork` /
  `Game_GetDataManager` is named `workContext` / `contextArg` (0.5–0.6).
- **Zero / 0xFF / -1 initialised stack slots** — descriptor and clip-record tails cleared with
  `func_001113EC` / `func_00116AE0` are named `zero<offset>`, `noTargetId*`, `descByte*`,
  `rowShort*`, `descZero*`. They are real padded structure fields, so a positional name is the only
  true statement available.
- **Descriptor / row blocks** — stacked parameter blocks passed by address to a create/measure call
  are named after their consumer (`spanParams`, `childCreateParams`, `measureFlags`, `copyBuf`,
  `rowFillPtr`, `layoutVecX/Y/Z`).
- **Register-merged temporaries** — variables that Ghidra reused for several meanings (alloc size,
  then object pointer, then class chain) are named `scratchInt`, `scratchValue`, `poolTemp`,
  `scratchPtr`, etc., with the reuse spelled out in the evidence string.
- **VFP/FPSCR words** — every `in_fpscr` is `fpscrValue` (bits 22–23 supply the rounding mode for
  `VectorSignedToFloat` / `VectorUnsignedToFloat`). Confidence 0.7.
- **`unaff_rN` / `in_rN` / `in_lr`** in damaged bodies — named for the only role visible
  (`linkRegister`, `maybe_reg4..reg11`, `maybe_cr4Value`, `maybe_initialWord`) at 0.45, so the
  `maybe_` prefix marks them as register debris rather than recovered meaning.

Every entry with confidence < 0.5 has the `maybe_` prefix on **all** of its names (the tool enforces
this). Names already present in a function's "already used names" note were never reused, and no two
names inside one function collide.
