## What was named and how

- **Unused parameters** (56 across the batch, e.g. `arg2`/`arg3` on the Actor status getters, the sort
  comparators and the slide-window handlers) were named `maybe_unusedArgN` with confidence < 0.5, since
  the body never reads them.
- **Work-context arguments** that only seed a stack out-buffer for `Game_GetWork`/`Game_GetDataManager`
  were named `workCtx` (`Casino_*`, `Actor_CheckVisibleFlags`).
- **FPSCR register artifacts** (`in_fpscr`, and locals of that shape) were named `fpscr`; only their
  rounding bits are consumed by `VectorSignedToFloat`/`VectorUnsignedToFloat`.
- **Unmodelled register leftovers** (`extraout_r1`, `unaff_r4`..`unaff_r10`, `in_r3`, `in_s0`) were
  named for the one role they play: forwarded call argument, loop counter, heap top index, written value,
  or work context.
- **Large stack blocks** were named by structure: span/colour-animator blocks (`spanBlock0..5`,
  `colAnimArg0..5`), child descriptors (`childParam0..7`, `childRectMinX..childRectMaxY`),
  encounter-record copies (`recordCopy0..35`), glyph style/cell components (`cellValue*`, `styleValue*`,
  `matValue*`) and channel buffer regions (`regionBaseC..H`).
