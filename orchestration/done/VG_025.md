## Naming scheme

Plane/block converters (functions 1–8) — decompiler reuses registers as byte lanes, so names follow the
data flow, not the declared type:

- pixel words and their lanes: `curPixelWord`/`nextPixelWord`, `curPixelByte0..3`,
  `nextPixelByte0..3`, plus `rowAboveByte*`/`rowBelowByte*` for the banded reads;
- per-byte averages: `avgByte0..3`;
- clamped differences from `UnsignedSaturate`: `satDiff1..15`; direction-paired diffs:
  `gradA..gradD`, `diffPackA..diffPackD`, `edgeDiffClamp`, `mixDiffA/B`;
- fixed constants and their per-byte spread: `oneConst` (0x01010101), `biasConst` (0x20202020),
  `oneConstByte0..3`, `biasByte0..3`; channel constants `f10*`/`f14*` (`self->f_10`, `self->f_14`);
- loop state: `rowLength`, `savedRowLength`, `outerCount`, `outerLimit`, `remainingCount`,
  `savedLoopCount`, `innerCount`, `planeOffset`;
- buffer/temporaries: `copyWord0..7`, `planePtrScratch`, `planeRowPtr`, `planeRowPtr2`,
  `laneBlockPtr`, masked lane words `maskedLaneA..D`, `maskedShiftA/B`, `laneWord*`, `planePtrA/B`.

Strip converter (function 9): the only unnamed value was the leftover r1 return used as the destination
strip start — `dstStartPtr`.

MC prediction family (functions 10–27): these are damaged decompilations where only `unaff_*` /
`extraout_*` registers remain. The same four roles recur in every body:

- `unaff_r5` — byte offset added to the context for the plane pointers at +0xc / +0x24 -> `maybe_planeOffset`
- `unaff_r6` — feeds `mvX` and is passed as the filter width -> `maybe_xOffset`
- `unaff_r11` — added to both source and destination pointers per row -> `maybe_yOffset`
- `extraout_r1` — the leftover r1 used as the second chroma destination -> `maybe_chromaDstPtr`
- `arg4` (Apply variants only) — the incoming r1 destination pointer -> `maybe_dstPtrParam`
