## Naming conventions used

* Unused parameters were still named (`unusedArg2`, `unusedArg3`, `unusedArg1`) because their only
  role is to occupy the call slot; `maybe_Math_Vector3_SetFrom`/`maybe_Ui_Widget_ApplyScreenTransform`
  /`maybe_Ui_StatusWindow_ApplySlotFrames` and the `*Move_Begin/End/Cancel` pair are the cases.
* The `+0x15CC`/`0x15CC` block selector, the 0x1C-stride work entry and the 0x10-stride path entry
  recur across the camera batch, so the record blocks in 0x001D15AC/0x001D15F4, 0x001D43C0,
  0x001D4DA4 and 0x001D462C were named as one layout (`recordHandle`/`recordKind`/
  `recordPosition*`/`recordDirection*`/`recordFlags`), and the stack-saved argument copies as
  `*Arg`.
* Generic temporaries that carry several unrelated values in turn are `scratchInt`/`scratchWord`/
  `scratchPtr`; FPSCR/condition-code words are `fpControlReg`/`compareWord`/`compareFlags`; the
  condition bits derived from them are `lessThanFlag`/`equalFlag`/`unorderedFlag`.
* Setup-record link slots kept as `recordLinkNext`/`recordLinkPrev` (functions 1, 13, 17) matching
  the `recordLink` name the first pass already used.
