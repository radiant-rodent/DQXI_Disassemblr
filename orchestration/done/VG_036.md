# VG_036 — second naming pass (109 functions)

Status: 109 answers, `--check` reports 0 problems.

## Variables named

Every variable that the tool listed in the "variables still to name" tables was named
(params, locals, stack slots, register leftovers and float registers), for all 109
functions. Naming conventions used:

- loop/accumulator temps -> `index`, `scratchValue`, `scratchValue2`, `rowIndexValue`
- return/status values kept in a temp -> `result`-style names (`checkResult`, `statusValue`,
  `classTagResult`, `nameResult`, `lookupResult`, `rngRemainder`, `rngValueA/B`)
- stack scratch handed to a call -> `workOutBuffer`, `workArg`, `resourceArgBuf`, `layoutArgBuf`
- pointer to a located record -> `entryPtr`, `listEntryPtr`, `actorRef`, `reelModel`, `vmPtr`
- filler floats in transforms/matrices -> `valueA`..`valueH`, `vecX/Y/Z`, `basisWord0..2`
- local param/descriptor blocks -> `paramBlock*`, `childParams*`, `effectField*`,
  `defaultBlock*`, `transformWord*`, `nameWord*`, `bindParam*`, `flagByte*`
- register leftovers with no recoverable meaning -> `savedArg`, `flagsArg`, `scratchCharPtr`,
  `maybe_inValue*`, `unusedArg`, `unusedReg`
- all recovered magic-divisor temps -> `divMagic`, `scaleFactor`, `allocSize`, `sizeBytes`
- fpscr images used for float compare/rounding -> `fpscr`
- entries whose role could not be justified were still named and given `maybe_` prefixes on
  every name with confidence below 0.5 (damaged/decompiler-artefact bodies):
  `maybe_Script_VM_RunClosure` (0x2C9CD4), `maybe_Ui_JackpotScreen_CtorParts` (0x2C8C3C),
  `maybe_Ui_JackpotScreen_CtorWidgets` (0x2C8D22), `maybe_Battle_UpdateUnitDisplay` (0x2D9E00),
  `Battle_UiList_CalcContentWidthEx` (0x2DCC28), `Battle_UiFlow_OpenSelectionWindowEx`
  (0x2DE93C), `Battle_UiFlow_ToggleDetailWindow` (0x2DF3EC),
  `Battle_UiFlow_RefreshPartyRowValues` (0x2DF648), `Battle_UiFlow_OpenItemNameWindow`
  (0x2DD958), `Battle_Popup_Update` (0x2E1E3C), `Gfx_Scene_RemoveSpriteEntries` (0x2E5A90),
  `Battle_Popup3D_UpdateRoot` (0x2E8AC8), `Ui_MenuActor_UpdateEffects` (0x2F0D0C).
