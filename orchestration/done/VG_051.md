## How the hard ones were named

- Ghidra pseudo-registers: `in_fpscr` -> `fpscrPseudo` (rounding-mode source of
  float conversions), `in_cr0/cr5/cr14` -> `cr*Pseudo`, `in_r3`/`in_s0` ->
  `incomingWord` / `floatArg`, `extraout_r1*` -> `unusedR1*`.
- Unused parameters were named `unusedArg0..2` / `unusedArg`; parameters that only
  seed an `Os_GetGameWork`/`GetWork` out buffer were named `tokenArg`, `sceneToken`,
  `gameWorkBuf`; forwarded-only parameters `forwardArg0..2`, `childArg`, `valueArg*`.
- State-machine scratch variables that carry the 0x16xx/0x5xx/0x8xx state ids were
  named `*StateValue`/`stepValue`/`nextStateValue`.
- Stack descriptor blocks (sprite/effect/animator/popup-entry parameter blocks) were
  named by role and position: `childDescBuf`, `effectParams`, `paramWord0..5`,
  `entryId0/1`, `entryMask`, `entryValidFlag`, `flagByte0..N`, `blockA0..5`,
  `blockB0..5`, `matCopy0..10`, `matM00..M23`, `rotM00..M23`, `identW0..W11`.
- Constant-table pointers and globals got positional names (`constTablePtr`,
  `axisX/Y/Z`, `dirConstX/Y/Z`, `scaleConst3c/40/44/4c`, `thresholdValue`).
- Field-derived pointers were named from the offsets actually read, e.g.
  `nearestUnitPtr` (f_9a), `slotPtr` (f_1a4/f_c4), `targetNodePtr` (f_14/f_18/f_1c),
  `nodePtr` (f_238), `styleBlock`/`styleData`.
