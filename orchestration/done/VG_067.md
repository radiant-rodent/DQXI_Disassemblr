## What was left out and why

Nothing. Every variable the tool listed for all 75 functions received a name, so no row was skipped.

No entry needed the `maybe_` prefix: each name is at least a true statement about the slot's role, so every entry was submitted at confidence 0.5 or above (range 0.5–0.7).

Naming conventions used where the body gave no stronger meaning:

- Shared return-code temporaries (`iVar1`, `iVar2`, `iVar3`, `iVar6`, `iVar8`) → `status`, or `tmpValue`/`tmpWord` where the same register is reused for pointers and counts as well.
- Unreferenced parameters (`arg1`, `arg2`, `arg3`) → `unusedArg`.
- Uninitialised registers forwarded to a call (`unaff_r4..r6`, `in_lr`, `in_r1..in_s13`) → `memArg*`, `floatArg*`, `cmdbufReg`.
- Zero-initialised stack slots with no visible reader → `zeroWord*`, `zeroByte*`, `scratchWord*`, `scratchBuf`.
- Packed PICA descriptor bytes → `<group>Byte<N>` (`cmdByte`, `texByte`, `paramByte`, `blendByte`, `drawByte`, `packetByte`, `descByte`), numbered by stack offset.
- FPSCR reads feeding the vector conversion helpers → `fpscr`.
- Float scratch temporaries → `tmpFloatA`…`tmpFloatN`.
