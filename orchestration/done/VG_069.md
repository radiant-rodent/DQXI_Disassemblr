## Naming conventions used

- Register-derived inputs: `in_fpscr` → `fpscr`, `in_cr0/cr12/cr13/cr14` → `cr0Value`/`cr12Value`/`cr13Value`/`cr14Value`, `in_r3`/`in_r12` → `inR3`/`inR12`, `unaff_rN` → `unaffRN`.
- `extraout_r1` → `extraR1`, except in `Save_Crypto_ExpandKey` where the four returns became `keyIndex0`..`keyIndex3`.
- Stack copies of a parameter → `<param>Copy` (`dataKeyCopy`, `gridCopy`, `layerCopy`, `xCopy`, `yCopy`, ...).
- Parameters never read → `unusedParamN`.
- Stack blocks and descriptors → `descFieldN`, `queryFieldN`, `rectFieldN`, `vecFieldN`, `bufWordN`, `rowA0`..`rowA14`/`rowB0`..`rowB14`, `blockField0`..`blockField8`.
- `iVarN`/`uVarN`/`fVarN` scratch → `tmpInt`, `tmpWord`, `tmpFloat`, `spreadBits`, `packedPair`, `packedX`, `actorX`/`actorY`, `scenePtr`, `recordPtr`, `elemPtr`, `handleMapBase`, `alignSize`, `blockSize`, `elementType`.
- Loop counters → `index`/`i`; return values kept in a temp → `result`/`status`; stack buffers passed to a call → `buf`/`scratch`.
