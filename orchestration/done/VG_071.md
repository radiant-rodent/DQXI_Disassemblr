## Naming notes

- No entry was submitted below confidence 0.5, so no `maybe_` prefix was applied to a
  variable name. Entries range from 0.5 to 0.7; the reasoning for each is in the
  `evidence` field of the saved answer.
- Where the printed body was truncated by the tool, names were derived from the
  `hint`, `calls`, `fields` and `consts` columns only. Those variables are deliberately
  vague but true: `tmpWord`, `prevWord`, `tmpFloat`, `matElem7`, `matElemCast`,
  `tmpFloatA`/`tmpFloatB`/`tmpFloatC`, `sentinelPtr`, `isDifferent`, `inRegValue`,
  `unaffR5Ptr`/`unaffR6Ptr`/`unaffR7Value`, `cr2In`/`cr4In`/`cr14In`.
- Parameters that the body never reads are named `unusedArg2`/`unusedArg3`
  (0x0019EE04, 0x0022C390, 0x002AE444, 0x00284784, 0x00422348).
- Matrix and vector temporaries are named by element position (`mat00`..`mat23`,
  `worldM00`..`worldM23`, `camM00`..`camM22`, `rotRow0X`..`rotRow2W`,
  `partMat01`..`partMat23`, `localMat01`..`localMat23`) because the bodies are
  straight-line element copies and products.
- Camera-basis functions (0x002435E0, 0x00282CFC, 0x00297D04, 0x0039E374) share the
  `dirX`/`dirY`/`dirZ`, `rightX`/`rightY`/`rightZ`, `upX`/`upY`/`upZ`,
  `transX`/`transY`/`transZ` scheme, matching the names the first pass already used in
  those functions.
- The eight `Field2D_SpatialGrid_*` functions each had only the `arg3` parameter left;
  all eight are the same cell-table index, named `cellIndex`.
