## Naming patterns used

- `unusedArgN` — parameter never read in the body (the decompiler kept the slot, the code ignores it).
- `scratchValue` / `scratchSlot` / `scratchBuf` / `scratchOut` — the incoming value copied into the local
  whose address is handed to `Os_GetGameWork` / `Game_GetWork` / `Ui_GetCore` / `Gfx_GetContext`, i.e. a
  dead out-parameter slot.
- `maybe_scratchValue` — same thing for the bare `in_r3` register spill; these entries carry confidence
  0.45 and are the only ones prefixed `maybe_`.
- `actorManager`, `actorRecord`, `targetRecord`, `locatorContainer`, `handleSentinel`, `handleGeneration`,
  `fpscrValue`, `rotMatrix1/2` — reused temporaries named from their dominant structural use.
- `fieldWordN` / `fieldByteN` / `fieldValueN` — per-field copies of a record being rebuilt on the stack
  (BattleEndToTraining, BattleEndToDefaultField); the number is the source offset.
- `paramByteN` / `paramValueN`, `zeroFieldNN` — same idea for the message-parameter blocks.
