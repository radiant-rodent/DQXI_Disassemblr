## Recurring patterns behind the names

- `workArg` / `workArgBuf`: the incoming register value copied into a stack slot whose address is
  handed to `Os_GetGameWork`, `Game_GetWork`, `Game_GetDataManager`, `Ui_GetCore` or
  `Gfx_GetSceneSpriteContext`. The slot itself is `workArgBuf`, the value it carries is `workArg`.
- `incomingArg`: same idea where the decompiler kept the raw register (`in_r3`) instead of a stack
  slot, and the value is a handle/id rather than a work-buffer argument.
- `unusedArgN`: the parameter is never referenced anywhere in the body. The name records that fact
  rather than inventing a meaning.
- `forwardArgN` / `forwardRegN` / `linkReg`: the value is only ever forwarded as a trailing argument
  of one callee, so nothing about its meaning is recoverable beyond "it is passed through".
- `fpscr`: the FPSCR pseudo-register; `(u8)(in_fpscr >> 0x16) & 3` is the rounding mode handed to
  `VectorSignedToFloat` / `VectorUnsignedToFloat`.
- `rectA0..rectD3` in `txf`: four contiguous four-float stack blocks that are passed to
  `Field2D_Scene_RenderIntersectingObjectsA/B` and `Field2D_SpatialGrid_DispatchRenderObjectsA/B`.
  The component order inside a block is not recoverable from the truncated body, so the slots are
  numbered rather than named x/y/w/h. `rectA0Copy` is the lone copy of `rectA0`, `rectD*` is a copy
  of `rectA*`.
- `vecY` / `vecZ` in `LoadField`: the two words directly above `vecBuf` that are read back as
  `forwardY`/`posY` and `forwardZ`/`posZ` after `Math_QuatToForwardVector` and
  `Field_SceneNode_GetPosition` fill the vector.
