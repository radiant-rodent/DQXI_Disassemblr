# V_020 done

2026-11-10: 150/150 functions processed -> `orchestration/types/out/V_020.json`
(119 functions named, 460 names; 31 damaged stubs intentionally left empty)

Names below confidence 0.5 carry `maybe_`. Batch tokens that no longer exist in the
current readable C (e.g. `f18`, `f58`, `f98`, `fc`, `partyGetActiveMemberCount`) were
omitted rather than guessed. Apply with M3_vars_merge.

## What was done

- Read `WORKER_RULES.md`, the batch instruction and the existing V_01x output schema.
- Resolved every batch address against the *current* readable C via
  `out/scratch/V_020/dump.py` (batch `readable` paths had drifted after merge).
- Decided names per function from the body, call names, vtable slots, globals,
  strings and constants, then wrote 15 decision chunks
  (`out/scratch/V_020/chunk00.json` ... `chunk14.json`).
- `out/scratch/V_020/merge.py` merges the chunks, validates them and writes the
  deliverable `orchestration/types/out/V_020.json`.

## Decisions worth knowing

- Packed slot handles: tag = `h >> 0xC`, index = `h & 0xFFF`, `0xFFFFF` =
  invalid tag, `Pack_FreeHandleEntry` / `Pack_ReleaseHandle` manage the entries.
  Used for the three `Ui_SmithMenu_SetSlotHandle*` functions and
  `Ui_SmithMenu_ReleaseSlotHandle`.
- Lazy engine block construction (`g_memoryManagerInitFlag`, `func_0011FE8C`,
  `func_0011CFAC`, `func_00116AE0`, `func_001064D4`, `g_uiLayoutBlockVtable`)
  named `memoryManagerPtr` / `uiLayoutBlock` / `elemSize` / `allocSize`.
- `g_messageFormatArgSlots` (+0x844 / +0x848 / +0x84C) anchors the
  `Ui_Message_SetArgsFromRecord*` names (`argSlotTable`, `argSlotBase`,
  `argumentContext`).
- `Ui_GetCore` result consistently named `uiCore`; its argument stack scratch
  (`auStack_*`, `in_r3`, `uStack_*`) is never renamed.
- The 90-slot item bag layout is shared by `maybe_ItemBag_CountValidSlots`,
  `maybe_ItemBag_CountItemsOfType` and the accessors `func_0066B534` /
  `func_0066AF08`.

  `Party_CountLearnedSkills` (batch `maybe_MonsterBook_CountRecorded`),
  `maybe_Ui_QueryTransitionBusyInState7` / `InState1A` / `...BusyB`
  (batch `maybe_Script_MessageConditionCheckA/C/D`),
  `maybe_Gfx_Resource_IsBusy` / `...B` (batch `...ConditionCheckB` /
  `...AnimConditionCheck`), `Ui_ListCursor_GetSelectedMemberIdB`
  (batch `maybe_Ui_ListText_GetSlotFlags`). Suggested follow-up: decide whether
  the batch names or the recovered names win and update the function DB.
- Ghidra-damaged expressions were worked around, not fixed:
  invalid-handle clears like `x 0xFFFFF000 | 0xFFFFF000`, and
  `Party_GetActiveMemberCount&self->maybe_listCursor` in
  `Ui_ListCursor_GetSelectedMemberIdB`.
- `Anim_BuildMotionPackPath` pointer/offset table layout is only partially
  understood (count at +0x60, data offset at +0x58->+0x24, strides 0xC/8/4);
  names are descriptive, not definitive.
- Nothing was compiled, exported or emulator-tested - static naming only.
