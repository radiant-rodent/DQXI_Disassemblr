  `local_30`→`uiCoreOut`, `auStack_2c`→`gameWorkOut`, `auStack_28`→`itemRecord`.
  Conflict recorded in the evidence: N_021's doc calls `uVar4` a "measured width", but the callee is
  now `Item_RollStatBoostDelta` (R_K01, verified against the disassembly) and the value is added to
  `member->f_1c8`; I trusted the callee and used the vague `statBoostDelta`.
* **Pane push/pop families** (0x006D774C–0x006D8F74, 25 functions in 4 body shapes): `paneCount`
  (`self[9]`/`self[0xf]` capacity test), `paneIndex` (slot index `self[i*3+3..5]`), `uiCore` /

  blocks): `resNameTable` (`&g_resName…` passed to `func_00124B24`), `packEntry`, `typeNode`

* **Damaged bodies** (0x006E51E4, 0x006E53A4, 0x006E5C68, 0x006E6180, 0x007135D4, 0x007139AC):
  confidence 0.3, every name `maybe_`, and only the parts the disassembly still shows

## Found but NOT fixed (outside my ownership)

1. **19 of the 105 batch `readable` paths are stale** (the function was renamed after the batch was
   generated, e.g. 0x006D774C is now `Ui_JumonWindow_PushSubPane`, 0x00640514 is now
   `Ui_Panel_IsShowing`). I resolved them by address suffix
   (`decomp/readable/functions/*_<addr>.c`). The batch generator should do that at dispatch time.
2. **58 of the 536 renames are no-ops at merge time.** `readable_c.apply_local_map` runs *before*
   the readability pass's own heuristic renames, so a batch token that the heuristic had already
   renamed (`result`, `uiGetCore`, `gameGetWork`, `partyGetActiveMemberCount`, `f4c`, `f8c`, `f13`,
   `skillPanelCanUnlockSkill`) no longer exists in the text it rewrites. 478/536 renames do apply.
   Fix: have `tools/typedb/inventory.py` emit the Ghidra tokens (`uVar1`, `puVar1`, …), or run the
   locals map after the heuristic renames in `tools/readable_c.py`.
3. **32 of the 95 merged keys are the old `locals.json` name** while the readable C now uses a
   different one (`maybe_Ui_ListCursor_IsAtPartyCountSlot` vs `Ui_ListCursor_IsAtPartyEndRow`, …).
   `tools/readable_c.py:472` looks the map up by `func["name"]`, so those 32 maps would be silently
   dropped when the readable C is regenerated. Fix: look the locals map up by address
   (`maps["function_by_address"]` already exists).
