# V_025 — local variable / `argN` rename batch (150 functions)

## What I did

Renamed local variables and remaining `argN` parameters for all 150 functions in
`orchestration/types/batches/V_025.json`, using only `tools/batchview.py` (no tree walks, no
custom dump scripts, no docs reads — batch mode per WORKER_RULES rule 15).

Workflow: `--todo` → `batchview V_025 A:B` in chunks of 10 → write
`out/scratch/V_025/chunk.json` → `--add` (validator: tokens, lowerCamelCase, keywords,
duplicates, `maybe_` rule) → repeat. 15 chunks, every one accepted on the first `--add`.

## Naming conventions reused (kept consistent with earlier V_ batches)

* `Game_GetWork(...)` result → `work`; `*work` → `gameWork`; `work + 0x24A98` → `saveWork`;
  `work + 0x24ACC` → the item bag.
* `func_0035EB98(work, idx)` → `member`; `Item_LookupRecord` out-buffer → `itemRecordBuf`,
  returned record → `itemRecord`.
* `Ui_GetRootSingleton` → `uiRoot`; `&self->f_3574` page object with vtable `+0x14`/`+0x10`
  → `pageObject`; `self->f_3534` bit word → `commandMask`.
* `func_0062F070(self)` loop guard → `childCount`; intrusive-list walkers → `childNode`.
* Item/shop helpers: `itemPrice`, `maxCount`, `affordableCount`, `memberIndex`, `equipSlot`,
  `inventorySlot`.
* Damaged decompilation (`unaff_rN`, `in_NG/ZR/OV`, `in_fpscr`, `in_lr`, `halt_baddata`) left
  unnamed rather than guessed.

## Open problems / not verified

* **Not verified against the merged readable C.** `M3_vars_merge` has not run yet, so no name
  here has been seen applied. The validator only checks shape (tokens exist, casing, keywords,
  duplicates, `maybe_` rule), not semantic fit.
* **`0x00310900` (`maybe_Text_LineFillCharsEx`) is a false function entry** — it is inside the
  constructor at `0x00310844` (no prologue, live `r4`–`r8`, falls through). Its whole answer is
  `maybe_` at confidence 0.4; the real fix is to delete the symbol, not to name it.
* **`0x00310844` (`maybe_Text_LineFillChars`) has no readable C** (heavy `unaff_*`/`in_*`
  damage). Only the allocation chain (`allocSize`/`align`/`alignedSize`) and the work pointer
  are named; ~9 tokens are left as-is.
* **`0x0031120C` and `0x00311450`** read a 6th argument (`arg6`) that Ghidra dropped from the
  signature; the five batch params were mapped by position from the body, which is a judgement
  call worth a second look.
* Several functions in this batch are still misnamed at the function level (e.g.
  `Text_LineGetMaxInsertCount` is really `Shop_GetMaxAffordableCount`,
  `Text_LineInsertChars` is `Shop_BuyItemForMember`, `Text_LineInsertGlyph` is
  `Shop_SellItem`, `maybe_Ui_DebugLabel_ShowGlyphInfo` is `Ui_ItemScreen_ShowItemInfo`).
  Renaming functions is out of scope for a V_ batch; the evidence strings record the real
  roles.
