# V_026 — local variable / argN renaming batch

## What was done

Renamed the local variables and remaining `argN` parameters of all **150** functions in
`orchestration/types/batches/V_026.json` (UI window / list-window / shop-window / record-window /
message-window / casino-slot / actor-animation cluster around `0x0037B490..0x0039D664`).

* 150 of 150 functions answered, 0 to do.
* 1,345 names written (params + locals), of which 657 carry the `maybe_` prefix because the
  evidence did not justify a confident name.
* Every entry has an `evidence` string naming the concrete signal used (callee name, vtable slot,
  string constant, field offset/width, sentinel constant).

* `orchestration/types/out/V_026.json` — the only owned output file (150 records, UTF-8).

## Decisions taken (no orchestrator available)

* **Table is authoritative.** In several functions the readable body and the variable table
  disagree on token names (e.g. `0x0037DBC8` body says `textGetCharPairStyle`, table says
  `puVar1`; `0x00387258` body says `partyEntryMatchesSelectedId`, table says `bVar2`). I renamed
  the tokens the table lists, because that is what the merge applies.
* **Damaged decompilations stay vague.** Functions with `unaff_rN` / `in_NG` / `in_ZR` / `in_OV`
  (`0x0037F3FC`, `0x003847A0`, `0x00384C64`, `0x0037F384`) got function confidence 0.3–0.5 and
  `maybe_` on every name.
* **No-body functions** (`0x003807D8` has no readable C; `0x00398D8C` has a two-line stub) were
  answered from the variable table alone with low confidence, or with empty maps when there was
  nothing to rename.
* **Trivial loop counters left alone.** `Casino_Slot_StopAllReels`, `Casino_Slot_HideSymbols`,
  `maybe_Casino_Slot_ResetRows`, `maybe_Casino_Slot_ApplyRowState` only have `i`/`j` indices and
  already-meaningful params, so they were answered with empty maps at confidence 0.9.
* **Duplicate-name rule.** The validator rejects two identical new names inside one function, so
  repeated roles got `B`/`C` suffixes (`itemRecordPtr`/`itemRecordPtrB`, `maybe_workOut`/
  `maybe_workOutB`..`E`).
* **Zeroed stack words** in `Anim_SaveStateToSlot` / `Anim_SaveCurrentState` (16 words that are
  only set to 0 before a `std_memcpy`) were named `maybe_zeroWord01..16` rather than invented
  field names.

## Open problems / not verified

* The names are **not** applied to `decomp/readable/` yet — that is `M3_vars_merge`. Nothing here
  was compiled or run.
* `0x003802FC` (`maybe_Ui_Window_ApplyDisplayScale`) has a **mismatched readable body**: the
  signature is a UI display-scale setter but the body is the casino slot bet routine
  (`Casino_Slot_GetPayoutRank`, gold change via `func_0061251C(work+0x24A98, -amount)`). I named
  the variables after the body (the code that will actually be renamed) and noted the mismatch in
  the evidence. The function name itself is wrong and needs a separate naming pass.
* `0x003807D8` (`maybe_Ui_MessageWindow_SelectRowStyle`) has no readable C at all; its names are
  guesses from the variable table (glyph-width loop) and are all `maybe_`.
* `0x0039A024` (`Model_AttachEquipmentMeshes`) has ~70 locals, most of them fields of one config
  struct; only the ~20 meaningful ones got real names, the rest are `maybe_configByteNN` /
  `maybe_configFloatNN`.
