# V_029 - local variable naming batch

## What I did

Worked through all 150 functions of `orchestration/types/batches/V_029.json` with
`python3 tools/batchview.py V_029 next` / `--add`, one chunk at a time, and wrote the maps to
`orchestration/types/out/V_029.json`.

- 149 functions answered (one function was recorded as "reviewed, nothing clear" and is not in the
  output file).
- 28 `argN`/`extra` parameters renamed.
- 1309 local declaration tokens renamed.
- 6 answered functions had nothing to rename (only an already-named `self` parameter, or only
  variables the rule pass had already named); they are present with empty `params`/`locals` and an
  `evidence` note saying why.
- `python3 tools/batchview.py V_029 --check` reports `149 answers, 0 problem(s)`.
- The output file parses as JSON (checked with `json.load`).

## How names were chosen

Names come from the merged field/global names in the readable C, the callee names, the string and
constant evidence in the batch table, and the struct offsets. Where a token is reused for several
unrelated quantities in one function (Ghidra register reuse), it got a deliberately vague name
(`scratchValue`, `scratchIndex`, `chosenPtr`, `cellBitsA`) rather than a precise wrong one.

## What I skipped and why

- **Unused or forward-only `argN` parameters** were left unnamed: `arg2`/`arg3` in the Casino
  getters (`0x006011BC`, `0x00601C48`, `0x00601C88`), `arg2`/`arg3`/`arg4` in
  `0x00601320`/`0x0060160C`, `arg4` in `0x005A71E8`, `arg1` in the four item comparators
  (`0x006112EC`, `0x006113D0`, `0x00611460`, `0x00611538`), `arg4`/`arg5` in
  `0x005C8500`, `arg4`/`arg5`/`arg6` in `0x005CABE4`, `arg2`/`arg5` in `0x005CFE40`, and `arg6`
  in `0x005CEC18`. In every case the parameter is only forwarded to another call, so no noun is
  justified.
- **`0x005CEC18` (`maybe_Font_GlyphQuad_InitParams`)** has no readable C in the batch, so only the
  variable table was available; two of its three locals are `maybe_`-prefixed.
- **`0x005AF9F8` (`maybe_Script_JumpTableDispatch`)** has an unrecoverable jump table (Ghidra
  "bad instruction data"), so its locals are named after the descriptor/guard structure only.
- **`0x005C8654`, `0x005C86A0`, `0x005D0640`, `0x005E7828`** have only an already-named `self`
  parameter and no locals; nothing to rename.
- **`0x004D98AC`, `0x0050EE18`** (earlier chunks) had no locals at all.

## Notes for the merge

- `gameWork` is frequently already taken by the rule pass; where `Game_GetWork` needed a name I used
  `workPtr` and said so in `evidence`. Same pattern for `dataManagerPtr`, `entryTablePtr`.
- Function-level `confidence` is 0.5-0.6 throughout. Individual names that are genuinely vague carry
  their own `maybe_` prefix even when the function confidence is >= 0.5.
