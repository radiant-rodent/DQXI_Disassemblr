# V_030 - local variable naming

Batch: `orchestration/types/batches/V_030.json` (150 functions).
Output: `orchestration/types/out/V_030.json`.

## Result

- 150 of 150 functions answered; `batchview.py V_030 --check` reports `150 answers, 0 problem(s)`.
- 879 names total: 80 parameters and 799 locals.
- 1 name carries the `maybe_` prefix (confidence below 0.5).
- 10 functions were reviewed with nothing to add: their only locals were already named by the
  rule pass (loop counters, values from named getters, fields), so they were recorded as
  reviewed and left untouched.

## How the names were derived

- Every function was read from the current merged readable C printed by `batchview.py`, so
  merged field and global names (`unit->targetUnit`, `g_itemCategoryTextColorTable`,
  `g_saveMemberPresenceOffsets`, `g_uiResultRowRenderConfig`, ...) were used directly as the
  basis for local names.
- Recurring vocabulary kept consistent across the batch: `gameWork`/`workOut`/`workArg`/
  `extraArg` for `Game_GetWork` plumbing, `dataManager`/`dataManagerOut` for
  `Game_GetDataManager`, `itemRecordBuf`/`itemRecord` for `Item_LookupRecord` buffer+pointer
  pairs, `member` for `func_0035EB98` results, `storageBase` for `work+0x24A98`,
  `entryPtr`/`entryCount`/`endEntry`/`srcEntry`/`dstEntry` for the sort and container
  families, `slotIndex`/`rowIndex`/`cursorIndex`/`matchCount` for index and count locals.

## What was skipped and why

- Field tokens that are not standalone locals (`fc`, `f10`, `f34`, `f20`, `f60`, `f768`,
  `f12f4`, `f3648`, `f27218`, `f11`, `f8668`..`f86a0`) were deliberately left unnamed.
- Parameters that are never read in the body were left as `argN`.
- Locals whose single token is reused for several unrelated purposes (for example `i` in
  `maybe_Item_ValidateAndCompactStorage`, used as loop counter, slot entry and item bound)
  were left unnamed rather than given a misleading name; the reason is recorded in that
  record's `evidence`.
- Where the batch record's tokens did not match the merged readable signature (for example
  `maybe_Item_ComputePriceWithMultiplier`), the parameters were left unnamed and the mismatch
  noted in `evidence`.
- No readable C file was modified; `M3_vars_merge` applies the maps.
