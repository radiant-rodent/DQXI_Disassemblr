# V_031 - local variable naming

Batch: `orchestration/types/batches/V_031.json`, 113 functions.
Output: `orchestration/types/out/V_031.json` (113 records, valid JSON, `--check` reports 0 problems).

## What was done

- Worked through all 113 functions in 17 `batchview.py V_031 next` chunks; every function was viewed once.
- 898 names written: 20 `argN` parameters and 878 local declaration tokens.
- 67 of those names carry the `maybe_` prefix (confidence below 0.5); 8 records have a function-level
  confidence below 0.5.
- Names were derived from the merged field/global names in the readable C, the callee names
  (`Item_LookupRecord`, `Data_GetFieldById`, `Item_CompareEntryKey32`, `Item_CompareFieldKey16`,
  `std_push_heap_*`, `Actor_ReleaseAttachedObjects`, `Game_GetWork`, ...), the constants in the
  variable table and the loop/pointer structure of the body.
- Recurring conventions: `gameGetWork` -> `gameWork`/`workPointer`, `Game_GetWork` out-params ->
  `workBase`, `uStack_*`/`auStack_*` work buffers -> `workBuffer`, `result` -> the semantic return
  (`selectableCount`, `isVisible`, `rowIndex`, `slotCount`, `inventoryCount`, `didPop`, ...),
  `paneId` -> `memberIndex`, `bVar1` -> `rowKind`, `uVar2` -> `itemId`, `component` -> `actor`/`object`/
  `pane` depending on the callee. Sort family: `byteLength`, `pivotValue`/`pivotRecord`/`pivotKey`,
  `leftScanPtr`/`rightScanPtr`, `partitionPtr`, `heapIndex`/`holeIndex`/`leftChildIndex`/`childIndex`/
  `heapSize`/`heapSizeInit`, `siftValue`, `swapLowHalf`/`swapHighByte`, `compareCtx`/`compareCtx2..4`,
  `lookupA`..`lookupI` for the `Item_LookupRecord` buffers, `firstCopy`/`lastCopy`/`depthCopy`/
  `contextCopy` for the stack copies of the parameters.

  `0x0066AD94 maybe_Work_FindLastNamedRow`, `0x0066B19C maybe_Work_CountNamedRows`,
  `0x0066B1FC maybe_Work_CountNamedRowsB`, `0x0066B264 maybe_Work_AreAllNamedRowsUsed`,
  `0x0066D398 maybe_Actor_DtorThunk`, `0x0066DAD0 maybe_Actor_ReleaseComponent`,
  `0x0066DD10 maybe_Actor_HandleFlagEvent`, `0x007088A8 maybe_Text_NormalizeKanaName`
  (thin thunks / single-call wrappers whose locals are pure register shuffles).
- Left unnamed inside otherwise named functions: opaque struct copies, pure float/bit-twiddle
  temporaries, unused `argN`, `unaff_rN` registers, `joined_*`/`LAB_*` goto tokens, and locals whose
  storage is reused for two unrelated roles in the same body (those that were named anyway got
  `maybe_` and a note in `evidence`).
- `0x0071E598 std_insertion_sort_u16_item` is decompiled from damaged input (bad instruction data,
  overlapping instructions at 0x71efc4); only the clearly readable roles were named there.
- No readable C, header or other batch file was touched; the full test run was skipped as instructed
  and replaced by a JSON syntax check of the output.
