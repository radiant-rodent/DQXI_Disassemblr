# V_033 - local variable naming

Batch: `orchestration/types/batches/V_033.json` (150 functions).
Output: `orchestration/types/out/V_033.json`.

## What was done

Worked through the batch with `python3 tools/batchview.py V_033 next` in 22 chunks and
submitted each chunk with `--add`. Final state: `--check` reports **149 answers, 0 problems**;
the JSON parses (`json.load`) and holds 149 records.

- 131 functions received names: **16 parameters** (`argN` -> noun) and **625 locals**.
- 18 functions were reviewed and left unnamed (recorded as "reviewed, nothing clear").
- 17 of the 641 names carry the `maybe_` prefix (confidence < 0.5).
- Confidence distribution: 0.5 x8, 0.55 x20, 0.6 x39, 0.65 x54, 0.7 x7, 0.75 x3.

Names were derived from the merged field/global names in the current readable C, the callee
names, vtable slots, string and constant arguments. Recurring conventions: `poolHead` =
`g_movieCmdPoolHead`, `trackSlot` = `f_c + track*0x70`, `soundPoolState` =
`&g_soundVoicePoolState`, `criticalSection` = `&g_movieTrackCriticalSection`; IPC senders use
`ipcBuffer` / `errorCode` / `serviceHandlePtr` / `replyWord1`; the icon cache uses
`serviceState` / `serviceMonitor` / `openMonitor` / `atlasMonitor` / `atlasStateFlags`;
allocators use `poolRoot` / `poolMonitor` / `createdObject` / `createdHandle`.

## What was skipped and why

- 18 functions: nothing justifiable. They are trivial wrappers (AddRef/ReleaseRef, ctors/dtors,
  destroy helpers, CECD read/write/delete/open/close dispatch stubs) whose only locals are the
  already-named `self`/single parameter or a bare return value, so no name could be justified
  from the body.
- Individual locals were left unnamed where one register/token is reused for several unrelated
  roles in the same function (e.g. `piVar4`/`piVar5` in `maybe_Regex_MatchSequence`, `result` in
  `maybe_Regex_MatchNode`); the reason is stated in that record's `evidence`.
