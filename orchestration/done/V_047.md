# V_047 - local-variable naming batch (done)

## What I did

Worked through all 150 functions of `orchestration/types/batches/V_047.json` with
`python tools/batchview.py V_047 next`, answering each printed chunk via
`--add -` in one call. The batch tool merged everything into
`orchestration/types/out/V_047.json`.

- Batch tool result: `150 answers, 0 problem(s)` (`--check`).
- Output JSON re-parsed as UTF-8: 150 records, 427 local renames, 0 parameter
  renames.

## Coverage

- 150/150 functions reviewed.
- 427 locals renamed (about 2.8 per function on average).
- 0 `argN`/`self` parameters renamed. Every batch signature printed the
  remaining parameters as unused (`r1/w0` - zero writes) or already named
  (`self`, `window`, `frame`, `eventId`, `handle`, `rank`, ...), so there was
  nothing to justify changing. `self` was kept per the rules.

## What I skipped and why

- Rule-pass named variables (`piVarN->gameWork`, `iVar->i`, `puVarN->player`,
  etc.) were left alone as instructed.
- Variables reused for several unrelated meanings inside one function (a very
  common pattern here: one register holding a `GameWork*`, then an allocation
  result, then a state id) were left unnamed rather than given a wrong noun.
- Pure constants, frame-flag bit tests (`bVarN = SBORROW4(...)`), float
  temporaries that never leave an arithmetic chain, `unaff_*`/`in_*` register
  remnants and stack scratch buffers that only feed `Os_GetGameWork` /
  `Sound_GetPlayer` twice in the same function (duplicate name would be
  rejected) were skipped.
- 20 functions were recorded as "reviewed, nothing clear" (single `self`
  parameter, or only one mixed-use temporary). Those records have empty
  `locals` and confidence 0.4.
- Where the batch's variable table listed a token that no longer appears in the
  current readable C (the merge renamed some of them, e.g.
  `containerValidateHandle` vs `uVar3`, `uiObjectDtorBody` vs `iVar1`), I used
  the token that batchview accepts, i.e. the one in the batch record.

## Confidence policy

Names carry per-function confidence 0.4-0.8. Names whose own confidence was
below 0.5 were prefixed `maybe_`: `maybe_allocOut`, `maybe_animRefBuf`,
`maybe_cursorXValue`, `maybe_descValue`, `maybe_fieldObject`,
`maybe_memberIds`, `maybe_modelVariant`, `maybe_stringField`,
`maybe_touchPhaseResult` (9 names). Recurring, well
supported names reused across the batch: `gameWorkOut`, `soundWorkOut`,
`soundPlayer`, `nextState`, `setStateFn`, `childCount`, `stateController`,
`callbackTable`, `spanCursor`, `triggerRadius`, `radiusMode`.
