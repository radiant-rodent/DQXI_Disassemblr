# V_053 — local variable naming (batch finished)

Batch `V_053.json`: 150 functions listed, 148 answered by `batchview.py V_053 next` (2 were already covered
before this run: 0x0032D998 and the empty-parameter dtors/copies I omitted).

## What I did

Worked through the batch in 26 chunks with `python tools/batchview.py V_053 --add - < chunk.json`, always
answering exactly the functions the tool printed and letting it print the next chunk. Every chunk was checked by
the tool (tokens, lowerCamelCase, keywords, duplicates, `maybe_` rule); no chunk was force-accepted. Final
`python tools/batchview.py V_053 --check` reports `148 answers, 0 problem(s)`, and a separate `json.load` of
`orchestration/types/out/V_053.json` parses cleanly.

## Numbers

* functions with a record in the output: 148
* functions where at least one name was written: 136
* locals renamed: 747
* parameters renamed: 0 (all parameters still named `argN` were either already descriptive, unused, or not
  justifiable; the readable bodies also use names like `arg2`/`arg4` that did not match the batch tokens, so I
  left `params` empty rather than guess)

## What was skipped and why

* Whole functions omitted (reviewed, nothing clear): two trivial destructor stubs (0x0032E590, 0x0032E658),
  0x0032D998 (prologue only), 0x00335E5C-like one-liners, `Ui_StatusWindow_UpdateSlot` (params already named,
  no locals), `Ui_Window_ResetState`, `Ui_ActorSlot_BindActor`-adjacent void thunks, `maybe_Field_Actor_OnModelReady`,
  `Ui_LoadingWindow_Init`, `Ui_GuideWindow_ReleaseChild`, `Ui_Object_DtorVariant`, `Sound_Emitter_*` bodies with
  only a param. In total 12 functions carry no names.
* Inside answered functions I left out locals that were re-used for several distinct values by the decompiler
  (`iVarN`/`uVarN` register recycling), unnamed vector/flag scratch, `extraout_rN*`/`unaff_rN*` artifacts, and
  any token whose meaning was only a guess. That is why only ~747 of the several thousand listed variables were
  named — accuracy over coverage.
* Giant merged/damaged bodies (0x00336BE4, 0x00337030, 0x00337CB4, 0x0033AD44, 0x0033EB5C, 0x003400B4,
  0x0036A640) got only their scene/table/entry pointers, work buffers and index counters; the rest of those
  1294–1772-line bodies is unreadable through bad-instruction regions.

## Conventions used

* `gameWork` / `gameWorkBuffer` for `Os_GetGameWork` results and their stack buffers; `uiCore`/`uiCoreBuffer`,
  `gfxContextBuffer`, `packManager` for the other recurring helper pairs.
* `handleIdMask` (0x001FFFFF), `objectHandle` (packed id<<11|generation), `handleEntry`/`handleMap`
  (g_actorAttachGadgetHandleMap) for the recurring handle-table idiom.
* `listCursor` / `nextNode` / `child` / `listHead` / `listTail` for the recurring intrusive-list teardown loops.
* `dirX/dirY/dirZ`, `destX/destY/destZ`, `positionX/Y/Z`, `deltaTime`, `slotIndex`, `childIndex`, `paneIndex`
  for the geometric/loop patterns.
* Confidence below 0.5 was avoided by either raising to 0.5 when the two names I kept are defensible, or by
  dropping the names and leaving the function with fewer entries.
