  `animRecord`, `worldModelTable`, `spriteSheetId`, `placementId`, `messageId`, `playerHandle`, etc.
- Every name is lowerCamelCase and carries the reason (caller/callee, string constant, field offset) in `evidence`.

## Skipped / left unnamed and why
- Functions with no locals at all (pure `Ui_Object_DtorBase` + `func_0010F6CC` wrappers, `InitPanes` bodies that only
  call helpers, `maybe_Ui_DiveWarningWindow_InitPanes`, `maybe_Ui_DiveForm_BindControl`) were recorded as
  "reviewed, nothing clear". A few others (`maybe_Script_Handler_ResetState*`, `maybe_Camera_PickLayerAtPointEx`)
  were omitted for the same reason: 0x003B17C0 had no readable C and the ResetState pair only touched fields.
- Very damaged bodies were named only partially: `maybe_Ui_TsuyosaWindow_UpdateRowText` (overlapping instructions,
  `unaff_` registers) got two `maybe_` names; `maybe_Monster_FieldBehaviour_UpdatePhysics` and the
  `Field_ActorActionSeq_Update*` runners only got the buffers/state words that were provable.
- Tokens that did not exist in the readable C (hint-only names such as `f28`, `f164`, `fa4`, `f58`, `unaff_r*`,
  `extraout_r1`) were never renamed.
- Names with confidence < 0.5 carry the `maybe_` prefix as required. Multi-use decompiler temporaries (reassigned
  between unrelated roles, e.g. `iVar2` holding both a vtable and a node pointer) were left unrenamed on purpose.
