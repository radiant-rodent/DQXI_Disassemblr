# V_057 - local variable naming batch

Batch file: `orchestration/types/batches/V_057.json` (150 functions, Battle_ActionSequence /
Battle_Ui / FieldParty_Ui / HP-gauge / target-marker / dungeon-HUD / event-packet families).
Output: `orchestration/types/out/V_057.json`, 150 answers, `batchview --check` reports 0 problems.

## What was done

* Worked the batch only through `python3 tools/batchview.py V_057 next` / `--add`, one chunk at a
  time, using the current merged readable C and the merged field/global names.
* 123 functions received names: 687 local variables and 16 `argN` parameters renamed
  (e.g. `iVar2` -> `pendingActionCount`, `local_74` -> `mpCost`, `uStack_10` -> `gameWorkBuf`,
  `uVar7` -> `effectHandle`, `arg4` -> `gameWorkIn`).
* Naming was driven by the merged evidence only: named callees (e.g. `Battle_ActionSequence_GetPendingActionCount`,
  `Text_BuildRowForTarget`, `Effect_FindOrCreateInstance`, `Sound_PlaySeById`, `Ui_Row_AttachPairedSlots`),
  merged struct fields (`self->spellRecord`, `f_72C`, `balloonSlot11..13`), string/constant literals
  (0x342 free-MP popup, 0x4B popup, 0x158/0x15D SEs, `cbhm_tcs_mant`/`ccg392_v0xx`) and the
  vtable-slot roles already established by the class passes.
* 27 functions were reviewed with nothing safe to add (recorded as empty answers). Reasons:
  * only a `self`/`gimmick` parameter and nothing else - plain deleting destructors
    (`Ui_IconRowWindow_Dtor`, `Ui_GoldCounterWindow_Dtor`, `Ui_*Dtor`, ...), one-statement
    component-init wrappers (`Field_Gimmick_InitComponentA..D`), pane init/hide/toggle stubs;
  * truncated or `halt_baddata` bodies where the only names would have been guesses on dead
    registers (`Battle_ActionSequence_UpdateActorFlags`, `Battle_ActionSequence_NotifyUiActors`
    with no readable C);
  * functions whose whole body is a single forwarded call with no local at all
    (`maybe_Ui_Widget_AdaptLayout`, `maybe_Ui_Widget_HideSubPane`).
* Registers and decompiler artefacts (`unaff_rN`, `in_crN`, `in_fpscr`, `extraout_r1`, packed stack
  words) were never renamed. Reused temporaries that hold two different things in different
  branches (e.g. `iVar4`/`iVar2` in the battle dispatchers) were deliberately left anonymous.
* All per-name confidence values are >= 0.5, so no `maybe_` prefixes were needed; the per-function
  confidence in the JSON is 0.5-0.65. Everything vaguer than that was omitted instead of guessed.
* A few tokens present in the batch table do not exist in the current readable text
  (`uVar1`/`puVar4` variants in `RefreshAllMemberRows`, the `textMeasureTextRun` local in
  `ProcessActorCommand`); those were skipped rather than answered, because renaming a token that is
  not in the body would be meaningless.
* JSON validity of the batch output was verified with `batchview --check` (0 problems) and by
  re-parsing the file with Python; no build or test run was performed (not applicable to a naming
  batch).

## Notes for the merge

* Names are lowerCamelCase nouns and unique inside each function.
* `gameWork` / `layoutElement` / `player` / `dataManager` names created by the rule pass were left
  untouched; where a second buffer needed a distinct name, `gameWorkBuf`/`gameWorkIn`/
  `gameWorkStorage` were used instead of reusing `gameWork`.
