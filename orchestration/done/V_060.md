## Decisions worth recording

- Where a readable token was already a real name (rule pass output, `self`, `arg2`/`b`/`ctx` that
  never appear in the body), I left it alone; only `argN`/declaration tokens with body evidence were
  renamed.
- 2D field-object scene helpers: the `Gfx_GetSceneSpriteContext(&slot)` output slot is always named
  `sceneContext` / `sceneContextPtr`; `Os_GetGameWork` slots are `gameWorkBuffer` (A/B/C when a
  function uses several).
- Poker family (`Casino_Poker_*`): standardised on `savedCard` / `savedLowByte` / `savedHighByte`
  for the two-byte hand-slot swap, `deckCardPtr` for `func_00416638` results, `randomValue` /
  `randomSlot` for the `func_0051B1FC` + `Math_RandMod4` roll and `shuffleIndex` / `deckCursor` for
  the five-pass shuffle.
- `_4`-style ids of the quaternion/vector result pairs were named by their role (e.g.
  `transformQuatX/Y/Z/W`, `effectQuatX/Y/Z/W`, `basisQuatX/Y/Z/W`) rather than by byte order, which
  the decompiler does not make trustworthy.
- Confidence: most names 0.5-0.65; nothing below 0.5 was submitted without the `maybe_` prefix, and
  the tool accepted the set unchanged.
