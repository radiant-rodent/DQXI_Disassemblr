# V_062

Batch of 150 functions (`orchestration/types/batches/V_062.json`), all answered through
`tools/batchview.py V_062 --add`; `--check` reports 150 answers, 0 problems.

## What was done

- Named 764 param/local tokens across 129 functions (JSON `params`/`locals` maps).
- 195 of those names carry the `maybe_` prefix because their evidence is structural only
  (confidence < 0.5): fastcall/out-parameter stack buffers (`auStack_*`, `maybe_gameWorkBuf`),
  scratch temps whose register is reused for several different values, and constant
  initialisers of sprite/effect parameter blocks.
- Recurring, well-supported names were reused where the same code shape appears:
  - `gameWork` for the `Os_GetGameWork` result and `maybe_gameWorkBuf`/`maybe_workBuf` for its
    out buffer;
  - `effectHandle` for `self[0xb2]` / `variantModeOrFlag2EC` / `variantMotionId0` when checked
    against `g_fieldBattleActionSequenceMap` and passed to `Effect_ReleaseHandle`;
  - `handleEntry`/`symbolHandle`/`layoutHandle` for the `g_fieldEffect2DAttachActorHandleMap`
    key and its 8-byte entry;
  - `modelTable`/`modelIndex` for the `func_0066A7B8(gameWork+0xb4)` table and the
    `func_0062C388` key, `animInstance` for the `Mem_AllocAligned_2(0x178)` block handed to
    `Anim_Instance_CtorSprite`;
  - `nameHandleKind`/`nameHandleValue` for the `Script_MakeNameHandleByIndex` /
    `Field_SceneObject_RollWeightedState` out struct (tag byte + value words);
  - `nextNode`/`prevNode`/`nodeBase` for the intrusive-list teardown used by every
    `*_Dtor` / `*_DeletingDtor` pair;
  - `cellX`/`cellY` for `cellGridX`/`cellGridY`, `texCoordRect`/`effectPosX/Y/Z` etc. only where
    the callee (e.g. `Ui_PicturePane_SetTexCoords`, `Effect_CreateScaledInstance`) makes the role
    explicit.
