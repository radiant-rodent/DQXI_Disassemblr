## How the work was done

Each chunk was answered from the `batchview.py ... next` output only: readable C, the variable
table (reads/writes/calls/fields/constants) and the merged field/global names that already appear
in the body. Decisions per function are recorded in each record's `evidence`.

Bulk of the batch was SDK-side machinery repeated many times, which made naming cheap:

- IPC helpers (`Os_IpcSendCommand*`, `Os_IpcQueryCommand0C`, `Os_RefreshCachedHandle`): thread-local
  buffer from `coproc_movefrom User_R_Thread_and_Process_ID` named `ipcCommandBuffer`, return word
  `replyWord`.
- Result classifiers (`Os_SvcCallChecked`, `Os_SvcCallCheckedAlt`, `Os_IpcSendCommand06AndClearPending`,
  `Fs_ClassifyResult*`): `resultClass` / `expectedResult` / `resultCode`.
- The lazy sound-singleton block (0x1EB0-byte manager, `Anim_Sequence_CtorBase`,
  `g_animSequenceVtable`) that appears in well over 30 functions: consistently `soundPlayerPtr`,
  `allocSize`, `allocUnit`/`allocOffset`, `blockAddr`, `soundWork`.
- The UI/Object and Container destructor family (five byte-identical `g_osSequenceTaskBaseVtable`
  copies, plus the `+0x12/+0x13`, `+0x48/+0x4C` variants): `eraseKey`, `nextNode`, `prevNode`.
- Save/load slot code (`Save_*`), where `Ui_UiManager_GetInstance` results became `uiManager` /
  `uiManagerObj` and the per-slot state word `slotState` / `slotIndex`.
- The printf engine (`std_Format_*`): `remainingCount`, `padChar`, `minDigits`, `extraZeros`,
  `digitIndex`.
