## Naming approach

- Used the merged readable C plus the merged struct field / global names as the primary evidence:
  locals that only carry `x->field` or a named vtable/ctor were named after that role
  (`attachSlot`, `titlePane`, `riderObject`, `fillPane`, `spLabel`, ...).
- Recurring constructor pattern (`from <base ctor>` + vtable store + `Ui_Object_InitMemberPair` +
  `std_ConstructArray`) named consistently: `childCtor`, `<window>`, `memberPairSeq`, `listHead`,
  `nodeCursor`, `drawCursor`.
- `Game_GetDataManager(&local)` spill slots named `ctxStorage` (they only forward a register
  argument); pure register leftovers (`extraout_r1`, `in_cr*`, `in_fpscr`, `unaff_r5`) and
  `in_stack_00000000` left unnamed.
- Loop counters: `i`/`j` kept where they are plain indices, otherwise the counted thing
  (`entryIndex`, `slotIndex`, `memberIndex`, `rowIndex`, `symbolIndex`, `reelIndex`).
