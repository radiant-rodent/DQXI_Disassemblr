# V_097 - local variable naming

Batch: `orchestration/types/batches/V_097.json` (150 functions).
Output: `orchestration/types/out/V_097.json` - 148 records, 616 renamed tokens
(params + locals), `batchview.py V_097 --check` reports 0 problems.

## What I did
- Worked through every chunk printed by `batchview.py V_097 next` (12 add calls) and
  renamed only tokens present in the batch table, never the rule-pass names.
- Names come from renamed struct fields / globals in the merged headers, the callee
  names, string/constant evidence and the doc comment; each record carries its
  confidence and an evidence string.
- Recurring patterns got consistent names across the batch: `extension` /
  `extensionWord` for the Sound_SeqParam vtable-slot merges, `found` / `fieldValue`
  for the `func_00661534` tagged-field getters, `dataManager` / `managerArg` for the
  `Game_GetDataManager` wrappers, `descriptorVtable` / `descriptorCallback` /
  `descriptorOwner` for the Field2D overlay task descriptors, and
  `leftChipId` / `rightChipId`, `meshPartRow` / `stripStartIndex` / `stripEntry`
  for the mesh-chunk draw paths.

## Skipped / left unnamed
- `0x0065C468` Gfx_BoneMatrix_AppendCached and `0x00663474` std_CopyBlock64: only
  already-descriptive parameters, no locals to justify.
- `0x00670A64` maybe_Field2D_Map_SelectLayerRange: no readable C available; left
  untouched rather than guess from the variable table alone.
- Within answered functions I deliberately left the Ghidra shadow-register
  artifacts (`in_fpscr`, `in_s0`, `in_s1`, `in_r12`, `extraout_r1*`, `unaff_r*`),
  interleaved FPU condition words (`uVar1`/`bVar2` bit-splices in the float
  helpers) and locals whose role changes mid-function (e.g. `iVar6` in
  `Gfx_MaterialState_WriteConstants`, the `local_c0..local_ac` union scratch in
  `Math_BuildCombinedBounds`) unnamed, since any single name would be wrong.
- Names I rated below 0.5 were dropped rather than written with `maybe_`.
