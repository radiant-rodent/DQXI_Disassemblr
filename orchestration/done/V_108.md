## What was named

Most renames came from the merged field names in the readable C, not from guessing:

- Actor/action position triples: `animInstance->f_9c/f_a0/f_a4` became `startPosX/Y/Z`,
  `animPosZ`, `orientationX/Y/Z`, `forwardX/Y/Z` where the same three-word out-parameter
  pattern appeared.
- Intrusive circular-list destructors (`Field_NpcManager_DeletingDtor`,
  `Ui_PresentList_Dtor`, `Battle_CommandQueue_Clear`, `Ui_PresentList_DeletingDtor`): the
  repeated `while (*p != sentinel) { next = p[1]; elem = *p; ... }` shape gave
  `currentNode` / `nextNode` / `listElement` / `headNode` / `tailNode`.
- ARM member-function-pointer pairs (`Ui_Delegate_*`, `Ui_EventListener_AttachSlot*`,
  `Ui_Callback_DispatchEvent`): `functionPtr` / `thisAdjust` / `callbackFn` /
  `callbackContext`, justified by the `(adj & 1)` + `adj >> 1` vtable resolution.
- Allocator wrappers (`func_0028E630`, `func_0028EE8C`, `func_0028EF18`, `func_004712D0`):
  the returned object plus the two stack words handed in became `spriteDescriptor` /
  `commandQueue` / `actionQueue` and `flagsValue` / `descriptorValue` / `capacityValue`.
- Virtual-dispatch predicates (`(*self->subActionState->f_14)(...)`): `predicateResult`,
  and the object passed as `this` became `subAction` / `handlerObject`.
- Window-open helpers (`Battle_Command_Open*TargetWindow`): the `+0x4C` return stored into
  `activeSubWindow` became `targetWindow`.

## What was skipped and why

  `event_type` / `dt` / `show_flag` / `visible` / `input` / `ctx` / `parent_mat` /
  `anim_frame` / `size` / `material_vtable` / `vtable_ptr` / `viewport*`), so there was
  nothing left to rename. These are recorded as reviewed with nothing to add.
- `Battle_ActorAnim_StepTimeline` (0x00389746): the decompilation is coprocessor
  intrinsics (`coprocessor_movefromRt`, `coprocessor_store`) over unaffiliated registers
  with no recoverable data flow. Nothing justified.
- `Math_CalcBufferOffset` (0x003A6994): body is `return in_r12 + unaff_r5`, pure register
  artifacts. Nothing justified.
- `Ui_Pane_SetVisibilityFlag`, `Ui_Pane_UpdateTransform`, `Gfx_Sprite_AllocInstance`,
  `Gfx_Sprite_Ctor`, `Gfx_Sprite_DeletingDtorThunk`, `Gfx_Sprite_FreeInstance`,
  `Ui_Callback_DeletingDtor`, `Ui_PresentMessage_Manager_Reset`,
  `Ui_PresentMessage_Manager_FreeBuffer`, `Battle_Command_UpdateSelection`: bodies are
  `halt_baddata()` only, no variables to name.
- `Ui_Panel_UpdateRowData` (0x00378FF0): named the clear parts only. `iVar6` was left
  alone because it is reused as a row offset, a UI-context pointer and a

- `Ui_Dialog_ProcessInput`, `Ui_Dialog_Render`, `Ui_Text_ProcessWideString`,
