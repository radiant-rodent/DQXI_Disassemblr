Output: `orchestration/types/out/V_109.json` - 145 records, 156 names, `--check` reports 0 problems.

## What was done

Worked through the batch in 16 `batchview.py next` chunks. 58 functions received names
(156 renames total: 5 `argN` parameters plus 151 locals); the remaining 87 were recorded as
"reviewed, nothing clear".

Dominant patterns that produced names:

- `Ui_Element_ResolveResourceRef*` family (8 copies, 0x003AB824 / 0x003BEDC4 / 0x003D27CC /
  0x003D2810 / 0x003E07B0 / 0x003E0840 / 0x003E3998 / 0x003E39DC): the single local is the
  serialized word at `stream+4` resolved through the reader vtable slot `+0x24` and written
  back, so it became `resourceRef` (confidence 0.6).
- `Ui_MessageCmd_*` / `Ui_MessageWindow_*` state handlers: `self->f_d3c` compared against
  2/3/4/5 became `widgetState`, the animController slot `+0x14` return became
  `animQueryResult`, the `self->f_d60` bit mask word became `textFlags`.
- 0x18-byte step drivers (`Ui_AnimController_Advance`, `maybe_Ui_AnimQueue_Update`,
  `maybe_Ui_MessageCmd_UpdateQueue`, `maybe_Ui_MessageWindow_UpdateAnim`): the 1/30 s constant
  0x3D088889 became `fixedFrameDelta`, the table entry `table + (entry->f_38>>1)` became
  `dispatchTableEntry`, the entry callback became `stepCallback`.
- Handle-list walks (`maybe_Container_HandleList_ReleaseByType` / `_FindByType`): the
  0x001FFFFF sentinel became `invalidHandle`, `&g_actorAttachGadgetHandleMap` became
  `handleMapBase`, `&g_actorBaseClass` became `actorBaseClass`, the walked class chain
  `classCursor`, the resolved object `object`.
- Actor-action snapshot helpers: the pointer whose `+0x228..+0x240` / `+0x260..+0x280` words are
  copied into the action transform block became `targetActor`; the `func_0029E488` byte stored
  into `targetActor->f_b8->f_128` became `stateByte`.

## What was skipped and why

- 87 functions omitted entirely. The large majority are `halt_baddata` fragments
  (`maybe_Ui_Row_FillValueTextA..P`, `maybe_Ui_QuestList_*` continuations,
  `maybe_Ui_DiveForm_*`, `maybe_Battle_Ui_ActionSequence_*`) whose only variable is `self`.
- ~45 scalar deleting destructors (`*_DtorDelete*`, `*_DeletingDtor*`) with only `self` and
  `vtable` parameters - both already meaningful, nothing to rename.
- Damaged bodies whose locals are uninitialised registers or coprocessor pseudo-variables
  (`unaff_r7`, `unaff_r9`, `in_cr8`, `in_cr9`, `in_cr10`, `in_cr13`, `auStack_9c`,
  `CONCAT44`): 0x003C36E8, 0x003C3704, 0x003C48FC, 0x003D9DF0, 0x003E28B2 (partly named).
- `std_LoadU64` (0x003BDB1C): `arg1`/`arg2` are ignored by the body, `p` is already named.
- `maybe_Ui_QuestList_BuildSortedIds` (0x003B2674): `count` is really an object pointer used
  only as `count->f_28` in a packed argument; no defensible noun.
- `maybe_Ui_TwoTextWindow_DtorDelete`: `arg2` is unused, left alone.
- `maybe_Ui_MessageWindow_DispatchPageCallback`: `iVar3` and `bVar5` were left unnamed - the
  register is reused as `index*3`, `self+0x210` and `self+500`, so no single noun fits.
