- 74 functions got no names. The large majority are deleting destructors whose whole body is
  `baseDtor(); operator delete();` with only the `self` parameter, which the rules say to keep.
- Ghidra-damaged bodies (`halt_baddata`, `software_bkpt`, `unaff_rN`, `in_ZR`/`in_CY` flag
  spillage, undeclared `argN`): `Battle_ActionAnim_PreMove1..4_*`, `maybe_Battle_ActionAnim_*Body`,
  `maybe_Battle_CommandListRow_Update*`, `maybe_Ui_SpiritCapture_CreateLayoutParts`,
  `Ui_ListView_UpdateItemCountAndVisibility`, `maybe_Ui_ListView_MoveSelectedItem`,
  `Ui_NumberPlate_UpdateDigits`, `Ui_PlateWindow_UpdateText`. Nothing in them is justifiable.
- `Camera_Shake_Update`: only `pfVar1`, `uVar8` and `cONCAT44` were named; the `fVarN` locals are
  each reused for several unrelated quantities, so they were left alone.
- `maybe_Ui_Gauge_StartValueAnimation`: the pure scratch locals (`iVar4`, `uVar5`, `fVar8`,
  `fVar9`, `in_fpscr`, `uVar3`, `in_s0`) were left unnamed for the same reason.
- `Ui_TalkWindow_Close` `arg2`, `Ui_PlaySelectLoopForRecord` `arg1`: unused in the recovered body,
  so no name could be justified.
