# V_112 - local variable naming

Batch: `orchestration/types/batches/V_112.json` (150 functions, 149 processed by the tool).
Output: `orchestration/types/out/V_112.json`.

## Result

- 149 records written, `--check` reports `149 answers, 0 problem(s)`.
- 248 names total: 8 `argN`/`self` parameters and 240 local declarations.
- 81 functions received at least one name; 68 were reviewed with nothing to add.

## What was named

- DragonJump action family (0x475B2C-0x476DE0): jump variant byte, state-request results,
  per-frame X/Y/Z step and delta floats, basis-vector components, tick counters.
- Battle UI unit-model widgets (0x47E074-0x47E770): the `vt[0x14]` node pointer, remembered
  base position, tween target, depth/visible bytes.
- Arc-list window (0x49BC24-0x49EA68): anchor triples from `func_005753BC`, the 0x34A marker id,
  child slot pointers, found-marker flags.
- Handle-map resolvers (0x4A1E04, 0x4AF35C, 0x4AF41C/0x4AF480/0x4AF4D4): tag token vs walked
  class token, bucket entry, resolved target object, packed handle fields.
- Constructors (0x471D58, 0x473834, 0x47E898, 0x4B3374, 0x4AEBC0, 0x4AF524): allocated object,
  the `local_10`/`local_c` alloc-descriptor pair, secondary vtable, float constant temporaries.
- Small accessors and destructors: vtable stores, `func_00669DD4` animation-finished tests,
  `func_00630DC8` unit counts, `func_0064C368` digit values.

## What was skipped and why

- 68 functions had nothing justifiable: 40 are deleting destructors whose only variable is the
  already-named `self`; 14 are `halt_baddata()` stubs or coprocessor/`unaff_` fragments
  (0x4751A8, 0x479278, 0x47927C, 0x47E4CC, 0x484A44, 0x48C4A8, 0x492608, 0x49AAFA, 0x49D806,
  0x4A4F84, 0x4A6612, 0x4A6E74, 0x4A6E88, 0x4A6E74); the rest expose only parameters that were
  already named in the merged readable C.
- Field pseudo-variables (`f134`, `f138`, `f13c`, `f140`, `f48`, `f3ec`, `f3f0`, `fa0`, `f3e4`,
  `f4c`, `fa8`, `f28`, `f260`, `fd80`) were renamed only where the merged header already gave the
  field a name (`jumpMaxHeight`, `primaryHandle`, `targetHandle`, `pendingInput`, `actor`); the
  others were left alone because they are field accesses, not declarations.
- Register-reuse temporaries that carry two or more unrelated values in one function were given
  honest scratch names (`scratchValue`, `scratchFloat`, `scratchPointer`, `scratchOffset`,
  `floatBits`) rather than a precise-but-wrong noun.
- `arg2`/`arg3` of `Battle_ActionModel_NotifyEffect` (0x485108) are never read, so they stay
  unnamed; only `arg4` was renamed.

## Notes

- No name was given a confidence below 0.5, so no `maybe_` prefix was needed.
- `self` was renamed only where the merged readable C already used a better noun
  (`window`, `animRef`, `widget`).
