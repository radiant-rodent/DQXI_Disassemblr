## What was done

Worked through the batch in 29 `batchview.py --add` chunks. 140 functions answered:

- 58 `argN`/`self` parameters renamed
- 860 local declaration tokens renamed
- 918 names total, all lowerCamelCase nouns, no duplicates inside a function, no C keywords
- 0 names carry the `maybe_` prefix: every entry with confidence < 0.5 was left with no names at all,
  so the prefix rule never had to fire

Naming was driven by the merged field/global names in the current readable C (`unit->targetUnit` style),
the call targets, and the constants. Recurring decisions:

- IPC wrappers (`Svc_Ipc_*`, `Svc_Cecd_*`, `Svc_Cfg_*`, `Svc_Snd_*`, `Svc_Ndm_*`): the TLS pointer from
  `coproc_movefrom_User_R_Thread_and_Process_ID()` is `cmdBuffer`; `&g_fsArchiveEventHandle` is
  `sessionHandlePtr`.
- Fx particle emitters: `firstParticle`, `particle`, `particleId`, `particleDef`, `spawnCount`,
  `spawnAccumulator`, `frameDelta`, `particlePool`, `trigEntry`, `lcgMultiplier`, `oneFloat`/`zeroFloat`/
  `twoFloat`/`halfFloat`/`rngScale`/`piValue`/`angleScale`, `gpuRegWord`, `cmdBuffer`, `frameState`.
- Fx list updaters (`maybe_Fx_UpdateParticleList*`): `self` -> `emitter`, `node`/`nextNode` for the
  `f_e0`/`f_e4`/`f_e8` list walk, `updateTable`/`updateKind` for the `g_fxParticleListUpdateTable`
  dispatch, `keyframe`/`spriteNode`/`templateRec` for the `f_144`/`f_154`/`f_150` records.
- Fx sprite emitters: the batch's `keyframe` is the readable C's `particle` and the batch's `particle` is
  the readable C's `out` cursor, so they were renamed `particle` / `outCursor`; corner colours are
  `redA`/`greenA`/`blueA` and `redB`/`greenB`/`blueB` with their `*Byte` conversions.
- Billboard helpers: `basisX/Y/Z`, `dirX/Y/Z`, `crossX/Y/Z`, `axisX/Y/Z`, `isValid`, `scaleX/Y/Z`.
- Mem/ExpHeap: `self` -> `heap`, `g_memBlockRegistryRoot` -> `listRoot`, descriptors -> `block`/`node`.

## Notes on the data

- The batch table sometimes lists a stale token (`uVar2`, `f1c`, `forwarded2`, `arg5`, `f68`) while the
  readable C already shows a rule-pass name. The batch token was used as the key (the tool validates
  against it) and the mismatch noted in `evidence`; the variable was skipped when the readable C already
  had a good name.
- Bodies truncated in the batch view (104–369 more lines) were named only where the visible part was
  conclusive; the `evidence` field says the body is truncated and lists the reused temporaries left alone.
- Tokens reassigned to unrelated values mid-function were left unnamed and called out in `evidence`.
