# V_116 - local variable naming

Batch: `orchestration/types/batches/V_116.json`, 150 functions listed, 144 printed by
`batchview.py V_116 next` (the remaining 6 had no variables left to name).

## Result

- 144 records written to `orchestration/types/out/V_116.json`.
- 112 functions got at least one name; 32 were recorded as "reviewed, nothing clear".
- 453 locals and 20 `argN` parameters renamed.
- 40 names carry the `maybe_` prefix (28 functions with confidence < 0.5).
- `python3 tools/batchview.py V_116 --check` -> `144 answers, 0 problem(s)`.
- JSON re-parsed with `json.load` after the check: 144 records, valid.

## What was named

Worked in 18 chunks of 8 functions. Names came from the merged readable C: field names
(`self->bindingCount`, `self->cells`, `self->slotSize`, `self->childListHead`), global names
(`g_uiLayoutPlayerVtable`, `g_soundVoiceVtable`, `g_uiTextLayoutRunCallbacks`,
`g_glyphCacheFreeSpanFlag`) and the callee names in the body.

Main groups:

- UI resource cache / animator (0x00535580-0x00538F2C): cache entries, owned objects, binding
  records, pane transforms, layout pane name lookups.
- UI text layout / text buffer (0x0053ADA0-0x00554E58): metrics blocks, draw-flag words,
  glyph quad arrays, text-run copies, scroll value integration.
- Font glyph cache (0x0056C4D8-0x0056EEB8): 0x58- and 0x54-byte cell descriptors, span
  alloc/free, atlas fill pass, glyph key/metric copies.
- SARC / buffered stream (0x00535E50-0x0054972C): SFAT node table, hash lookup, buffer window.

## Skipped and why

- 32 functions omitted entirely: bodies are `halt_baddata` (unaligned interior addresses such
  as 0x00535EDC, 0x00546D4E, 0x00546D62), are one-line virtual forwarders with no argument use
  (0x00542BDC, 0x00542E44), are `GetInstance` stubs whose only remaining entry is a return
  pseudo-variable (`g_005477ac`, `g_0054b700`, `g_00555bec`, ...), or have only already-named
  parameters.
- 0x00556B3E (`maybe_Text_InsertSorted_Label`): the whole variable table is register artifacts
  (`unaff_r4/r5/r6`, `in_OV`, `in_fpscr`, `in_cr15`, `in_s1`); nothing justifiable.
- Register artifacts were left alone everywhere (`in_fpscr`, `in_s0/s1`, `extraout_r1`,
  `unaff_r*`, `in_ZR` except where it carried a real branch condition).
- Plain index-only loop counters were left as `i`/`j`/`k` where the rules allow it
  (0x00541B38, 0x0054EC70, 0x0056C4D8, 0x0056C518).
- `arg3` in 0x0056D8C4 and `arg4` in 0x00542FB8/0x00542FF0 are never referenced in the body,
  so they keep their `argN` names.
