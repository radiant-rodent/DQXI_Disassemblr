## What was named

- `Gfx_ColorTable_*` (8 functions): the fixed 12-entry RGBA palette writers. `puVar2`/`puVar1`
  became `colorTable`/`alphaEntry`, the `(u8)fill` cast `fillByte`, the `&1`-tested global
  `initGuard`, and the moving table pointer in `InitOpaqueC` `tableCursor`.
- `Gfx_Movie_*` (10 functions): the allocator-hook pairs (`g_movieStreamAllocatorA/B/C`,
  `g_movieSliceTableAllocator`) gave `allocatorHook`/`allocFunc`/`freeHookPtr`; the allocated
  objects `streamObject`/`codecContext`/`sliceTable`; the 1/0 returns `success`; the slice/row
  loops `sliceIndex`/`planeIndex`/`rowIndex`/`stagingBuffer`. `Gfx_Movie_AllocStreamObjectB`
  gave the only two parameter renames: `arg2 -> isFrameReady`, `arg3 -> syncMutex`, read
  straight off the merged field names in the body.
- `Gfx_GpuState_WriteScreenScale` (0x006B8484): command-list cursor/end (`cmdCursor`,
  `cmdCursorPtr`, `cmdEndPtr`), `packedFloat`, `floatExponent`, `reciprocalConst`, `sizeTable`,
  `scaleFactor`, `fpscr`.
- `std_StateSequence*` (about 100 functions): one shared template, so one shared naming.
  `ChangeState` -> `previousStateId`/`targetStateId`/`isValidTarget`/`stateRecord`/
  `callbackTarget`/`callbackFunc`/`didChange`; `Tick` -> `didChange`/`deltaTime`;
  `SetState` -> `accepted`.
- `Gfx_GpuState_MarkDirty` -> `gpuState`; `MoLive_Decoder_GetStreamInfo` -> `streamRecord`/
  `recordType`; `Script_Vm_GetSlotValue` -> `stackSlot`; `Field_RegisterActorClass_Actor` ->
  `classListNode`/`initializedFlag`/`registryHeadNode`/`selfLink`/`registryNode`.

## Skipped and why

- 27 functions: every `std_StateSequence*_Delete` destructor (a single `func_0010F6CC(self)`
  tail call, `self` already named) plus `std_StateSequence39_Delete`. Nothing to rename.
- Parameters left as `argN` where the body never reads them or only stores them into an
  unnamed field: `Gfx_ColorTable_FillOpaque` (`arg1`/`b`/`c`/`dst` unused, the real pointer is
  `in_r3`), `Gfx_ColorTable_InitOpaqueC` (`arg1`), `Gfx_Movie_AllocStreamObjectA` (`arg2`/
  `arg3` -> +0x14/+0x18), `Gfx_Movie_AllocSliceTable` (`arg2` -> +0x10),
  `Gfx_Movie_AllocStreamObjectC` (`arg2`/`arg3` -> f_20/f_24), `Gfx_Codec_GetStreamInfo`
  (`arg2`), and all four params of `Gfx_CmdList_AddQuadFixed` (the batch tokens `coord`/`scale`
  do not match the current signature `width`/`height`, and none of them is read).
- Locals reused for two unrelated values were left unnamed rather than given a wrong name:
  `iVar4` in `Field_RegisterActorClass_Actor`, `iVar3` in `Gfx_Movie_AllocSliceTable` and
  `Gfx_Movie_AllocStreamObjectC`, `iVar2` in `Gfx_Movie_ConvertSliceRowsTo16bpp`, `i` in
  `Gfx_Movie_ConvertFrameRowsTo16bpp`, `iVar3` in `std_StateSequence41_ChangeState`.
- Damaged decompilations: `std_StateSequence12_QueueState` (`unaff_r6`, `in_r12`, `arg4`
  undefined) got only the four names the visible code supports, at confidence 0.5;
  `Script_Vm_GetSlotValue`'s `in_NG`/`in_OV` condition-flag pseudo-variables were left alone.

## Notes for the merge

- `Gfx_CmdList_AddQuadFixed` (0x006B8484) has a stale variable table: the batch lists params
  `arg1, arg2, coord, scale` while the current readable C declares `arg1, arg2, width, height`.
  Only locals were renamed there, so the merge cannot mis-apply a parameter name.
- `std_StateSequence*` names are deliberately identical across the ~100 clones; they describe
  the same vtable-slot contract (slot 3 ChangeState, slot 4 QueueState, slot 5 SetState).
