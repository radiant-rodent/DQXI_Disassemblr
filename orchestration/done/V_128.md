# V_128 - local variable naming

Batch `orchestration/types/batches/V_128.json`, 146 functions. The rule pass had already named 45 of
them, so `batchview.py` printed 101 functions to review; all 101 were answered.

## Result

- 101 records in `orchestration/types/out/V_128.json`
- 25 `argN`/`self` parameters renamed
- 347 local declaration tokens renamed
- 31 names carry the `maybe_` prefix (confidence below 0.5)
- `python3 tools/batchview.py V_128 --check` -> `101 answers, 0 problem(s)`
- JSON re-parsed with `json.load` after the last write: valid

## What the batch contained

Almost the whole batch is one module's UI colour/palette initialisers plus its static-object
registration stubs, so the naming is highly repetitive and rests on the same evidence each time:

- `Ui_InitColorPalette_*` (about 60 functions): `puVar1`/`puVar2` is always the byte pointer into the
  0x30-byte palette block (`paletteBytes`); `uVar1` is `(u8)alpha` (`alphaByte`); `puVar1` in the
  `*currentColor = arg3` variants is the four-0xff current-colour word (`currentColorBytes`); a
  `puVar3`/`pbVar1` that is only dereferenced as a one-time-init flag is `initStateFlag`. The
  remaining `arg3` parameter of the three-argument variants is the alpha word written into
  `currentColor[0..2]`, so it became `alpha`.
- `Ui_RegisterStaticObject_*` / `Ui_CreateStaticTextWidgets_*` (about 25 functions): the recurring
  pattern is `pcVar*` = `&g_fieldActorRegistryInitializedFlag` (`registryInitFlag`), `piVar*` =
  `&g_fieldActorRegistryHeadNode` (`registryHeadNode`), the allocated node (`registryNode`) with its
  self-referential next pointer (`nodeSelfPtr`), the vtable word (`widgetVtable`), the allocation
  size from `func_0011FE8C` (`blockSize`), and the class record that receives the `s_*` string at
  `f_10` and `g_fieldGadgetListArray`/`&g_actorBaseClass` at `f_c` (named after that string, e.g.
  `playerMenuRecord`, `roofSwitchRecord`, `dragonRiderRecord`).
- `std_InsertionSort*` / `std_IntrosortLoop16BitRecords` / `std_Sort16BitRecords` /
  `std_U64ToDouble`: named from the sort structure (`current`, `previous`, `writeCursor`,
  `readCursor`, `currentId`, `otherRecord`, `pivotElement`, `pivotKey`, `mantissa`,
  `exponentWord`).

## Skipped / left alone

- 4 functions recorded as reviewed with nothing to add:
  - `0x006944CC Ui_InitColorPalette_7AB514` - no locals, both parameters already descriptive.
  - `0x00697A48 maybe_Ui_InitColorPalettesAndMetrics_7ABEB4` - readable C not found; only
    uninitialised `unaff_r5`/`unaff_r6` registers.
  - `0x0069AE50 maybe_Ui_InitStateBlock_7AC230` - readable C not found; `arg2`/`b` have no body to
    justify a name.
  - `0x00723EF0 maybe_std_DoubleToUnsigned` - body is only a call plus `halt_baddata`; the single
    parameter is already named `value`.
- `unaff_*`, `in_r3`-style uninitialised registers, `in_cr13`/`in_cr15` coprocessor registers and
  literal-only temporaries (`uVar5`/`uVar6` holding `0x00100000`/`0x002A56A4` for `func_0010009C`,
  `puVar5`/`puVar6`/`puVar7` register leftovers) were deliberately not renamed: nothing in the body
  justifies a noun.
- `self` was kept wherever it was already `self`; it was only replaced where the parameter is
  demonstrably a state block (`arg2` -> `stateBlock` in `Ui_RegisterStaticObject_7A3FB8`).
- Already-descriptive parameters (`alpha`, `currentColor`, `begin`, `end`, `depth`, `lo`, `hi`,
  `shift`, `value`, `flags`, `target`, `b`) were left untouched unless the body showed the name was
  wrong (`flags` -> `alpha` in `Ui_InitColorPalette_7A598C`, where `(u8)flags` fills every palette
  slot).
- Functions whose decompilation is corrupt (`0x006972A0`, `0x00697454`, `0x0069D0C4`) got only the
  names that survive the corruption; the garbage prologue variables were left alone.

## Decisions worth knowing

- `iVar7`/`iVar8`/`iVar9` in the registration stubs are reused for two unrelated values (allocator
  slot, then `*headNode + 4`); they are named `maybe_slotIndex` rather than pretending to one role.
- Where a class record variable is reused across two registrations in one function, it is named
  after its dominant (first) use and the reuse is noted in `evidence`.
- Literal float/colour words (`0x3F2E40F1`, `0x3F800000`, `0x3F490FDB`) got `maybe_colorWord` /
  `maybe_scaleValue` / `maybe_angleValue` rather than a subsystem guess.
