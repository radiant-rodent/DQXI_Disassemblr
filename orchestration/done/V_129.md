## Naming basis

Names come from the merged field and global names in the readable C (`gameWork`, `uiCore`,
`fieldActor`, `g_actorAimLocatorHandleMap`, `g_actor2DHandleTable`, `g_actorAttachGadgetHandleMap`,
`g_dataManager`, `g_gameDataManagerVtable`, `g_messageFormatArgSlots`, ...) plus the callee names in
each body. Recurring patterns resolved the same way across the batch:

- `*(int *)(*gameWork + 8)` -> `gameState`; `+0x6c` -> the field gadget/script list; `+0x50` ->
  `fieldActor`; `+0x48` -> `partyStatus`; `+0x54` -> the 2D/field object; `+0xb4` -> the
  environment/scene object; `+0x24a98` -> the game data table.
- The `f_430`/`f_434` pair is an array of 0x10-stride actor entries, so `arg1` bounds-checked
  against `(f_434 - f_430) >> 4` became `actorIndex` and the entry itself `actorEntry`.
- The `>> 6` / `& 0x3f` handle split with a lookup in `g_actorAimLocatorHandleMap` or
  `g_actor2DHandleTable` gave `locatorHandle`/`actorHandle` plus `handleEntry`.
- `uStack_10`/`uStack_18`/`uStack_20` slots whose address is passed to `Os_GetGameWork` or
  `Game_GetWork` became `gameWorkOut`; the `Ui_GetCore` equivalent became `uiCoreOut`.
- `osGetGameWork`/`gameGetWork`/`uiGetCore` locals became `gameWork`/`uiCore` where the rule pass
  had not already claimed that token in the same function.
