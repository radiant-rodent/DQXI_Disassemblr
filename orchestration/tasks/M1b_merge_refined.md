Apply the refined (second-pass) naming proposals and regenerate the readable C.

Input: `orchestration/naming/refine/out/R_###.json` (from the `R_*` tasks, generated by
`R1_refine_plan`). Each entry carries `address`, `name`, `signature`, `params`, `summary`,
`confidence`, `evidence`, `previous_name`, `previous_confidence`, `change`
(`confirmed` | `corrected` | `kept_maybe`).

Owns: `tools/merge_names.py` (additive changes only — add a refine mode, do not rewrite the
existing N_* merge path), `symbols.json`, `symbols_recovered.json`,
`decomp/ghidra/functions_merged.jsonl`, `decomp/ghidra/functions_index.json`,
`decomp/readable/**`, `orchestration/done/M1b_merge_refined.md`.

Steps:

1. **Validate.** Same checks as M1: every batch file address has a proposal (say which are
   missing and re-batch just those with
   `python tools/make_refine_batches.py --prefix R_redo --addresses missing.txt`); all addresses
   exist in `functions_index.json`; every `name` is a valid C identifier; no proposal/name
   clashes with any other final name (ties broken by lower address, `_2` suffix as in M1; the
   refine merge must stay idempotent like M1: rerun keeps `_2`, never `_3`).
   `change:"confirmed"` entries must keep `previous_name` minus its `maybe_` prefix;
   `kept_maybe` entries must keep confidence < 0.5 and the `maybe_` prefix; refuse to merge any
   entry where `change:"confirmed"` but confidence < 0.5 (fix mechanically: treat as
   `kept_maybe`, flag it in the report).
2. **Spot check 30 random entries** against their readable C body + named neighbours, as M1 did.
   If any batch has >30% wrong proposals, regenerate a redo batch for its addresses
   (`--prefix R_redo --addresses <file>`) and record it.
3. **Apply.** Extend `tools/merge_names.py` with a refine mode (e.g. `--refine`) that:
   - reads `orchestration/naming/refine/out/R_*.json`,
   - applies the new names/signatures/summaries/confidence/evidence/params on top of the merged
     state of the addresses they cover (refined names win over the R1-time names; untouched
     addresses keep their current values),
   - keeps `change`, `previous_name`, `previous_confidence` and `batch:"R_###"` in the merged
     rows/symbol entries so history is auditable,
   - re-runs the M1 name-clash machinery across ALL final names (refined + existing).
4. **Regenerate.** `decomp/readable/` in full (clear first, as M1 did). Verify no file re-read
   fails strict UTF-8.
5. **Keep the build green.** Required before finishing:
   - `python tools/build.py` — `code.bin`/`.code` must still bit-match retail (naming never
     touches bytes; if it fails something else changed the tree — halve scope and rerun).
   - `python tests/run_all.py` (must pass as currently, 223/223 at last count).
   - `python tools/verify_project.py` (OVERALL PASS).
   - `python tools/merge_names.py --check` (extended to cover refine inputs) cleanly.
6. **Report** (`orchestration/done/M1b_merge_refined.md`), and put the numbers where the
   orchestrator reads them:
   - `maybe_` count before and after (merged catalog),
   - how many `confirmed` / `corrected` / `kept_maybe`,
   - batches with problems/redo,
   - coverage: named (non-`maybe_`) functions 8,492 → ?/18,787.
7. **Next round.** If >1,500 `maybe_` remain AND this pass converted >20% of its inputs,
   generate ONE more round the same way:
   `python tools/make_refine_batches.py --prefix R2` (after re-running the merge + readable
   regen so the scores see the new context) and write `orchestration/tasks/R2_###.md`
   accordingly (dependencies `after: R1_refine_plan` → `M1b_merge_refined`).
   If not, stop, and instead list the remaining `maybe_` functions that need manual reverse
   engineering in the done report (group by cluster/region, largest first).

Never modify `..\3DS_Translate`, `asm/`, `original/`, or the readable-C generator's
own behaviour (`tools/readable_c.py` beyond what M1 already does). All text/JSON writes are
UTF-8.
