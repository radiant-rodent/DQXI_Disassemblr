# P1_progress_types - show globals, classes and locals on the progress overview

The overview (`progress/progress.html`, generated by `tools/progress.py`) only tracks native
**functions**: named share, summaries, coverage map. The type-recovery work - global
variables (`G_*`), classes/struct fields (`S_*`) and local variables (`V_*`) - runs as
hundreds of batches but is invisible there, so the user cannot see it moving. Add it.

Owns ONLY: `tools/progress.py`, `tests/test_progress*.py` (create one if none covers this),
`progress/**` (regenerated output), `AGENT_LOG.md` and `orchestration/done/P1_progress_types.md`.
Do not touch `orchestration/dispatch.py`, the batches, or any worker output.

## Data (read-only)

- Inputs to recover: `orchestration/types/globals.json`, `orchestration/types/structs.json`,
  `orchestration/types/locals.json` (what exists), and the batch files in
  `orchestration/types/batches/` (`G_*.json` globals, `S_*.json` classes/fields, `V_*.json` locals).
- Worker answers: `orchestration/types/out/{G,S,V}_*.json`. An answer counts as **named** when
  its name does not start with `maybe_` and its confidence is >= 0.5 (same rule as functions);
  `maybe_` answers count as **guessed**.
- Merged result (after `M2_types_merge` / `M3_vars_merge` run): `orchestration/types/merged/`
  and `include/dqxi/**`. Report "merged into headers" separately from "answered by a worker".
- Read `orchestration/types/README.md` for the formats. Inspect a few real files before coding;
  tolerate missing/partial/malformed files (count them, never crash - the dispatcher runs this
  script after every task and ignores its failures, so a crash silently freezes the page).

## What to add

1. In `progress.json`: a `types` block with, for globals, classes, fields and locals:
   `total`, `answered`, `named` (confident), `guessed` (`maybe_`), `merged`, and batch counts
   `done / total` per kind (done = `orchestration/done/<id>.md` exists).
2. On the overview page: a "Data & types" card next to the functions card, same visual style,
   one row per kind with a progress bar (named + guessed stacked) and the batch counts; plus a
   `progress/badge-types.svg` badge like the existing ones.
3. A line in the history (`history.jsonl` / `history.svg`) so the trend shows, if that fits the
   existing history format without breaking old entries.
4. Keep the run time of `tools/progress.py` about where it is (it runs after every task).

## Done when

- `python tools/progress.py` succeeds and `progress/progress.html` shows the new card with real
  numbers (state them in your report).
- `python -m pytest tests -q -k progress` passes, including a new test that feeds a small fake
  types tree (one G, one S, one V answer, one malformed file) and checks the counts.
- The functions numbers are unchanged by your edit (compare before/after in the report).
